# Sarvam AI 面试题库

这一家的题有一个统一的前提：**语言是低资源的，硬件不是数据中心。**
这两个约束推出了一整套与"英文 + 8 卡 H100"完全不同的算术。

**第一件事是"低资源"贯穿全栈。**
它在 tokenizer 上表现为 **fertility 是英语的 2.7 倍**（纯英文词表下印地语 6.00 vs 英语 2.24），
在向量检索上表现为 **泰米尔语 recall 只有 0.62**（印地语 0.85），
在评测上表现为 **机翻的题目更简单、得分反而更高（0.78 vs 母语者重写的 0.61）**。
**而这三处都源于同一个机制：该语言在"训练配比"里的占比。**
所以这一家最核心的一句话是：**"fertility 是词表配比的函数，不是语言的固有属性。"**

**第二件事是"约束会改变工具箱"。**
没有数据中心 GPU 时，**端侧的硬约束是显存与带宽而不是算力**（3B INT4 的权重读取 30.0 ms vs 算力 0.75 ms，差 40 倍），
所以 **MoE 这种"省算力不省显存"的技术不适合端侧**。
250 ms 的电话延迟预算里，**朴素串行是 1,130 ms（超 4.5 倍）**，
所以答案不是"换个更快的模型"，而是 **填词（200 ms）+ 缩短 hangover（130 ms）+ 小模型起草（200 ms）+ 流式 TTS（100 ms）** 的叠加。

**第三件事是"要敢报负结果"。**
VAD 的实验里，**自适应噪声底在高 SNR 下不如紧阈值（0.893 vs 0.931）、在 −5 dB 时也崩（0.223）**；
**谱平坦度把误报从 5.5% 压到 0%，但漏报从 17.9% 升到 32.8%，F1 反而下降**。
这两条都与"教科书结论"相反，但它们是实测出来的——**而"诚实地说测不出来"比"报一个小数点差异"更专业**。

准备这一家时，建议把**"按配比加权"**（fertility、recall、评测分数）和**"约束倒推"**（延迟预算、准确率门槛）练熟。
前者解释"为什么低资源语言处处吃亏"，后者解释"为什么答案往往不是'换更好的模型'"。

## 准备建议

1. **先把"按配比加权"练熟**：01 的流量加权 fertility、04 的查询分布加权 recall、08 的语言分层分数。**三道题都在说同一件事：平均值会掩盖低资源语言的短板。**
2. **02 与 01 是一对**：**01 讲"怎么测"、02 讲"为什么它排第一"**。而 02 的核心是"一个系数同时缩放四个量"——**这个说法值得背下来**。
3. **03、06、12 是"约束倒推"的三道题**：一个从"没有数据中心 GPU"倒推工具箱、一个从"只有 5 千句"倒推能教什么、一个从"人工错误率 2%"倒推准确率门槛。**它们的共同方法是"先算约束，再选方案"。**
4. **05 与 06 是一对**：**05 讲"用 RLVR 提正确性"、06 讲"只有几千句时怎么适配"**。而 05 的核心论证是"**12 种语言的偏好数据要 3,000 FTE，而检查器跨语言复用**"。
5. **09、10、11 是语音链路的三段**：**VAD（入口）→ ASR（转写）→ TTS（输出）**。而 07 是它们共同的延迟预算。**四道题连起来看就是完整的语音系统。**
6. **09 与 10 都有"反直觉"的实测结果**：**自适不是万能的、谱平坦度不是免费的改进、VAD 门控能修幻觉**。准备时要把这些"负结果"讲清楚——**它们是这一家最看重的东西**。
7. **08 与 12 是"评估"的两面**：一个讲"模型能力怎么测"、一个讲"上线门槛怎么定"。**两者共享"金标准集 + 人工评审 + 功效计算"。**
