# Together AI 面试题库

Together AI 的面试有一条很清楚的主线：**把「推理」当作一门有单位经济性的生意来做**。所以它的题几乎都带一个可算的判据——
调度器要看 KV 与 token 预算、定价要看吞吐与利用率、投机解码要看接受率与算力是否闲置、训练效率要按通信量分解。
七道题里没有一道是「背概念」，全部要求落到**数字与取舍**上。

另一个特征是**客户视角**：第 7 题直接就是「客户要迁移，你怎么推进」，第 4 题是「给专用 endpoint 定价」。
这意味着面试官会反复问「你的依据是什么、代价是什么、怎么验证」。

## 这家公司的面试怎么准备

**第一，所有答案都要带一个算式。** 这个题库里每一道题都能落到一个可算的判据上：集群调度看 KV 与 token 预算、定价看「GPU 数 × 单价 ÷ 吞吐」、投机看 $\mathbb{E}[A]/(1+c\gamma)$、训练效率看「通信字节 ÷ 带宽」与「$(p-1)/(m+p-1)$」、serverless 看「到达率 × 加载时间」。**面试里能写出式子并代入本仓库常数（989 TFLOPs、3.35 TB/s、320 KiB/token、\$2/GPU·h），基本就赢了一半。**

**第二，分清「哪个区间」。** 本库反复出现的结论都是**分区间的**：batch 在权重受限区越大越便宜，进 KV 受限区后就不再便宜；投机在算力闲置时是收益、饱和时是税；扩展效率在弱扩展与强扩展下含义完全不同。**答这类题时先说清「我在哪个区间」，再给结论**，比直接报一个数字专业得多。

**第三，客户交付题要有顺序与兜底。** 第 7 题的评分点是"先澄清动机 → 建客户评估集 → 选型与形态 → 补缺口 → 算平价 → 灰度迁移 + 回退"。**顺序错了（例如先选模型）就会被扣分**；没有回退方案会被直接追问。

**第四，注意「不做什么」的判断。** 什么时候该建议客户**不要**迁移、什么时候该关掉投机、什么时候该显式拒绝请求而不是无限换出——这类「负向结论」在本库里出现频率很高，也正是平台公司最看重的判断力。
