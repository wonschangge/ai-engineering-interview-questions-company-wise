# Databricks 面试题库

这家公司的面试流程本身就是信号：**技术初筛偏实战编程（并发或数据密集型）**，onsite 里有一轮**分布式系统或 Spark 内部机制**，
还有一轮 **GenAI/ML 设计**。所以这个题库的九道题呈现出很清晰的两段式结构——
**前五道是「能不能把数据规模的活干对」**（并发、近似算法、区间检索、倾斜、恰好一次），
**后四道是「能不能把 AI 系统交付出去」**（微调决策、上线门禁、客户分歧、模型下线）。

值得特别准备的是：**这里的每道题都有「机制层」的追问**。
答「加盐解决倾斜」不够，要能说出「AQE 为什么对单一超大 key 无效」；
答「Delta 支持 exactly-once」不够，要能说清「写已提交但 commit log 未写」这一格靠什么兜住。

## 这家公司的面试怎么准备

**第一，每道题都要能往下钻两层。** 这个题库的所有题在机制层都有明确答案：
批处理的「锁内不做 IO」、top-K 的「三种保证形式」、CIDR 的「两种语义」、倾斜的「AQE 为什么无效」、
Streaming 的「幂等键在哪一层」。**能说出机制，才算答对。**

**第二，一定要能手算。** 2 TB / 128 MB = **16,384 个 task**；70B 全量微调优化器状态约 **16 字节/参数**；
1 万区间下二分查询 **数百万次/秒**；检出 5 个百分点差异需要 **几百对**样本。
这些数字在这一家的面试里出现频率极高。

**第三，交付题要按「事先条件 → 计划 → 门禁 → 兜底」来讲。** 第 07–09 三道题是同一套方法论的三个应用：
**先问「你怎么知道它坏了」，再问「你怎么退回去」**。把红线（二值项）与加权项分开，是这个题库反复强调的纪律。

**第四，学会用数据说服人（包括客户）。** 第 08 题的核心不是技术判断，而是**把分歧转化为可检验的实验**：
预注册判据、留出集、配对比较、TCO。**「我说服了客户」远不如「我们事先约定了判据，数据说了算」。**
