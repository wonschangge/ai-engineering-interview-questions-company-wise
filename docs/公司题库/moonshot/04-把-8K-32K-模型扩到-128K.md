## 一句话答案

> **三步走：改位置编码 → 少量继续预训练 → 按位置分层验证。**
> **① 为什么外推会失效（可算）**：RoPE 每个维度对有自己的波长 $\lambda_i=2\pi\cdot\text{base}^{2i/d}$。**波长超过训练长度的维度「从未转满一圈」**——模型没见过的相位区间，外推必然失效。本机算例（$d_{\text{head}}=128$、base=10,000、训练 8K）：**64 个维度里有 14 个（22%）波长 > 8K**；训练 4K 时是 **28%**。
> **② 三种改法，按「是否保住局部分辨率」排序**：
> | 方法 | 做法 | 拉伸方式 | 代价 |
> | --- | --- | --- | --- |
> | **PI（位置插值）** | 位置除以 $s=L_{\text{target}}/L_{\text{train}}$ | **所有维度均匀拉伸 $s$ 倍** | **近距离分辨率压到 $1/s$**（s=16 时压到 1/16） |
> | **NTK 缩放** | 改 base：$\text{base}'=\text{base}\cdot s^{d/(d-2)}$ | **逐维度拉伸 $s^{2i/(d-2)}$**：$i{=}0$ 时 **1.00×**、$i{=}63$ 时 **$s$×** | 需要少量微调；实现简单 |
> | **YaRN** | **NTK-by-parts 斜坡** + **注意力温度补偿（mscale）** | 高频**不动**、低频**拉满**、中间**平滑过渡** | 实现稍复杂，但**微调数据需求最小** |
> 本机算例（8K → 128K，s=16）：
> - **NTK 的逐维度拉伸**：$i{=}0$ **1.00×**（不动）、$i{=}16$ 2.02×、$i{=}32$ 4.09×、$i{=}48$ 8.27×、$i{=}63$ **16.00×**；**64 个维度里 16 个拉伸 <2×**（局部分辨率基本保住），而 **PI 是全部 16×**；
> - **YaRN 的分段**：**26 个维度完全不插值**、**14 个完全插值**、**24 个在斜坡上**（平均插值比例 0.24）；
> - **注意力温度**：$\text{mscale}=0.1\ln s+1=1.277$（等效温度 **0.783**）——因为长上下文下注意力分布变平，需要补偿。
> **③ 继续预训练仍然必需**（改位置编码只解决「能不能算」，不解决「会不会用」）：
> - **数据稀缺性**：若语料里只有 **0.5%** 的 token 来自 ≥32K 文档，要凑 **10B** 长上下文 token 得扫描 **2T** 原始 token（相当于把预训练语料再过一遍）；
> - **数据形态**：长文档（跨段推理）+ 打包后的短文档（局部任务）都要有——**只喂拼接的短文档会学到「假长上下文」**。
> **④ 验证必须按位置分层**：只看困惑度会漏掉「中间遗忘」（串 [[moonshot-01]]）。
> 一句话判据：**"扩上下文 = 改位置编码（保局部、拉全局）+ 少量继续预训练（教它用）+ 分层验证（确认真的能用）"**——三者缺一不可。

## 面试官在考什么

- **能否解释外推失效的机制**：**RoPE 的波长与训练长度的关系**（哪些维度从未转满一圈）——这是最硬的技术点，能算出来最好。
- **是否知道 PI 的代价**：**均匀拉伸会压扁近距离分辨率**（s=16 时压到 1/16）——只答「插值就行」是不完整的。
- **能否说清 NTK 的「逐维度」本质**：**高频不动、低频拉满**（本机：1.00× → 16×），而不是「把 base 调大」这么含糊。
- **YaRN 的两个组成**：**NTK-by-parts 斜坡** + **注意力温度补偿**（mscale）——尤其后者常被忽略。
- **继续预训练的必要性**：能否指出「改位置编码 ≠ 会用长上下文」，以及**长文档数据的稀缺性**（0.5% → 2T 扫描）。
- **数据形态**：能否区分「长文档训练」与「拼接短文档训练」的差别（后者可能学到假的长上下文）。
- **评估方法**：能否指出**按位置分层测**（开头/中间/结尾），而不是只看困惑度或单一 benchmark。
- **工程取舍**：能否指出不同方法的**微调数据需求差异**（PI 需要更多、YaRN 更少），以及**推理时的实现代价**（mscale 需要改 kernel）。
- **诚实**：承认「名义窗口 ≠ 有效窗口」，且**扩窗之后仍要配合检索**（串 [[moonshot-07]]）。

**常见错误答案**

- 只说「把 RoPE base 调大」（不讲逐维度拉伸与高频保持）。
- 认为「位置插值就够了，不用再训练」（**外推只是让它能算，不保证会用**）。
- 忽略 PI 的局部分辨率损失（近邻 token 的位置变得几乎无法区分）。
- 不提注意力温度补偿（长上下文下注意力分布变平，是真实的性能问题）。
- 只喂拼接的短文档当长上下文数据（学到「假长上下文」）。
- 用困惑度作为唯一验收标准（漏掉中间遗忘）。
- 认为扩到 128K 就能「不用检索」（有效窗口远小于名义窗口，串 [[moonshot-01]]）。
- 忽略推理实现代价（mscale/YaRN 需要 kernel 支持，否则吃不到收益）。

## 原理与推导

### 1. 为什么外推会失效：波长分析

RoPE 把每个维度对 $(2i,2i+1)$ 当作一个二维旋转，频率

$$\theta_i=\text{base}^{-2i/d}\quad\Rightarrow\quad\lambda_i=\frac{2\pi}{\theta_i}=2\pi\cdot\text{base}^{2i/d}$$

**判据**：**若 $\lambda_i>L_{\text{train}}$，这个维度在训练上下文内从未完成一次完整旋转**——它见过的相位是训练长度决定的**子区间**，超出之后就是外推。

**本机算例**（$d_{\text{head}}=128$、64 个维度对、base=10,000）：

| 训练长度 | $\lambda<L/32$（高频，确定） | 临界带 | $\lambda>L$（**从未转满一圈**） |
| --- | --- | --- | --- |
| 4,096 | 21 | 25 | 18（**28%**） |
| **8,192** | 26 | 24 | **14（22%）** |
| 32,768 | 36 | 24 | 4（6%） |
| 131,072 | 46 | 18 | 0 |

**读法**：**训练长度越短，「未转满一圈」的维度越多**——这就是「8K 训练的模型直接喂 128K 会崩」的机制。**注意 22% 不是小数**：这些维度的相位在长上下文里完全落在训练分布之外。

### 2. PI：均匀拉伸，代价是局部分辨率

**做法**：把位置 $m$ 换成 $m/s$（$s=L_{\text{target}}/L_{\text{train}}$）——等价于**所有维度的波长都乘以 $s$**。

**收益**：位置范围被压回训练区间，外推变成「内插」。

**代价**：**相邻 token 的位置间隔缩小 $s$ 倍**——**近距离分辨率被压到 $1/s$**（s=16 时压到 1/16）。而语言里**大量依赖近距离顺序**（词序、语法、局部指代），所以 PI 通常需要**更多微调**才能恢复。

### 3. NTK：逐维度拉伸（高频不动、低频拉满）

**做法**：把 base 调大：

$$\text{base}'=\text{base}\cdot s^{\frac{d}{d-2}}\quad\Rightarrow\quad
\frac{\lambda_i'}{\lambda_i}=s^{\frac{2i}{d-2}}$$

**关键**：**拉伸因子随维度变化**——

| 维度 $i$ | 原波长 | **PI 拉伸** | **NTK 拉伸** | NTK 新波长 |
| --- | --- | --- | --- | --- |
| 0（最高频） | 6 | 16.0× | **1.00×（不动）** | 6 |
| 16 | 63 | 16.0× | 2.02× | 127 |
| 32 | 628 | 16.0× | 4.09× | 2,569 |
| 48 | 6,283 | 16.0× | 8.27× | 51,952 |
| 63（最低频） | 54,410 | 16.0× | **16.00×（拉满）** | 870,562 |

**统计（s=16）**：**16/64 个维度拉伸 <2×**（局部分辨率基本保住）、32/64 拉伸 <4×、16/64 接近拉满。**而 PI 是全部 16×。**

**读法**：**这就是「PI 伤局部、NTK 不伤」的量化解释**——高频维度（决定「相邻 token 的区分度」）保持不变，只把长波长维度拉伸去覆盖新范围。

### 4. YaRN：把 NTK 做成「分段斜坡」+ 注意力温度

**① NTK-by-parts**：按波长把维度分三类（$\beta=32$、$\gamma=1$ 是常用取值）：

| 类别 | 判据 | 处理 |
| --- | --- | --- |
| 高频 | $\lambda<L_{\text{train}}/\beta$ | **完全不插值**（保住局部顺序） |
| 低频 | $\lambda>L_{\text{train}}\cdot\gamma$ | **完全线性插值**（覆盖新范围） |
| 中间 | 其余 | **线性斜坡过渡**（避免突变） |

**本机算例**（8K → 128K）：**26 个完全不插值、14 个完全插值、24 个在斜坡上**（平均比例 0.24）。

**② 注意力温度补偿**：长上下文下注意力分布会**变平**（熵上升、关键 token 权重被摊薄，串 [[moonshot-01]] 的「注意力稀释」）。YaRN 用一个与 $s$ 相关的缩放：

$$\text{mscale}=0.1\ln s+1$$

| $s$ | mscale | 等效温度 |
| --- | --- | --- |
| 4 | 1.139 | 0.878 |
| **16** | **1.277** | **0.783** |
| 32 | 1.347 | 0.743 |

**读法**：**这是 YaRN 区别于「纯 NTK」的关键一步**——它不只改位置，还**补偿了注意力分布的统计变化**。**代价是需要 kernel 支持**（否则拿不到收益）。

### 5. 继续预训练：数据是真正的瓶颈

**改位置编码只解决「能不能算」，不解决「会不会用」**——模型必须**见过长上下文样本**才知道如何利用它们。**数据稀缺性是硬约束**：

| 目标长上下文 token | 语料中 ≥32K 文档占比 | 需扫描原始 token |
| --- | --- | --- |
| 1B | 0.5% | 0.2T |
| **10B** | **0.5%** | **2.0T** |
| 10B | 5% | 0.2T |

**读法**：**长文档越稀缺，长上下文训练越贵**。若只有 0.5% 的 token 来自 ≥32K 文档，凑 10B 长上下文 token 要扫描 **2T** 原始 token——**相当于把预训练语料再过一遍**。**这就是为什么「长上下文」是一项数据工程，而不只是算法技巧。**

**数据形态也很重要**：
- **真长文档**：教「跨段聚合/全局推理」；
- **打包的短文档**：教「局部任务」，但要**保证注意力不跨文档泄漏**（否则学到错误的关联）；
- **只喂拼接短文档**：模型学到的是「假长上下文」（在拼接边界处表现异常）。

### 6. 完整配方（三步）

| 步骤 | 做什么 | 关键参数/判据 |
| --- | --- | --- |
| **① 改位置编码** | NTK-by-parts 斜坡 + mscale | $\beta=32$、$\gamma=1$、$s$ 取目标/训练长度 |
| **② 少量继续预训练** | 长文档 + 打包数据混合 | 数据量按「目标长 token / 长文档占比」估算；学习率小、步数少 |
| **③ 分层验证** | 按位置分层测（头/中/尾）+ 跨段聚合任务 | 不能只看困惑度；要看**有效窗口** |

**读法**：**三步缺一不可**——只做①会「能算但不会用」，只做②会在错误的位置编码上浪费算力，不做③会**误判能力**。

```python
# 长上下文扩展：RoPE 波长分析、PI/NTK/YaRN 的逐维度拉伸、注意力温度与数据需求
import math
import statistics
from dataclasses import dataclass
from typing import Dict, List, Tuple

D_HEAD, PAIRS, BASE = 128, 64, 10_000.0

def wavelengths(base: float = BASE) -> List[float]:
    """RoPE 第 i 个维度对的波长 λ_i = 2π · base^(2i/d)"""
    return [2 * math.pi * base ** (2 * i / D_HEAD) for i in range(PAIRS)]

def classify(L_train: float, base: float = BASE, beta: float = 32.0,
             gamma: float = 1.0) -> Tuple[int, int, int]:
    lam = wavelengths(base)
    hi = sum(1 for l in lam if l < L_train / beta)        # 高频：不做插值
    lo = sum(1 for l in lam if l > L_train * gamma)       # 低频：完全插值
    return hi, PAIRS - hi - lo, lo

print(f"① 波长分析（d_head={D_HEAD}、{PAIRS} 个维度对、base={BASE:.0f}）")
print("   λ_i = 2π·base^(2i/d)；波长 > 训练长度 的维度【从未转满一圈】-> 外推必然失效")
print(f"  {'训练长度':>9} {'高频(λ<L/32)':>12} {'临界带':>8} {'λ>L(未转满一圈)':>15} {'占比':>7}")
for L in (4096, 8192, 32768, 131072):
    hi, mid, lo = classify(L)
    print(f"  {L:>9} {hi:>12} {mid:>8} {lo:>15} {lo/PAIRS:>7.0%}")
print("   读法：**8K 训练时 22% 的维度从未转满一圈**（4K 时 28%）—— 这就是直接喂 128K 会崩的机制")

print("")
print("② PI vs NTK：拉伸方式的本质差别（s = 16，即 8K -> 128K）")
s = 16.0
print("   PI : 所有维度波长 × s（均匀）")
print("   NTK: 第 i 维波长 × s^(2i/(d-2))（逐维度）")
print(f"  {'维度 i':>6} {'原波长':>10} {'PI 拉伸':>9} {'NTK 拉伸':>10} {'NTK 新波长':>12}")
for i in (0, 8, 16, 24, 32, 40, 48, 56, 63):
    l0 = wavelengths()[i]
    f = s ** (2 * i / (D_HEAD - 2))
    print(f"  {i:>6} {l0:>10,.0f} {s:>8.1f}x {f:>9.2f}x {l0 * f:>12,.0f}")
facs = [s ** (2 * i / (D_HEAD - 2)) for i in range(PAIRS)]
print(f"  统计（s={s:.0f}）：拉伸 <2x 的维度 {sum(1 for f in facs if f < 2)}/{PAIRS}（局部分辨率保住）、"
      f"<4x 的 {sum(1 for f in facs if f < 4)}/{PAIRS}、接近拉满的 {sum(1 for f in facs if f >= s/2)}/{PAIRS}")
print("   读法：**高频不动（1.00x）、低频拉满（16.00x）** —— 这就是「PI 伤局部、NTK 不伤」的量化解释")

print("")
print("③ YaRN 的分段斜坡（NTK-by-parts，β=32、γ=1）")
def ramp(L_train: float, base: float = BASE, beta: float = 32.0, gamma: float = 1.0) -> List[float]:
    out = []
    for l in wavelengths(base):
        if l < L_train / beta:
            out.append(0.0)
        elif l > L_train * gamma:
            out.append(1.0)
        else:
            out.append((l - L_train / beta) / (L_train * gamma - L_train / beta))
    return out
r = ramp(8192)
mid_vals = [x for x in r if 0 < x < 1]
print(f"  8K -> 128K：完全不插值 {sum(1 for x in r if x == 0.0)} 个 | "
      f"完全插值 {sum(1 for x in r if x == 1.0)} 个 | 斜坡 {len(mid_vals)} 个"
      f"（平均比例 {statistics.mean(mid_vals):.2f}）")
print("   读法：**三段处理避免了「要么全插值、要么不插值」的两难** —— 这是 YaRN 数据效率更高的原因")

print("")
print("④ 注意力温度补偿（mscale = 0.1·ln(s) + 1）")
print(f"  {'s':>4} {'mscale':>8} {'等效温度':>9}")
for sx in (1, 2, 4, 8, 16, 32):
    m = 0.1 * math.log(sx) + 1
    print(f"  {sx:>4} {m:>8.3f} {1/m:>9.3f}")
print("   读法：**长上下文下注意力分布变平（熵上升）**，需要温度补偿；s=16 时 mscale=1.277 ——")
print("         这一步需要 kernel 支持，否则拿不到收益（也是 YaRN 区别于纯 NTK 的关键）")

print("")
print("⑤ 继续预训练的数据需求（长文档稀缺性）")
print(f"  {'目标长上下文 token':>18} {'≥32K 文档占比':>13} {'需扫描原始 token':>16} {'占语料比例':>11}")
for target, frac in ((1e9, 0.005), (1e9, 0.05), (10e9, 0.005), (10e9, 0.05)):
    need = target / frac
    print(f"  {target/1e9:>16.0f}B {frac:>13.1%} {need/1e12:>14.1f}T {target/need:>11.1%}")
print("   读法：**只有 0.5% 的 token 来自 ≥32K 文档时，凑 10B 长上下文 token 要扫描 2T 原始 token** ——")
print("         这就是「长上下文首先是数据工程」的量化依据")

print("")
print("⑥ 完整配方（三步，缺一不可）")
@dataclass
class Step:

    what: str
    key: str
STEPS = [
    Step("① 改位置编码", "NTK-by-parts 斜坡 + mscale", "β=32、γ=1、s=目标/训练长度"),
    Step("② 少量继续预训练", "长文档 + 打包数据混合", "数据量 = 目标长 token / 长文档占比"),
    Step("③ 分层验证", "按位置分层（头/中/尾）+ 跨段聚合", "不能只看困惑度，要看有效窗口"),
]
print(f"  {'步骤':<18} {'做什么':<28} 关键参数/判据")
for st in STEPS:
    print(f"  {st.name:<18} {st.what:<28} {st.key}")
print("   读法：**只做①会「能算但不会用」、只做②会在错的位置编码上浪费算力、不做③会误判能力**")
```

预期输出要点（实跑）：① **8K 训练时 64 个维度里有 14 个（22%）波长超过训练长度、「从未转满一圈」**（4K 时 28%、32K 时 6%、128K 时 0）——这是外推失效的机制；② **PI 把全部维度均匀拉伸 16×，而 NTK 是逐维度拉伸：$i{=}0$ 时 1.00×、$i{=}63$ 时 16.00×**，**16/64 个维度拉伸 <2×**（局部分辨率保住）；③ **YaRN 的分段**：26 个完全不插值、14 个完全插值、**24 个在斜坡上**（平均 0.24）；④ **mscale = 1.277（s=16）**，等效温度 0.783；⑤ **长文档占比 0.5% 时，凑 10B 长上下文 token 要扫描 2T 原始 token**；⑥ 三步配方与各自的关键判据。

## 常见追问

- **追问**：为什么不能直接把 RoPE 的 base 调大就完事？
  - 要点：**因为「调大 base」是逐维度拉伸，效果取决于调多少**。$\text{base}'=\text{base}\cdot s^{d/(d-2)}$ 让拉伸因子从高频的 1× 平滑升到低频的 $s$×（本机：1.00× → 16.00×）——**这恰好是「保局部、拉全局」想要的效果**。但**纯 NTK 少了注意力温度补偿**（mscale），所以长上下文下注意力分布变平的问题没被解决。**「调 base」是对的起点，不是完整方案。**
- **追问**：PI 与 NTK 的差别到底在哪？
  - 要点：**PI 是均匀拉伸（所有维度 ×s），NTK 是逐维度拉伸（高频 ×1、低频 ×s）**。语言里**大量依赖近距离顺序**（词序、语法、局部指代），PI 把近距离分辨率压到 $1/s$（s=16 时 1/16）会直接伤到这些能力，所以**PI 通常需要更多微调**才能恢复。**NTK 保住了高频，所以数据效率更高。**
- **追问**：YaRN 为什么数据效率更高？
  - 要点：**两个原因**：① **NTK-by-parts 的分段处理**避免了「一刀切」——高频维度完全不插值（不用重新学局部顺序），低频维度完全插值（直接覆盖新范围），中间平滑过渡；② **注意力温度补偿**修正了长上下文的注意力分布变化，**减少了对训练数据的依赖**。论文报告的微调步数比 PI 少一个数量级左右（**该数字来自论文，本仓库未复现**）。
- **追问**：扩完窗之后还需要检索吗？
  - 要点：**通常需要**——因为**有效窗口远小于名义窗口**（串 [[moonshot-01]]：中间位置利用率最低）。判据（串 [[moonshot-07]]）：① **信息是否必须同时在场**（跨文档推理/全局摘要 → 长上下文）；② **是否可定位**（单点事实 → 检索更便宜）；③ **成本敏感度**（1M 上下文的单请求成本高两个数量级）。**实践主流是「检索 + 中等窗口」。**
- **追问**：继续预训练要多少数据？
  - 要点：**由「目标长上下文 token 数」反推**，而这个数又受**长文档占比**限制（本机算例：0.5% 占比 → 10B 长 token 要扫描 2T）。实践常见量级是**数十亿到数百亿**长上下文 token（远小于预训练的 15T 量级），**学习率小、步数少**（避免灾难性遗忘）。**关键是「数据形态」而不是「数据量」**——长文档与打包数据都要有。
- **追问**：怎么验证扩窗真的成功？
  - 要点：**三层验证**：① **困惑度曲线**（按位置分层看，而不是整体平均）；② **针在草堆**（不同深度位置分别测，**中间位置是关键**）；③ **跨段聚合任务**（多文档摘要、跨文档推理——这才是长上下文真正的价值）。**注意：很多「长上下文 benchmark」其实只测单点检索，会高估能力**（串 [[moonshot-10]] 的 agentic 评估思路）。
- **追问**：扩窗会影响短上下文性能吗？
  - 要点：**可能会**（「对齐税」）：① **位置编码改动**会让模型在短距离上的相位分布与预训练不同 → 短任务退化；② **继续预训练的数据分布**偏向长文档 → 短任务数据占比下降；③ **注意力温度补偿**改变了 softmax 的锐度 → 影响所有长度。**所以必须同时评测短上下文任务**，并在数据配比里保留短数据。
