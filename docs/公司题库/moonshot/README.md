这一家的题有一条非常清晰的主线：**超长上下文**。十道题里有六道直接落在它上面
（01 限制分析、02 KV 压缩、04 位置编码扩展、05 PD 分离、06 前缀缓存、07 与检索的分工），
另外四道分别是 MoE 训练系统成本（03）、训练稳定性（08）、RL 配方（09）与评估方法（10）。

准备这一家时，建议把**「名义能力 ≠ 可用能力」**当成口头禅：
**名义窗口 ≠ 有效窗口**、**pass@k ≠ pass^k**、**激活参数 ≠ 总参数**、**算力效率 ≠ 成本效率**。
这四组区分贯穿了整套题——能主动做这种区分，就是这家公司想听的思维方式。

## 这家公司的面试怎么准备

**第一，一切都要能落到「速率」上。** 这一家的技术讨论几乎都在比较**不同量随规模的增长速率**：
KV 是 $O(L)$、注意力是 $O(L^2)$、预填充是混合、PRM 可靠性是 $a^d$、联合覆盖是 $r^N$、
pass^k 是 $p^k$。**能说出「谁的增长更快、交叉点在哪」，比记住结论更重要。**

**第二，数字要能脱口而出。** 高频锚点：**320 KiB/token（GQA-8）与 90 KiB/token（MLA）**、
**21,504 token 的 attention/FFN 交叉点**、**$O(K^2)\to O(K)$ 的 10.5×**、
**6σ 配对的期望个数**、**pass@k 与 pass^k 的差距**、**\$3/\$15 每百万 token**。

**第三，把「名义」与「可用」分清楚。** 这是这一家最看重的判断力：
**名义窗口 1M ≠ 有效窗口**、**pass@k ≠ pass^k**、**1T 总参 ≠ 32B 激活的成本**、
**算力效率 ≠ 成本效率**。**每讲一个能力，补一句「在什么条件下才真的可用」。**

**第四，承认「简单」与「便宜」是两件事。** 第 09 题的核心结论是：
**K1.5 的简单配方省的是算法复杂度，长 CoT 的 rollout 成本一分没少**——
复杂度是从算法搬到了基础设施。**这种「不把工程选择说成免费」的态度，是这家公司的技术语境。**
