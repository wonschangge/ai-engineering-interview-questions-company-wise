# Palantir 面试题库

这一家的题有一个共同的前提：**代码要跑在客户的真实系统里，而真实系统里有真实的数据问题**。
所以几乎每道题都会在某个时刻逼你回答**"这个数字对不对"**——
join 之后金额被重复累加了吗？分页时数据变了会不会漏读？聚合查询能不能反推出个体？
"100 万条"在分层之后还剩多少？

准备这一家时，建议把**"对账"**当成习惯动作：
**任何结论都要能用一个守恒量检验**——行数、金额总和、唯一键数、人时。
这一家的面试官明显更在意**"你的答案能不能被验证"**，而不是"你知不知道某个技术"。

另一个特征是**大量题目都在考"边界与副作用"**：
写操作的状态机、同步的权威源、共享数据的隐私、模型的覆盖缺口。
**"能跑通"只是起点，"出错时会怎样"才是考点。**

### 编程与数据（01–07）

| --- | --- | --- |
| 01 | [形状类与扩展](01-形状类与扩展.md) | **题目里"然后扩展它们"就是全部提示**：分支式要改核心函数（**1 处**）、多态只需新增类（**0 处**）；**负半径平方后变正 → 12.566（错误被掩盖）** |
| 02 | [SQL join 与聚合](02-SQL-join-与聚合.md) | **扇出让 `SUM` 得到 700（真值 300，+133%）**，而单行客户不受影响；**`SUM(DISTINCT)` 是另一种错误**；`AVG` 的分母是 2 不是 3 |
| 03 | [REST API 分页拉取](03-REST-API-分页拉取.md) | **插入→重复 45 条、删除→漏读 50 条**；**游标分页 0/0**；**"用实际返回条数推进"最容易被忽略** |
| 04 | [HashMap 重复计数](04-HashMap-重复计数.md) | **可变键让条目永久不可达（查得 0）**；**归一化缺失让键数膨胀 4 倍**；**复用 map 让 userB 报告含 userA 的数据** |

| 06 | [800 行 pipeline 脚本](06-800-行-pipeline-脚本.md) | **float32 累加误差 9.58e-3**（float64 是 1.33e-11）；**时区让 16/24 小时错位**；列表→set **加速两个数量级** |

## 准备建议

1. **先把 01–07 做一遍**：它们共同考"对账意识"——**扇出、漂移、同一性、状态污染、时间轴、精度、阻塞**。每一道都能用几十行代码复现，而且**每一道都有"看起来对但实际错"的版本**。
2. **08–10 是这一家的特色**：**"检索 vs 聚合"、"代码 vs 语义层"、"意图 vs 能力边界"**——三组区分贯穿始终。准备时把这三组区分背熟。
3. **11–12 是平台视角**：**能力矩阵**与**离线-在线差距**。这两道题的答案都是"先算数，再设计"。
4. **13–18 是前置部署场景**：共同点是**"先收敛范围、再量化、后给方案"**。注意其中反复出现的三个工具：**基率与特异度、人时/单位经济、对照实验**。
5. **19–20 不要留到最后**：这两道题考的是"结构"而不是"立场"——**动机要具体到团队、异议要带方案与数据、价值观要给出可执行的阶梯与红线**。
