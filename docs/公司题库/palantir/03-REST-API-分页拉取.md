## 一句话答案

> **分页的坑不在"怎么翻页"，而在"数据在翻页期间变了"**——**本机：OFFSET 分页在持续写入下重复 45 条；在持续删除下漏读 50 条。**
> **★ 量化一：OFFSET 分页的两个失效模式（按时间倒序的 feed，1000 条、每页 100）**
> | 变动方向 | 读到 | 唯一 | **重复** | **漏读** |
> | --- | --- | --- | --- | --- |
> | **只在前面插入新记录** | 1050 | 1005 | **45** | 0 |
> | **只在后面删除旧记录** | 950 | 950 | 0 | **50** |
> | **两者同时发生** | 1000 | 980 | **20** | **25** |
> | **游标分页（同样插入）** | 1005 | 1005 | **0** | **0** |
> **读法**：**"插入 → 重复"、"删除 → 漏读"**——**两个失效模式成对出现，取决于数据集往哪个方向变**。**所以 OFFSET 分页只适用于静态数据集**；**持续写入的场景必须用游标**。
> **★ 量化二：游标分页的正确形态**
> ```sql
> WHERE ts < :cursor ORDER BY ts DESC LIMIT :n
> ```
> | 特性 | 说明 |
> | --- | --- |
> | **不重不漏** | **本机 0/0**（**因为条件基于"值"而不是"位置"**） |
> | **代价** | **不能跳页**（**只能顺序翻**） |
> | **前提** | **游标列必须唯一且可排序**（**`ts` 重复时要加 tie-breaker 如 id**） |
> **读法**：**"游标列必须唯一"是最容易踩的前提**——**如果 `ts` 有重复，`ts < cursor` 会跳过同一时间戳的记录**（**所以要用 `(ts, id)` 复合游标**）。
> **★ 量化三：分页接口的另外三个坑**
> | 坑 | 后果 | 处理 |
> | --- | --- | --- |
> | **`total` 与实际条数不一致** | **"最后一页"判断错** | **以"返回空页"为终止条件，别信 `total`** |
> | **page size 被服务端上限截断** | **按请求 size 算页码 → 漏读** | **用实际返回条数推进** |
> | **限流 429 / 5xx** | **中途失败** | **指数退避 + 从当前游标续传** |
> **读法**：**"用实际返回条数推进"最容易被忽略**——**服务端把 size 从 500 降到 200 时，按请求 size 算页码会直接漏掉 60% 的数据（而且不报错）**。
> **★ 实现要点**：
> | # | 要点 |
> | --- | --- |
> | ① | **优先用游标分页**（**除非 API 只提供 offset**） |
> | ② | **以"空页"为终止条件**（**不要用 `total` 算页数**） |
> | ③ | **用实际返回条数推进**（**不假设服务端遵守 size**） |
> | ④ | **重试要幂等**（**从当前游标续传，而不是从头**） |
> | ⑤ | **去重兜底**（**按主键去重**——**即使上游保证了顺序**） |
> | ⑥ | **记录进度**（**支持断点续传**） |
> 一句话判据：**"先问'数据会不会变' → 会变就用游标 → 以空页为终止 → 用实际条数推进 → 重试从游标续传 → 按主键去重兜底"**。

## 面试官在考什么

- **★ 是否意识到"数据会变"**：**能否指出 OFFSET 的重复/漏读**（本机：**45 / 50**）——**这是本题的分水岭**。
- **★ 是否知道游标分页**：**能否写出 `WHERE ts < cursor ORDER BY ts DESC LIMIT n`**。
- **游标的唯一性**：**能否指出"ts 重复时要加 tie-breaker"**。
- **终止条件**：**能否指出"用空页而不是 total"**。
- **实际条数**：**能否指出"服务端可能截断 page size"**。
- **重试**：**能否指出"从游标续传"**（**而不是整体重试**）。
- **限流**：**能否给出指数退避 + 抖动**。
- **去重**：**能否指出"按主键去重兜底"**。
- **可观测性**：**能否指出"要记录已拉取的游标"**。
- **诚实**：**承认"很多 API 只提供 offset，所以要接受近似"**。

**常见错误答案**

- **直接用 `page`/`page_size` 循环**（**不讨论数据变动**）。
- **用 `total` 算页数**（**`total` 可能不准**）。
- **假设服务端返回的条数等于请求的 size**（**漏读**）。
- **失败后从头重试**（**重复拉取、浪费配额**）。
- **不去重**（**重复数据进入下游**）。
- **不考虑限流**（**被 429 打回**）。
- **游标用非唯一列**（**漏读同一时间戳的记录**）。
- **不记录进度**（**无法断点续传**）。

## 原理与推导

### 1. ★ 为什么 OFFSET 会错

| 变动 | 机制 | 结果 |
| --- | --- | --- |
| **前面插入** | **窗口后移，已读记录再次进入窗口** | **重复** |
| **后面删除** | **窗口前移，未读记录被跳过** | **漏读** |

**读法**：**"OFFSET 是位置，不是值"**——**位置会随数据集变动而漂移**（**本机两种方向都实测到了**）。

### 2. 游标分页

$$\text{下一页}=\{r:\ r.\text{key}<\text{cursor}\}\ \text{按 key 倒序取前 }n$$

| 要点 | 说明 |
| --- | --- |
| **条件基于值** | **不受插入/删除影响** |
| **必须有序** | **游标列要有索引** |
| **必须唯一** | **重复值要用复合游标** |
| **不能跳页** | **产品上要接受** |

**读法**：**"复合游标 `(ts, id)`"是处理重复时间戳的标准做法**——**条件变成 `(ts, id) < (cursor_ts, cursor_id)`**。

### 3. 终止条件与页数

| 做法 | 问题 |
| --- | --- |
| **用 `total` 算页数** | **`total` 可能过时/近似** |
| **用"返回条数 < size"判断** | **服务端可能截断 size** |
| **用"返回空页"判断** | **最稳**（**推荐**） |

**读法**：**"空页"是唯一不依赖任何元数据的终止条件**——**代价是多一次请求**（**可接受**）。

### 4. 重试与限流

| 情形 | 处理 |
| --- | --- |
| **429** | **读 `Retry-After`，指数退避 + 抖动** |
| **5xx** | **退避后重试**（**从当前游标续传**） |
| **超时** | **重试**（**幂等**） |
| **部分成功** | **记录已提交的游标** |

**读法**：**"从游标续传"而不是"从头重试"**——**它把重试的代价从 $O(N)$ 降到 $O(1)$**（**对大数据量拉取是决定性的**）。

### 5. 去重与幂等

| 层面 | 做法 |
| --- | --- |
| **拉取层** | **按主键去重**（**内存集合或布隆过滤器**） |
| **写入层** | **`UPSERT` / 幂等键** |
| **批次层** | **记录"已处理的游标范围"** |

**读法**：**"即使上游保证不重，也要兜底去重"**——**因为上游的保证可能随版本变化**（**而且"保证"通常只对静态数据集成立**）。

### 6. 接口形态对比

| 形态 | 优点 | 缺点 |
| --- | --- | --- |
| **OFFSET/LIMIT** | **可跳页、简单** | **数据变动时错** |
| **游标（不透明 token）** | **不重不漏** | **不能跳页** |
| **时间范围** | **语义清晰** | **需客户端理解时间** |
| **快照 ID** | **一致性读** | **需服务端支持** |

**读法**：**"快照 ID"是最强的形态**（**它保证整个翻页过程看到一致的数据**）——**但需要服务端配合**（**如数据库的 `REPEATABLE READ` 或导出快照**）。

import random
rng=random.Random(0)
print('① 场景：按创建时间倒序的 feed（新记录出现在最前面），翻页期间持续有新记录写入')
N=1000; PAGE=100
def feed(): return [{'id':i,'ts':i} for i in range(N-1,-1,-1)]   # ts 越大越新，倒序排列
def offset_scan(page=PAGE, inserts=50):
    data=feed(); out=[]; off=0; ins=0
    while True:
        if ins<inserts:                                   # 每翻一页，来 5 条新记录
            for _ in range(5):
                data.insert(0,{'id':N+ins,'ts':N+ins}); ins+=1
        chunk=data[off:off+page]
        if not chunk: break
        out.extend(chunk); off+=page                       # 朴素的 OFFSET 推进
    return out
print(f'  {"变动方向":<26} {"读到":>7} {"唯一":>7} {"重复":>7} {"漏读":>7}')
def offset_scan(page=PAGE, inserts=0, deletes=0):
    data=feed(); out=[]; off=0; ins=0; dele=0
    while True:
        if ins<inserts:
            for _ in range(5):
                data.insert(0,{'id':N+ins,'ts':N+ins}); ins+=1
        if dele<deletes:
            for _ in range(5):                      # 删除靠后的记录（模拟下架）
                if len(data)>PAGE*2: data.pop(); dele+=1
        chunk=data[off:off+page]
        if not chunk: break
        out.extend(chunk); off+=page
    return out
RES={}
for name,kw in (('只在前面插入新记录',{'inserts':50}),
                ('只在后面删除旧记录',{'deletes':50}),
                ('两者同时发生',{'inserts':25,'deletes':25})):
    g=offset_scan(**kw); ii=[r['id'] for r in g]; uu=set(ii)
    miss=[i for i in range(N) if i not in uu]
    RES[name]=(len(ii),len(uu),len(ii)-len(uu),len(miss))
    print(f'  {name:<26} {len(ii):>7} {len(uu):>7} {len(ii)-len(uu):>7} {len(miss):>7}')
print("  读法：**「插入 -> 重复」、「删除 -> 漏读」**（本机两种方向都出现）——")
print('        所以 OFFSET 分页的两个失效模式是**成对出现**的，取决于数据集往哪个方向变')
print()
print('② 游标分页：WHERE ts < cursor ORDER BY ts DESC LIMIT n')
def cursor_scan(page=PAGE, inserts=50):
    data=feed(); out=[]; cursor=None; ins=0
    while True:
        if ins<inserts:
            for _ in range(5):
                data.insert(0,{'id':N+ins,'ts':N+ins}); ins+=1
        pool=[r for r in data if cursor is None or r['ts']<cursor]   # 严格小于游标
        pool.sort(key=lambda r:-r['ts'])                             # 保持倒序
        chunk=pool[:page]
        if not chunk: break
        out.extend(chunk); cursor=chunk[-1]['ts']
    return out
got2=cursor_scan()
ids2=[r['id'] for r in got2]; uniq2=set(ids2)
missing2=[i for i in range(N) if i not in uniq2]
print(f'  游标分页：读到 {len(ids2)} 条、唯一 {len(uniq2)} 条 -> **重复 {len(ids2)-len(uniq2)} 条、漏读 {len(missing2)} 条**')
print(f'    （新插入的 50 条 ts 更大，落在游标之前 -> **不会被重复读到**）')
print()
print('③ 对比表')
print(f'  {"方案":<22} {"读到":>7} {"唯一":>7} {"重复":>7} {"漏读":>7} 适用')
for name,(rd,uq,dup,ms) in RES.items():

print('  读法：**OFFSET 的两个失效模式成对出现**（插入->重复、删除->漏读）——')
print("        而游标分页**不重不漏**（代价是「不能跳页」、「游标列必须唯一且有序」）")
print()

## 常见追问

- **追问**：如果 API 只支持 OFFSET 怎么办？
  - 要点：**三条缓解**：① **缩小时间窗口**（**"只拉最近 1 小时"**——**窗口内数据变动少**）；② **用稳定排序 + 去重**（**按 `(created_at, id)` 排序，本地去重**）；③ **接受近似并记录**（**报告"可能有重复/漏读"**）。**读法**：**"缩小窗口"是最实用的缓解**——**因为变动率与窗口长度成正比**。
- **追问**：游标怎么做"并发拉取"？
  - 要点：**按分片而不是按页**：① **先用一个维度分片**（**如按客户 ID 取模**）；② **每个分片独立游标**（**并行拉取**）；③ **分片键要均匀**（**否则长尾**）。**读法**：**"游标不能跳页"意味着"并行要靠分片"**——**这是"拉全量"的标准做法**。
- **追问**：怎么测试分页函数？
  - 要点：**四类用例**：① **静态数据**（**不重不漏**）；② **翻页期间插入**（**验证不重复**）；③ **翻页期间删除**（**验证不丢**——**注意游标分页"不丢已存在的记录"**）；④ **服务端截断 size / 返回 429**（**验证重试与推进**）。**读法**：**"用会变的假数据源做测试"是这道题的关键**——**静态数据的测试全绿不代表正确**。
- **追问**：怎么保证"不漏"？
  - 要点：**两条**：① **游标分页保证"不重复读已读过的"**（**但新插入的记录在本次扫描中不会出现**——**这是特性不是 bug**）；② **如果要"最终不漏"，就定期做全量对账**（**如每天一次按时间窗口重扫**）。**读法**：**"一次性扫描不可能既看到历史又看到新增"**——**这是"一致性 vs 完整性"的取舍**。
- **追问**：拉取进度怎么持久化？
  - 要点：**存游标而不是页码**：① **`{"cursor": "...", "updated_at": "..."}`**；② **分片时每个分片一个游标**；③ **注意游标是"不透明 token"时不要解析它**（**它是服务端的实现细节**）。**读法**：**"不要解析不透明游标"是一条重要的接口契约**（**解析了就依赖了服务端实现**）。
- **追问**：这道题与"800 行 pipeline 脚本"有什么关系？
  - 要点：**同一类"偶尔算错"的根源**：① **分页漂移导致重复/漏读**；② **join 扇出导致重复累加**（**串 [[palantir-02]]**）；③ **两者都属于"数据在变动 / 粒度混乱"导致的静默错误**。**读法**：**"静默错误"比"崩溃"危险得多**——**所以要有对账与总量守恒检查**。
