# ElevenLabs 面试题库

ElevenLabs 的题有一半落在**语音链路独有的物理约束**上：音频必须攒够一个可播块才能出声、文本前端常常不能流式、
播放侧还有抖动缓冲与欠载约束、译文长度会直接撑破时间轴。**这些约束在纯文本 LLM 的题里根本不存在**，
也正是这家公司面试的区分度所在。

另一半是**交付与安全**：给医院集团做预约电话系统、给联络中心替换 IVR、为语音克隆设计同意与水印。
这些题考的不是模型，而是**边界感**——什么绝不能让 AI 做（给医学建议、克隆未授权声音）、
什么必须留兜底（按键菜单、转人工、可撤销）、什么必须事先签下来（门禁与 kill criteria）。

## 这家公司的面试怎么准备

**第一，把「音频的时间账」算清楚。** 这一家的题几乎都能落到同一个换算：**48 KB/s（24 kHz/16-bit 单声道）、
首块 120 ms、jitter buffer 按抖动 p99 取、RTF 决定每卡并发、音频秒可从文本预估**。
能把这些量在脑子里串起来（首块 → TTFA → 缓冲 → 欠载 → 容量），答案自然有说服力。

**第二，区分「可播」与「可显示」。** 这是 TTFA 与 TTFT 的分水岭，也是本库最容易被漏掉的一条：
文本 1 个 token 就能显示，音频必须攒够一个可解码块；**任何「TTFA = TTFT + TTS 首包」的答案都不完整**。

**第三，安全题先谈边界再谈技术。** 医院场景先说「绝不给医学建议 + 红旗症状立即升级」，
语音克隆先说「同意、水印、响应三层缺一不可」，再说实现。**顺序错了就是扣分。**

**第四，交付题必须带门禁与回退。** 第 07、08 两题的评分点是「分阶段 + 量化门禁 + kill criteria + 可回退」，
以及**诚实的三档预测与盈亏平衡点**（甚至主动打折）。这一家很看重「不做过度承诺」。
