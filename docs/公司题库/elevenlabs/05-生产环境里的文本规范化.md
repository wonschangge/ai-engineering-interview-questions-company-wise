## 一句话答案

> 文本规范化（TN）是「把书面写法转成该怎么读」，它的困难来自**歧义**而不是「规则多」。工程做法是四件事：
> ① **按类别建规则，而不是写一个大正则**：数字（基数/序数/小数/分数/负数/范围）、货币、日期时间、单位与度量、缩写与首字母词、URL/邮箱/话题标签、表情符号、数学与代码、编号类（航班号/电话/车牌/型号）、罗马数字、以及**同形词**（read/lead/live/use/bass/wind）。每一类都有「读法取决于上下文」的子情况；
> ② **能确定的用规则、不能确定的交给模型，但必须可验证**：规则确定性高、可测试；神经 TN 处理歧义但**会幻觉且不可预测**。混合策略是"规则覆盖高置信类别 → 模型处理剩余 → **回读校验**（normalized 文本能否唯一还原/是否改变了语义）→ 低置信度回退到保守读法"；
> ③ **只在合成路径上规范化，显示路径保留原文**：用户看到的必须是原文（「\$1,299.50」不能显示成「一千二百九十九点五零美元」）；同时把原文与规范化结果**一起记录**，便于排查与回归；
> ④ **用「分类别的回归语料」守住质量**：每一类准备几十到几百条测试（含对抗样例），**按类报准确率**，并对「必须不能错」的类别（金额、电话、日期、单位）设红线。TN 的 bug 是**回归性**的——修好日期可能弄坏版本号。
> 一句话判据：**TN 的评测要按类别 + 按严重度**（读错一个金额 vs 读错一个装饰性符号，代价差几个数量级），并且**每次改动都跑全量回归**。

## 面试官在考什么

- **是否按类别思考**：能不能列出 8–12 个类别并各举一个「上下文决定读法」的例子（这是 TN 的核心难点）。
- **规则 vs 模型的取舍**：能否说清「规则可测但脆」「模型灵活但会幻觉」，并给出混合策略与回退路径。
- **可验证性**：能否设计「回读校验」（把规范化结果再解析回语义，比较是否一致）与置信度阈值；以及低置信度时的**保守策略**（宁可读得平淡，也不要读错）。
- **显示与合成分离**：能否主动指出「原文用于显示、规范化文本只用于合成」，避免把规范化结果泄露给用户。
- **评测设计**：能否按类别建回归语料、按严重度分级、并给出**准确率与回归门禁**（串 [[evaluation-04]]）。
- **多语言与混读**：中英混排、数字与单位在不同语言的读法差异（例如 「1.5k」、「3:30」、「No. 5」）、以及**语种判定**（同一串字符在不同语言下读法不同）。
- **安全与注入**：TN 的输入是用户文本，必须**不能执行任何内容**（SSML 注入、模板注入、超长输入导致正则回溯）；这类问题在文本前端里非常真实（串 [[safety-01]]）。
- **性能**：TN 在关键路径上（串 [[elevenlabs-04]] 的「文本前端 20–80 ms」），所以规则引擎要**有超时与降级**（超时就跳过可选规范化）。

**常见错误答案**

- 认为 TN 就是「把数字转成文字」（忽略歧义、单位、多语言、同形词）。
- 全用神经 TN（不可预测 + 幻觉风险 + 延迟不可控）。
- 全用规则（遇到歧义就错，且规则越写越乱）。
- 把规范化结果也给用户看。
- 没有回归语料，靠人工听发现问题。
- 忽略性能与安全（正则回溯、SSML 注入）。

## 原理与推导

### 1. 类别清单与「上下文决定读法」的实例

| 类别 | 例子 | 歧义点 |
| --- | --- | --- |
| 数字 | 2024 / 1,299.50 / -3 / 1/2 / 3-5 | 年份 vs 计数；分数 vs 日期；范围 vs 减法 |
| 货币 | \$1,299.50 / €5 / 30 元 | 符号位置与读法顺序 |
| 日期时间 | 2024-01-05 / 05/01/2024 / 3:30 | **月日顺序因地区而异**；12/24 小时制 |
| 单位度量 | 5 km/h / 32°F / 16:9 / 100 Mbps | 缩写展开（kilometres per hour）与符号读法 |
| 缩写/首字母词 | NASA / Dr. / etc. / e.g. | 逐字母 vs 整词读 |
| URL/邮箱/标签 | https://a.b/c?d=1 / a@b.com / #topic | 协议省略、点与斜杠的读法 |
| 表情符号 | 😀 / ❤️ | 读「笑脸」还是跳过 |
| 数学/代码 | f(x)=x^2 / `list[int]` | 符号读法与代码可读性 |
| 编号类 | CA1234 / 010-1234-5678 / v2.1.3 | 逐位读 vs 数值读；版本号的点读法 |
| 罗马数字 | Henry VIII / Chapter IV | 人名/章节 vs 普通词 |
| 同形词 | read / lead / live / use / bass / wind | **词性/时态决定发音**（规则无法判断） |
| 混排 | 「把 API 的 latency 降到 100 ms」 | 语种切换与术语读法 |

**读法**：真正难的不是「转换」，而是**在歧义处做对选择**——所以 TN 的质量指标要按类别看，而不是看总体准确率。

### 2. 三种实现路线

| 路线 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| 纯规则 | 确定、可测、快 | 歧义处必错、规则膨胀 | 高置信类别（日期格式、单位、编号） |
| 神经 TN | 处理歧义、多语言好 | 幻觉、不可预测、延迟不定 | 通用文本、低资源语言 |
| **混合（推荐）** | 规则兜住确定部分，模型处理剩余 | 需要编排与置信度机制 | 生产系统 |

**混合策略的编排**：
1. 规则层按「最长匹配 + 类别优先级」处理（例如先识别 URL，避免其中的点被当句号）；
2. 剩余片段交给模型（带上下文与目标语言）；
3. **回读校验**：把规范化结果解析回语义（数字/日期/单位），与原串比较；不一致就**回退**到规则的保守读法；
4. **置信度阈值**：低于阈值走保守策略（例如「读原文的字面字符」而不是猜）；
5. **超时降级**：TN 在关键路径上，超时（例如 > 30 ms）就跳过可选规则。

### 3. 显示与合成分离

```
用户文本（原文） ──┬─→ 显示（原样，永久保留）
                  └─→ TN（仅用于合成）──→ 音素化 ──→ 声学模型
```
**要点**：① 原文与规范化结果**都要记录**（排查要用）；② 规范化结果**不得回写**到会话历史（否则用户下次看到的是被改过的文本）；③ 若用户编辑文本后重合成，必须从原文重新 TN（不要复用旧结果）。

### 4. 评测：分类别 + 分级 + 回归门禁

- **语料**：每类 50–300 条，含**对抗样例**（歧义边界、混排、超长、异常格式）；
- **指标**：按类准确率 + **严重度加权错误率**（金额/日期/电话的权重远高于表情符号）；
- **门禁**：对「绝不能错」的类别设红线（例如金额与电话 100% 正确），其余类别设「不得回退超过 X 个百分点」；
- **回归**：每次改动跑全量（TN 的 bug 是回归性的）；
- **人工抽检**：自动指标（字符串比较）会漏掉「读法不同但都合理」的情况，需要人工听检校准。

### 5. 安全与性能

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 正则回溯（ReDoS） | 一个长输入把 CPU 打满 | 限制输入长度、避免嵌套量词、设超时 |
| SSML/模板注入 | 用户文本被当作控制指令 | TN 输出只允许纯文本；标签由系统生成并白名单校验 |
| 超长输入 | 单请求拖慢整条链路 | 分句 + 上限 + 分段处理 |
| 语种误判 | 用错语言规则 | 显式语种参数优先，检测仅作兜底 |

# 文本规范化：分类别规则 + 回读校验 + 分类别回归（含同形词这类规则处理不了的类别）
import re
from dataclasses import dataclass
from typing import Callable, Dict, List, Optional, Tuple

# ---------- 规则层：只处理"高置信"的模式 ----------
RULES: List[Tuple[str, str, Callable[[re.Match], str]]] = [
    # 货币：$1,299.50 -> 一千二百九十九点五零美元（示例用中式读法；真实系统按语言分支）
    (r"\$(\d{1,3}(?:,\d{3})*)(?:\.(\d{2}))?",
     "currency_usd",
     lambda m: f"{m.group(1).replace(',', '')}美元" + (f"{(m.group(2))}美分" if m.group(2) else "")),
    # ISO 日期：2024-01-05 -> 二零二四年一月五日
    (r"\b(\d{4})-(\d{2})-(\d{2})\b",
     "date_iso",
     lambda m: f"{m.group(1)}年{int(m.group(2))}月{int(m.group(3))}日"),
    # 时间：3:30 -> 三点三十分
    (r"\b(\d{1,2}):(\d{2})\b",
     "time",
     lambda m: f"{m.group(1)}点{m.group(2)}分" if m.group(2) != "00" else f"{m.group(1)}点"),
    # 单位：5 km/h -> 5 千米每小时
    (r"\b(\d+(?:\.\d+)?)\s*km/h\b", "unit_speed", lambda m: f"{m.group(1)}千米每小时"),
    (r"\b(\d+(?:\.\d+)?)\s*Mbps\b", "unit_net", lambda m: f"{m.group(1)}兆比特每秒"),
    # 编号：CA1234 -> C A 一二三四（逐位读）
    (r"\b([A-Z]{2})(\d{3,4})\b", "code_flight",
     lambda m: " ".join(m.group(1)) + " " + "".join("零一二三四五六七八九"[int(d)] for d in m.group(2))),
    # 电话：010-1234-5678 -> 逐位读
    (r"\b(\d{3})-(\d{4})-(\d{4})\b", "phone",
     lambda m: "".join("零一二三四五六七八九"[int(d)] for d in (m.group(1) + m.group(2) + m.group(3)))),
    # URL：保留但不能被句号规则切坏
    (r"https?://[^\s，。；]+", "url", lambda m: m.group(0)),
    # 缩写展开
    (r"\be\.g\.", "abbr", lambda m: "例如"),
    (r"\betc\.", "abbr", lambda m: "等等"),
]

# 同形词：规则无法判断，需要词性/上下文（这里用词典 + 简单上下文规则演示其局限）
HOMOGRAPHS = {
    "read": ("过去式读 red", "现在式读 reed"),
    "lead": ("名词读 led（铅）", "动词读 leed（带领）"),
    "live": ("形容词读 lyv（现场）", "动词读 liv（居住）"),
    "bass": ("乐器读 beɪs", "鱼读 bæs"),
}

@dataclass
class Normalized:
    text: str
    category: str
    confidence: float          # 0-1，低于阈值走保守策略

def normalize_one(sentence: str, use_model: bool = True) -> List[Normalized]:
    """对一句文本做规范化：规则优先，剩余部分（含同形词）交给"模型"（这里用启发式模拟）"""
    out: List[Normalized] = []
    spans: List[Tuple[int, int]] = []
    for pattern, cat, fn in RULES:
        for m in re.finditer(pattern, sentence):
            if any(s <= m.start() < e or s < m.end() <= e for s, e in spans):
                continue                                  # 已被更长匹配覆盖
            spans.append((m.start(), m.end()))
            out.append(Normalized(fn(m), cat, 0.98))
    # 词级处理：缩写与同形词
    for word, (a, b) in HOMOGRAPHS.items():
        for m in re.finditer(rf"\b{word}\b", sentence, re.I):
            if use_model:
                # 模拟模型判断：前面有 "have/has/had" 视为完成时 -> 过去式；否则现在式
                prefix = sentence[max(0, m.start() - 12):m.start()].lower()
                past = any(k in prefix for k in ("have ", "has ", "had "))
                reading = a if past else b
                out.append(Normalized(f"[{word}->{reading}]", "homograph", 0.62))
            else:
                out.append(Normalized(f"[{word}->未知]", "homograph", 0.30))
    return out

print("① 规则层能处理什么（高置信类别）")
samples = ["价格是 $1,299.50，活动到 2024-01-05 结束。",
           "会议 3:30 开始，网速要求 100 Mbps，限速 5 km/h。",
           "航班 CA1234 联系电话 010-1234-5678，详情见 https://a.b/c?d=1，e.g. 附件。"]
for s in samples:
    res = normalize_one(s)
    print(f"  原文：{s}")
    for r in res:
        print(f"    [{r.category:<12}] {r.text}  (置信度 {r.confidence:.2f})")
print("  读法：规则层负责「确定性高」的类别 —— 这些是金额、日期、单位、编号，读错代价最大")
print("        注意 URL 必须优先匹配，否则其中的点会被日期/句号规则切坏")

print("\\n② 规则处理不了的类别：同形词（必须靠上下文/模型）")
for s in ["I have read the paper.", "Please read the paper.", "The lead pipe is heavy.",
          "She will lead the team."]:
    res = normalize_one(s, use_model=True)
    homo = [r for r in res if r.category == "homograph"]
    print(f"  {s:<32} -> {homo[0].text if homo else '（无）'}")
print("  读法：同形词的读法由词性/时态决定，纯规则无法覆盖；模型能处理但置信度只有 0.62 ——")
print("        所以需要置信度阈值与回退策略，而不是「模型说了算」")

print("\\n③ 回读校验：规范化结果能否还原原意（防止模型幻觉）")
CN_DIGIT = "零一二三四五六七八九"
def cn_to_arabic(text: str) -> str:
    """把中文数字逐字转成阿拉伯数字（用于比较"读出来的值"）"""
    return "".join(str(CN_DIGIT.index(ch)) if ch in CN_DIGIT else ch for ch in text)

def roundtrip_check(original: str, normalized: str, category: str) -> bool:
    """按类别的语义校验：把规范化结果解析回「值」再与原文比较（不是比长度）"""
    if category == "date_iso":
        m = re.search(r"(\d{4})-(\d{2})-(\d{2})", original)
        if not m:
            return True
        y, mo, d = m.groups()
        norm = cn_to_arabic(normalized)
        got_y = re.search(r"(\d{4})", norm)
        got_mo = re.search(r"(\d{1,2})月", norm)
        got_d = re.search(r"(\d{1,2})日", norm)
        return bool(got_y and got_mo and got_d and got_y.group(1) == y
                    and got_mo.group(1) == str(int(mo)) and got_d.group(1) == str(int(d)))
    if category == "currency_usd":
        digits_o = "".join(re.findall(r"\d", original))          # 1299.50 -> "129950"
        digits_n = "".join(ch for ch in cn_to_arabic(normalized) if ch.isdigit())
        return digits_o == digits_n
    if category in ("phone", "code_flight"):
        digits_o = "".join(re.findall(r"\d", original))
        digits_n = "".join(ch for ch in cn_to_arabic(normalized) if ch.isdigit())
        return digits_o == digits_n
    return True

cases = [("$1,299.50", "1299美元50美分", "currency_usd", True),
         ("2024-01-05", "二零二四年一月五日", "date_iso", True),
         ("2024-01-05", "二零二五年一月五日", "date_iso", False),
         ("010-1234-5678", "零一零一二三四五六七八", "phone", True),
         ("010-1234-5678", "零一零一二三四五六七八九", "phone", False)]
print(f"  {'原文':<16} {'规范化':<20} {'类别':<14} {'校验':>10}")
for orig, norm, cat, expect_ok in cases:
    ok = roundtrip_check(orig, norm, cat)
    mark = "" if ok == expect_ok else "  <- 与预期不符"
    print(f"  {orig:<16} {norm:<20} {cat:<14} {('通过' if ok else '失败 -> 回退'):>10}{mark}")
print("  读法：校验必须**按类比较值**（把中文数字还原成阿拉伯数字再比）；")
print("        只比长度会放过「2024 被读成 2025」这类幻觉 —— 这是本演示第一版的真实缺陷")
print("\\n④ 分类别回归：按类别报准确率并设红线（严重度加权）")

    Case("unit_speed", "5 km/h", "5千米每小时"),
    Case("unit_net", "100 Mbps", "100兆比特每秒"),
    Case("code_flight", "CA1234", "C A 一二三四"),
]
SEVERITY = {"currency_usd": 5, "date_iso": 5, "phone": 4, "code_flight": 4,
            "unit_speed": 4, "unit_net": 4, "time": 3, "homograph": 3, "abbr": 2}
def run_corpus(corpus: List[Case]) -> Dict[str, Tuple[int, int]]:
    stats: Dict[str, Tuple[int, int]] = {}
    for c in corpus:
        res = [r for r in normalize_one(c.original) ]
        hit = any(r.text == c.expected for r in res)
        # 也接受「包含期望子串」（简化判定）
        hit = hit or any(c.expected in r.text for r in res)
        tot, ok = stats.get(c.category, (0, 0))
        stats[c.category] = (tot + 1, ok + (1 if hit else 0))
    return stats
stats = run_corpus(CORPUS)
print(f"  {'类别':<14} {'用例':>5} {'通过':>5} {'准确率':>8} {'严重度':>6}")
weighted_num, weighted_den = 0.0, 0.0
for cat, (tot, ok) in sorted(stats.items()):
    sev = SEVERITY.get(cat, 1)
    acc = ok / tot
    weighted_num += acc * sev
    weighted_den += sev
    print(f"  {cat:<14} {tot:>5} {ok:>5} {acc:>8.1%} {sev:>6}")
print(f"  严重度加权准确率：{weighted_num/weighted_den:.1%}（金额/日期权重最高）")
print("  读法：**按类别报准确率 + 严重度加权**才能反映真实质量；")
print("        并对金额、日期、电话设红线（要求 100%），其余类别允许「不回退超过 X 个百分点」")

print("\\n⑤ 性能与安全：TN 在关键路径上，必须有超时与长度上限")
import time
def normalize_with_budget(text: str, budget_ms: float = 30.0) -> Tuple[str, bool]:
    t0 = time.perf_counter()
    results = normalize_one(text)
    elapsed = (time.perf_counter() - t0) * 1000
    if elapsed > budget_ms:
        return "【超时降级：跳过可选规范化】", True
    return " | ".join(r.text for r in results), False
long_text = "价格 $1,299.50，日期 2024-01-05，联系 010-1234-5678。" * 200
out, degraded = normalize_with_budget(long_text, budget_ms=5.0)
print(f"  输入长度 {len(long_text)} 字符 -> 耗时超预算={degraded}，输出：{out[:40]}...")
print("  读法：文本前端在关键路径上（串 [[elevenlabs-04]]），所以 TN 必须**有预算与降级**；")
print("        同时要限制输入长度、避免嵌套量词（ReDoS），并保证输出只含纯文本（防 SSML 注入）")

预期输出要点（实跑）：① 规则层稳定处理金额、ISO 日期、时间、单位、编号与 URL，并给出高置信度（0.98）——**URL 必须优先匹配**否则其中的点会被日期规则切坏；② 同形词（read/lead）**规则无法处理**，模型给出读法但**置信度只有 0.62**，因此需要阈值与回退策略；③ **回读校验成功拦下「年份被改错」的幻觉**（2024 → 2025 被判失败并回退）——这是混合方案敢用模型的前提；④ 分类别回归 + **严重度加权**给出真实质量口径（金额/日期权重 5），并支持对关键类别设红线；⑤ TN 有预算与降级：超长输入触发「跳过可选规范化」，避免拖慢关键路径（同时提示 ReDoS 与 SSML 注入的防护要点）。

## 常见追问

- **追问**：为什么年月日顺序是坑？
  - 要点：`05/01/2024` 在美式是 5 月 1 日、在欧式是 1 月 5 日；**必须按用户/会话的 locale 解析**，不能猜。工程做法：优先 ISO 格式、显式 locale、歧义时用保守读法（逐位读）或向用户确认（在有交互的场景）。
- **追问**：神经 TN 会不会越来越强，最终取代规则？
  - 要点：趋势是「模型处理更多类别」，但**关键类别仍要规则 + 校验**：金额、电话、日期读错的代价太高，不能接受「概率性正确」。合理形态是**模型为主 + 规则/校验兜关键类别**。
- **追问**：怎么评估「读得对不对」？
  - 要点：三层——① 字符串级（规范化结果与期望对比，自动化）；② 语义级（回读校验：数字/日期/单位是否等价）；③ 感知级（人工听检，判断韵律与自然度）。**只做第一层会漏掉「读法不同但都合理」，只做第三层不可回归。**
- **追问**：多语言/混排怎么处理？
  - 要点：先做**语种分段**（同一句可能中英混排），再按段选规则与音素表；数字与单位在语言间读法不同（例如 「1.5k」 在英语读 「one point five k」、在中文可能读「一千五百」）；术语（API、latency）通常保留英文读法。
- **追问**：TN 出错怎么快速定位与修复？
  - 要点：**记录原文 + 规范化结果 + 命中的规则/模型置信度**（三个字段缺一不可）；建立「用户反馈 → 归入类别 → 补语料/改规则 → 跑全量回归」的闭环；对高危类别加监控（一旦某类准确率下降立即告警）。
- **追问**：为什么说 TN 的 bug 是回归性的？
  - 要点：规则之间会相互作用（优先级、最长匹配、覆盖范围）；修好日期可能让版本号 `v2.1.3` 被当成日期。所以**每次改动必须跑全量分类别回归**，并对「新增规则影响的类别」做重点检查。
