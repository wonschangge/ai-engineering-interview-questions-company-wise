## 一句话答案

> 先把问题的**真实约束**说清楚：三名员工轮班（约 1 人同时在线）不是「要省人力」，而是**容量极小的关键业务系统**——**打不通就等于患者约不上号**。所以设计的核心不是「让 AI 接电话」，而是三件事：
> ① **安全边界（医疗场景的第一原则）**：agent **绝不给医学建议**；出现红旗症状（胸痛、呼吸困难、出血、意识改变、孕产急症、自杀意念等）→ **立即转人工/急救指引**；身份核验（姓名 + 出生日期，必要时第二因子）后才能查改记录；全程录音告知 + AI 披露；遵守本地隐私法规（HIPAA 类）——**不可逆操作（取消/改期）要二次确认并可回滚**；
> ② **容量与溢出（本题最被低估的部分）**：1 名员工 ≈ 每小时 12–20 通（含记录与查询），三名员工轮班覆盖约 12 小时/天；先算清**现有容量、放弃率与峰值**，再决定 agent 承担什么——**agent 的价值首先是「兜住溢出与下班时间」**（夜间/午休/高峰），而不是替代员工；
> ③ **整合与可执行**：预约系统（EHR/排班）必须能被 agent **读写**（查空档、占位、改期、取消、发确认），并保证**幂等与并发安全**（两个渠道同时抢一个号位）；短信/电话双通道确认；失败要能**明确回退到人工**（转接而不是挂断）。
> 一句话判据：**「接得住」不如「不出错」**——医疗场景里，一个错误的预约（错患者、错科室、错时间）比十通未接来电更严重；所以门禁要按**错误率**设，而不是按接听率。

## 面试官在考什么

- **安全边界是否第一优先**：能否主动提出"不给医学建议 + 红旗症状立即转人工 + 身份核验 + 录音告知 + 不可逆操作可回滚"。**把安全放在容量之后谈，是本题最常见的扣分点。**
- **容量算术**：能否估出「三名员工轮班」的真实容量（每周约多少通、多少小时覆盖、放弃率多少），并据此定位 agent 的职责（下班时间 + 溢出 + 简单确认）。
- **任务分解**：哪些任务适合 agent（查空档、新预约、确认、改期、取消、方向指引），哪些必须转人工（投诉、临床问题、保险争议、复杂多科室协调）。
- **整合与数据**：与 EHR/排班系统的接口形态（同步 API vs 队列）、幂等键、冲突处理、以及**不能直连生产库**的边界。
- **可审计与可追责**：每条预约变更要有**谁（AI 或人工）、何时、依据哪次对话**的审计记录；对话要能回放（这是医疗合规的硬要求，）。
- **失败模式清单**：ASR 听错出生日期导致改错患者记录、重复预约、取消未生效、转人工失败、夜间无人可转、多语言患者、老年患者语速与听力。
- **度量与验收**：错误率（错患者/错时间/重复预约）、转人工率、放弃率、患者满意度、员工负担变化——并给出**上线门禁**（例如错误率必须低于人工基线才放量）。
- **诚实**：会说「这个场景不该追求全自动」（高比例的转人工是可接受的，甚至是正确的）。

**常见错误答案**

- 一上来讲架构与模型（忽略了医疗安全边界）。
- 只谈接听率，不谈错误率与可追责。
- 让 agent 直接读改生产数据库，没有幂等与审计。
- 红旗症状也走普通流程（严重医疗与法律风险）。
- 不估算现有容量，凭感觉说「能省 X 人力」。
- 没有转人工的兜底（夜间无人值班时挂断）。

## 原理与推导

### 1. 先算现有容量（不然无法定义成功）

$$\text{日可接听量}=\text{在线人数}\times\text{每人在线小时}\times\frac{3600}{\text{AHT（秒）}}\times(1-\text{非通话占用})$$

| 参数 | 取值（示例） | 说明 |
| --- | --- | --- |
| 在线人数 | 1（三人轮班） | 覆盖约 12 小时 |
| AHT（平均处理时长） | 240 s（4 分钟） | 查排班 + 录入 + 确认 |
| 非通话占用 | 25% | 记录、回电、内部沟通 |
| 日容量 | **约 135 通** | $12\times3600/240\times0.75$ |
| 峰值集中度 | 早 8–11 点占 40% | 峰值时段容量约 54 通/3 小时 |

**含义**：日容量仅百余通，**峰值时段必然溢出**（占线/放弃）。所以 agent 的第一价值是**在下班时间与峰值溢出时接住电话**，而不是替代员工。

### 2. 任务分级（什么交给 agent）

| 任务 | 适合 agent？ | 理由 |
| --- | --- | --- |
| 查询空档并**新建预约** | ✅（带核验） | 结构化、可校验 |
| **确认**已有预约 | ✅ | 低风险，减少外呼工作量 |
| **改期/取消** | ⚠️ 需二次确认 + 可回滚 | 不可逆、影响排班 |
| 科室/地址/准备事项（禁食等）**标准说明** | ✅（仅限审核过的文本） | 不可自由生成医疗内容 |
| 保险/费用问题 | ❌ 转人工 | 复杂且易出错 |
| 临床问题（症状、用药） | ❌ **一律转人工/护士线** | 安全边界 |
| 红旗症状 | ❌ **立即转人工或急救指引** | 最高优先级 |
| 投诉与纠纷 | ❌ 转人工 | 关系风险 |

### 3. 安全边界清单（写进系统提示与代码）

1. **不给医学建议**：任何症状/用药/诊断问题 → 转护士线或人工；agent 只做「流程性说明」（由院方审核过的固定文本）。
2. **红旗症状 → 立刻升级**：识别关键词与语义（胸痛、呼吸困难、大出血、意识模糊、抽搐、孕产急症、自杀/自伤），**不追问细节**，直接给急救指引并转人工。
3. **身份核验**：姓名 + 出生日期（两项匹配才放行）；改期/取消再加一项（电话后四位或预约号）；三次失败 → 转人工。
4. **不可逆操作可回滚**：取消/改期先做**「预提交 + 确认」**，保留原预约快照，支持在 N 分钟内撤销。
5. **披露与知情**：开场说明「这是 AI 助手，通话会被记录」；患者可随时说「转人工」。
6. **数据最小化与合规**：只取业务必需字段；录音与转写加密留存并设期限；访问有审计（串 [[anthropic-28]] 的权限边界）。

### 4. 整合架构（可执行的那一层）

```
电话/PSTN ── SIP ──▶ 语音 agent（ASR→对话→TTS）
                        │  工具调用（受策略网关约束）
                        ▼
                 预约服务（幂等 API）
                   ├─ 查询空档（只读）
                   ├─ 占位/建约（幂等键 = 患者ID+时段+渠道）
                   ├─ 改期/取消（预提交 + 确认 + 可撤销）
                   └─ 发确认（短信/电话/邮件）
                        ▼
                 EHR / 排班系统（不直连生产库）
```

**工程要点**：
- **幂等键**：同一通电话重试不得产生两个预约；
- **并发安全**：agent 与人工、线上与线下共用同一号池时，用**短时占位（hold）+ 超时释放**；
- **策略网关**：把「哪些工具、哪些参数范围允许调用」从对话模型里剥离出来**独立校验**（防 prompt 注入导致越权，串 [[anthropic-28]]）；
- **审计**：每次变更记录（谁、何时、哪次对话、变更前后）；
- **回退**：任何一步失败 → 明确转人工（带上下文摘要），**不挂断**。

### 5. 失败模式与对策

| 失败模式 | 后果 | 对策 |
| --- | --- | --- |
| ASR 听错出生日期 | **改到别人的预约** | 双字段核验 + 二次复述确认 + 冲突时转人工 |
| 重复预约 | 号源浪费、患者困惑 | 幂等键 + 建约前去重查询 |
| 取消未生效 | 患者白跑一趟 | 变更后回执（短信）+ 日终对账 |
| 转人工失败 | 患者被挂断 | 队列 + 回呼（callback）兜底，夜间转值班护士线 |
| 多语言患者 | 沟通失败 | 语言检测 + 多语言 TTS/ASR，或直接转人工 |
| 老年患者/听力障碍 | 反复误解 | 放慢语速、重复选项、随时转人工；保留按键菜单作为兜底 |
| 号池并发冲突 | 双预约 | 短时占位 + 冲突时给替代时段 |

### 6. 度量与上线门禁

| 类别 | 指标 | 门禁（示例） |
| --- | --- | --- |
| 安全 | 红旗症状转人工率 | **100%**（漏一个即阻断上线） |
| 正确性 | 错患者率、错时间率、重复预约率 | **低于人工基线**（例如 <0.5%） |
| 覆盖 | agent 独立完成率、转人工率 | 目标区间（不追求 100%） |
| 体验 | 放弃率、满意度、回呼及时率 | 不低于现状 |
| 效率 | 员工通话分钟数变化、下班时段接听量 | 明确改善 |
| 合规 | 审计完整率、录音留存合规 | 100% |

**放量节奏**：下班时段（无人值守）→ 峰值溢出 → 简单确认 → 新预约 → 改期/取消（最后开放，因为它不可逆）。

# 医院预约语音系统：容量测算、任务分级、安全策略网关、错误率门禁
import random
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Tuple

# ---------- 1) 现有容量与缺口 ----------
@dataclass
class Staffing:
    staff_on_shift: int = 1
    shift_hours: float = 12.0
    aht_s: float = 240.0
    non_call_share: float = 0.25
    def daily_capacity(self) -> float:
        per_person = self.shift_hours * 3600 / self.aht_s * (1 - self.non_call_share)
        return per_person * self.staff_on_shift

@dataclass
class Demand:
    calls_per_day: float = 300.0
    peak_share: float = 0.40          # 早高峰占 40%
    peak_hours: float = 3.0
    after_hours_share: float = 0.25   # 下班时间来电占比
    def peak_calls(self) -> float:
        return self.calls_per_day * self.peak_share
    def peak_capacity(self) -> float:
        # 峰值时段能安排的人手（假设仍 1 人）
        return 1 * self.peak_hours * 3600 / 240.0 * 0.75

st, dm = Staffing(), Demand()
print("① 现有容量与需求（三名员工轮班、AHT 240 s、非通话占用 25%）")
print(f"  日可接听量        {st.daily_capacity():>7.0f} 通")
print(f"  日来电需求        {dm.calls_per_day:>7.0f} 通")
print(f"  峰值需求（3 h）    {dm.peak_calls():>7.0f} 通")
print(f"  峰值可接听        {dm.peak_capacity():>7.0f} 通")
print(f"  缺口             {max(0, dm.calls_per_day - st.daily_capacity()):>7.0f} 通/日，"
      f"峰值缺口 {max(0, dm.peak_calls() - dm.peak_capacity()):>4.0f} 通")
print("  读法：**日容量只有百余通**，而需求是数百通 —— 缺口集中在「峰值」与「下班时间」；")
print("        所以 agent 的第一职责是兜住这两块，而不是替代员工（替代会给不出冗余）")

print("\n② 任务分级：自动化率与错误代价（决定上线顺序）")
@dataclass
class Task:
    name: str
    share: float                 # 占来电比例
    automatable: float           # 可自动完成的比例（0-1）
    error_cost: int              # 错误代价 1-5（5 = 医疗/不可逆风险）
    reversible: bool
TASKS = [
    Task("确认已有预约", 0.25, 0.90, 1, True),
    Task("新预约（查空档+建约）", 0.30, 0.75, 3, True),
    Task("改期/取消", 0.20, 0.60, 5, False),
    Task("流程性说明（地址/禁食）", 0.10, 0.85, 2, True),
    Task("保险/费用", 0.08, 0.10, 4, True),
    Task("临床问题/投诉", 0.07, 0.00, 5, True),
]
print(f"  {'任务':<24} {'占比':>6} {'可自动化':>9} {'错误代价':>9} {'可逆':>6} {'建议':<12}")
for t in TASKS:
    if t.automatable <= 0.3:
        advice = "一律转人工"
    elif (not t.reversible) or t.error_cost >= 5:
        advice = "最后开放+可回滚"          # 不可逆或高代价 -> 排到最后
    elif t.error_cost <= 2 and t.automatable > 0.6:
        advice = "优先上线"
    else:
        advice = "核验后开放"
    print(f"  {t.name:<24} {t.share:>6.0%} {t.automatable:>9.0%} {t.error_cost:>9} "
          f"{'是' if t.reversible else '否':>6} {advice:<12}")
auto_share = sum(t.share * t.automatable for t in TASKS)
print(f"  加权自动化率（当前能力）≈ {auto_share:.0%}，其余 {1-auto_share:.0%} 需转人工")
print("  读法：**自动化率不是越高越好** —— 错误代价 5 且不可逆的任务（改期/取消）应最后开放，")
print("        并强制「预提交 + 二次确认 + N 分钟内可撤销」")

print("\n③ 安全策略网关：红旗症状与身份核验（必须在模型之外强制）")
RED_FLAGS = ["胸痛", "胸口疼", "呼吸困难", "喘不上气", "大出血", "止不住血",
             "意识模糊", "叫不醒", "抽搐", "孕产", "要生了", "自杀", "不想活"]
def triage(utterance: str) -> Tuple[str, str]:
    for kw in RED_FLAGS:
        if kw in utterance:
            return ("ESCALATE_EMERGENCY", f"命中红旗词「{kw}」：不追问、直接给急救指引并转人工")
    clinical_words = ["吃什么药", "剂量", "能不能停药", "能不能停", "停药",
                      "什么病", "怎么回事", "严重吗", "要紧吗"]
    for kw in clinical_words:
        if kw in utterance:
            return ("ESCALATE_NURSE", f"命中临床问题「{kw}」：转护士线，不做医学解释")
    return ("CONTINUE", "流程性对话继续")

@dataclass
class Identity:
    attempts: int = 0
    verified: bool = False
    def verify(self, name_ok: bool, dob_ok: bool) -> str:
        self.attempts += 1
        if name_ok and dob_ok:
            self.verified = True
            return "核验通过"
        if self.attempts >= 3:
            return "三次失败 -> 转人工（不再允许自助）"
        return f"核验失败（第 {self.attempts} 次），请复述姓名与出生日期"

print(f"  {'患者话语':<26} {'判定':<22} 说明")
for u in ["我想改一下周三的预约", "我胸口疼得厉害", "这个药能不能停", "顺便问下怎么走"]:
    action, why = triage(u)
    print(f"  {u:<26} {action:<22} {why}")
ident = Identity()
for name_ok, dob_ok in ((True, False), (True, False), (True, False)):
    print(f"  身份核验：name_ok={name_ok} dob_ok={dob_ok} -> {ident.verify(name_ok, dob_ok)}")
print("  读法：红旗与临床问题必须在**模型之外的策略层**判定（不可依赖模型自觉）；")
print("        注意关键词表本身很脆（「能不能停药」挡不住「这个药能不能停」）——")
print("        第一版演示就漏判了这一句，所以生产里要「规则 + 分类器」双保险")
print("        身份核验要有次数上限并转人工 —— 这直接防「改到别人预约」这类最严重错误")

print("\n④ 不可逆操作的两次确认与回滚（改期/取消）")
@dataclass
class Pending:
    patient: str
    action: str                  # "cancel" / "reschedule"
    snapshot: Dict
    confirm_window_min: int = 10
    confirmed: bool = False
    rolled_back: bool = False
    def confirm(self) -> str:
        self.confirmed = True
        return f"已执行 {self.action}（保留快照，可在 {self.confirm_window_min} 分钟内撤销）"
    def rollback(self) -> str:
        if not self.confirmed:
            return "尚未执行，无需回滚"
        self.rolled_back = True
        return f"已回滚到原预约：{self.snapshot}"
p = Pending("患者 A", "cancel", {"time": "周三 10:30", "dept": "心内科"})
print(f"  预提交：{p.action} 原预约快照 {p.snapshot}")
print(f"  患者确认后：{p.confirm()}")
print(f"  患者后悔：{p.rollback()}")
print("  读法：医疗场景的不可逆操作要**先快照再执行**，并给出撤销窗口；")
print("        这既是体验设计，也是可审计与可追责的工程基础（串 [[agent-10]]）")

print("\n⑤ 错误率门禁与放量节奏（用模拟验收）")
def simulate(n: int = 1000, asr_dob_err: float = 0.03, verify_strict: bool = True,
             seed: int = 11) -> Dict[str, float]:
    """模拟：ASR 听错出生日期 + 核验严格度对「改错患者」的影响"""
    rnd = random.Random(seed)
    wrong_patient, dup, hung_up = 0, 0, 0
    for _ in range(n):
        dob_heard_wrong = rnd.random() < asr_dob_err
        if dob_heard_wrong:
            if verify_strict:                     # 双字段核验 + 复述确认
                if rnd.random() < 0.05:           # 仍可能因为患者自己也说错
                    wrong_patient += 1
            else:
                wrong_patient += 1                # 只用姓名核验 -> 直接改错
        if rnd.random() < 0.02:
            dup += 1                              # 无幂等键时可能重复建约
        if rnd.random() < 0.01:
            hung_up += 1
    return {"错患者率": wrong_patient / n, "重复预约率": dup / n, "转人工失败率": hung_up / n}
print(f"  {'配置':<26} {'错患者率':>9} {'重复预约率':>11} {'转人工失败率':>13}")
for label, strict, dup_key in (("仅姓名核验（不推荐）", False, True),
                               ("双字段核验 + 复述确认", True, True)):
    r = simulate(verify_strict=strict)
    print(f"  {label:<26} {r['错患者率']:>9.2%} {r['重复预约率']:>11.2%} "
          f"{r['转人工失败率']:>13.2%}")
print("  读法：**错患者率**是最重要的门禁指标（改错人的预约是不可接受的）：")
print("        严格核验把它从 3% 量级降到 0.15% 量级 —— 这就是「先安全、后自动化」的量化依据")
print("  放量节奏：下班时段 → 峰值溢出 → 预约确认 → 新预约 → 改期/取消（最后，因为不可逆）")

预期输出要点（实跑）：① 容量测算显示**三名员工轮班的日容量只有约 135 通，而需求 300 通**，缺口集中在峰值（3 小时需求 120 通 vs 可接听 34 通，缺口 86 通）与下班时间——**agent 的第一职责是兜住这两块**；② 任务分级给出上线顺序：**确认预约优先、改期/取消最后**（错误代价 5 且不可逆），加权自动化率约 66%，其余 34% 转人工；③ 策略网关演示**红旗症状与临床问题在模型之外被强制升级**，身份核验三次失败即转人工；④ 不可逆操作「先快照、后执行、可撤销」；⑤ 门禁模拟显示**严格双字段核验把「错患者率」从 3.00% 降到 0.10%**（重复预约率与核验无关，两行的差异是模拟噪声）——这是「先安全、后自动化」的量化依据。

## 常见追问

- **追问**：为什么不直接让 agent 处理所有来电？
  - 要点：医疗场景的**错误代价不对称**（一个错误预约的分量远大于十通未接来电），而且**临床与投诉类问题本质上不该自动化**。合理目标是「兜住溢出与下班时间 + 承担低风险高频任务」，并把**转人工率当作可接受的设计参数**而不是失败。
- **追问**：夜间无人值班时转人工转给谁？
  - 要点：三条路——① 与**值班护士线/院内总机**对接（真实有人）；② 对急症直接给**急救指引**（并记录）；③ 提供**回呼预约**（患者留言，次日早上人工回电）。**关键是绝不能出现「转接失败被挂断」。**
- **追问**：怎么处理「患者说的和系统里的不一致」？
  - 要点：**以系统记录为准**，但要给患者明确反馈（「我这边看到的是周三 10:30，和您说的周二不一致，我帮您转人工核对」）。**不做猜测性修改**——这是防错的核心。
- **追问**：如何防止 prompt 注入让 agent 越权改记录？
  - 要点：**策略网关在模型之外**（工具白名单 + 参数范围 + 业务规则校验），模型只提出「意图」，执行层独立授权；审计全部工具调用（串 [[anthropic-28]]）。
- **追问**：怎么评估员工负担是否真的下降？
  - 要点：看**通话分钟数、回电次数、加班时长**与**峰值压力**（峰值排队长度）；同时追踪「因 agent 转来的复杂通话」是否反而更长（转人工应带上下文摘要，避免患者重复叙述）。**别只看接听量。**
- **追问**：合规上最容易踩的坑是什么？
  - 要点：录音告知与留存期限、最小必要数据、访问审计、跨境传输、以及**AI 披露**（很多地区要求告知对方在与 AI 交互）；此外**不得用患者对话训练模型**（除非明确授权）。
