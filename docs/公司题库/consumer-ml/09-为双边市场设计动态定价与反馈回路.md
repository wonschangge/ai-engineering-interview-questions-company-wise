## 一句话答案

> 动态定价不是「预测一个价格」，而是**带约束的闭环控制问题**：观测供需与成交状态 → 估计弹性与匹配概率 → 决定倍率 → 执行 → 观测响应。目标函数也从来不是单一的「成交额最大」，而是**完成率、等待时间、司机时薪、乘客价格感知、长期留存**这组相互冲突的量在约束（价格上限、监管、公平性）下的权衡。
> 最容易出事的是**反馈回路**，可以分四类：① 供给诱导（高溢价把司机拉上线，供给恢复后溢价回落——负反馈，通常稳定）；② 需求抑制（溢价赶走乘客，需求下降又让供给过剩、溢价更低，若用户永久流失就是不可逆的损伤）；③ **预期博弈**（司机学会等溢价才上线，制造虚假稀缺，溢价越等越高——这是最危险的一条）；④ 竞品耦合（对手定价改变你的供需）。
> 工程上的答案是三条纪律：**限幅 + 死区 + 滞后**（控制论层面抑制振荡）、**地理随机化做实验**（溢价会在相邻区域之间溢出，时间切换实验会被污染）、以及**用长期指标而不是当周成交额做验收**（串 [[consumer-ml-02]]）。

## 面试官在考什么

- 是否把它当**控制问题**而不是预测问题：会不会主动谈闭环、响应延迟、振荡、稳定性，而不是只谈「用什么模型拟合价格-需求曲线」。
- 是否知道**预测会改变被预测的对象**：可引用 performative prediction 的口径——当预测支持决策时，预测会影响它试图预测的结果；这种内生分布漂移如果被忽略，会表现为「莫名其妙的分布漂移」，通常被误当作需要重训的信号（论文原话大意如此）。这条正是本题「反馈回路」的理论坐标。
- 是否理解**双边**：乘客侧弹性与司机侧弹性不同、响应时间也不同（司机上线要分钟级，乘客决策是秒级），所以同一个倍率在两边的效应是错位的。
- 是否给出**护栏与不可逆性分析**：价格上限、每期最大调整幅度、平峰回补、以及对「用户永久流失」这种不可逆损失的检测与止损。
- 能否区分**短期指标与长期价值**：当周成交额上升但次月留存下降，是负价值；要能说出用哪些指标（留存、复购、投诉率、司机时薪分布）去识别它。

**常见错误答案**

- 「用需求曲线求最优价格」——静态最优化忽略了闭环：你定完价，需求和供给都会变，而且会因为你的定价而变。
- 「溢价越高供给越多，所以上调到供需平衡」——忽略预期博弈：司机可能学会等待，供给曲线会随策略变化而移动。
- 「用 A/B 测试切换开关来评估」——同城不同时段会互相污染（司机与乘客会跨时段迁移），地理随机化才可靠。

## 原理与推导

### 1. 定价要控制的到底是什么

设某区域某时刻：乘客需求率 $\lambda_p(p)$（随价格递减）、司机供给率 $\lambda_d(s)$（随司机实收 $s$ 递增）、匹配概率 $m(\lambda_p,\lambda_d)$、以及等待时间 $w$。平台的倍率 $\theta$ 同时影响两端：乘客支付 $p=p_0\theta$，司机实收 $s=p_0\theta(1-c)$（$c$ 为抽成）。

要优化的是一组目标而不是一个：

$$\max_{\theta\in[\theta_{\min},\theta_{\max}]}\ \underbrace{\text{完成率}}_{m}\ -\ \alpha\underbrace{w}_{\text{等待}}\ -\ \beta\underbrace{\text{流失风险}}_{\text{长期}}\ +\ \gamma\underbrace{\text{司机时薪}}_{\text{供给侧}}$$

这个式子的意义不在求解，而在**逼你说出权重**：把 $\alpha,\beta,\gamma$ 摆到台面上，才能解释为什么有时「明明可以涨到 2.5× 却不涨」。

### 2. 为什么不能用排队代替定价

供需失衡时有两种分配机制：**排队**（先到先得，等待时间吸收全部压力）与**定价**（出价高者得，价格吸收全部压力）。定价的优势是即时、无需物理队列；代价是把「谁得到服务」变成支付能力问题，且会**筛选用户**（价格敏感的长期用户被挤走）。工程上常见的是混合：设价格上限 + 高溢价时引入排队，避免价格无上限。

### 3. 四类反馈回路（本节是题眼）

| 回路 | 机制 | 方向 | 风险 |
| --- | --- | --- | --- |
| 供给诱导 | 溢价 → 司机上线 → 供给增加 → 溢价回落 | 负反馈（自稳） | 若司机响应慢于溢价更新周期，会来回振荡 |
| 需求抑制 | 溢价 → 需求下降 → 供给相对过剩 → 溢价回落 | 负反馈 | **不可逆部分**：被赶走的用户可能不再回来 |
| 预期博弈 | 司机学会「等溢价」→ 高峰期先不上线 → 供给更缺 → 溢价更高 | **正反馈** | 虚假稀缺，价格与等待同时恶化 |
| 竞品耦合 | 你的溢价把需求推给对手，对手的供给被吸走 | 交叉 | 区域性价格战，双方都亏 |

再加一条**测量回路**：你用日志训练下一个模型，而日志是你过去的定价策略产生的（策略决定了你看到什么数据）。这正是 performative prediction 描述的情形——模型的部署改变了数据分布本身；论文给出的关键概念是 **performative stability**：预测应当在「人们会对预测做出反应之后」的分布上保持校准，而不是在历史分布上。工程含义是：**评估新策略必须用反事实方法**，不能只用历史日志的回放（串 [[consumer-ml-02]] 的离线-在线不一致）。

### 4. 稳定性设计：控制论的三件套

1. **限幅（rate limit）**：每期倍率变化不超过 $\Delta_{\max}$（例如每 5 分钟不超过 ±0.2×）。它把「一步到位」变成「多步逼近」，代价是收敛慢，收益是不振荡。
2. **死区（dead zone）**：供需比在阈值内不动价（例如偏离目标 5% 以内保持当前倍率）。它消除小幅噪声引起的抖动。
3. **滞后（hysteresis）**：进入溢价的阈值高于退出的阈值（例如供需比 > 1.3 才涨、< 1.15 才降），避免在边界反复横跳。

再加**频率限制**（同一区域两次调价至少间隔 $T$）与**冷却期**（一次溢价结束后 N 分钟内不再触发），这两条专门对付预期博弈：让「等待」不再有可预测的收益。

### 5. 实验与评估

溢价有**空间溢出**：A 区涨价会把需求推到 B 区、把 B 区的司机吸到 A 区。所以：

- 时间切换 A/B（今天涨价、明天不涨）会被天气、赛事、通勤节律污染；
- **地理随机化**（随机选一批城市/区域作处理组，保留相邻对照）更可靠，但要把溢出显式建模（用缓冲区区域或 switchback 设计）；
- 评估指标要分短期（完成率、等待、成交额）与长期（留存、复购、司机留存）；只看短期会系统性地高估涨价的价值；
- 反事实评估框架（串 [[evaluation-09]]）用于在没有实验时估计策略变化的影响。

## 数值与代码验证

### 表 1：回路的可观测信号与止损动作

| 回路 | 早期信号 | 止损动作 |
| --- | --- | --- |
| 供给诱导振荡 | 倍率与在线司机数呈周期性反相 | 降增益、加死区、拉长调价周期 |
| 需求抑制 | 该区域活跃用户数持续下降、竞品份额上升 | 设价格上限、平峰优惠回补、分层定价 |
| 预期博弈 | 高峰前在线司机数异常下降、溢价的「可预测性」上升 | 加冷却期、随机化调价时刻、平峰时段补贴前置 |
| 竞品耦合 | 两城/两区的倍率同步性异常上升 | 区域独立策略、避免公开可预测的调价规则 |

| 参数 | 取值示例 | 作用 |
| --- | --- | --- |
| 调价周期 $T$ | 5 min | 与司机响应时间匹配（过短会追着噪声跑） |
| 单期最大调整 $\Delta_{\max}$ | ±0.2× | 限幅，抑制振荡 |

### 可运行代码

```python
# 价格-供给-需求闭环模拟：对比「激进调价」与「限幅+死区+滞后」
def simulate(periods=40, gain=1.0, damp=False, dead=0.0, cap=0.2,
             surge_min=1.0, surge_max=2.5, seed=7):
    import random
    rnd = random.Random(seed)
    surge, drivers, log = 1.0, 100.0, []
    for t in range(periods):
        demand = 120.0 - 40.0 * (surge - 1.0) + rnd.gauss(0, 3)      # 需求随价格下降
        supply = 60.0 + 55.0 * (surge - 1.0) + rnd.gauss(0, 3)       # 供给随价格上升
        ratio = demand / max(supply, 1e-6)
        err = ratio - 1.0                                            # 目标：供需比 1
        if damp and abs(err) < dead:
            err = 0.0                                                # 死区
        step = gain * err
        if damp:
            step = max(-cap, min(cap, step))                         # 限幅
        new_surge = max(surge_min, min(surge_max, surge + step))
        if damp:                                                     # 滞后（单侧缓慢回落）
            if new_surge < surge and (surge - new_surge) > cap / 2:
                new_surge = surge - cap / 2
        log.append((t, round(surge, 3), round(ratio, 3)))
        surge = new_surge
    return log

def stats(log):
    s = [x[1] for x in log[5:]]
    return max(s) - min(s), sum(abs(s[i] - s[i-1]) for i in range(1, len(s))) / (len(s) - 1)

for name, kw in (("激进（增益 1.0，无限幅）", dict(gain=1.0, damp=False)),
                 ("限幅+死区+滞后",        dict(gain=1.0, damp=True, dead=0.05))):
    log = simulate(**kw)
    span, tv = stats(log)
    print(f"{name}: 后 35 期倍率极差 {span:.3f}，平均单期变动 {tv:.4f}")
    print("   前 12 期:", [x[1] for x in log[:12]])

# 增量价值算例：把「短期成交额」与「长期留存」分开看
DAU, RIDES_PER_USER, AVG_FARE, TAKE_RATE = 1_000_000, 0.30, 18.0, 0.22
def weekly_gmv(uplift, churn_pp):
    rides = DAU * RIDES_PER_USER * (1 + uplift)
    users_next = DAU * (1 - churn_pp)
    return rides * AVG_FARE * TAKE_RATE, users_next * RIDES_PER_USER * AVG_FARE * TAKE_RATE
now = weekly_gmv(0.0, 0.0)[0]
surge_now, next_week = weekly_gmv(0.06, 0.005)      # 本周 +6% 成交，代价是 0.5pp 流失
print(f"\n本周抽成 {now:,.0f} → 涨价后本周 {surge_now:,.0f}（+{surge_now/now-1:.1%}），"
      f"但下周基数 {next_week:,.0f}（{next_week/now-1:+.1%}）")
```

预期输出要点：**激进组**的倍率极差明显更大（在 1.0–2.5 之间来回摆动），平均单期变动也更高；**限幅+死区+滞后组**的极差与单期变动都显著更小——这就是「用收敛速度换稳定性」的量化体现。第二段算例显示：本周抽成上升 6%、但流失 0.5pp 会让下周的基数下降约 0.5%，**几周内就能把短期收益吃回去**——所以「按周看成交额」是错的验收方式。

## 常见追问

- **追问**：溢价会不会把需求永久赶走？
  - 要点：会，且不可逆。所以要区分「价格敏感的临时抑制」与「用户流失」：前者在溢价结束后需求回来，后者不会。检测手段是看该区域/该用户群在溢价结束后的**恢复率**，而不是溢价期间的成交额。
- **追问**：怎么区分「短期成交额上升」与「长期价值」？
  - 要点：把指标分层——即时（完成率、等待）、短期（成交额、抽成）、长期（留存、复购、司机留存、投诉）。验收用长期层，短期层只作为过程指标；并给长期指标设护栏阈值。
- **追问**：监管价格上限怎么进模型？
  - 要点：作为硬约束（$\theta\le\theta_{\max}$）而不是惩罚项——惩罚项在最优点附近仍可能越界。上限之外的压力用排队、平峰补贴或供给侧激励吸收。
- **追问**：为什么地理随机化比时间切换更可靠？
  - 要点：溢价有空间溢出（需求与司机跨区流动），时间切换会被天气/赛事/通勤节律污染且无法分离；地理随机化把溢出隔离在缓冲区，代价是需要更多区域与更长周期。
- **追问**：司机学会等溢价怎么办？
  - 要点：破坏可预测性——随机化调价时刻与幅度、加冷却期、把激励前置到平峰（让「等」不再最优）；同时监控「高峰前在线司机数」这个专门信号。
- **追问**：如果模型完全不用 ML，纯规则也能做，为什么要 ML？
  - 要点：规则能做兜底与限幅，ML 的价值在于**估计弹性与匹配概率**（不同区域、时段、用户群差异很大），以及在多维特征下做更细的分层定价。但要警惕：ML 只该在规则的安全边界内优化。
