## 一句话答案

> 监控要分**四层**，因为不同层坏掉的修法完全不同：**数据层**（特征分布、缺失率、上游新鲜度）、**模型层**（预测分布与校准）、**业务层**（点击/转化/时长，且必须分群看）、**系统层**（延迟、QPS、错误率）。只在业务层看指标，问题出现时你已经损失了流量；只在数据层看分布，又会把无害的漂移当成故障。
> 重训触发不能只看单一阈值——要同时满足三个条件：**统计显著 + 效应量够大 + 连续 N 个窗口持续**，并且要能**归因到一个「重训能改善」的机制**上。因为漂移有三种，只有前两种通常能靠重训缓解：$P(X)$ 变（协变量漂移，重训常常有用）、$P(Y\mid X)$ 变（概念漂移，重训有用但要更快）、$P(Y)$ 变（标签先验变，往往只是**采样或口径变化**，重训可能白做甚至更糟）。
> 还有一条容易被忽略的分界线：**漂移 vs bug vs 业务变化**。上游特征表停更、埋点口径改了、竞品动作，看起来都像漂移；用重训去「修」bug 是浪费且危险。

## 面试官在考什么

- **漂移三分类**是否清楚（协变量 / 概念 / 标签先验），以及各自的检测手段与应对方式不同。有人一张口就是「数据分布变了就重训」，那是初级答案。
- 是否知道**检测方法的实证结论**：可引用 *Failing Loudly* 的口径——作者研究了检测数据集漂移的方法，跨多种协变量与标签分布的扰动后发现，**用预训练分类器做降维后再做两样本检验**的方法表现最好；而判别式（domain-discriminator）方法更适合**定性地刻画漂移并判断它是否有害**。这条正好回答「怎么区分无害漂移与有害漂移」。
- 是否理解**标签延迟**：转化可能要 7 天甚至 30 天才知道，所以业务层指标天然滞后，必须用**代理指标**（点击、加购、会话时长）做早期信号，并在标签到齐后回填校验（串 [[consumer-ml-02]]）。
- 触发条件是否考虑**代价不对称**：误报（无害漂移就重训）浪费算力并可能引入回归；漏报（该重训没重训）损失流量。两者要用不同的阈值策略。
- 是否记得**重训本身的陷阱**：训练-服务偏斜、时间穿越（point-in-time correctness）、以及**用自己产生的日志训练自己**导致的反馈回路（串 [[consumer-ml-09]]）。

**常见错误答案**

- 「PSI > 0.25 就重训」——阈值只能当参考，必须结合业务影响与持续性；而且 PSI 对样本量与分箱很敏感。
- 「看线上 CTR 掉了就重训」——CTR 掉可能是季节、竞品、上游 bug、或曝光结构变化，先归因再动手。
- 「每天自动重训最省事」——高频重训会让模型追着噪声跑，且把反馈回路放大（模型越贴合自己产生的日志，偏差越固化）。

## 原理与推导

### 1. 漂移的形式化与三种类型

设线上数据分布 $P_t(X,Y)$ 与训练时的 $P_0(X,Y)$：

| 类型 | 变化的部分 | 例子 | 检测重点 | 重训是否有效 |
| --- | --- | --- | --- | --- |
| 协变量漂移 | $P(X)$ | 节假日流量结构变化、新机型占比上升 | 特征分布 + 两样本检验 | 通常有效 |
| 概念漂移 | $P(Y\mid X)$ | 用户偏好变了、竞品改了推荐策略 | 校准与残差、分群指标 | 有效，且要更快 |
| 标签先验漂移 | $P(Y)$ | 促销期转化率整体上移、埋点口径变化 | 标签率时间序列 | 视原因而定，常常无效 |

关键工程含义：**检测手段要能分辨这三类**，否则触发逻辑会把「无害的 $P(X)$ 变化」和「危险的 $P(Y\mid X)$ 变化」当成同一件事。

### 2. 四层监控的指标清单

| 层 | 指标 | 典型窗口 | 说明 |
| --- | --- | --- | --- |
| 数据层 | 特征缺失率、均值/分位数、类别占比、上游表新鲜度、特征回填延迟 | 分钟–小时 | 最先坏、最便宜、最容易被忽略（上游停更不会报错） |
| 模型层 | 预测分数分布（均值/分位）、校准误差（预测 CTR vs 实际 CTR）、覆盖率 | 小时–天 | 校准比 AUC 更贴近线上决策质量 |
| 业务层 | CTR/CVR/时长/完成率，**分群**：新老用户、地区、设备、内容类目 | 小时–天 | 标签延迟要用代理指标兜 |
| 系统层 | p50/p99 延迟、超时率、QPS、错误率、特征取值耗时 | 分钟 | 系统退化会伪装成模型退化（串 [[evaluation-07]]） |

### 3. 检测方法：从统计检验到「是否有害」

1. **单变量统计**：KS 检验（连续）、卡方/PSI（类别）、缺失率与均值漂移。便宜、可解释，但高维下会大量误报（做几百个特征就必然有几个「显著」）——所以要**多重比较校正**并按特征重要性加权。
2. **多变量两样本检验**：可引用 *Failing Loudly* 的实证结论——**用预训练分类器降维后再做两样本检验**在该研究覆盖的多种扰动下表现最好；直接用原始高维空间做检验会因维度灾难失效。
3. **判别式/领域分类器**：训练一个「区分训练集与线上样本」的分类器，AUC 高说明可分（即有漂移），并能给出**哪些特征在驱动漂移**；但作者也指出这类方法更适合定性刻画与判断危害，不宜单靠它做阈值判定。
4. **校准与残差监控**：对模型层最直接——预测 CTR 与实际 CTR 的比值随时间变化，比 AUC 更能反映「线上决策是否还准」。
5. **代理指标 + 标签回填**：用点击等即时信号做早期预警，标签到齐后回填，重算真实指标并校正早期判断（避免「假警报—重训—无改善」的循环）。

### 4. 重训触发的判定逻辑

我实际会实现的触发规则（三条同时满足才算触发，另加一条豁免检查）：

```
触发 = 显著(p < α, 经多重比较校正)
     且 效应量 ≥ δ（业务可感知，例如校准偏差 > 5% 或分群 CTR 相对下降 > 3%）
     且 持续 ≥ N 个连续窗口（例如 6 个 1 小时窗 / 3 个天窗）
     且 归因检查通过：不是上游 bug、不是埋点口径变更、不是已知的周期性事件
```

三个补充规则：

- **周期性豁免**：周末、节假日、大促的模式在训练数据里出现过就不算漂移（用「与上个同周期对比」而不是与「上一小时」对比，即**同比而非环比**）。
- **概念漂移要更快**：校准监控连续 2 个窗口恶化就可以触发，不必等 6 个（概念漂移的危害更大）。
- **重训前先回滚或降权**：如果线上指标在恶化，先用旧模型或规则兜底，再从容重训（重训不是急救手段）。

### 5. 重训的三种模式与陷阱

| 模式 | 触发 | 优点 | 陷阱 |
| --- | --- | --- | --- |
| 定期 | 日历（周/月） | 简单可预期 | 与真实漂移脱节；低频漏、高频浪费 |
| 触发式 | 监控条件 | 精准、省算力 | 阈值标定难；有检测延迟 |
| 持续/在线 | 流式更新 | 响应最快 | 反馈回路放大、灾难性遗忘、难回滚 |

**必须一起做的三件事**：① **时间穿越检查**——特征只能用预测时刻之前已知的值（point-in-time correctness），否则离线指标虚高、上线崩；② **训练-服务一致性**——同一套特征定义与计算逻辑（串 [[consumer-ml-04]]）；③ **对抗反馈回路**——保留探索流量、用逆倾向加权（IPW）校正日志偏差，否则模型会越来越偏向自己推荐的物品（串 [[consumer-ml-03]] 的位置偏差与 [[consumer-ml-09]] 的 performative 效应）。

### 6. 上线门禁与回滚

重训产出的是候选模型，必须过门禁才能上：离线指标不退化（含分群）、校准在可接受范围内、线上小流量灰度（1%–5%）观察业务层与系统层、并预设自动回滚条件（主指标恶化超过阈值、或护栏指标越界）。可引用的工程取向来自 Google 的规则清单：上线前先定义指标与护栏、先规则后模型（串 [[evaluation-04]]）。

### 可运行代码

```python
# 漂移检测 + 触发判定：PSI、KS 两样本检验、多重比较校正与持续性
import random, math
from statistics import mean

def psi(base, cur, bins=10):
    """总体稳定性指数：分箱后比较两组占比"""
    lo, hi = min(base + cur), max(base + cur)
    if hi == lo:
        return 0.0
    w = (hi - lo) / bins
    def hist(xs):
        h = [0] * bins
        for x in xs:
            i = min(bins - 1, int((x - lo) / w))
            h[i] += 1
        return [c / len(xs) for c in h]
    hb, hc = hist(base), hist(cur)
    return sum((c - b) * math.log((c + 1e-6) / (b + 1e-6)) for b, c in zip(hb, hc))

def ks_stat(a, b):
    a, b = sorted(a), sorted(b)
    i = j = 0
    d = 0.0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            i += 1
        else:
            j += 1
        d = max(d, abs(i / len(a) - j / len(b)))
    return d

def ks_critical(n, alpha=0.05):
    return 1.36 * math.sqrt(2.0 / n)      # 两样本 KS 的近似临界值

random.seed(11)
base = [random.gauss(0, 1) for _ in range(20000)]
scenarios = {
    "无漂移":        [random.gauss(0, 1) for _ in range(20000)],
    "轻微协变量漂移": [random.gauss(0.05, 1.02) for _ in range(20000)],
    "明显协变量漂移": [random.gauss(0.50, 1.30) for _ in range(20000)],
}
print(f"KS 临界值(α=0.05, n=20000) ≈ {ks_critical(20000):.4f}\n")
for name, cur in scenarios.items():
    p, d = psi(base, cur), ks_stat(base, cur)
    print(f"{name:<14} PSI={p:6.3f}  KS={d:.4f}  "
          f"{'显著' if d > ks_critical(20000) else '不显著'}  "
          f"{'PSI 预警' if p > 0.10 else 'PSI 正常'}")

# 触发判定：显著 + 效应量 + 持续性 + 归因
def should_retrain(windows, alpha=0.05, effect=0.03, need=3, cause_is_bug=False):
    hits = [w for w in windows if w["p"] < alpha and w["effect"] >= effect]
    if cause_is_bug:
        return "不重训（归因到上游 bug，先修数据链路）"
    if len(hits) >= need:
        return f"触发重训（连续 {len(hits)} 个窗口达标）"
    return f"不触发（达标窗口 {len(hits)}/{need}）"

cases = {
    "概念漂移（校准连续恶化）": ([{"p": 0.01, "effect": 0.06}] * 4, False),
    "单次抖动":                 ([{"p": 0.002, "effect": 0.05}] + [{"p": 0.4, "effect": 0.01}] * 5, False),
    "上游特征停更":             ([{"p": 0.001, "effect": 0.20}] * 4, True),
}
for name, (w, bug) in cases.items():
    print(f"{name:<22} -> {should_retrain(w, cause_is_bug=bug)}")
```

预期输出要点：无漂移场景 KS 不显著、PSI 正常；**轻微漂移**可能统计显著（KS 超临界值）但 PSI 仍在预警线下——这正是「显著性 ≠ 有害」的体现，要叠加效应量；**明显漂移**两者同时报警。触发判定演示了三种典型情况：连续达标才触发、单次抖动不触发、以及**归因到上游 bug 时明确不重训**——这条规则能省掉大量无效重训。

## 常见追问

- **追问**：PSI 的 0.1 / 0.25 阈值能直接用吗？
  - 要点：只能当起点。PSI 对分箱数、样本量、以及「漂移方向」都敏感；要用业务后果标定（该特征漂移多大时线上指标真的会动），并叠加效应量与持续性判断。
- **追问**：标签延迟 7 天，业务层指标怎么监控？
  - 要点：三层替代——即时代理（点击、加购、会话时长）、模型层校准（用已到齐的部分标签做滚动估计）、以及把「标签回填后」的真实指标用于事后校验与重训决策。绝不能用未到齐的标签算成「指标下降」。
- **追问**：重训后指标没有恢复怎么办？
  - 要点：说明原因不在「模型过期」——依次排查上游数据（是否停更/口径变）、特征穿越、训练-服务偏斜、以及**问题本身不可学**（用户偏好真的变了且没有新标签可学）。此时正确动作是修数据或改问题定义，而不是继续重训。
- **追问**：如何防止「用自己的日志训练」放大偏差？
  - 要点：保留探索流量（ε-贪心或 bandit 采样）、用 IPW 校正曝光偏差、监控推荐结果的多样性/集中度（模型自我强化的早期信号）、并定期用无偏的小规模随机曝光做校准（串 [[consumer-ml-03]]）。
- **追问**：多久重训一次合适？
  - 要点：由**概念漂移速度**与**重训成本**共同决定；多数场景是「定期（如每周）+ 触发式补训」的组合。判断依据是「模型新鲜度曲线」：测量不同训练截止时间的模型在同一线上分布上的表现落差。
- **追问**：怎么区分漂移与业务变化（例如大促）？
  - 要点：用同比而非环比、把已知事件标注进时间线、并在训练数据里显式加入事件特征（节假日/大促标记），使模型能学而不是被当成漂移。
