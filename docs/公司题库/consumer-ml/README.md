# 面向消费者的规模化 ML 公司面试题库

这是公司题库里**唯一按公司群组**出题的一家：Uber、Netflix、LinkedIn、Airbnb、Pinterest、Spotify 这类公司的
面试风格高度一致——**不看你会不会调模型，看你能不能在一个有供给约束、有反馈回路、有海量流量的系统里把指标做对**。
所以这十四篇的共同骨架是：先切清目标函数与约束（完成率、留存、预算、延迟），再把代价算成数字，最后交代反馈回路与护栏。

## 这家（类）公司在考什么

把十四题放一起，能看到一条非常清晰的能力画像，四条主线：

1. **代理指标的自觉**（02、03、11、14）：离线指标、点击、CTR 全都是代理，面试官反复在问「你的代理离真实目标有多远、你怎么知道」。
2. **约束下的优化**（05、09、11、12）：延迟预算（<100 ms 的 ETA）、价格上限与监管、拦截与人审预算、权限与升级人工——**没有约束的最优解在业务上不存在**。
3. **反馈回路**（09、11、13、02）：定价改变供需、风控改变对手、用自己产生的日志训练自己、离线评测集被线上分布甩开。这条线在别的公司少见于这么集中的密度。
4. **工程链路与规模化**（01、04、06、07、10）：有界内存的流式结构、feature store 与训练-服务偏斜、亿级候选的两阶段漏斗、万级目录的探索、视觉检索的索引账。

## 建议学习顺序

- **指标与实验主线**：`02 → 03 → 13 → 14`。四题连读就是一条完整闭环——离线为什么骗人、日志为什么有偏、线上怎么监控、最后怎么向业务交代。
- **系统设计主线**：`05 → 06 → 09`（同一家公司里最常连着问的三题：实时预测、漏斗排序、闭环定价），再按兴趣补 `07 / 08 / 10 / 11 / 12`。
- **基础与实现**：`01`（流式结构）与 `04`（feature store）是其余所有题的地基，建议先看。
- 时间紧就按 `02 → 03 → 13` 过一遍：这三题的思路在其余十一题里反复出现。

## 自测清单

能不看资料回答下面这些问题，说明这类公司的准备到位了：

- 有界内存下怎么做流式 top-k？精确解与近似解的内存和时间各是多少？
- 滑动窗口速率计数器有哪几种实现？分桶法与精确日志法的误差-内存权衡是什么？
- 离线涨线上不涨，你会按什么顺序排查？哪一类成因只能靠查链路而不是换模型解决？
- position bias 的生成模型怎么写？IPW 的权重怎么算、方差为什么会爆炸？
- feature store 要固定哪几件「接口」？训练-服务偏斜的五类成因里，哪一类最常见？
- 网约车 ETA 有哪几种？为什么用分位数而不是均值？<100 ms 预算怎么分配？
- 两阶段排序中，候选生成与排序的优化目标分别是什么？为什么不能共用一套指标？
- 目录只有万级时，推荐系统的瓶颈为什么从检索变成探索？冷启动用什么信号？
- PYMK 与职位推荐的目标函数差在哪？为什么照抄 feed 只能拿一半分？
- 动态定价的四类反馈回路分别是什么？哪一条是正反馈、为什么危险？
- 「相似图片」的三种定义分别需要什么表征与索引？为什么需要去重与两阶段？
- 类别不平衡 + 对抗对手时，为什么不能用准确率、也不该只调阈值？
- 客服助手升级人工时要移交哪些状态？权限过滤为什么必须在检索阶段做？
- 漂移监控分哪四层？重训触发的四个条件是什么？哪一类漂移重训通常无效？
- 讲业务价值时，价值链四段各自会怎么衰减？怎么用样本量直觉判断「提升 1%」是否可信？
