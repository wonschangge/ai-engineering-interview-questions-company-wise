# 阿里巴巴（Qwen）面试题库

这是公司题库里的第一家「前沿 AI 实验室」。Qwen 的面试有个很鲜明的特征：**题目几乎都落在「这个技术选择为什么这么做、代价是什么」上**——
不是问「Qwen 有多少参数」，而是问「为什么词表要 151K」「为什么同时有 dense 和 MoE」「为什么数字要逐位切分」。
所以这十篇的共同骨架是：**先说清机制，再把代价算成数字，最后说清生产里会踩什么坑**。

## 这家公司在考什么

把十道题放在一起看，Qwen 的面试在四个方向上反复施压：

1. **词表与序列层面的一阶选择**（01、02、05）：FIM 的拼接格式、byte-level BPE 的底表、长上下文的 $\cos/\sin$ 表——这些都是「一次决定、影响所有下游」的选择，面试官想看你能不能把它们的连锁代价说清。
2. **架构与训练配方的取舍**（03、04、06）：统一思考模式、MoE 与 dense 的分工、强到弱蒸馏。共同点是**没有免费选项**，每一处收益都对应一处成本，答案必须带数字。
3. **后训练与评测治理**（07、08）：可验证奖励的 RL 与榜单可信度。这两题连着问的意图很明显——**能力怎么来、以及你怎么证明能力是真的**。
4. **多模态与战略面**（09、10）：动态分辨率 VLM 与 Apache 2.0。前者考技术判断，后者考你能否把商业约束翻译成工程选择。

## 建议学习顺序

- **技术主线**：`02 → 05 → 09`（词表 → 长上下文 → 视觉 token），三题都在算「token 层面的账」，连着读能建立统一的数量感。
- **训练主线**：`06 → 07 → 03`（蒸馏 → 可验证 RL → 统一思考模式），这条线回答「能力从哪来、怎么复制、怎么服务化」。
- **工程与面谈**：`04 → 08 → 10`（选型 → 发布可信度 → 战略与决策），适合面试前一天过一遍，练的是「把取舍讲成数字」的表达。
- `01` 单独看即可，它是唯一一道需要写代码的实现题，重点在拼接格式与 loss 掩码。

## 自测清单

能不看资料回答下面这些问题，说明这家公司的准备到位了：

- 仓库级 FIM 的一条样本怎么拼？为什么只对中间段算 loss？仓库级比文件级多给了什么监督？
- 151K 字节级 BPE 的三项收益分别是什么？代价分别落在哪（压缩率、序列长度、embedding 参数量）？
- 为什么把数字逐位切分？它对算术能力与序列长度各有什么影响？
- 一个模型怎么同时支持思考与非思考？思考预算在服务侧具体控制什么？
- 30B-A3B 与 32B dense 在什么流量形态下各自更优？为什么稀疏 MoE 的瓶颈在权重读取？
- YaRN 改了哪一部分？为什么说它「免训练」？DCA 解决的是哪个具体问题？
- 强到弱蒸馏为什么要求同词表？on-policy 与 off-policy 蒸馏的差别在哪个分布上？
- RLVR 相比学出来的奖励模型好在哪四条？组内奖励全同时为什么没有梯度、怎么缓解？
- 发布开放权重时，你会交付哪四样东西来证明数字可信？$n$-gram 去污染为什么挡不住改写？
- 原生动态分辨率与固定切块相比，收益与代价各是什么？MRoPE 的三个分量在图像与视频上分别取什么值？
- Apache 2.0 与「开放权重但附加限制」的实质差别是什么？开源削弱的是哪一部分溢价？
- 讲一个你做过的模糊决策：当时的判据是什么、哪一步是可逆的、复盘时改了哪个机制？
