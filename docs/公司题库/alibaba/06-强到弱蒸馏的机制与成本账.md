## 一句话答案

> 强到弱蒸馏 = 同族旗舰给出 token 级分布与长思考轨迹 + on-policy 对齐 + 一次性成本。旗靓（Qwen3-235B-A22B 一类）与学生（Qwen3-32B 到 0.6B 那串 dense）共享 byte-level BPE 词表与架构，logits 能逐位对齐，于是 teacher 的分布可以直接当监督信号；学生自己在同一批 prompt 上采样、由 teacher 纠正，避开了 off-policy SFT 的 exposure bias。
> 便宜的原因是监督信号的**性质变了**：直接把「稀疏标量奖励 + 反复探索」换成「逐 token 密集监督 + 一次复制」——同一道题上 Qwen3-8B 的 on-policy 蒸馏只要 1,800 GPU·h（直接 RL 要 17,920 GPU·h，约 1/10），AIME'24 反而是 74.4 对 67.6。边界同样要说清：teacher 是能力天花板，teacher 生成数据是一笔要单列的一次性成本，通用数据配比不到位就灾难性遗忘。

## 面试官在考什么

- 能否把「同族」讲成前提而不是背景：共享词表与 chat template，logits 才能逐位对齐；跨厂商 teacher 拿不到 logits、词表也对不齐，只能退到数据蒸馏。
- 能否区分 on-policy 蒸馏与 off-policy SFT 的**分布视角**：前者在学生自己生成的序列上讲，训练分布与部署分布一致；后者只在 teacher 的分布上拟合，学生一偏离就没人纠（R1 式的推理蒸馏属于后者）。
- 能否写出 Hinton 口径的损失与温度，以及 $T^2$ 补偿的**梯度尺度依据**，而不是照抄公式。
- 是否知道推理能力的蒸馏主力是**序列级**（学思考过程，不只学答案），并且理解 logit 蒸馏在长轨迹上的存储代价——能报出 top-k 压缩的量级。
- 能否复算成本：蒸馏 1,800 vs RL 17,920 GPU·h、$6ND$ 反推 token、teacher 的权重读取与吞吐、以及回本点，并说明便宜是对**总账**成立而不是把某笔账算成 0。

**常见错误答案**

- 「随机初始化小模型，让 teacher 的输出当标签从头训」——LLM 时代的数据蒸馏是拿已有小基座做 SFT，从头训（结构蒸馏那种）既贵又学不到。
- 「蒸馏能让几十亿的小模型变成旗舰」——蒸馏只传递**已被采样出来**的行为；teacher 的能力上限、幻觉与格式怪癖都会被继承。
- 「部署时也要开温度 $T>1$ 才有蒸馏收益」——温度只是训练期技巧，推理一律 $T=1$。

## 原理与推导

### 1. 先钉死「强到弱」：同族、同词表、同模板

Qwen3 的「强」指旗舰（235B-A22B 这类 MoE 大模型），「弱」指同代的小 dense 学生（32B/14B/8B/4B/1.7B/0.6B）。三者共用 byte-level BPE 词表（Qwen 侧 config 声明 151,936，实际 151,669 + added token）与同一套 chat template，所以 teacher 在每个位置的 logits 与 student 是一一对应的——这正是 LLM 时代 logit 蒸馏唯一还常用的场景。跨厂商 teacher 拿不到 logits，词表也对不齐，只能做数据蒸馏。

### 2. 两个可叠加的监督信号：序列级与分布级

- **序列级/数据蒸馏**：teacher 在 prompt 上生成轨迹，学生把轨迹当 SFT 数据。学到的是行为与过程，不需要 teacher 的 logits，跨族也能用。
- **分布级/logit 蒸馏**：直接对齐 teacher 的下一 token 分布，监督密度是前者的数十倍，但要求同词表。

主线是 **on-policy**：学生与 teacher 在同一批 prompt 上各自产出序列，用 teacher 的输出分布监督学生的对应位置。价值在于训练分布等于部署分布——学生在自己会走到的状态上被纠正，避开 exposure bias；off-policy 只在 teacher 的分布上拟合，学生一旦偏离就没人纠。两者可叠加：先 off-policy 灌格式，再 on-policy 提分。

### 3. 损失、温度与 $T^2$：为什么必须补梯度尺度

复合损失（Hinton 口径）在硬标签项之外加一项带温度的软标签项：

$$L=\alpha\cdot \mathrm{CE}(y,p_s^{1})+(1-\alpha)\cdot T^{2}\cdot \mathrm{KL}\!\left(p_t^{T}\,\|\,p_s^{T}\right),\qquad p_i^{T}=\frac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}$$

$-T^2$ 不是拍脑袋的系数，它来自对 logits 求导的量级分析（Hinton 原文的脚注口径）。记软标签项（不带 $T^2$）对某个学生 logit 的偏导为 $g_T$：

$$\frac{\partial C_{\text{soft}}}{\partial z_i}=\frac{1}{T}\left(p_i^{T}-q_i^{T}\right)\;\propto\;\frac{1}{T^{2}}\quad\text{（}T\ \text{大时}\;p^T-q^T\sim 1/T\text{）}$$

依据：softmax 的雅可比给出 $1/T$ 因子，高温下 $p_t^{T}-p_s^{T}$ 本身再按 $1/T$ 收缩，两项相乘就是 $1/T^2$。不补偿的话，$T=16$ 时软标签梯度只剩 $1/16^{2}=1/256\approx 0.0039$ 的权重，一开高温软标签项就被硬标签项淹没，蒸馏退化成普通 SFT。乘 $T^2$ 之后两项梯度重归同一量级。

两个必须提的实现细节：① 温度只是训练期技巧，部署仍按 $T=1$ 推理；② teacher 与 student 必须同词表/同分词器，同族蒸馏天然满足，不一致时只能退到数据蒸馏。

### 4. 推理能力：序列级那一半更关键——学过程不只学答案

- 样本保留 teacher 的思考链（`</think` 之前的轨迹），格式与解题习惯一起迁；只留最终答案等于把 CoT 的能力丢掉。
- 按最终答案的**可验证性**过滤：答案错的轨迹一律丢，否则把错误推理当正确过程学进去。
- 超长轨迹按思考预算裁剪，控制单样本成本与线上行为。
- Qwen3 自己就把旗舰的 thinking 数据与 non-thinking 数据混进同一批 SFT，把两种模式一次固化——蒸馏数据同样要覆盖两种模式。

### 5. 结构蒸馏只作对照：DistilBERT 证了什么

DistilBERT 用 12 层 teacher、6 层 student，损失是 LM loss + 蒸馏 loss + **cosine 距离**三项（cosine 对齐 hidden state 的方向），换来参数约减 38.8%（66M → 40M）、保留约 97% 的语言理解、推理快约 60%。它证明「小模型能继承大模型能力」，但 LLM 时代的主力是数据/序列级：结构蒸馏要求逐层对应，层数一变就得重新设计映射，扩展性差；数据蒸馏对架构没有约束。

### 6. 成本更低的第一层：信号性质——从搜索改成抄写

RL 侧（GRPO）的账：一条 rollout 只在序列末尾拿到一个标量奖励，组内相对优势 $A_i=(r_i-\operatorname{mean})/\operatorname{std}$，奖励全同的组优势恒为 0、整组白烧。$G=8$、单次通过率 $p=0.05$ 时有 66.3% 的组全错、$p=0.9$ 时有 43.1% 的组全对，两端都是零梯度；再叠上 reward model／verifier 的调用与 policy logprob 重算，单位有效梯度非常贵。

蒸馏侧：监督信号是 teacher 在每个位置的分布（数据蒸馏是整条轨迹），每个 token 都有梯度；KL/CE 是监督式损失，方差小，不需要 advantage 估计、不需要 clip、不需要反复 roll-out。一句话：RL 用「采样 → 打分 → 更新」去**搜索**一个行为，蒸馏把搜到的行为**抄写**下来；搜索成本随难度与采样次数涨，抄写成本只随数据量线性涨。这也是 [[finetuning-10]] 那条规律的推广——RL 探索出的行为一旦稳定就固化进数据，别给每个新模型重跑一遍 RL。

### 7. 第二层：数字自己复算

锚点（Qwen3 技术报告口径，经 [[alibaba-03]] 复算；layer 数与 KV 头数取自 config）：Qwen3-8B 直接 RL 需要 17,920 GPU·h、AIME'24 67.6 / AIME'25 55.5；同一模型走 on-policy 蒸馏只要 1,800 GPU·h、AIME'24 74.4 / AIME'25 65.5。算力约 1/10（$17{,}920/1{,}800=9.96$）而分数更高，这就是「为什么便宜」的硬证据。

学生训练那笔账（仓库统一常数：H100 bf16 dense 989 TFLOPs、MFU 40%、$6ND$）：

$$E_{\text{train}}=1{,}800\times 3{,}600\ \text{s}\times 989\times 10^{12}\times 0.4=2.56\times 10^{21}\ \text{FLOPs}$$

$$N_{\text{tok}}=\frac{2.56\times 10^{21}}{6\times 8\times 10^{9}}=5.3\times 10^{10}\ \text{token}\;\Rightarrow\;6.7\ \text{token/参数（含多 epoch）}$$

换算成钱：$1{,}800\times 2=\$3{,}600$。**这一步最容易被算错**：若把 $1{,}800\,\text{GPU·h}$ 折成 $1.86\times 10^{22}$ FLOPs，就与 $1{,}800\times3{,}600\times989\times10^{12}\times0.4=2.56\times10^{21}$ 差 7.26 倍，反推出的 $3.9\times10^{11}$ token（约 48 token/参数）也就不成立。按仓库常数老老实实算，token 预算约 $5.3\times10^{10}$。直接 RL 的 17,920 GPU·h 是 $2.55\times10^{22}$ FLOPs，按 8B 前向+反向 $4.8\times10^{10}$ FLOP/token 折算约 $5.3\times10^{11}$ token，差额正是「无效 rollout 与 advantage 估计」那笔开销。

为什么蒸馏能白拿这份便宜：旗舰的探索成本由旗舰付一次（完整四段配方：Long-CoT 冷启动 SFT → Reasoning RL → 思考模式融合 → General RL），同一份能力被复用 $N$ 次，小模型这一侧只需付学生训练。要在正文里把「一次性成本」与「服务成本」分开写：1,800 GPU·h 是一次性训练，teacher 生成数据是另一笔一次性成本，两者一起摊到线上 token 上（下一节给平衡点）。

### 8. 第三层：teacher 生成数据那笔账必须单列

teacher 的能力上限决定了这份便宜的上限，它自己的推理成本不能算成 0。Qwen3-235B-A22B 是 MoE（激活约 22B），decode 每 token 要读一遍激活参数 $22\times 10^{9}\times 2\ \text{B}=44\ \text{GB}$：

$$R_{\text{stream}}=\frac{3.35\times 10^{12}\ \text{B/s}}{44\times 10^{9}\ \text{B/token}}\approx 76\ \text{token/s（单条序列）}$$

$$R_{\text{card}}=\frac{989\times 10^{12}\times 0.4}{2\times 22\times 10^{9}}\approx 8{,}991\ \text{token/s/卡}\;\Rightarrow\;3.24\times 10^{7}\ \text{token/(GPU·h)}$$

**这里有个常见的量级陷阱**：把 teacher 生成吞吐取成 $10^{6}$ token/(GPU·h)，它实际上等于 278 token/s，比上面那条单序列带宽上限（76 token/s 对应的 $2.7\times10^{5}$ token/(GPU·h)）还高，等于把假设写得比物理下限还乐观。按仓库常数，batch 摊薄后的算力上限是 $3.24\times10^{7}$ token/(GPU·h)，真实吞吐只能落在带宽下限与它之间。两个口径一起给：造 1,000 万条 × 平均 16k token 的思考轨迹 = $1.6\times10^{11}$ token，按 $3.24\times10^{7}$ 是 $4.9\times10^{3}$ GPU·h ≈ **\$9,900**，按极小 batch 的单序列下限 $2.7\times10^{5}$ 是 $5.84\times10^{5}$ GPU·h ≈ **\$1.17M**——真实值落在两者之间，取决于 batch 与 prefix cache 能摊多薄。

结论写成设计规则而不是吓人的数：蒸馏的成本公式 $C\approx C_{\text{teacher\_gen}}(N_{\text{traj}},L_{\text{traj}})+C_{\text{student\_train}}(6ND)$，其中 $C_{\text{teacher\_gen}}$ 随轨迹条数与长度线性涨、又受单卡吞吐上限约束，所以必须压 $N_{\text{traj}}$（拒绝采样只留 Pass@N 为正的轨迹）、对同批 prompt 用 batch 摊薄、用 prefix caching 复用系统提示与 few-shot 前缀（Qwen3 公开口径命中率 81.25%）、并对数据去重。要换墙钟时间，可以用 2–4 个中间尺寸 teacher 并行产数据（与小模型直接 RL 的对照见 [[alibaba-03]] 表 5）。追问「蒸馏比 RL 便宜」时主动补一句：便宜是对**总账**成立（学生训练 1/10），teacher 生成那笔钱要单列，别把它算成 0。

### 9. 服务侧与回本点：$r$ 从哪来，什么时候不回本

学生换来的服务侧收益有两块且口径不同。① 真正随规模线性放大的是**权重读取**：每 token 要读 $22\times10^{9}\times 2\ \text{B}=44\ \text{GB}$（teacher）对 $8\times10^{9}\times2\ \text{B}=16\ \text{GB}$（student），比值 $r=44/16=2.75\times$——这就是 $r$ 的物理来源，比笼统说「小模型更快」有说服力。② KV cache 按 $k=2LH_{kv}d_{\text{head}}\cdot\text{bytes}$ 算：Qwen3-8B 是 $2\times36\times8\times128\times2\ \text{B}=147{,}456\ \text{B}=144\ \text{KiB/token}$，32k 上下文 4.5 GiB，对照 LLaMA-3-70B 的 320 KiB/token → 10 GiB。KV 只是「每请求并发上限」的成本，不是随流量线性放大的那部分。

回本点：学生每 100 万 output token 的服务成本 $c_s=2/(8{,}000\times3{,}600)\times10^{6}=\$0.0694$（H100 8B dense 有效吞吐 8,000 token/s 口径），一次性成本 $D$，则

$$Q^{*}=\frac{D}{c_s\,(r-1)},\qquad r-1=1.75$$

- 只算学生训练：$Q^{*}=3{,}600/(0.0694\times1.75)\approx 2.96\times10^{4}$ 单位（≈$3.0\times10^{10}$ output token）。
- teacher 生成按 \$21 万量级（$1.06\times10^{11}$ token 口径）全价计入：$Q^{*}\approx(3{,}600+212{,}000)/0.1225\approx 1.77\times10^{6}$ 单位（≈$1.8\times10^{12}$ token）。

两条口径都要写，并说清 $r$ 越小（或学生与旗舰尺寸越接近）越不回本——$r\to1$ 时 $Q^{*}\to\infty$，这是权重读取比给的硬约束，不是运营上的激励。端侧/私有化/许可证这类非成本收益要另外给理由：蒸馏是换结构，量化是换位宽，两者正交，典型链路是「蒸馏 → 量化 → 端侧」。同时留一句诚实的边界：蒸馏不降低 student 的服务成本结构（仍按 token 付款），它降的是「用旗舰能力服务同一批流量」的成本。

### 10. 工程坑与失败模式（按会炸的概率排序）

1. **教师是天花板**：数据蒸馏只传递采样出来的行为，teacher 的幻觉、偏见、格式怪癖会被继承；student 在评测集上达到 teacher 的 90 分不代表行为等价。
2. **窄数据导致灾难性遗忘**（串 [[finetuning-07]]）：只用数理推理轨迹做蒸馏，通用对话、指令跟随、多语言会一起掉；缓解手段是把通用/人类数据按 5–20% 混进蒸馏集，再按评测调比例，而不是拍一个数。
3. **暴露偏差与错误累积**：off-policy SFT 之后学生一离开 teacher 的分布就退化，这是走 on-policy 的动机；on-policy 必须保证采样引擎与训练侧同 tokenizer／同 kernel／同精度，logprob 对不齐会让 KL 项算在错误的样本分布上。
4. **同质化**：所有下游都学同一个 teacher 的分布，措辞、推理风格乃至错误趋同；保留多源 teacher、留一部分自采样与人类数据。
5. **数据污染与评测自证**：蒸馏数据与评测集必须去重，评测集不能由 teacher 生成，否则是自己给自己出题。仓库既有做法是把评测集独立留出（[[rag-04]] 的口径）。
6. **logit 蒸馏在长轨迹上存不下**：Qwen 词表声明 151,936，bf16 每个 token 一份分布是 $151{,}936\times2\ \text{B}=303{,}872\ \text{B}\approx 296.75\ \text{KiB}$；仅按 1,000 万 token 的轨迹算就是 2.76 TiB。工程手段是只存 top-k：$k=64$ 时 $64\times(2\ \text{B value}+4\ \text{B index})=384\ \text{B/token}$，约 791× 压缩，代价是丢掉长尾的绝对量级。
7. **长轨迹自带服务成本**：蒸馏学到的 16k token 思考链会原样搬到线上，Qwen3-8B 单条就是 $144\ \text{KiB}\times16{,}384\approx2.25\ \text{GiB}$ KV（32k 时 4.5 GiB），预算与并发要跟着重算（见 [[alibaba-03]] 的预算服务化与 [[inference-serving-09]]）。
8. **学生起点**：从已有预训练小基座出发，不要随机初始化——结构蒸馏才需要从头训，LLM 的数据蒸馏是「拿基座做 SFT」。

## 常见追问

- **追问**：蒸馏和直接 RL 只能二选一吗？
  - 要点：不是，但要讲顺序——先 RL 出旗舰、再蒸馏小模型。RL 能探索出蒸馏数据里没有的行为（可以超过教师轨迹的覆盖），蒸馏只能复现已被采样到的行为，反过来不成立。蒸馏数据覆盖不到的能力（例如预算内自我收尾）会出现能力空洞，这就是「学生可控性受教师轨迹覆盖度约束」。
- **追问**：为什么一定要 on-policy？直接用 teacher 轨迹做 SFT 不是更省？
  - 要点：省的是数据，贵的是分布偏移。学生推理时走的是自己的分布，off-policy 只在 teacher 分布上拟合，一旦偏离就没人纠（exposure bias 与错误累积）。on-policy 让学生在自己生成的序列上被 teacher 纠正，训练分布等于部署分布，代价是要在线跑 teacher 采样。
- **追问**：logit 蒸馏和数据蒸馏怎么选？
  - 要点：同族同词表才能做 logit，收益是监督更密（每个位置一份分布）；跨厂商 teacher 拿不到 logits、词表也对不齐，只能做数据蒸馏。长轨迹上 logit 还受存储约束，实践里多用 top-k 压缩（$k=64$ 约 790×），或者干脆只保留序列。
- **追问**：单 teacher 还是多 teacher？
  - 要点：多 teacher 缓解同质化（措辞、推理风格、错误趋同），但成本上升、不同 teacher 的分布会互相冲突，需要一个合并策略——按任务路由，或按比例混配后统一蒸馏。
- **追问**：学生能超过老师吗？
  - 要点：个别任务上会。原因是数据过滤与任务聚焦让有限容量集中在目标能力上、软标签本身有标签平滑作用、蒸馏集里混进了 verifier 筛出的更强信号。要答成「聚焦与提纯的收益」，不是「蒸馏能凭空造能力」。
- **追问**：把旗舰的能力搬到小模型，是不是可以用量化代替？
  - 要点：两者正交。蒸馏换的是结构与参数量（能力迁移），量化换的是数值位宽（同样参数的更省显存与带宽）。典型链路是「蒸馏 → 量化 → 端侧」，先蒸馏出小模型，再量化它。量化不会给你一份蒸馏数据带来的能力。
