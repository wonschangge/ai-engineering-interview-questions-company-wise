## 一句话答案

> 选型分三步：先问客户硬件三件事（tensor core 与算子库支持哪些 dtype、显存容量与带宽、是否必须离线打包在 on-prem 或端侧分发），再由硬件代次定可选集合——INT8 从 Turing（SM75）起、FP8 从 Hopper/Ada（SM89/SM90）起、FP4/NVFP4 从 Blackwell（SM100/SM120）起——于是 Hopper/Ada 首选 FP8 W8A8，Blackwell 上考虑 NVFP4，Turing/Ampere 只能 INT8 或 W4A16，端侧与 CPU 走 INT4/INT8 加融合 kernel。
> 证明质量没有下降靠可复现的分层回归：固定 prompt 集、temperature/top-p/max tokens 与评测脚本，逐档只改一个变量（bf16 → FP8 → INT4），报相对基线的差值而不是绝对值，并给出同档多 seed 的噪声范围；评测要分层（语言建模困惑度、数学、代码、长链推理、多语言、指令遵循，再加客户业务集），并记录输出长度分布与拒答率。
> Mistral 交付的是开源权重、客户常常自己部署，所以这道题的落点是「交哪种量化权重、长上下文 KV cache 用哪个精度、在客户卡上实测 goodput」，而不是格式定义的推导。

## 面试官在考什么

- 是否先问约束再选档位：把硬件 dtype 支持、容量与带宽、分发方式问清楚，而不是直接背「4 bit 是当前甜点」。
- 会不会算三笔账并写明口径：权重、量化元数据、KV cache；知道 per-group 128 加 FP16 scale 是 4.125 bit，不是 4 bit。
- 是否清楚收益来源的差别：W4A16 省字节（容量与带宽），W8A8/FP8 才省算力（tensor core 吞吐）；prefill 是计算受限阶段，weight-only 量化几乎没有算力收益。
- 有没有把「证明没降」当成实验设计题：基线可复现、单变量、报相对差值、给出噪声范围、分层评测加业务集，而不是拿一个 perplexity 数字当验收线。
- 是否把验收标准做成 goodput：TTFT、TPOT 与 ITL p99 连同吞吐一起报，只有落在 SLO 内的吞吐才算有效产能。

常见错误答案：

- 「perplexity 没变就是没退化」。困惑度对 3~4 bit 的退化不敏感，数学、代码、多语言这些长尾任务会先掉；AWQ 论文专门用 coding/math 基准与指令微调模型评测，就是为了把它暴露出来。
- 「4 bit 就是 3.5 GB」。漏掉 per-group 的 scale 与 zero point，实际交付的是 4.125~4.5 bit 的产物（7B 上从 3.5 GB 变成 3.6~4.1 GB）。
- 「量化一定更快」。W4A16 的收益来自权重字节减少，长 prefill 上几乎没有算力收益，kernel 每次把 4 bit 解包回 FP16 时收益还可能被反量化开销吃掉。

## 原理与推导

### 1. 先问客户三件事，再由硬件代次定可选集合

选型不是从格式开始，而是从约束开始。三个问题按顺序问：

1. **硬件支持什么**：哪一代 tensor core 原生吃哪些 dtype、算子库（cuBLASLt、CUTLASS、TensorRT-LLM、vLLM 的量化 kernel）有没有对应路径、W4A16 的解包 kernel 是否可用。
2. **容量与带宽是多少**：容量决定权重与 KV cache 能不能同时放下，带宽决定 batch 1 的 decode 能快多少（第 6 节的 roofline 分母就是它）。
3. **怎么分发**：能不能联网、有没有 GPU、是否必须离线打包进 on-prem 或端侧固件、授权与合规上能不能用第三方 kernel。

代次再去裁剪可选集合：

| 代次 | SM | 原生低精度 tensor core | 现实可选档位 | 典型卡 |
| --- | --- | --- | --- | --- |
| Turing | 7.5 | INT8 | W8A8 INT8、W4A16 | T4 |
| Ampere | 8.0 / 8.6 | INT8、BF16（无 FP8） | W8A8 INT8、W4A16 | A100、A10、RTX 30 |
| Ada | 8.9 | FP8 E4M3 / E5M2 | FP8 W8A8、W4A16 | L4、L40S、RTX 40 |
| Hopper | 9.0 | FP8 | FP8 W8A8、FP8 KV cache | H100、H200 |
| Blackwell | 10.0 / 12.0 | FP4 / NVFP4、FP6、FP8 | NVFP4（W4A16 / W4A4） | B200、RTX 50 |
| AMD CDNA3 / CDNA4 | gfx942 / gfx950 | FP8 / FP4、FP6 | FP8 W8A8 / FP4 | MI300X / MI355X |
| 端侧 NPU 与 CPU | — | 以 INT8 为主，部分 INT4 | INT4/INT8 加融合 kernel | 手机与 PC NPU、CPU |

「原生支持」的含义是 dense GEMM 直接吃这个 dtype；**W4A16 不是原生路径**，它把 4 bit 解包回 FP16 再用 FP16 tensor core 算（Marlin 这类 kernel），所以省的是读取字节而不是算力峰值。这条差别决定了什么时候能拿到算力收益，也决定了端侧为什么偏爱 INT4/INT8 加融合 kernel（llama.cpp 的 GGUF K-quant 用 32/64 元素的 block 共享 scale，有效位宽落在 4.5~5 bit）。

### 2. 三笔账：权重、元数据、KV cache

**权重** $M_w = N \cdot b_w / 8$。**元数据**按 per-group 加：group size $g$、每组一个 FP16 scale（2 字节），相对 4 bit 主体的额外开销是 $4/g$（2 B ÷ 每参数 0.5 B × g），即 g128 加 3.1%、g64 加 6.25%；非对称量化再加一个 FP16 zero point，元数据翻倍（g128 → 6.25%、g64 → 12.5%）。这就是「4 bit 的 7B 为什么不是 3.5 GB」：名义 7B 上是 14.0 GB → 3.61 GB（4.125 bit）→ 3.72 GB（4.25 bit），按 config 复算的 7.24B 则是 14.48 → 3.73 → 3.85 GB。

**KV cache** 沿用 [[llm-internals-02]] 的公式 $M_{kv} = 2 \cdot L \cdot H_{kv} \cdot d_{head} \cdot S \cdot b \cdot p$。Mistral 7B（32 层、8 个 KV 头、head_dim 128、bf16）每 token 是 $2 \times 32 \times 8 \times 128 \times 2 = 131{,}072$ B = **128 KiB**，FP8/INT8 直接减半到 64 KiB、FP4 再减半到 32 KiB。sliding-window attention（窗口 4096）再给一个封顶：rolling buffer 只保留最近 4096 个位置的 K/V，单序列固定 512 MiB（FP16）/256 MiB（INT8），此时 cache 不随 $S$ 增长。两件事要分开报：封顶是结构给的，量化是在封顶之后再乘 $1/2$。

**稀疏 MoE**（Mixtral 8x7B，46.70B 总参 / 12.880B 每 token 激活）要换一套口径：量化不省 expert 驻留显存，8 个 expert 都必须在卡上；省的是每 token 读取的激活专家字节。因此 roofline 的分母用激活参数量而不是总参数量——bf16 每 token 读 25.8 GB、INT4(g128+zp) 读 6.84 GB，而驻留占用分别是 93.4 GB 与 24.8 GB。前者决定一台卡装不装得下，后者决定 tok/s。

### 3. 选方案的次序：先 PTQ 后 QAT，先权重后激活

1. **先试 PTQ**（训练无关、几小时可完成、可回滚）；QAT 只在 PTQ 达不到验收线、且客户愿意重训时用。
2. **显存与带宽吃紧 → W4A16**：GPTQ 用近似二阶信息逐列量化并回补误差（论文口径 175B 约 4 GPU 小时压到 3~4 bit，精度损失可忽略）；AWQ 只保护约 1% 的显著权重通道，显著通道按激活分布挑、用等价通道缩放实现、不做重建，因此不容易过拟合校准集，也能推广到指令微调模型。
3. **要拿算力收益 → W8A8 / FP8**：H100 上 FP8 与 INT8 的稠密算力相同（都是 bf16 的 2 倍），差别是 FP8 有 4~5 位指数——E4M3 在 $[2^{-9}, 448]$ 上覆盖约 $2^{17.8}$ 的区间，对区间内任何值都给 6.25% 的相对误差上界，而定点只有一个由 $\max\lvert x\rvert$ 决定的绝对步长 $s/2$。
4. **激活 outlier 撑爆 per-tensor scale → SmoothQuant 类迁移**：$Y = (X\,\mathrm{diag}(s)^{-1})(\mathrm{diag}(s)\,W)$，$s_j = \max\lvert X_j\rvert^{\alpha} / \max\lvert W_j\rvert^{1-\alpha}$，$\alpha \approx 0.5$。变换数学等价，只是把量化难度从激活搬到权重，W8A8 才跑得通。
5. **KV cache 单独决策**：K 用 per-channel、V 用 per-token（K 的少数通道幅度远大于其它通道，比 V 难压）。长上下文场景这一项的收益常常大于把权重再压一档。
6. **交付前验证兼容性**：量化格式与 TP/EP 切分、prefix caching、continuous batching 是否兼容，scale 布局与 packed 权重是否需要专门 kernel。

### 4. 「质量没下降」到底在说什么：三层扰动

- **单值误差**：E4M3 的单值相对误差上界 6.25%；FP16 → BF16 只是尾数从 10 位降到 7 位（单值误差放大 8 倍），多数评测里落在噪声内。
- **张量级 scale 塌缩**：定点的误差是绝对的 $s/2$。INT8 per-tensor 在 $\max = 1$ 时步长 0.007874、误差上界 0.003937，是 FP16 在 1 附近半个步长（$4.88 \times 10^{-4}$）的 8 倍；同一个张量里出现 60 的 outlier 时步长被撑到 0.472441，0.01 被压成 0（100% 相对误差），而同样条件下 E4M3 只损失 4.6%。
- **概率分布的次序扰动**：top-1 常常不变，但排在后面的候选 token 相对次序会变。贪心解码看不出这件事，温度一高就变成「输出质量」问题；所以验收要同时看 top-1 一致率与分布级距离（KL 或 TV）。

### 5. 把质量论证做成可复现实验

- **基线可复现**：固定 prompt 集、解码参数（temperature / top-p / max tokens）、评测脚本与硬件；continuous batching 会让同一 prompt 的输出随并发变化，评测时要么固定 batch 组成，要么全部用贪心。
- **单变量**：bf16 → FP8 → INT4 逐档只改精度，其它不动，报告**相对基线的差值**而不是绝对值。
- **噪声范围**：同档换 3 个 seed 报极差。二项口径下 n=500、$p = 0.75$ 的 95% CI 就有 ±3.80%，只有配对设计能把方差压下来：discordant 25/500 时 $\Delta$ 的 95% CI 约 ±1.96%，discordant 50/500 时约 ±2.77%。**客户业务集最好做成配对样本**，否则一两个点的差距根本解释不了。
- **分层**：语言建模困惑度、数学、代码、长链推理、多语言、指令遵循、安全与拒答，再加客户的业务集；每一层给样本量与 CI，低样本量的层只报趋势不下结论。
- **行为指标**：输出长度分布、提前 EOS 率、JSON / 工具调用格式合法率。量化会改变停止行为，只跑一个基准会被分布扰动骗过去。
- **上线后仍要监控**：验收通过不等于长期安全。交付时留下权重版本与量化参数的可追溯记录，在客户环境里做灰度切换，并对线上输出持续抽样做精度回归；on-prem 缺这套，出问题只能整体回滚权重版本，代价比留一个监控钩子大得多。

### 6. 速度侧：先给 roofline 上界，再在客户机器上实测 goodput

batch 1 的 decode 是带宽题（推导见 [[inference-serving-10]]）：

$$\text{tokens/s} \approx \frac{BW_{\text{eff}}}{W_{\text{per-token}} + KV_{\text{per-token}}}$$

7B bf16 权重 14.48 GB 在 A100（2.0 TB/s）上的上界是 138 tok/s，INT4(g128+zp) 的 3.85 GB 是 519 tok/s。这个上界假设 HBM 利用率 100% 且 kernel 零开销，工程上乘 0.6~0.8 再实测。

验收用 **goodput**：在 TPOT 不超 SLO 的前提下能跑多少吞吐。L4（300 GB/s）上 7B INT4 权重 3.85 GB 加 INT8 KV（窗口 4096，每序列 256 MiB）：b=1 每步读 4.12 GB、13.7 ms/step；b=32 读 12.44 GB、41.5 ms/step，聚合 772 tok/s；把 SLO 定在 TPOT ≤ 50 ms，可用 batch 约到 41、约 830 tok/s。b=64 的 913 tok/s 已经掉到 70.1 ms/step，**超出 SLO 的那部分不算产能**。TPOT 通常会随量化一起下降，因为权重与 KV 的读取字节都变少了。

## 数值与代码验证

```python
"""mistral-05 的数值复算（仅标准库）"""
import math, random
GB, GiB, KiB, MiB = 1e9, 1024 ** 3, 1024, 1024 ** 2
D, I, VOCAB, L, HKV, DH = 4096, 14336, 32000, 32, 8, 128
ATT, MLP, EMB = 2 * D * D + 2 * D * HKV * DH, 3 * D * I, VOCAB * D
N7 = L * (ATT + MLP) + 2 * EMB                       # 7.24B，不 tie embedding
assert round(N7 / 1e9, 2) == 7.24


def wbytes(n, bits, group=None, asym=False):          # 权重 + per-group 元数据
    total = n * bits
    if group:
        total += (n // group) * 16 * (2 if asym else 1)
    return total / 8


print("权重 GB:", {name: round(wbytes(N7, b, g, a) / GB, 2) for name, b, g, a in
                   [("bf16", 16, None, False), ("int8", 8, None, False),
                    ("int4-g128-s", 4, 128, False), ("int4-g128-szp", 4, 128, True),
                    ("int4-g64-szp", 4, 64, True)]})
meta = lambda g, zp: (wbytes(N7, 4, g, zp) - N7 / 2) / (N7 / 2)   # 元数据相对 4 bit 主体的占比
print("元数据占比:", f"g128 {meta(128, 0):.2%}", f"g128+zp {meta(128, 1):.2%}", f"g64+zp {meta(64, 1):.2%}")

# KV cache：2*L*H_kv*d_head*S*b*p
kv = lambda S, p=2, b=1: 2 * L * HKV * DH * S * b * p
print(f"KV/token {kv(1)} B = {kv(1)/KiB:.0f} KiB | 窗口 4096: {kv(4096)/MiB:.0f} MiB(FP16) "
      f"{kv(4096, 1)/MiB:.0f} MiB(INT8) | 32 并发 INT8 {kv(4096, 1, 32)/GiB:.2f} GiB")

# goodput：L4 上 INT4 权重 + INT8 KV（窗口 4096）
w4 = wbytes(N7, 4, 128, True)                         # 4.25 bit 的 3.85 GB
for b in (1, 8, 32, 64):
    ms = (w4 + b * kv(4096, 1)) / 300e9 * 1e3
    print(f"b={b:3d} 每步读 {(w4 + b*kv(4096,1))/GB:5.2f} GB -> TPOT {ms:5.1f} ms, 聚合 {b/ms*1e3:6.1f} tok/s")
b_slo = int((0.05 * 300e9 - w4) / kv(4096, 1))        # TPOT <= 50 ms 的可用 batch
print(f"TPOT<=50ms 时 b={b_slo}, 聚合 {b_slo / ((w4 + b_slo*kv(4096,1)) / 300e9):.0f} tok/s")

# 数值误差
e4m3 = lambda x: min([2 ** (1 - 7) * (m / 8) if e == 0 else 2 ** (e - 7) * (1 + m / 8)
                      for e in range(16) for m in range(8) if (e, m) != (0xF, 0x7)], key=lambda v: abs(v - x))
print(f"E4M3 上界 {2**-4:.2%} | BF16/FP16 单值误差倍率 {2**10/2**7:.0f} | "
      f"INT8 步长 {1/127:.6f}, 上界 {1/254:.6f}, 与 FP16 半步比 {(1/254)/2**-11:.1f}")
for xmax in (1.0, 60.0):
    q8 = round(0.01 / (xmax / 127)) * (xmax / 127)
    qf = e4m3(0.01 / (xmax / 448)) * (xmax / 448)
    print(f"  max={xmax:5.1f}: INT8 {q8:.5f} ({abs(q8-0.01)/0.01:.1%}) | E4M3 {qf:.5f} ({abs(qf-0.01)/0.01:.1%})")

# 评测噪声：独立 vs 配对
for n, p in ((300, .75), (500, .75), (5000, .75)):
    sd = math.sqrt(p * (1 - p) / n)
    print(f"n={n:5d} 独立 95% CI ±{1.96*sd:.2%}", end="  |  ")
    for d in (25, 50):
        print(f"配对 discordant={d}: ±{1.96*math.sqrt(d)/n:.2%}", end="  ")
    print()

# 分布扰动：合成 lm_head（16 个候选、256 维 hidden，8 组随机 hidden）上的 bf16 与 INT4-g32
rnd, V, DV = random.Random(7), 16, 256
W = [[rnd.gauss(0, 1) for _ in range(DV)] for _ in range(V)]
bf16 = lambda x: 0.0 if x == 0 else round(math.frexp(x)[0] * 256) / 256 * 2 ** math.frexp(x)[1]
def q4(r, g=32):                                      # 对称 per-group(32) 量化一行权重
    s = [max(abs(x) for x in r[i:i+g]) / 7 for i in range(0, len(r), g)]
    return [round(v / s[i // g]) * s[i // g] for i, v in enumerate(r)]
probs = lambda l: [math.exp(x - max(l)) / sum(math.exp(y - max(l)) for y in l) for x in l]
lg = lambda Wm, h: [3.0 * sum(a * b for a, b in zip(r, h)) / math.sqrt(DV) for r in Wm]
acc = {k: [0, 0.0, 0.0, 0] for k in ("bf16", "INT4-g32")}
for t in range(8):
    h = [rnd.gauss(0, 1) for _ in range(DV)]
    base = lg(W, h); rb = sorted(range(V), key=lambda i: -base[i]); pb = probs(base)
    for name, Wq in (("bf16", [[bf16(v) for v in r] for r in W]), ("INT4-g32", [q4(r) for r in W])):
        q = probs(lg(Wq, h)); rq = sorted(range(V), key=lambda i: -q[i])
        d = (rb[0] == rq[0], 0.5 * sum(abs(a - b) for a, b in zip(pb, q)),
             sum(a * math.log(a / b) for a, b in zip(pb, q)), set(rb[:3]) == set(rq[:3]))
        acc[name] = [acc[name][i] + d[i] for i in range(4)]
for k, s in acc.items():
    print(f"{k}: top-1 一致 {s[0]}/8 | 平均 TV {s[1]/8:.4f} | 平均 KL {s[2]/8:.5f} | 前 3 名集合相同 {s[3]}/8")
```

## 常见追问

- **追问**：客户的卡是 Ampere（A100），没有 FP8，怎么选？
  - 要点：可选集合只剩 W8A8 INT8 与 W4A16。A100 的 INT8 tensor core 稠密算力是 FP16 的 2 倍（624 TOPS 对 312 TFLOPS），所以 W8A8 INT8 既省带宽也省算力，是不缺 FP8 时的正解；真正的限制在动态范围——激活 outlier 必须靠 per-channel/per-token 粒度或 SmoothQuant 类迁移兜住，否则掉点会比 FP8 明显。只要容量与带宽、不要算力收益时，W4A16 加 INT8 KV cache 更省事。
- **追问**：为什么不用 QAT 一步到位？
  - 要点：PTQ 训练无关、几小时可完成、可以逐档回滚，先试的成本最低；QAT 要改训练流程、要客户交出训练数据与算力，周期从小时级变成天级。只有在 PTQ 掉点超过验收线、且客户有重训意愿时才值得，而且 QAT 的产物与框架/kernel 的耦合更强，on-prem 升级时会变成负债。
- **追问**：校准集怎么选？
  - 要点：分布要贴近客户的真实流量（语言、领域、长度分布、system prompt），规模几百到几千条通常够，关键是覆盖而不是数量；必须与评测集隔离，重叠会让量化参数在真实分布上失灵。AWQ 不做重建、不依赖反向传播，正是为了不容易过拟合校准集；GPTQ 用 Hessian 近似，对校准数据更敏感一些。
- **追问**：为什么 KV cache 量化常常比把权重再压一档更划算？
  - 要点：KV 量化的收益是双份的——容量与每步读取带宽同时减半，所以通常连 TPOT 一起降；而权重从 8 bit 到 4 bit 只把权重那部分再砍一半，长上下文时 KV 的读取量已经接近甚至超过权重（Mistral 7B 在窗口 4096、b=32 时 KV 是 8.00 GiB，是 INT4 权重 3.85 GB 的两倍多）。K 用 per-channel、V 用 per-token 是把风险压下来的常用粒度。
- **追问**：怎么区分「真的没退化」和「噪声盖住了退化」？
  - 要点：三条。① 配对样本（同一批 prompt 两边都跑），把方差从二项口径压到 discordant 口径；② 先测噪声底——同档换 3~5 个 seed 得到极差，小于这个极差的差值不下结论；③ 分层看长尾任务，别用总体平均把数学/代码上的掉点摊平。如果业务集只有几百条，直接把 CI 一起报给客户。
- **追问**：客户要部署 Mixtral 这类稀疏 MoE，量化账怎么算？
  - 要点：显存按总参数量算（46.70B 的 bf16 是 93.4 GB，单张 80 GB 卡放不下；FP8 46.7 GB、INT4 24.8 GB 才能单卡驻留），速度按每 token 激活量算（12.880B：bf16 读 25.8 GB、INT4 读 6.84 GB）。另外要单独验证路由与专家并行的兼容性：expert 切分后 all-to-all 的通信量、以及某些 expert 是否被量化得更差（校准集里低频 expert 的统计不足）。
