## 一句话答案

> 最可能是灾难性遗忘，但诊断顺序不能反：先把评测 harness 钉死（同一评测集、同一 few-shot 设置、同一解码参数）在微调前后各跑一次，再排掉与权重无关的变量——chat template 与特殊 token 变了、system prompt 变了、解码默认值变了、推理侧换成了 4-bit/8-bit 量化、adapter 没被正确加载或合并、serving 栈与训练配置不一致。这些排干净后指标仍然下降，才归因到权重。
> 处置按代价从低到高：① 回滚到基线 adapter；② 降学习率与 epoch，用少量通用/校准数据把漂移掉的接口重新对齐；③ 重训时四层缓解——数据层混入 5%–10% 通用数据、参数层用 LoRA 冻结底座、目标层加 KL 或蒸馏约束、流程层把能力回归集写进验收门禁；④ 客户要的若是新知识而非新行为，改走 RAG。

## 面试官在考什么

- **会不会先归因再下结论**。上来就说「灾难性遗忘」的人，通常没有把评测口径与推理配置排干净；真正区分水平的是那串「与权重无关但会让人误判」的检查清单。
- **有没有度量口径**。报绝对跌幅与相对跌幅 $(R_o - R)/R_o$，同时看通用回归集分数、通用语料上的 loss/perplexity、旧任务线性探针在新表示上的准确率三个视角；只说客户指标涨了多少，是没法做决策的评测。
- **能不能把机制讲成两条互补的视角**：优化视角（目标函数里没有旧任务、新旧梯度冲突）与表示视角（共享表示漂移，遗忘分「能力被覆盖」与「接口变了」两层），并说清这两层对应完全不同的补救代价。
- **处置方案有没有代价排序和数字**。回放把算力推高多少、LoRA 把可训练参数压到多少、约束加强会让客户指标掉多少，都要能报数；「加正则、少训一点、多混点数据」不是答案。
- **有没有交付意识**。Mistral 的微调产品线以 LoRA adapter 为主（微调 API 与开源的 mistral-finetune），所以动作要落在 adapter 上：加载与合并的验收、多 adapter 的路由与版本化、按客户隔离、SOW 里的回归门槛与可回滚开关。

常见的错误答案：

- 「多训几个 epoch 让它适应」——客户数据窄而少（几百到几千条），再训下去只会把旧能力覆盖得更彻底，方向是反的。
- 「用 LoRA 就不会遗忘」——adapter 仍会改变前向行为，低秩容量写满时同样回退；PEFT 削弱遗忘，不等于消除遗忘。

## 原理与推导

### 1. 归因分级：先排掉与权重无关的变量

微调项目里「全面变差」的报告，有相当一部分根本不是权重问题，而是评测与推理链路变了。按下面的清单逐项排除，全部零成本、可回滚：

| 变量 | 典型症状 | 排除动作 |
| --- | --- | --- |
| 评测口径 | 差异只出现在某一版评测脚本上 | 固定 few-shot 数、prompt 模板、答案解析器、temperature、max tokens、停止条件，前后各跑一次 |
| chat template / 特殊 token | 输出格式乱、答非所问、提前 EOS | 打印 `apply_chat_template` 的结果与训练时实际喂入的字符串逐字对比；检查 BOS/EOS 与工具 token |
| system prompt / 推理前缀 | 语气、拒答边界整体变化 | 用同一条 system prompt 在两边重跑 |
| 解码默认值 | 「变笨」集中在长答案与重复输出 | 对齐 temperature、top_p、repetition penalty、stop 字符串 |
| 推理精度 | 全面小幅变差 | bf16 的最大相对表示误差是 $2^{-8}\approx0.39\%$，而 4-bit 每权重只剩 $2^4=16$ 个候选级别；同一份权重分别用 bf16 与量化版各跑一次 |
| adapter 加载/合并 | 连客户任务指标一起掉 | 检查 target module 名是否匹配（不匹配会被静默跳过）、$\alpha$ 与 $r$ 口径是否与训练一致、合并前后在同一批 prompt 上的 logits 一致性 |
| serving 栈 | 只在线上复现 | vLLM / TensorRT-LLM 对 LoRA 与上下文长度的支持是否与训练时一致（[[inference-serving-11]]） |

只有这张表全部排干净、固定 harness 下指标仍然下降，才把结论写成「遗忘」。

### 2. 优化视角：目标函数里只有客户任务

设旧能力损失 $L_{\text{old}}(\theta)$、客户任务损失 $L_{\text{new}}(\theta)$，微调只优化后者：

$$\theta_{t+1} = \theta_t - \eta \nabla_\theta L_{\text{new}}(\theta_t)$$

对旧能力做一阶展开：

$$\Delta L_{\text{old}} \approx -\eta \left\langle \nabla L_{\text{old}}, \nabla L_{\text{new}} \right\rangle$$

当两个梯度的内积为负（方向冲突）时 $\Delta L_{\text{old}} > 0$：只要参数容量被共享、任务梯度冲突，**优化客户任务的那一步更新必然抬高旧能力损失**。这是一个纯几何结论，与模型大小无关。遗忘速度由三件事共同决定：冲突程度（$\cos$ 角）、学习率 $\eta$ 与步数、以及旧能力对该参数的依赖度。

补救思路直接从这条式子读出来：把 $L_{\text{old}}$ 加回目标（回放）、压小 $\eta$ 与步数、按依赖度保护参数（正则、参数隔离）、或者让新旧任务共享的参数变少（PEFT）。四条路径分别对应下文四层缓解。

### 3. 表示视角：遗忘包含两层，不是一件事

参数是一份**共享表示**。微调会同时改变特征提取器与下游映射，即使旧任务的输出看起来还勉强对，中间表示也已经整体平移旋转——用旧表示训练好的线性探针去读新表示会失效。于是「遗忘」里混着两种东西：

- **能力真的被覆盖**：旧能力所在的子空间被新任务占掉，只能靠回放或重训补回。
- **能力还在但接口变了**：特征漂移导致旧的输出映射对不上，用几十到几百条校准数据在新表示上重新拟合映射（重对齐）就能修回大部分。

两层的工程含义完全不同：后一层当天就能救，前一层要走重训。「数值与代码验证」一节的实验量出了这个分解：端到端相对跌幅 48.02% 的那一档里，1000 条校准数据能补回 79.77% 的跌幅——**大部分跌幅落在「接口漂移」这一层**，这也解释了为什么「先校准再决定要不要重训」是最省钱的顺序。

### 4. 实证口径：1B–7B 持续指令微调（Luo 等）

论文在 5 个彼此不相似的指令任务上做持续指令微调（每任务 10 万条、3 个 epoch、lr 2e-5、最大长度 512），从领域知识（MMLU 5-shot）、推理（BoolQ / PIQA / Winogrande / Hellaswag / MathQA / Mutual，zero-shot）、阅读理解（RACE）三个维度测评，四条结论：

1. 1b–7b 区间**所有被测模型都出现灾难性遗忘**。
2. 该区间内**模型越大遗忘越严重**，作者归因于大模型初始性能更高、相对跌幅因此更显眼。
3. **通用指令微调能缓解后续微调中的遗忘**：LLAMA-7b 平均 FG 32.54%，ALPACA-7b 只有 12.00%（低 63.12%）；更直接的是混合训练实验——LLAMA-7b 的 MMLU-human 初始 34.72%，只训指令数据掉到 26.8%，混入 1 万条通用指令后回到 30%。
4. 按能力类型看**阅读理解跌得最狠**（BLOOMZ 四档终态口径 25.81%–35.02%），推理最轻（6.92%–16.75%）。

引用时必须带上三条限定：实验范围是 **1B–7B**，不能外推到 100B 级；「越大越忘」是相对跌幅口径下的区间结论，不是普适规律；「阅读理解跌最多」的排序会随模型与口径变化，不能当成普适排序。

混合训练的算术值得单独看一眼：混 1 万条通用指令只补回了 $3.2/7.92 = 40.40\%$ 的跌幅，**仍残留 59.60%**。回放是缓解，不是消除——这一点决定了它必须和参数层、目标层的手段叠加使用。

### 5. 度量口径：三个视角加一道门禁

| 视角 | 指标 | 口径 | 用途 |
| --- | --- | --- | --- |
| 端到端能力 | 通用回归集分数 | 固定 harness，报绝对跌幅与相对跌幅 $(R_o - R)/R_o$ | 决策主指标，写进 SOW 门禁 |
| 分布拟合 | 通用语料上的 NLL / perplexity | 同一分词器与同一模板，序列级平均 | 对小幅退化比准确率更敏感 |
| 表示 | 旧任务线性探针在新表示上的准确率 | 冻结底座、只重拟合线性头 | 区分「接口漂移」与「能力覆盖」 |
| 客户任务 | 目标指标 | 与回归集同一 harness | 与上面三条一起看，缺一不可 |

三条纪律：**训练 loss 不是证据**（客户数据窄，训练 loss 下降只说明拟合了窄分布）；**只报客户指标涨幅的评测无法决策**；**门禁要在 SOW 里写死**，例如「通用回归集相对跌幅 ≤5% 且客户任务指标达标」，基线 62.5 分对应的下限就是 59.38 分（相对 5% 等于绝对 3.12 分）。

### 6. 处置路径：按代价从低到高

| 档位 | 动作 | 代价 | 见效速度 |
| --- | --- | --- | --- |
| ① 回滚 | 切回基线 adapter 或基座，保留可回滚开关 | 接近零（前提是 adapter 与基座都版本化） | 分钟级 |
| ② 少训 + 校准 | 降低学习率（常见 1/10）、减少 epoch，用几十到几百条通用数据重对齐映射 | 一次推理级评测 + 一点训练 | 小时级 |
| ③ 重训四层 | 数据层混入 5%–10% 通用指令数据或接近预训练分布的语料；参数层改用 LoRA 冻结底座；目标层加 KL 到参考模型或 soft-target 蒸馏（带 $T^2$ 因子）；流程层把回归集写进门禁 | 算力 1.05×–1.11×，新任务上限略降 | 天级 |
| ④ 换路线 | 客户要的是新知识而不是新行为时，改走 RAG | 检索链路与运维成本 | 天级，但换来可引用与时效性 |

第 ③ 档的数据层动作有一个容易被忽略的性质：把通用数据混进垂直数据一起训，等于把「持续学习」问题**退化成多任务学习**——联合目标里同时有新旧任务的损失项，第 2 节那条几何关系里负内积的破坏性被直接约束住了。这是四层里性价比最高的一层。

### 7. 成本账：为什么「回放 + LoRA」是可行组合

回放配比 $\rho$ 定义为「每个 batch 里旧数据占比」，则旧数据每过 1 个 epoch 只被见到 $\rho/(1-\rho)$ 遍（$\rho=5\%$ 时 0.0526 遍），想让旧数据也过 1 遍需要新数据过约 $1/\rho$ 个 epoch（19 个）。算力上，要覆盖同样多的新数据必须多跑 $1/(1-\rho)$ 步：$\rho=5\%$ 是 1.053×，$\rho=10\%$ 是 1.111×（口语里按 1+ρ 估成 1.05×–1.10×，与精确值最多差约 1%）。

真正让这套方案付得起的是参数层。按混合精度 Adam 口径，每个**可训练**参数 16 字节（bf16 权重 2 + bf16 梯度 2 + fp32 master 4 + Adam $m,v$ 8），7B 全量微调是 $7\times10^9 \times 16\ \text{B} = 104.31$ GiB，其中优化器状态 78.23 GiB；LoRA $r=8$ 只适配 q、v 时，可训练参数 $32\times 2\times 2\times 8\times 4096 = 4,194,304$（占 7B 的 0.0599%），对应训练态约 0.0625 GiB，bf16 落盘只有 8 MiB，而底座 bf16 常驻约 13.04 GiB 是两种方案都要付的。

代价那一半也必须说清：低秩与回放都会压低新任务上限，KL 或蒸馏约束越强越稳、越快「学不动」。两者的量级不一样：本文玩具实验里 5%–10% 回放对客户指标的代价落在 1 点以内的噪声里，而「学习率降一个数量级 + 步数减到三分之一」的代价是 22.30 点。约束强度最终由**回归集分数与客户任务指标两条曲线**共同调出来，不是拍出来的（[[finetuning-07]]）。

### 8. Mistral 交付场景：动作落在 adapter 上

- **先确认加载链路**：chat template、特殊 token、adapter 的 target module 名、$\alpha$ 与 $r$ 的口径、serving 栈（vLLM / TensorRT-LLM）对 LoRA 与上下文长度的支持，逐项与训练配置对齐。合并回权重之前，先在回归集上验收。
- **把 adapter 当产物管理**：按客户/租户隔离 adapter、多 adapter 路由与版本化、每个适配器记录训练数据版本、超参与回归集分数；一个底座挂多个租户适配器时，回归集要覆盖所有租户共用的通用能力。
- **在 SOW 里定义门禁与开关**：通用回归集相对跌幅上限、客户任务指标下限、回滚路径与责任边界。客户排查问题时，先给「同权重、同 harness」的对照实验，再谈重训。
- **路线判据**：注入新知识（事实、时效、权限、需要引用）优先 RAG（[[finetuning-08]]）；固化新行为（格式、语气、术语、拒答边界）才微调。数据只有几百到几千条窄样本时，正确的动作通常是「更小的学习率 + 更少 epoch + 回放」，而不是「更多步」。

## 数值与代码验证

### 可运行实验：端到端跌幅里有多少是「接口漂移」

构造一个共享 trunk（Linear(32→16)+ReLU）加两个头：任务 A 是 8 类、类均值铺满 32 维的「通用能力」；任务 B 是 4 类、只落在 6 维子空间、方差更小的「窄客户任务」。只在 A 上训出基线，然后冻结 A 头、在 B 上全参微调。三个量分别是：A 的端到端分数（用微调前的 A 头直接读漂移后的表示）、A 的校准分数（冻结 trunk，用 $k$ 条 A 数据在新表示上闭式重拟合线性头）、B 的客户指标。

```python
import torch, torch.nn as nn

torch.manual_seed(0)
D, H, CA, CB, N = 32, 16, 8, 4, 4096   # A：8 类铺满 D 维；B：4 类只落在 6 维子空间

def make_means(c, scale, sub, g):
    m = torch.zeros(c, D)
    m[:, :sub] = torch.randn(c, sub, generator=g) * scale
    return m

def sample(m, n, noise, g):
    y = torch.randint(0, m.shape[0], (n,), generator=g)
    return m[y] + noise * torch.randn(n, D, generator=g), y

g = torch.Generator().manual_seed(1)
mA, mB = make_means(CA, 1.0, D, g), make_means(CB, 0.30, 6, g)
xA, yA = sample(mA, N, 0.9, g);   xAt, yAt = sample(mA, 2000, 0.9, g)
xB, yB = sample(mB, N, 0.40, g);  xBt, yBt = sample(mB, 2000, 0.40, g)

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.trunk = nn.Sequential(nn.Linear(D, H), nn.ReLU())
        self.headA, self.headB = nn.Linear(H, CA), nn.Linear(H, CB)

@torch.no_grad()
def acc(net, head, x, y):
    return (head(net.trunk(x)).argmax(1) == y).float().mean().item()

def train(net, head, x, y, steps, lr):
    opt = torch.optim.Adam(list(net.trunk.parameters()) + list(head.parameters()), lr=lr)
    lf = nn.CrossEntropyLoss()
    for _ in range(steps):
        opt.zero_grad(); lf(head(net.trunk(x)), y).backward(); opt.step()

def calibrate(net, k):   # 冻结 trunk，用 k 条通用数据在漂移后的表示上重拟合头
    with torch.no_grad(): F, T = net.trunk(xA[:k]), net.trunk(xAt)
    Y = torch.nn.functional.one_hot(yA[:k], CA).float()
    W = torch.linalg.solve(F.T @ F + 1e-2 * torch.eye(H), F.T @ Y)
    return ((T @ W).argmax(1) == yAt).float().mean().item()

base = Net(); train(base, base.headA, xA, yA, 600, 3e-3)
print("基线          A=%.4f  B=%.4f" % (acc(base, base.headA, xAt, yAt), acc(base, base.headB, xBt, yBt)))

def finetune(rho, lr=3e-3, steps=800):
    net = Net(); net.load_state_dict(base.state_dict())
    for p in net.headA.parameters(): p.requires_grad = False   # 旧头冻结，只当体检仪
    n = int(N * rho / (1 - rho))                               # 旧数据占每个 batch 的 rho
    idx = torch.randperm(N, generator=torch.Generator().manual_seed(7))[:n]
    lf = nn.CrossEntropyLoss()
    opt = torch.optim.Adam(list(net.trunk.parameters()) + list(net.headB.parameters()), lr=lr)
    for _ in range(steps):
        opt.zero_grad()
        loss = lf(net.headB(net.trunk(xB)), yB)
        if rho > 0: loss = loss + lf(net.headA(net.trunk(xA[idx])), yA[idx])
        loss.backward(); opt.step()
    return net

for rho, lr, steps in [(0.0, 3e-3, 800), (0.0, 3e-4, 267), (0.05, 3e-3, 800), (0.10, 3e-3, 800)]:
    net = finetune(rho, lr, steps)
    print("rho=%.2f lr=%.1e steps=%3d  A=%.4f  A(校准1000条)=%.4f  B=%.4f"
          % (rho, lr, steps, acc(net, net.headA, xAt, yAt), calibrate(net, 1000), acc(net, net.headB, xBt, yBt)))
```

```text
rho=0.00 lr=3.0e-04 steps=267  A=0.9945  A(校准1000条)=0.9980  B=0.5705
rho=0.05 lr=3.0e-03 steps=800  A=0.9760  A(校准1000条)=0.9845  B=0.8005
rho=0.10 lr=3.0e-03 steps=800  A=0.9725  A(校准1000条)=0.9880  B=0.7995
```

整理成表（$R_o = 0.9985$ 是 A 的基线；末行是同一设置的补充实验：把 A 数据加回，继续训 trunk + A 头 800 步）：

| 配置 | A 端到端 | A 相对跌幅 | A + 1000 条校准 | 客户任务 B |
| --- | --- | --- | --- | --- |
| 基线 | 0.9985 | — | — | 0.2005（4 类随机 ≈ 0.25） |
| 只训客户任务 | 0.5190 | 48.02% | 0.9015 | 0.7935 |
| 只训客户任务 + lr/10 + 267 步 | 0.9945 | 0.40% | 0.9980 | 0.5705 |
| 回放 $\rho=5\%$ | 0.9760 | 2.25% | 0.9845 | 0.8005 |
| 回放 $\rho=10\%$ | 0.9725 | 2.60% | 0.9880 | 0.7995 |
| 只训客户任务后用 A 数据回炉重训 | 0.9925 | 0.60% | — | — |

结论有四条：① 目标指标从 0.2005 升到 0.7935（+59.30 点）的同时，通用能力相对跌 48.02%，**两条曲线必须同时报**；② 校准把 A 从 0.5190 拉回 0.9015（1000 条）与 0.7980（100 条），分别补回 79.77% 与 58.19% 的跌幅，「能力还在、接口漂了」占大头；③ 回放 $\rho=5\%$–$10\%$ 把 A 拉回 0.97 以上，代价是 B 基本不动（0.7935 → 0.8005，在单种子噪声内）——在这个玩具里，塑性代价体现在下一行而不是回放本身；④ 真正把 B 打下来的是「降学习率 + 少步数」这一档：A 保住 0.9945，B 却掉到 0.5705，比只训客户任务低 22.30 点。**稳定与可塑的交换是实打实的，最便宜的那一档往往也是新任务损失最大的一档。**

这是 H=16 的刻意受限 trunk，只能说明方向与分解，不能把 48%、22.3 点这类幅度外推到真实模型；真实口径要看下表的论文数字。

### 论文数字的复算

| 量 | 原始数值 | 复算 |
| --- | --- | --- |
| LLAMA-7b / ALPACA-7b 平均 FG | 32.54% / 12.00% | ALPACA 比 LLAMA 低 $(1-12.00/32.54)=63.12\%$ |
| MMLU-human：只训指令数据 | 34.72% → 26.8% | 相对跌幅 $(34.72-26.8)/34.72 = 22.81\%$ |
| MMLU-human：混 1 万条通用指令 | 34.72% → 30% | 相对跌幅 13.59%，补回 $3.2/7.92 = 40.40\%$，仍残留 59.60% |
| BLOOMZ 阅读理解（终态口径） | 25.81%–35.02% | 跌幅最狠的能力项；同一口径下推理性 6.92%–16.75% |

FG 是论文对全部训练步取平均的相对跌幅，与「终态时刻相对跌幅」口径不同，两列数值不可混用。

### 复算：显存、回放与合并精度

| 量 | 计算 | 结果 |
| --- | --- | --- |
| 7B 全量微调训练态 | $7\times10^9 \times 16$ B | 104.31 GiB（优化器状态 78.23 GiB） |
| LoRA $r=8$、q/v（$d=4096$、$L=32$） | $32\times2\times2\times8\times4096$ | 4,194,304（7B 的 0.0599%），训练态 0.0625 GiB，bf16 落盘 8 MiB |
| LoRA $r=16$、q/k/v/o | 上式的 4 倍 | 16,777,216（0.2397%），训练态 0.25 GiB，落盘 32 MiB |
| 底座 bf16 常驻 | $7\times10^9 \times 2$ B | 13.04 GiB（全量与 PEFT 都要付） |
| 回放算力倍率 | $1/(1-\rho)$ | $\rho=5\%$：1.053×；$\rho=10\%$：1.111× |
| 旧数据每 epoch 实际遍历 | $\rho/(1-\rho)$ | $\rho=5\%$：0.0526 遍（旧数据过满 1 遍需新数据过 19 个 epoch） |

合并精度也顺手量了：取 $d=4096$、$r=8$、$\alpha=16$ 的随机权重，$\Delta W = \frac{\alpha}{r}BA$ 分别以 bf16 与 fp16 做合并再与 fp32 结果比，同一批输入的输出相对误差是 $2.35\times10^{-3}$（bf16）与 $2.94\times10^{-4}$（fp16）。结论：合并的舍入误差在千分之一量级，**比真实能力回归（几十个百分点）小两个数量级**——所以线上「前后不一致」几乎不会是精度问题，而是配置或口径问题（target module 名不匹配被静默跳过、$\alpha$ 或 $r$ 写错、adapter 根本没挂上），这些必须单独查。

## 常见追问

- **追问**：客户说「模型变笨了」，你怎么在半小时内给出判断？
  - 要点：先跑对照实验，不动权重：同一批 prompt、同一 harness、同一批解码参数，分别在基座和微调后权重上跑；再换一个推理精度（bf16 vs 4-bit）跑一遍；再检查 chat template 与 adapter 是否真的加载。三类都排除后才承认是权重变化，然后按相对跌幅给出严重程度。
- **追问**：校准数据要多少条、从哪来？
  - 要点：量级是几十到几百条，来自通用语料或客户业务里**不相关**的旁路数据，用途是在新表示上重拟合输出映射，不是重新训练。上面实验里 1000 条补回 79.77% 的跌幅，这是「接口漂移」比例的下界（校准冻结了 trunk，只重拟合输出映射，能补回的部分必然属于接口层，被覆盖的能力它补不回来）；100 条量级通常也能补回一半左右。校准只能在接口层生效，覆盖类遗忘它救不了。
- **追问**：回放的通用数据从哪来、配比怎么定？
  - 要点：来源优先级是「与预训练分布接近的通用指令数据 > 客户业务里的无关旁路数据 > 客户任务数据本身」。配比从 5% 起，同时看两条曲线：回归分数掉超阈值就加配比或降学习率，客户指标涨不动就减配比。注意旧数据每个 epoch 只被过 $\rho/(1-\rho)$ 遍，5% 配比靠的是**每步都有一个保旧能力的梯度约束**，不是把旧数据重新学透。
- **追问**：为什么不能靠「多训几个 epoch」把两边都训好？
  - 要点：客户数据窄而少，继续训只会把参数推向窄分布的最优点，旧能力被覆盖得更彻底；第 2 节的式子已经给出方向——内积为负时 $\Delta L_{\text{old}}$ 必然为正，要让旧损失转跌就得把 $L_{\text{old}}$ 加回目标函数（回放、正则），继续加 epoch 只是在放大冲突。
- **追问**：LoRA 就一定安全吗？
  - 要点：不一定。adapter 仍会改变前向行为，低秩容量写满时同样回退；$\alpha/r$ 缩放口径与 target modules 的选择决定它影响多少层。PEFT 的价值是把可训练参数量从 104.31 GiB 的训练态压到 0.0625 GiB 量级，让「回放 + 多轮试」付得起，同时天然削弱遗忘，但它不是免疫。
- **追问**：什么时候应该直接放弃微调、改走 RAG？
  - 要点：客户要的是**新知识**（事实、时效、权限、可引用、频繁更新）时走 RAG，微调注入知识既贵又不可回指；客户要的是**新行为**（固定 schema、术语、语气、拒答边界）才微调。判据是「把材料放进 prompt 模型能不能答对」（[[finetuning-08]]）。
