# 智谱面试题库

这一家的题有一条清晰的主线：**从"一个统一的理解与生成目标"出发，一路走到"能替你操作手机的 agent"。**
所以**它同时考架构（MoE、MTP）、后训练（专家、蒸馏、RL）与系统（GUI agent、云服务）**，
而**每一层都有一个可以用算术讲清的取舍。**

**第一件事是"稀疏比解耦了算力与显存"。**
**355B 总参数、32B 激活意味着每 token 算力等于稠密 32B、而显存要装 355B**——
**买算力、付显存与网络**。
**而真正的代价是两点：低 batch 时算术强度只有 0.5（脊点 295），
以及 all-to-all 在 batch 256 时吃掉单卡 IB 的三分之一。**

**第二件事是"长任务的误差是指数复利"。**
**单步 0.99 时 50 步只有 60.5%**——**所以 agent 的可靠性不能靠模型单步准确率**，
**而要靠技能库（把 50 步压到 6 步 → 94.1%）与验证恢复（→ 98.3%）。**

**第三件事是"评测本身会骗人"。**
**数据污染能让 35 分的真实能力显示成 53 分**，
**脚手架能让同一个模型从 0.12 到 0.58**，
**而要检出 3 分的差异需要每臂约 14 次独立运行**——
**所以排行榜上的单点比较没有意义。**

准备这一家时，建议把**"算力看激活、显存看总量"**、**"误差复利"**、**"污染虚高 18 分"**这三条练熟。
它们分别解释了"MoE 该怎么部署"、"agent 该怎么设计"、"评测该怎么读"。

## 题解清单

### LLM 内部原理与架构（01–05）

| # | 题目 | 一句话看点 |
| --- | --- | --- |
| 01 | [GLM 的空白填充目标](01-GLM-的空白填充目标.md) | **关键不是"双向+能生成"而是"段内自回归"**（**BERT 的掩码位置被假设独立、所以算不出联合概率**）；**统一 = 靠空白位置切换任务**；**但 GLM-4.x 已是标准 AR 模型** |
| 02 | [GLM-4.5 的 MoE 经济账](02-GLM-45-的-MoE-经济账.md) | **算力看激活（32B）、显存看总量（355B）**；**低 batch 算术强度只有 0.5（脊点 295）**；**all-to-all 在 batch 256 时吃掉 IB 的三分之一**；**不均衡 1.5× = 33% 算力浪费** |
| 03 | [top-k MoE 路由实现](03-top-k-MoE-路由实现.md) | **难点在变长分组**；**两种均衡方案的根本区别是"是否加梯度"**；**受控实验必须先造出偏斜（随机 gate 本来就均匀）**；**loss-free 400 步把 1.94× 压到 1.45×** |
| 04 | [Multi-Token Prediction](04-Multi-Token-Prediction.md) | **推理时的价值是"免费的投机解码"**（**复用 KV、额外显存只 +2%**）；**接受率是命门**（**0.8 时 k=5 得 2.64×、0.6 时只有 1.70×**）；**最优 k 由搜索确定** |
| 05 | [中英双语模型的取舍](05-中英双语模型的取舍.md) | **生育率就是算力成本**（**中文退到字级是 1.9 倍**）；**词表预算是零和的**；**双语付 22% 容量稀释**；**而干扰不是必然的（两边都加可帕累托改进）** |

## 准备建议

1. **先建立"算力看激活、显存看总量"的直觉**（02）。**这一条决定了 MoE 的部署形态**，也解释了为什么它适合大 batch 服务而不适合端侧。
2. **02 与 03 是"为什么"与"怎么做"**：**02 讲负载不均浪费 33% 算力、03 讲怎么把它压下去**。**负载均衡的收益可以直接换算成 GPU 成本。**
3. **04 与 02 在推理侧互补**：**MoE 优化吞吐、投机解码优化延迟**。**两者解决不同的问题，不能互相替代。**
4. **07 与 09 共享一套方法论**：**"模式"本质上是一种特殊的"领域"**，所以混合推理与专家蒸馏可以用同一套"先分开、再统一"的思路。
5. **06 与 10 是"内核与外壳"**：**06 讲 agent 的感知/动作/恢复、10 讲把它做成云服务**。**失效模式在两层都要考虑，而"不可逆动作"是唯一极高严重度。**
6. **08 的"版本窗口"是一个可迁移的概念**：**任何异步训练都要在"利用率"与"on-policy 程度"之间取舍**，而窗口 2–3 是一个实用值。
7. **11 的"运行间方差"最容易被忽略**：**方差来自运行而不是实例**，所以"多跑几个实例"解决不了它。**这是读排行榜时的第一道防线。**
8. **01 的历史定位值得单独记**：**GLM-4.x 已经是标准 AR 模型**，所以空白填充主要是历史意义。**诚实地说出这一点，比背诵论文更能显示判断力。**
