# Amazon 面试题库

这一家是题库里题量最大的一家，也是**结构最完整的一家**：
**从编程题一路走到行为题**，而**每一层都有一个可以用算术讲清的取舍**。

**第一件事是"成本要按钱分配、不能按 token 量分配"。**
**输出 token 的单价是输入的 5 倍**——
**所以在一个 2,500 输入 / 350 输出的工作负载上，
输出只占 token 量的 12%、却占了成本的 41.2%。**
**而先做成本归因更重要：5% 的请求占了 38% 的成本。**

**第二件事是"长任务的误差是指数复利，所以减步数比提单步更有效"。**
**单步 0.99 时 40 步只有 66.9%**，
**而把步数从 40 压到 6（技能回放）能到 98.8%、压到 1（结构化接口）能到 99.9%。**

**第三件事是"不确定性下的成本不对称"这个结构会反复出现。**
**报童模型的临界分位数 $c_u/(c_u+c_o)$ 决定订货量**，
**而精确率与召回率的取舍、库存的缺货与积压、推荐系统的推错与漏推，都是同一个结构。**

**第四件事是"先定位瓶颈再优化"。**
**8K 上下文下算术强度的上限只有约 52、远低于脊点 295**——
**所以即使 batch 1024 也仍是带宽受限，提高 batch 无法脱离这个区域。**
**不知道自己是带宽受限还是算力受限，就不知道该优化什么。**

准备这一家时，建议把**"输出贵 5 倍"**、**"误差复利"**、**"临界分位数"**、**"带宽受限"**这四条练熟。
它们分别解释了"成本怎么降"、"agent 怎么可靠"、"库存怎么订"、"推理怎么优化"。

## 准备建议

1. **先建立"成本要按钱分配"的直觉**（16）。**输出贵 5 倍、只占 12% 的 token 却占 41.2% 的成本**——这一条决定了所有成本优化的优先级。
2. **16 与 15 是"手段与物理上限"的关系**：**15 给出 8K 下算术强度上限约 52、所以全程带宽受限**，**16 的手段（提示缓存、批处理）本质上都在提高有效 batch**。**先知道上限再谈优化。**
3. **17 与 19 共享"误差复利"**：**agent 的步数、推荐漏斗的段数，都是相乘的结构**。**所以"补最弱的一环"与"减步数"是同一个方法论。**
4. **11、12、19 共享"成本不对称"**：**精确率/召回率、缺货/积压、推错/漏推是同一个数学结构**。**能把三题串起来说明理解到位了。**
5. **03、04、05、14 是一条线**：**闭式解的数值问题 → 正则化的几何 → 凸性证明 → 正则化的概率解释**。**四题分别从数值、几何、优化、概率四个视角看同一件事。**
6. **07、08、09 是"集成与序列模型"的基础**：**08 的偏差-方差分解直接解释了 07 里 RF 与 GBDT 的行为差异**，而**09 的结论（不可并行）解释了 15 的取代。**
7. **13 与 20 是"统计判据与工程判据"**：**13 讲怎么判断一个实验有效，20 讲怎么判断一个系统可以上线**。**两者都强调"先定判据再做事"。**
8. **三道行为题（21–23）不能用同一个故事**：**21 考分歧与投入、22 考认领与改变、23 考识别与说服**。**共同要求是"可验证的证据"，但指向不同。**
