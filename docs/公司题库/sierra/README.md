# Sierra 面试题库

这一家的题有一个统一的前提：**agent 会真的动客户的账户。**
所以"答错"不是"体验差"，而是"一笔错误的退款"。

**第一件事是"不可协商的东西不能靠概率"。**
一个 99% 守住的门槛，在 1,000 次请求里仍有 2 次超额退款（年损 1.2 万美元）；
而**攻击者会迭代**——单次拒绝率 99% 时，100 次尝试的成功概率是 **63.4%**。
所以这一家反复问同一个问题：**"这条规则在 prompt 里还是在代码里？"**
答案是：**约束（金额门槛/权限/幂等/PII/限流/日志）在代码里，语言（措辞/澄清/解释/选工具）才在 prompt 里。**

**第二件事是"聚合数字会骗人"。**
**92% 的通过率下藏着 40% 的层**，而最危险的层恰好分数最低；
按生产频率加权后是 97.1%，按严重度加权后是 90.8%；
而 **Simpson 悖论**能让"总体 +26 点、而每一层都降"。
所以这一家的评估题都在问：**"这个数字是怎么算出来的，它会掩盖什么？"**

**第三件事是"先止血、再归因"。**
模型升级后转人工率翻倍 = **每月多 15,000 次人工 = 12 万美元**，
而回滚只要一次部署——**所以"先回滚"是唯一合理的选择**。
而归因要用 **2×2**（模型 +14 点、提示词 +2 点），
并警惕最危险的混淆：**转人工检测器本身也被换掉了，"仪器"变了就无法归因。**

准备这一家时，建议把**"确定性 vs 概率性"**和**"这个数字掩盖了什么"**这两个问句练熟。
前者决定架构，后者决定你能不能相信自己的评测。

## 准备建议

1. **先记住一句话**：**"约束进代码、语言留 prompt。"** 03、04、09 都是它的实例，而 01 是它的"事后版本"（确认必须来自代码）。
2. **04 与 09 是一对**：**04 讲"业务约束"、09 讲"安全边界"**。两者的论证结构相同：**概率性防御会被迭代击穿**（04 用"守住率 99% 仍年损 1.2 万"、09 用"100 次尝试 63.4%"）。
3. **07 与 08 是"数字的两面"**：**07 讲"怎么读一个静态数字"、08 讲"怎么应对一个动态变化"**。两者共享"分层 + 2×2 + 加权"的方法。
4. **06 与 07 要一起准备**：**06 讲"怎么设计评测集"、07 讲"怎么解读评测结果"**。**没有 07 的 06 会给出误导的数字。**
5. **02 与 05 是一对**：**02 讲"什么时候弃答"、05 讲"弃答之后怎么转"**。两者的成本结构相同：**答错/漏升级的代价远高于转人工**。
6. **01 是这一家的"方法论题"**：**"先看轨迹、再读代码"**——它体现的是"定位优先于修改"。而它的四个信号值得背下来。
7. **10 是唯一一道"渠道"题**，但它考的是"意识到约束变了"：**延迟、朗读、读回、升级率**四个约束全变。
8. **11 与 12 是行为题**，但它们都有可量化的结构（时间分配、评分权重）。**准备时不要只讲"故事"，要讲"结构"。**
