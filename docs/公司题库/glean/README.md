# Glean 面试题库

这一家的题有一个统一的前提：**每一条结果都必须按用户权限过滤，而且这件事不能交给模型。**
所以**"权限"在这里不是一个功能，而是贯穿索引、检索、agent 与评估的一条主线。**

**第一件事是"权限与内容是两条通道"。**
**权限变更与内容变更完全无关**（**人进人出不影响文档**）——
**所以五类权限变更里有三类内容爬虫发现不了，而漏掉的正是撤权**。
**撤权延迟从 60 分钟降到 60 秒，靠的是独立 ACL 路径，而不是 SaaS 的配合。**
**同理，"用用户 token 而不是服务账号"是 agent 权限的支点**：
**混淆代理的本质是能力放大**（**3 → 50 个动作**）。

**第二件事是"图补的是另一类信号，而不是更好的语义匹配"。**
**最能说明问题的是权威版本**：**同样文本的两份文档，图权威分是 0.92 vs 0.08**，
**而 embedding 会给它们完全相同的分数**。
**所以图与嵌入是互补的，不是替代关系**——**它补的是结构、权威、时效、个性化、社交这五类。**

**第三件事是"冷启动不等于零信号"。**
**用户自己的近期活动第一天就有，单独值 +18 个点**——
**而"可迁移特征 + 该租户结构"能到 0.72，直接搬别人的模型只有 0.61**（**因为人员信号错位**）。
**所以"第一天就全量埋点"是最重要的一步**：**数据不能追溯补。**

准备这一家时，建议把**"权限是独立通道"**、**"权威版本 0.92 vs 0.08"**、**"能力放大 3 → 50"**这三条练熟。
它们分别解释了"索引该怎么建"、"图为什么值得建"、"agent 该用谁的身份"。

## 准备建议

1. **先建立"权限是独立通道"的直觉**（07）。**这一条决定了索引架构、检索实现与 agent 设计**，也是这一家最独特的地方。
2. **01 与 07 是"权限的消费侧与生产侧"**：**01 讲查询时怎么过滤、07 讲权限数据从哪来**。**写入侧的架构决定读取侧的能力。**
3. **05 与 06 是"身份与强制点"**：**05 讲用谁的身份、06 讲在哪强制**。**两者共同构成 agent 的权限架构，缺一不可。**
4. **04 与 10 是"数据边界的两面"**：**04 讲为什么不能在全量数据上微调、10 讲在看不到数据时怎么评估**。**合起来看才知道"数据边界"如何塑造整个产品。**
5. **08 与 09 是"信号与冷启动"**：**08 讲图能提供哪些信号、09 讲新租户怎么用它们**。**图权威是冷启动里唯一不依赖交互的结构信号。**
6. **03 的"PDF 占 9% 文档数但 45% 块数"值得单独记**：**成本结构的结论往往与直觉相反**。
7. **02 的"主导项取决于产品形态"是通用方法论**：**同一套系统在不同形态下优化方向相反**，所以"哪里最慢"必须先问形态。
8. **10 的"迁移比"概念可以迁移到任何合成评测**：**机制类 1.0、调权重 0.3**——**所以合成集适合做门禁、不适合做调优。**
