# Groq 面试题库

这一家的题有一个共同的前提：**编译器负责时序，而机器只有片上 SRAM**。
这两个前提推出了一整套与 GPU 完全不同的算术：

**"容量"变成了最紧的约束**——70B 的 INT8 权重 70 GB 需要 **304 颗芯片**，
而 **8 序列 × 100K 上下文的 KV 要 1,140 颗**（是权重的 3.7 倍）。
**在 GPU 上 KV 只是一个零头，在这里它比模型还贵。**

**"确定性"是产品定位而不是优化**——它消除的是"调度相关"的抖动（批组成、缓存、争抢），
保留的是"数据相关"的变异（输入长度）。所以诚实的说法是 **"固定输入下 p99 = p50"**。
而它对 agentic 负载的价值可以量化：**每步 1% 的尾部在 100 步时是 63.4% 的超时概率**，
确定性把它降到 9.5%。

**"batching 的账要重算"**——GPU 上 batching 摊薄的是"每 token 的权重读取"（1/B 线性），
而**权重分布式常驻时"每 token 的权重流量是 0"**，所以收益变成"阶梯式"的（摊薄固定开销 + 填满流水线）。
**这直接改变了定价方式**：从"按 token"转向"按容量"。

准备这一家时，建议把**"权重字节 ÷ SRAM"**和**"抖动 × 速率"**这两个除法练熟。
前者给出芯片数（304 颗），后者给出缓冲深度（**50 µs × 10 TB/s = 500 MB，超过 230 MB 的 SRAM**）。

### 编程与数据结构（01–04）

| # | 题目 | 一句话看点 |
| --- | --- | --- |
| 01 | [静态调度需要知道什么](01-静态调度需要知道什么.md) | **额外要知道的是"时间"**（延迟/到达/占用/全局时序）；**保守 10% 在 10 层依赖链上是 2.59 倍**；**"少插周期"是静默错误**（读到旧值但值合法） |
| 02 | [IR 与 residency 决策层](02-IR-与-residency-决策层.md) | **residency 必须与 tiling 合并成一级 pass**（高层空洞、指令层太晚）；**70 GB / 230 MB = 304× 的额外流量**；IR 必须暴露 bank 级容量与冲突模型 |
| 03 | [host 侧 runtime 的难点](03-host-侧-runtime-的难点.md) | **难点是时序不是带宽**：**50 µs 抖动 × 10 TB/s = 500 MB 在途**（**超过 230 MB 的 SRAM**）；**重试破坏确定性**，可靠性靠冗余 |
| 04 | [单芯片对但整机架错](04-单芯片对但整机架错.md) | **先二分芯片数**（1→4→2→3 四次定位）；**逐芯片 dump 640 次 → 二分层数后 56 次**；**确定性让"1 次"替代"约 300 次"** |

## 准备建议

1. **先把两个除法练熟**：**权重字节 ÷ SRAM**（→ 304 颗芯片）与 **抖动 × 速率**（→ 500 MB 在途）。05、06 与 03 分别是它们的直接应用。
2. **01、02、03、04 是一条链**：**01 讲"编译期要知道时间"、02 讲"IR 怎么组织这些信息"、03 讲"运行期怎么保证时间"、04 讲"没保证住怎么查"**。四道连起来看就是完整的"确定性系统"。
3. **05 与 06 是一对**：**05 算"带宽与容量的边界"、06 算"这要花多少颗芯片与多少钱"**。而 05 里最重要的结论是"**长上下文在 SRAM 机器上极其昂贵**"。
4. **07 与 08 是"商业"两面**：**07 讲"成本结构决定定价"、08 讲"可预测性降低风险"**。而两者的共同基础是"确定性"。
5. **09 是这一家最难的一道**：**它把"数据依赖"引入到了"结构"里**。注意区分"算空"（全算但每个专家都有活）与"算闲"（负载不均）——**后者才是真正的浪费**。
6. **10 与 11 是"客户现场"两面**：**10 讲"混合架构怎么设计"、11 讲"什么情况下不该卖"**。11 的六个问题值得背下来。
7. **12 不要留到最后**：它考的是**测量严谨性**，而"不超过理论下界"这一条能在 30 秒内证伪任何声称。
