## 一句话答案

> 「自主适应」不是一个能力，而是**四种适应**，工程上必须分开设计：
> ① **任务适应**——没见过的新任务类型：靠自然语言规格 + 少量示例 + 检索相似历史轨迹来泛化；
> ② **工具适应**——没见过的新 API/库：读文档 → 试探性调用 → 从错误信息修正（这要求工具返回可行动的错误）；
> ③ **环境适应**——陌生的代码库/系统：先探索建图（结构、入口、约定），把结论**写进记忆**而不是每轮重新发现；
> ④ **反馈适应**——从成功与失败中沉淀：成功轨迹变技能/示例，失败轨迹变「不要这样做」的约束与检查器。
> 系统真正的骨架是**记忆 + 自我验证 + 课程式飞轮**：没有记忆就没有适应（每轮从零开始），没有验证就没有自主（胡改无人纠），没有课程就没有效率（总做已会的任务不会进步）。
> 一句话纪律：**自主性的边界由验证能力决定**——你能验证多少，就能自主多少（串 [[agents-11]]）。

## 面试官在考什么

- **能否把「适应」分层**：只会说「用更强的模型/更多数据」是初级答案；高分答案会区分任务/工具/环境/反馈四个层次，并给出各自的机制（提示、记忆、探索、蒸馏）。
- **记忆体系的设计**：工作记忆（当前上下文）、**情景记忆**（历史轨迹：任务 → 动作 → 结果）、**语义记忆**（提炼出的规则与知识）。能否说出检索式复用（相似任务找历史轨迹）与写入门槛（什么值得记、如何防污染）。
- **自我验证是前提**：能不能给出验证信号的来源层级——强判据（测试、编译器、类型检查、schema 校验）> 弱判据（自一致性、交叉模型验证、规则检查）> 无判据（必须人类在环）。可引用的任务设计来自 τ-bench：在真实域名里让 agent 与模拟用户多轮交互、**以数据库最终状态判定任务是否完成**，并报告 pass^k——这正是「用可判定状态做判据」的范式。
- **课程与飞轮**：是否知道**最有学习价值的任务成功率在 20%–80% 之间**（全对无信息、全错无梯度），以及成功轨迹蒸馏、失败轨迹反思、技能库积累这三条沉淀路径。
- **安全与治理**：自主系统必须被约束——权限最小化、动作可逆、预算上限、危险操作审批；并且**适应不能改变自己的权限边界**。
- **评测**：能否设计「适应曲线」（第 1 次 vs 第 k 次尝试的成功率）、迁移距离（同域/跨域）与适应成本（token/时间），而不是只报一个成功率。

**常见错误答案**

- 「给 agent 一个 memory 数据库就行」——不说写什么、何时读、如何防污染，等于没设计。
- 「让它自己反思」——没有判据的反思容易变成自信的胡编（把错误结论写进记忆，反而更糟）。
- 「用 RL 端到端训练自主性」——忽略样本效率与安全；多数场景应先做提示/记忆/工具层面的适应。
- 「自主就是不要人」——自主的合法范围由验证能力与可逆性决定，越过边界就要人审。

## 原理与推导

### 1. 适应的形式化与三条路径

设任务分布 $P(T)$，agent 在任务 $t$ 上最多 $B$ 次尝试，目标是最大化期望成功率 $\mathbb{E}_{t\sim P}[\text{success}(t)]$。三条适应路径的成本与见效速度差异极大：

| 路径 | 机制 | 见效速度 | 成本 | 风险 |
| --- | --- | --- | --- | --- |
| 上下文适应 | 提示、示例、检索记忆 | 立刻 | 低（token） | 上下文有限、易受噪声干扰 |
| 参数适应 | 微调/蒸馏（成功轨迹做 SFT） | 天级 | 中高（算力 + 数据） | 灾难性遗忘、过拟合旧任务 |
| 结构适应 | 新增工具/技能/子 agent/检查器 | 小时到天 | 中（工程） | 复杂度膨胀、权限扩散 |

**工程顺序**：先把上下文适应与结构适应做到位（可解释、可回滚），再考虑参数适应。可引用的工程取向来自 *Building Effective Agents*：优先用简单可组合的模式，只在确实需要时增加复杂度。

### 2. 记忆体系：三种记忆与写入门槛

| 记忆 | 内容 | 读写时机 | 写入门槛 |
| --- | --- | --- | --- |
| 工作记忆 | 当前任务上下文、计划、已改内容 | 每轮读写 | 无需门槛（短生命周期） |
| 情景记忆 | 历史轨迹（任务 → 动作序列 → 结果 → 判据） | 任务开始时检索相似轨迹 | **必须有可判定的结果**（成功/失败明确） |
| 语义记忆 | 提炼的规则、约定、坑（「这个仓库用 pnpm」「这个 API 需要分页」） | 检索后注入提示 | 需**多次验证**或人工确认 |

**防污染是记忆系统的核心难点**：错误的经验一旦写进语义记忆就会被反复复用。三条防线：① 只从**有判据**的轨迹中提炼；② 语义记忆条目带**证据计数**（出现 N 次才升级为规则）；③ 支持失效与撤销（发现规则导致失败就降权并回溯影响）。

### 3. 自我验证：自主性的边界

验证信号按强度排序，agent 的自主权限应与验证强度匹配：

1. **强判据**：单元测试、编译器/类型检查、schema 校验、数据库最终状态、可执行断言。→ 可以全自动循环（跑 → 失败 → 修 → 再跑）。
2. **弱判据**：自一致性（多个采样投票）、交叉模型评审、规则/正则检查、检索到的引用核验。→ 可以自动迭代，但结果需标注置信度。
3. **无判据**：开放式写作、设计决策、涉及外部副作用的操作。→ 必须人类在环或限制为「建议 + 可逆应用」。

**关键推论**：一个 agent 的「自主程度」应当是按任务类型分档的，而不是全局开关——同一系统在「跑测试修 bug」上可以全自动，在「改生产配置」上必须审批。

### 4. 课程式飞轮：让系统越用越强

1. **难度选择**：用实时成功率筛任务，把训练/练习集中在**成功率 20%–80%** 的区间（$p$ 太高的任务没有信息量，太低的任务只有失败信号）。这一条与 RLVR 里的「无效组」问题同源（串 [[agents-12]]）。
2. **成功轨迹沉淀**：把完整轨迹（含失败的中间步骤）做成示例库；高质量轨迹可直接用于蒸馏微调。
3. **失败轨迹沉淀**：抽取「错误模式 → 检查器」，例如「改了这个文件必须同时改 X」。检查器比提示更可靠，因为它可执行。
4. **技能库**：把重复出现的多步操作固化为高层技能（skill/工具），减少后续任务的步数与不确定性——这是「结构适应」的主要产出。
5. **回归防护**：新技能与记忆上线也要过门禁（在历史任务集上不回退），否则系统会「学会新任务、忘掉旧任务」。

### 5. 安全与治理的硬边界

- **权限最小化**：默认只读 + 沙箱写入；权限提升需显式授权（串 [[cursor-08]] 的四道闸）。
- **可逆性**：所有副作用可撤销（草稿分支、检查点、软删除）。
- **预算**：步数/时长/费用上限，超限上报而非静默失败。
- **不可自授权**：适应机制不得修改自己的权限、审计或门禁配置（这是「自主」的绝对边界）。
- **审计**：轨迹可回放（谁在何时做了什么、依据什么记忆与规则）。

### 可运行代码

```python
# 1) 记忆复用：相似任务检索带来的适应速度提升（合成模拟）
import random, math
random.seed(101)

def simulate(episodes=400, memory=False, rule_bonus=0.0, skill_bonus=0.0, sim_threshold=0.6):
    """任务有隐藏类型；有记忆时相似历史轨迹可复用其解法"""
    base = 0.45
    learned = {}                      # 任务类型 -> 成功次数
    hist = []
    succ = []
    for ep in range(episodes):
        ttype = random.randrange(5)
        p = base
        if memory:
            sims = [h for h in hist if h[0] == ttype]
            if sims:
                # 相似轨迹越多，复用的初始成功率越高（上限 0.9）
                p = min(0.9, base + 0.12 * math.log1p(len(sims)))
        p = min(0.95, p + rule_bonus + skill_bonus)
        ok = random.random() < p
        hist.append((ttype, ok))
        succ.append(ok)
    def rate(a, b): 
        seg = succ[a:b]
        return sum(seg)/len(seg) if seg else 0.0
    return rate(0, 40), rate(200, 400)

print(f"{'策略':<28} {'前 40 次':>9} {'后 200 次':>10}")
for name, kw in [("无记忆", dict(memory=False)),
                 ("+ 情景记忆", dict(memory=True)),
                 ("+ 情景记忆 + 语义规则", dict(memory=True, rule_bonus=0.06)),
                 ("+ 情景 + 语义 + 技能库", dict(memory=True, rule_bonus=0.06, skill_bonus=0.05))]:
    a, b = simulate(**kw)
    print(f"{name:<28} {a:>9.3f} {b:>10.3f}")
print("记忆的价值体现在「后 200 次」：任务类型重复出现时，复用直接把起点抬高")

# 2) 课程学习：为什么成功率 20%-80% 的任务最有学习价值
def learning_value(p, k=8):
    """组内奖励方差的期望（越大信息量越高），0/1 奖励下 Var = p(1-p)"""
    return p * (1 - p)
print(f"\n{'任务成功率 p':>12} {'单次信息量 p(1-p)':>18} {'8 次尝试全同概率':>18}")
for p in (0.02, 0.2, 0.5, 0.8, 0.98):
    all_same = p**8 + (1-p)**8
    print(f"{p:>12.2f} {learning_value(p):>18.4f} {all_same:>18.3f}")
print("p 接近 0 或 1 时信息量趋零、全同概率趋高 —— 课程应把练习集中在 0.2–0.8")

# 3) 自一致性投票：弱判据下的收益与局限
from itertools import product
def majority_acc(p_single, k=5, correct_first=True):
    """k 次独立采样多数投票（k 为奇数）"""
    from math import comb
    acc = 0.0
    for i in range(k//2 + 1, k+1):
        acc += comb(k, i) * p_single**i * (1-p_single)**(k-i)
    return acc
print(f"\n{'单次准确率':>10} {'k=1':>8} {'k=3':>8} {'k=5':>8} {'k=9':>8}")
for p in (0.4, 0.5, 0.6, 0.7, 0.85):
    print(f"{p:>10.2f} " + " ".join(f"{majority_acc(p, k):>8.3f}" for k in (1, 3, 5, 9)))
print("注意 p=0.5 时投票毫无增益；且多数投票会把「一致的错误」放大 —— 弱判据需要交叉验证而非同一模型的重复采样")
```

预期输出要点：记忆策略的收益集中在「后 200 次」（相似任务出现后成功率从 0.45 抬到 0.7 以上）；课程表量化了为什么成功率 0.02 或 0.98 的任务没有学习价值（信息量 $p(1-p)$ 趋零、8 次全同概率高）；自一致性投票在 $p>0.5$ 时有效、$p=0.5$ 时无效，且**同一模型的重复采样会放大一致的错误**——这就是弱判据必须配交叉验证的原因。

## 常见追问

- **追问**：怎么防止记忆污染？
  - 要点：只从有判据的轨迹提炼；语义记忆带证据计数（N 次才升级）；支持失效与降权；把记忆条目与来源轨迹绑定以便回溯（并定期审计）。
- **追问**：没有明确判据的任务（写作、设计）怎么自主迭代？
  - 要点：构造代理判据（检查清单、约束校验、引用核验）、用交叉模型评审、把结果限制在「可逆应用 + 人类确认」；并明确标注置信度而不是假装确定。
- **追问**：怎么区分「适应」与「记住」？
  - 要点：用**留出任务类型**评测：训练/记忆过的任务上表现好不算适应；要测同域新任务（迁移）与跨域新任务（泛化），并报告尝试次数曲线。
- **追问**：多 agent 分工能提升适应能力吗？
  - 要点：能，但主要是通过**分工降低单 agent 的上下文负担**（探索者、实现者、验证者），而不是「更多 agent 更聪明」；必须防止互相覆盖（工作树与变更集隔离，串 [[cursor-08]]）。
- **追问**：什么时候该上微调而不是记忆？
  - 要点：当同一类失败**反复出现且无法靠提示/规则修**、且有足够高质量轨迹时才值得微调；微调前先用记忆与检查器（便宜、可回滚、可解释）。
- **追问**：自主系统上线后怎么发现它「学坏了」？
  - 要点：回归任务集门禁 + 记忆/技能变更审计 + 线上成功率与破坏率的持续监控；把记忆与技能当作模型一样的发布物管理（版本、门禁、回滚）。
