# Cursor（Anysphere）面试题库

这是公司题库里**唯一以「编辑器」为主语**的一家：所有题目最后都落回三个约束——**延迟、正确性、不打扰用户**。
十七道题可以看成一条链：**数据结构（01–05）→ 成本与上下文（06–07）→ agent 与并发（08–09、12–14）→ 交互延迟与索引（10–11）→ 评估与文化（15–17）**。
读的时候建议带着一个问题：「这个设计在用户正在打字的那一刻会怎样？」

## 这家公司在考什么

四条主线，且彼此咬合：

1. **数据结构的直觉**（01–05）：哈希树/Merkle、BFS 列号、三级哈希漏斗、文本缓冲区——考的是「你能不能为一个具体约束选出结构，并说清代价」。
2. **成本的算术**（06、07、11、14）：这家公司所有系统设计题都要求**把成本写成公式再优化**；答不出量级就很难过关。
3. **并发与不打扰**（08、09、12、13、14）：用户正在打字这件事贯穿始终——正确性靠「操作 + 快照 + 事务」，而不是靠快。
4. **把主观感受变成指标**（10、15、17）：接受率、存活率、回本周期、回本点——同一套量化思维在评估、行为题里反复出现。

与跨公司专题的重叠：[编程与数据结构](../../编程与数据结构/README.md)（01–05）、[推理、服务与 GPU 性能](../../推理、服务与%20GPU%20性能/README.md)（06、10）、
[RAG 与检索](../../RAG%20与检索/README.md)（07、11）、[Agent 与工具调用](../../Agent%20与工具调用/README.md)（08、09、12–14）、
[AI 系统设计](../../AI%20系统设计/README.md)（10、11、14）、[评估与可观测性](../../评估与可观测性/README.md)（15）。

## 建议学习顺序

- **两小时速览**：`06 → 07 → 10 → 11`（成本 → 上下文 → 延迟 → 索引）。这四题共享同一套约束，读完就抓住了这家公司的技术重心。
- **实现题**：`01 → 02 → 04 → 05`（哈希树 → Merkle → 重复文件 → 文本缓冲区），`03` 单独当热身。
- **agent 全景**：`08 → 12 → 13 → 14 → 09`（harness → 并发 → 应用 → 沙箱 → 自主适应）。
- **文化题**：`16 → 17 → 15`（主动性 → 长期主义 → 评估），三者都在考「你怎么把判断变成可验证的东西」。

## 自测清单

- 哈希树的叶子与内部节点分别摘要什么？为什么内部节点要绑定子节点个数？
- Merkle 摘要为什么必须绑定长度与类型？不绑定会出现什么攻击或歧义？
- 二叉树顶视图与左/右视图的区别是什么？为什么用 BFS 而不是 DFS 更自然？
- 「重复文件」的契约是什么？硬链接、大小写、稀疏文件要怎么处理？
- gap buffer 与 rope 各适合什么编辑模式？按行查找的索引怎么维护？
- 补全服务的成本公式怎么写？三个抓手分别作用于公式的哪一项？
- 长上下文为什么不能取代检索？说清成本、质量、工程三层理由。
- 「lost in the middle」对上下文组装的直接启示是什么？
- 多文件 harness 的四道闸分别防住什么失败？变更集如何保证原子性？
- 自主适应的四种适应分别靠什么机制实现？记忆的三级与写入门槛是什么？
- 流式编辑应用时的三类冲突分别怎么处理？为什么锚点要优于行号？
- 结构化 hunk 的两级匹配是什么？匹配失败要返回什么信息给模型？
- 双工作区架构下，agent 的中间态为什么不写进用户工作区？同步的三层含义是什么？
- 迭代循环的三件套优化各把时间从多少降到多少（数量级）？
- tab 预测为什么优化 prefill 而不是 decode？投机渲染如何不闪烁？
- monorepo 索引有哪四棵？增量更新如何用 Merkle 摘要定位变化？
- tab 与 agent 编辑的离线判据分别是什么？为什么「接受率」会骗人？
- 回本周期怎么算？为什么长期投入必须配退出条件？
- 两天没有任务时，你的 D1 上午具体做什么？为什么先跑通环境再动手？
