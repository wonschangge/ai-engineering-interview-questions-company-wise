# OpenAI 面试题库

这一家的题有一个很明显的特征：**每一道题都同时考"原理"与"交付"**。
问 KL 散度，会追到"从样本估计的偏差是多少"；问 self-attention，会追到"128K 时注意力矩阵要多少显存"；
问 agent 循环，会追到"卡死 50 步烧掉多少钱"；问客户投诉，会追到"这 3 个百分点显著吗"。

所以准备这一家时，建议把**"把话算成数"**当成习惯动作：
**任何结论都要能换算成一个可验证的数字**——显存、美元、秒、百分比、样本量。
这一家的面试官明显更在意**"你的判断能不能被检验"**，而不是"你知不知道某个名词"。

另一个特征是**行为题占比高（8/31）**，而且它们同样要求量化：
"犯过的错误"要算**修个案 vs 修一类的复利差**，"优先级分歧"要算**代价延迟**，
"最引以为豪的项目"要算**影响归因**。**空泛的 STAR 故事在这一家会显得很薄。**

## 准备建议

1. **先做 07–14 这八道**：它们是这一家的"数学底座"，而且每一道都能用几行 Python 验证——**练熟"先给解析式再验证数值"这个动作**。
2. **再攻 15–20 的系统设计**：六道题的共同点是**每一个设计选择都能算出一个数**（扇出、限额、并发、成本）。准备时把"拍脑袋"换成"算一下"。
3. **21–24 是"排查与安全"**：共同点是**基率与显著性**——**先问"这个现象是真的吗"，再问"怎么处理"**。
4. **行为题不要留到最后**：8 道题占了四分之一，而且它们要求量化。建议**用同一段经历准备"错误/冲突/优先级/自豪"四个角度**（互相印证，也显得真实）。
5. **把仓库里的统一常数记住**：H100 bf16 989 TFLOPs、3.35 TB/s、LLaMA-3-70B 的 KV 320 KiB/token、\$2/GPU·h、\$3/\$15 每百万 token——**这些常数在 17、19、20 三题里反复用到**。
