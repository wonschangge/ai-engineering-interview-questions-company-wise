# Apple 面试题库

这一家的题有一个统一的前提：**内存与功耗预算极紧，而且内容不能离开设备。**
前者把"模型服务"变成"内存预算问题"，后者把"数据驱动"变成"隐私设计问题"。

**第一件事是"批量 1 把问题从吞吐变成延迟"。**
数据中心的 batch 是 256、手机是 1；**带宽只有 1/56、功耗只有 1/140**；
而算术强度阈值在端侧是 **583**（数据中心 295）而 decode 只有 **2**——
**所以两边都是带宽受限，而端侧更缺带宽。**
内存预算的分解是 **1,500 MB 权重（int4）+ 470 MB KV + 150 MB 激活 = 2,120 MB**，
而 fp16 权重就要 6,000 MB——**所以 int4 不是优化而是前提。**

**第二件事是"约束会推出架构"。**
12 个功能各做一个全量微调要 **18,000 MB**（放不下 6 倍），
所以只能是 **"共享底座 + 小适配器"**——而按增益分层配置只要 **180 MB**。
**"一个模型服务多特征"不是设计偏好，而是内存算出来的。**

**第三件事是"隐私边界决定技术方案"。**
**内容不出设备、但统计信号可以**；
而 ε 是"隐私与效用的汇率"：**ε=1 时噪声 10 倍、等效样本降到 1/100**。
更具体的是**公平性问题**：**ε=1 要 1,600 用户/轮，所以小语种拿不到改进。**

准备这一家时，建议把**"内存预算表"**、**"算术强度阈值"**、**"端侧 vs 服务端的成本结构"**这三条练熟。
它们分别解释了"模型能不能装下"、"算力用得上吗"、"该在哪跑"。

## 准备建议

1. **先把"内存预算表"背熟**：**1,500 MB 权重 + 470 MB KV + 150 MB 激活 = 2,120 MB**（01、03）。**这张表是所有端侧决策的起点**——它决定了量化（02）、适配器（06）、甚至路由（08）。
2. **01 与 03 是一对**：**01 给出总预算、03 把 KV 那一块算清楚**。注意"无 GQA 时 KV 比权重还大"这个反直觉的结论。
3. **02 与 06 是"压什么"的两半**：**02 压底座权重、06 加特化适配器**。两者的内存账要合起来看（1,500 + 180 MB）。
4. **04 的诊断顺序值得单独学**：**先算"应该多久"、再找差额、再按成本排序排查**。这个方法论可以迁移到任何性能问题。
5. **05 与 09 是一条链的两端**：**09 是整条端侧链路、05 是其中"输出必须合法"那一环**。注意"模型抽引用、系统做解析"这个分工——它同时解决准确性与隐私。
6. **07 与 10 共享同一个隐私约束**：**07 是"不收集内容怎么训练"、10 是"不记录内容怎么评测"**。两者的基础都是"聚合指标 + DP"。
7. **08 的成本结构最值得记**：**第三方占 8% 流量却贡献 45% 成本**。这解释了为什么"端侧分流"是最大的杠杆。
8. **11 虽然是行为题，但它有可算的内核**：**"期望错误成本 vs 问的成本"**。把它当技术题答会比当软技能题答更有说服力。
