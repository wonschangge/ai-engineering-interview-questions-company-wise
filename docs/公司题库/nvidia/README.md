# NVIDIA 面试题库

这一家的题有一个统一的方法：**先算一个判据，再动手**。
慢 10 倍的 kernel 要先算**算术强度**（elementwise 的 0.25 说明它必然是带宽受限，所以只能从访问模式找原因）；
FP16 输出不对要先算**与 FP32 的余弦相似度**（1.0000 是数值退化、0.0635 是结构性 bug）；
单卡服务 70B 要先算**权重字节**（BF16 是 140 GB，8 卡放不下）；
"TensorRT 能帮多少"要先算**离最优下界的距离**（未融合的 elementwise 链是 5.00×、已调优的 GEMM 只有 1.27×）。

准备这一家时，建议把**"字节 ÷ 带宽"**和**"FLOPs ÷ 算力"**这两个除法练熟。
**大部分答案都是这两个数的比较**：
decode 是"每 token 读一遍权重 ÷ 3.35 TB/s"（70B 的 BF16 是 41.79 ms → 23.9 tok/s），
prefill 是"2 × P × token 数 ÷ 有效算力"，
而 roofline 的平衡点是 295 FLOPs/byte。
**能一眼看出"这是带宽受限还是算力受限"，这一家的题就解了一半。**

第二个反复出现的主题是**"优化空间 = 离上界多远"**：
**已经接近上界的场景（已调优的 GEMM、带宽受限的 decode）TensorRT 帮不上忙**；
**未融合的算子链有 5 倍空间**；
**batch=1 时的 4 tok/s 其实已达该 batch 上限的 17%**。
**"这个数字离理论上限有多远"是评估任何优化方案的第一句话。**

第三个主题是**"容量决定一切"**：
树的深度 12 意味着每叶子 2.4 个样本（必然记住噪声）；
大模型的标签噪声危害反而比小模型小（因为它远未到过参数化）；
405B 的 BF16 权重 810 GB 需要 10.4 张卡。
**"这个配置的容量够不够/太多了"是第二个要问的问题。**

### 编程与数据结构（01–03）

## 准备建议

1. **先把两个除法练熟**：**字节 ÷ 带宽** 与 **FLOPs ÷ 算力**。08 与 09 是它们的直接应用，01 的 roofline 是它们的比较。
2. **01 与 03 是一对**：一个诊断性能、一个诊断正确性，**方法都是"先算一个判据把问题分类"**（算术强度 / 相似度）。这两道最能体现这一家的风格。
3. **02 与 08 是一对**：**08 算"有多少显存"、02 算"怎么用这些显存"**。连起来看就是"单卡 70B"的完整方案。
4. **04、05、06 是"训练动态"三连**：**容量与正则化、优化器的尺度不变性、标签噪声**。它们的共同点是**"实测数字与直觉相反"**（小模型噪声损失更大、Adam 在小任务上更好、自动修标签更差）。
5. **07 是唯一一道"评估"题**，但它的结构与 [[perplexity-13]]、[[palantir-12]] 相通：**代理指标必须被外部信号校准**。
6. **10 有一个辨别点**：**题目问 EP，而稠密模型没有专家**——**敢指出这一点比硬答 EP 更重要**。
7. **12 与 13 是"客户现场"的两面**：**12 用数据定位问题、13 用约束表处理冲突**。这两道适合一起准备。
