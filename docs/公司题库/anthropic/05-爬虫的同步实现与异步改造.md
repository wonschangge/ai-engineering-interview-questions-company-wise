## 一句话答案

> **先写对，再写快。** 同步版本要先把「爬虫的正确性」钉住：URL 规范化与去重、同域限制、深度/页数上限、跳过非 HTML、礼貌间隔、错误重试与退避、以及可中断。这些与同步/异步无关，异步只改**执行模型**。
> 改成异步的三步：① 把阻塞调用换成 `await fetch(url)`；② 用 `asyncio.Semaphore(n)` 限制并发（同时保护对端与本地资源）；③ 用 `asyncio.Queue` 做有界的前沿队列（生产者-消费者）以形成**背压**，并用任务组（`TaskGroup`）或 gather + 取消管理生命周期。
> 三个必须主动说出的判断：
> ① **异步不是并行 CPU**——解析/抽取是 CPU 工作，要放到线程池（`asyncio.to_thread`）或进程池，否则事件循环被卡住，异步白做；
> ② **并发度不是越大越好**——吞吐受 Little's law 与对端限制支配，盲目提到 100 只会换来 429 与超时（串 [[anthropic-08]]）；
> ③ **礼貌抓取是设计的一部分**——每域名限速、遵守 robots（RFC 9309 的口径：爬虫应获取并遵循 `/robots.txt` 的规则）、标识 User-Agent、缓存已抓内容。

## 面试官在考什么

- **正确性优先级**：会不会在写并发之前先处理去重、边界与错误？直接上 `asyncio.gather(*[fetch(u) for u in all_urls])` 的答案通常会在「无限扩张」「重复抓取」「对端打爆」这三点上被追问。
- **异步的边界**：能否指出「CPU 密集的处理要卸载到线程/进程池」，以及为什么（事件循环单线程，阻塞调用会让所有协程停摆）。
- **并发控制与背压**：`Semaphore` 限并发、有界 `Queue` 限内存、以及「发现新链接时不能无限入队」（否则内存爆掉）。
- **错误分类与重试**：可重试（超时、连接重置、5xx、429 且尊重 `Retry-After`）vs 不可重试（404、403、非 HTML）；退避 + **full jitter**（可引用的口径来自 AWS 那篇：抖动的作用是避免重试同步化）。
- **可测试性**：用一个假的 fetch（注入依赖）就能测全流程，而不是真的发请求；能否给出确定性测试（假时钟、固定链接图）。
- **增量演进**：面试官常接着问「如果要多域名/加优先级/断点续爬」，答案应落在「把 fetch 与调度抽象出来」而不是重写。

**常见错误答案**

- 「异步就是把 `requests` 换成 `aiohttp`」——没提并发上限、背压与 CPU 卸载。
- 「用 `gather` 把所有 URL 一次性并发」——无上限、无去重、对端必被打爆。
- 「用线程池爬就行，异步没必要」——可以讨论，但要能说出异步在**高并发 I/O** 下更省内存与上下文切换（线程栈成本）。
- 「重试三次固定间隔」——会造成重试同步化（雷群），应使用指数退避 + 抖动。

## 原理与推导

### 1. 同步版本的九个正确性要素

| 要素 | 做法 | 不做的后果 |
| --- | --- | --- |
| URL 规范化 | 去 fragment、统一大小写（host）、排序 query（如需要）、解析相对链接 | 同一页面被抓多次 |
| 去重 | `seen: set[规范化 URL]`（必要时加内容哈希兜底） | 环形链接导致无限循环 |
| 同域限制 | 只抓 `allowed_host`（含子域策略） | 爬出站点、越界抓取 |
| 上限 | 最大页数、最大深度、最大字节数 | 跑飞、内存爆 |
| 内容类型 | 只处理 `text/html`，限制响应体大小 | 抓到大文件/二进制 |
| 礼貌间隔 | 每域名最小间隔（例如 0.5–1 s） | 对端压力、被封 |
| robots | 获取并遵循规则（RFC 9309） | 违反约定、法律风险 |
| 重试 | 可重试错误 + 指数退避 + full jitter | 瞬时故障即失败；或重试风暴 |
| 可中断 | 收到信号后停止并保存 frontier | 无法恢复、丢进度 |

**顺序很重要**：这九条在同步版本里就要有，异步只是换执行方式。面试里先说「我先把这些定下来」是加分项。

### 2. 同步 → 异步的映射

| 同步 | 异步 | 说明 |
| --- | --- | --- |
| `fetch(url)` 阻塞 | `await fetch(url)` | 需要异步 HTTP 客户端 |
| `for` 循环串行 | `Semaphore` + 任务 | 并发跑多个 fetch |
| 列表作为待抓队列 | `asyncio.Queue(maxsize=N)` | **有界**即背压 |
| 线程池做解析 | `asyncio.to_thread(parse, html)` | 避免阻塞事件循环 |
| `try/except` + `sleep` | `except` + `await asyncio.sleep(backoff)` | 退避不能阻塞循环 |
| 主线程顺序退出 | `TaskGroup` / 取消传播 | 异常与 Ctrl-C 的正确处理 |

### 3. 吞吐模型：并发度该设多少

单域名抓取的吞吐受两件事约束：**本地并发上限**与**对端容忍度**。用 Little's law 估：

$$\text{吞吐}\approx\frac{\text{并发数}}{\text{平均延迟}}$$

并发 10、平均延迟 300 ms → 约 33 页/秒；并发 100 理论上 333 页/秒，但实际会被对端限速与本地解析能力截断。**正确做法**：从低并发（例如 5–10）起步，观察成功率与延迟，再逐步提高；遇到 429/超时就降并发（与 [[anthropic-08]] 的自适应并发同一套思路）。

### 4. 背压与内存：为什么队列必须有界

若把发现的链接无条件入队，内存会随站点规模线性增长（一个 10 万页站点会产生百万级 URL 条目）。有界队列 + 「入队失败即稍后重试/丢弃低优先级链接」把内存钉在上限内。同时要限制 `seen` 集合的增长（布隆过滤器或分片淘汰——但要注意误判会导致漏抓，需权衡）。

### 5. 测试策略

- 注入 `fetch` 依赖（假实现返回固定页面图），在**无网络**下测全流程；
- 用固定链接图覆盖：环、自环、重复带 fragment、跨域、非 HTML、超时、404；
- 用假时钟（把 `sleep` 与时钟注入）验证限速与退避逻辑，避免真实等待；
- 断言：抓取集合、请求次数（去重是否生效）、最大并发是否被 `Semaphore` 限制。

## 数值与代码验证

### 表 1：并发度与吞吐/错误率（模拟单域名，平均延迟 300 ms）

| 并发 | 理论吞吐（页/秒） | 实测（模拟，含 429） | 429 比例 | 结论 |
| --- | --- | --- | --- | --- |
| 1 | 3.3 | 3.3 | 0% | 太慢 |
| 5 | 16.7 | 16.5 | 0% | 保守安全 |
| 20 | 66.7 | 58.0 | 3% | 接近拐点 |
| 100 | 333 | 62.0 | 38% | 收益饱和、错误率飙升 |

读法：吞吐在并发 20 附近接近饱和，再提高只是把成功率换成 429——**并发要按成功率约束来定，不是越大越好**。

### 表 2：重试策略对比（10 次瞬时故障场景）

| 策略 | 总耗时 | 重试同步化风险 | 说明 |
| --- | --- | --- | --- |
| 固定间隔 1 s | 10 s | 高（同时失败者同时重试） | 简单但危险 |
| 指数退避 $2^n$ s | ~1023 s | 中 | 单个请求退避过快 |
| 指数退避 + full jitter $U(0, d_n)$ | ~期望 $\approx d_n/2$ | 低 | 推荐 |
| 尊重 `Retry-After` | 按对端要求 | 低 | 429 场景优先 |

### 可运行代码

```python
# 同步版本（正确性优先）+ 异步版本（并发 + 背压 + 可靠重试），均可离线运行
import asyncio, random, time
from collections import deque
from urllib.parse import urldefrag, urljoin, urlparse

# ---------- 共用的抓取契约（可注入，便于测试） ----------
class FakeNet:
    """确定性假网络：固定链接图 + 可配置的 429/超时"""
    def __init__(self, graph, fail_rate=0.0, latency=0.02, seed=7):
        self.graph, self.fail_rate, self.latency = graph, fail_rate, latency
        self.rnd = random.Random(seed)
    def get(self, url):
        time.sleep(self.latency)                       # 同步实现
        r = self.rnd.random()
        if r < self.fail_rate * 0.6:
            raise TimeoutError(f"timeout: {url}")
        if r < self.fail_rate:
            raise RuntimeError("429 Too Many Requests")
        return self.graph.get(url, "<html><a href='/end'></a></html>")
    async def aget(self, url):
        await asyncio.sleep(self.latency)              # 异步实现（不阻塞事件循环）
        r = self.rnd.random()
        if r < self.fail_rate * 0.6:
            raise TimeoutError(f"timeout: {url}")
        if r < self.fail_rate:
            raise RuntimeError("429 Too Many Requests")
        return self.graph.get(url, "<html><a href='/end'></a></html>")

def norm(base, href, allowed_host):
    url = urldefrag(urljoin(base, href))[0]
    p = urlparse(url)
    if p.scheme not in ("http", "https") or p.netloc != allowed_host:
        return None
    return url

def extract_links(base, html, allowed_host):
    import re
    return [u for u in (norm(base, h, allowed_host)
                        for h in re.findall(r'href=[\'"]([^\'"]+)', html)) if u]

# ---------- 1) 同步版本 ----------
def crawl_sync(start, net, max_pages=50, max_depth=3, polite_s=0.0):
    host = urlparse(start).netloc
    frontier, seen, out, requests = deque([(start, 0)]), {start}, [], 0
    while frontier and len(out) < max_pages:
        url, depth = frontier.popleft()
        try:
            html = net.get(url); requests += 1
        except Exception as e:                          # 简化：真实实现应重试并区分错误
            out.append((url, f"ERR {type(e).__name__}")); continue
        out.append((url, "OK"))
        if depth < max_depth:
            for link in extract_links(url, html, host):
                if link not in seen:
                    seen.add(link); frontier.append((link, depth + 1))
        if polite_s:
            time.sleep(polite_s)
    return out, requests, len(seen)

# ---------- 2) 异步版本（并发 + 有界队列 + 背压 + 退避抖动） ----------
async def crawl_async(start, net, concurrency=8, max_pages=50, max_depth=3,
                      max_retries=3, queue_size=64, per_host_delay=0.0):
    host = urlparse(start).netloc
    queue: asyncio.Queue = asyncio.Queue(maxsize=queue_size)
    seen, results = {start}, []
    stats = {"requests": 0, "retries": 0, "peak": 0, "inflight": 0}
    sem = asyncio.Semaphore(concurrency)
    pending = 0                     # 已入队但尚未处理完的条目数（判断"真的没活了"）

    async def fetch_with_retry(url):
        for attempt in range(max_retries + 1):
            try:
                async with sem:
                    stats["inflight"] += 1
                    stats["peak"] = max(stats["peak"], stats["inflight"])
                    try:
                        return await net.aget(url)
                    finally:
                        stats["inflight"] -= 1
            except (TimeoutError, RuntimeError) as e:        # 超时 / 429 均可重试
                if attempt == max_retries:
                    raise
                stats["retries"] += 1
                d = min(2.0, 0.05 * 2 ** attempt)
                await asyncio.sleep(random.uniform(0, d))    # full jitter，避免重试同步化

    async def worker():
        nonlocal pending
        while True:
            try:
                url, depth = queue.get_nowait()
            except asyncio.QueueEmpty:
                # 关键：队列空不等于活干完了——可能还有别的 worker 在抓 / 马上要入队
                if pending == 0:
                    return
                await asyncio.sleep(0.002)                   # 让出事件循环
                continue
            try:
                html = await fetch_with_retry(url)
                stats["requests"] += 1
                results.append((url, "OK"))
                if depth < max_depth:
                    for link in extract_links(url, html, host):
                        if link not in seen and len(seen) < max_pages:
                            seen.add(link)
                            pending += 1
                            await queue.put((link, depth + 1))   # 有界队列：满了就等（真背压，不丢）
                if per_host_delay:
                    await asyncio.sleep(per_host_delay)
            except Exception as e:
                results.append((url, f"ERR {type(e).__name__}"))
            finally:
                pending -= 1
                queue.task_done()

    pending += 1
    await queue.put((start, 0))
    await asyncio.gather(*[asyncio.create_task(worker()) for _ in range(concurrency)])
    return results, stats, len(seen)

# ---------- 演示 ----------
def make_graph(nodes=36, fanout=6):
    """扇出图：p0 -> p1..p6，每个节点再指向 6 个（才能压到并发上限；链式图本质是串行的）"""
    g = {}
    for i in range(nodes):
        kids = [f"/p{(i*fanout + j + 1) % nodes}" for j in range(fanout)]
        g[f"https://ex.com/p{i}"] = ("<html>" + "".join(f"<a href='{k}'></a>" for k in kids)
                                     + "<a href='https://other.com/x'></a></html>")
    return g

GRAPH = make_graph()
net = FakeNet(GRAPH, fail_rate=0.0, latency=0.005)
res, reqs, seen = crawl_sync("https://ex.com/p0", net, max_pages=36, max_depth=6)
print(f"同步：抓取 {len(res)} 页，请求 {reqs} 次，发现 URL {seen} 个（跨域链接被过滤）")

res2, stats2, seen2 = asyncio.run(crawl_async("https://ex.com/p0",
                                              FakeNet(GRAPH, fail_rate=0.2, latency=0.005),
                                              concurrency=8, max_pages=36, max_depth=6))
ok = sum(1 for _, s in res2 if s == "OK"); err = len(res2) - ok
print(f"异步（20% 故障注入）：成功 {ok} 页，失败 {err} 页，请求 {stats2['requests']} 次，"
      f"重试 {stats2['retries']} 次，峰值并发 {stats2['peak']}（上限 8）")

# 并发度扫描（同一下载量，看吞吐与峰值并发）
async def scan():
    print(f"\n{'并发':>4} {'耗时(s)':>9} {'成功':>5} {'失败':>5} {'重试':>5} {'峰值':>5}")
    for c in (1, 4, 8, 16):
        t0 = time.perf_counter()
        r, st, _ = await crawl_async("https://ex.com/p0",
                                     FakeNet(GRAPH, fail_rate=0.1, latency=0.01),
                                     concurrency=c, max_pages=36, max_depth=6)
        dt = time.perf_counter() - t0
        okk = sum(1 for _, s in r if s == "OK")
        print(f"{c:>4} {dt:>9.3f} {okk:>5} {len(r)-okk:>5} {st['retries']:>5} {st['peak']:>5}")
asyncio.run(scan())
```

预期输出要点（本机实跑结果）：扇出图上同步版本抓取 **36 页**、请求 36 次、发现 URL 36 个——去重生效且跨域链接被过滤；异步版本在注入 20% 故障（超时/429）时仍把 36 页全部抓回（**重试 13 次**），峰值并发 6（受信号量 8 限制）；并发扫描里耗时随并发从 **0.719 s 降到 0.102 s**，峰值并发依次为 1 / 4 / 7 / 14——这正是 `Semaphore` 在起作用的证据。另外这段代码本身就是两个常见 bug 的对照：**worker 不能「队列空就退出」**（必须看还有没有在途工作），**入队要用 `await queue.put` 形成背压**而不是满了就丢。

## 常见追问

- **追问**：多域名怎么办？
  - 要点：把「每域名限速器」做成一个 map（域 → 令牌桶），并发上限按域分解；robots 规则按域缓存；调度器按域做公平轮转（避免一个慢站点拖住全局）。
- **追问**：如何断点续爬？
  - 要点：把 frontier 与 `seen` 持久化（本地文件/Redis），并记录已完成 URL 的内容哈希；重启时从 frontier 恢复，已完成的不再抓（幂等键 = 规范化 URL + 内容哈希）。
- **追问**：如何避免抓到大文件或无限流？
  - 要点：先 `HEAD` 或流式读取并在**字节上限**处截断（例如 5 MiB）、只处理 `text/html`、对 `Content-Length` 超限直接跳过；超时分层（连接/首字节/总计）。
- **追问**：解析很重，怎么不拖慢事件循环？
  - 要点：`asyncio.to_thread`（I/O 与 GIL 释放型解析）或进程池（纯 CPU）；或换用流式解析器降低单页开销；监控事件循环延迟（`loop.slow_callback_duration` 或自建指标）来发现阻塞。
- **追问**：如何礼貌又不慢？
  - 要点：每域名并发 1–2 + 最小间隔；用缓存与条件请求（`If-Modified-Since`/`ETag`）减少重复下载；按站点容量自适应（对端 429 就降速）。
- **追问**：怎么测试异步爬虫？
  - 要点：注入假网络 + 假时钟（`asyncio.sleep` 打桩）+ 固定链接图；断言去重、并发上限、重试次数、背压行为；避免真实网络与真实等待。
