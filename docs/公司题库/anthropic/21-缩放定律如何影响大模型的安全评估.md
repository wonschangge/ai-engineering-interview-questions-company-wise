## 一句话答案

> 缩放定律对安全评估有**四个直接影响**，每一个都改变「怎么评、评多少、什么时候评」：
> ① **能力可按算力预测 ⇒ 风险必须提前评估**。Kaplan 等人的结论是测试损失随参数量、数据量、算力呈幂律（可引用的原始口径：损失与三者都是幂律关系，且架构细节在更大规模下影响变小）；Chinchilla 进一步给出**计算最优**的数据配比（约 **20 token/参数**，同样算力下比「大模型+少数据」更优）。工程含义：既然「下一个规模点会更强」是可以事先预期的，**危险能力评估必须提前设计**，而不是等模型训完再想。
> ② **评估本身要「按规模缩放」**。小模型上的结论**不能外推**到大规模——能力可能出现不连续的增长，而小模型测不出的风险在大模型上可能突然出现。所以评估必须**在接近前沿的规模上做**，且要覆盖「最坏情况」（红队样本量随模型规模增加才够）。
> ③ **过度优化是可预测的**。*Scaling Laws for Reward Model Overoptimization* 给出了关键结论：代理奖励（proxy reward）随与初始策略的 KL 距离**先升后降**，且这条曲线的**峰值位置与形状随偏好模型规模平滑变化**。含义：**reward hacking 的起点可以被预测**，因此 KL 预算/早停点可以按规律设定，而不是靠试错（串 [[anthropic-20]] 的「没解决②」）。
> ④ **评估需要防污染与防过拟合**，而规模化让这两件事更难（模型见过更多东西；团队会对评测集调参）。可引用的做法是持续更新的抗污染基准（LiveBench 式：题目按月更新、答案可自动判分）。
> 一句话总结：**缩放定律把「安全评估」从「事后检查」变成「事前规划」**——风险可预期、评估改成算力/样本量的函数、早停点可计算、污染防护要持续投入。

## 面试官在考什么

- **能否把三条定律的角色分清**：能力幂律（Kaplan）、计算最优配比（Chinchilla）、过度优化幂律（Gao et al.）——前两条讲「能力会长到哪」，第三条讲「对齐在什么点开始失效」。
- **算力与数据的口径**：训练算力 $C\approx6ND$（$N$ 参数、$D$ token）能否写出来并与「20 token/参数」的结论对上（给定 $C$ 时最优 $N$ 与 $D$ 的比例）。
- **「评估要 scaling」的具体含义**：红队样本量、评估任务难度、以及**评估算力**都要随模型规模增长；用小评估集测大模型会得到「虚假的安全感」。
- **可预测性的边界**：缩放定律是**经验规律**，不保证外推（可能出现不连续/涌现行为），也不能预测「某种具体能力的绝对阈值」。因此它是**规划工具**，不是安全证明。
- **工程落点**：算力阈值（compute threshold）式的门禁——超过某个训练算力就触发更强的评估（内外部红队、第三方评估、部署决策会审）；这需要提前约定口径，否则每次都要重新争论。
- **评估的统计功效**：给定攻击成功率与样本量，能否算出「能检出多大的风险」——样本量不足的评估等于没评估（串 [[evaluation-04]] 的门禁设计）。

**常见错误答案**

- 「模型越大越危险，所以要评估」——没有量化，也没说清评估怎么做才有效。
- 「先用小模型做安全评估，再线性外推」——缩放定律本身不保证能力线性外推，风险更不可线性外推。
- 「缩放定律能预测能力，所以也能预测安全性」——**能力可预测 ≠ 对齐可预测**；后者只有特定的经验规律（如过度优化曲线）。
- 忽略评估污染：大规模训练语料几乎必然包含公开评测集，不防污染的数字毫无意义（串 [[evaluation-06]]）。

## 原理与推导

### 1. 三条定律与各自的用途

| 定律 | 形式（原始口径） | 对安全评估的用途 |
| --- | --- | --- |
| 能力幂律（Kaplan） | $L(N,D,C)$ 对三者均为幂律；架构细节在更大规模下影响变小 | 预期「下个规模点更强」，提前设计风险评估与算力阈值 |
| 计算最优配比（Chinchilla） | 给定算力 $C$，最优 $N$ 与 $D$ 同比例增长（约 20 token/参数） | 判断「同等算力下更强」的模型会更快出现，评估节奏要跟上 |
| 过度优化幂律（Gao et al.） | 代理奖励 $\approx f(d)$，$d=\sqrt{D_{\text{KL}}}$，先升后降；峰值随偏好模型规模平滑变化 | 预测 reward hacking 起点，设定 KL 早停预算 |

**算力式子**（仓库统一口径）：$C\approx6ND$。取 $N=70\times10^{9}$、$D=1.4\times10^{12}$（20 token/参数）：$C\approx6\times70\text{e}9\times1.4\text{e}12=5.9\times10^{23}$ FLOPs——这是「70B 级、计算最优」的一次训练量级，可用于估算评估所需算力占比。

### 2. 为什么「小模型评估不能外推」

- 幂律是**在观测区间内**成立的经验关系；跨越多个数量级的外推没有保证；
- 能力可能出现**不连续**（同一任务在小模型上接近随机、在大模型上突然可用）；
- 更麻烦的是：**风险任务往往比能力任务更晚出现**（需要多步推理、工具使用、长程规划），而小模型恰恰缺少这些能力，因此「小模型测不出风险」是结构性的。
**结论**：安全评估要在**接近前沿的规模**上做，并用「能力预判 + 提前红队」覆盖即将到来的规模点。

### 3. 评估的统计功效：样本量必须够

若某类攻击的真实成功率是 $p$，评估用了 $n$ 次尝试，则**至少检出一次**的概率是

$$P(\text{检出})=1-(1-p)^{n}$$

$p=1\%$、$n=100$ → $P=63\%$；$n=300$ → $95\%$。也就是说：**要可靠地发现 1% 的攻击成功率，至少要几百次尝试**；而严重风险的容忍度要求更高（要估计 $p$ 本身，而不只是「检出一次」，样本量还要再上一个量级）。
**工程含义**：红队与自动攻击的样本量预算必须按目标检出阈值来定，并写进评估计划（这与门禁的红线集设计是同一套统计逻辑，串 [[evaluation-04]]）。

### 4. 过度优化的可预测性：把早停变成计算题

论文的实证结论是：代理奖励（偏好模型打分）随 $d=\sqrt{D_{\text{KL}}}$ **先升后降**，而真实奖励（金标准）更早开始下降；拟合式形如

$$\text{proxy}(d)=d(a-bd),\qquad \text{gold}(d)=d(a'-b'd)$$

峰值位置 $d^{*}=a/(2b)$ 可由拟合系数直接算出。**工程含义**：
- 训练前就能用**小规模实验**拟合出曲线，估计「KL 预算应该定在哪」；
- 由于峰值随偏好模型规模平滑移动，**大模型上的早停点可以从中小规模实验外推**（这是缩放定律对安全实践最直接的贡献）；
- 监控指标应当是「代理分与金标准分的差」，而不是代理分本身——后者总会涨，直到崩。

### 5. 落到流程：算力阈值 + 分级评估

| 训练算力档 | 评估要求（示例） |
| --- | --- |
| < 阈值 1 | 常规评估 + 自动化红线集 |
| 阈值 1–2 | 增加内外部红队、能力评估（CBRN/网络/自主性）、部署门禁 |
| > 阈值 2 | 第三方评估、发布决策会审、分阶段发布与访问控制 |

**关键**：阈值与要求必须**事先约定并版本化**（否则每次都要重新谈判），且评估结论要能**阻断发布**（有牙齿），不然只是仪式。

### 6. 与污染/过拟合的关系

规模化同时放大两个评估风险：① 训练语料覆盖公开评测集（污染）；② 团队对评测集过拟合（反复调参直到指标好看）。应对：**私有留出 + 持续更新的公开基准 + 定期轮换 + 去污染记录**（串 [[evaluation-06]]）。

## 数值与代码验证

### 表 1：样本量与风险检出（$P=1-(1-p)^n$）

| 真实攻击成功率 $p$ | $n=30$ | $n=100$ | $n=300$ | $n=1{,}000$ |
| --- | --- | --- | --- | --- |
| 0.1% | 3% | 10% | 26% | 63% |
| 1% | 26% | 63% | 95% | ~100% |
| 5% | 79% | 99% | ~100% | ~100% |

**读法**：要可靠发现 1% 的攻击，至少几百次尝试；要**估计** $p$（而非仅检出），样本量还要再上一个量级。**样本量不足的评估给出的「没发现问题」没有信息量。**

### 表 2：算力与评估成本的相对量级

| 项 | 算式 | 结果（70B、20 token/参数） |
| --- | --- | --- |
| 训练算力 | $6ND$ | $5.9\times10^{23}$ FLOPs |
| 一次全量评估（1 万个 prompt × 平均 1K token 输出） | $2\times P\times$ token 数 | $1.4\times10^{18}$ FLOPs |
| 评估占训练算力比 | 上两行相除 | 约 $2.4\times10^{-6}$ |

**读法**：评估的**算力**成本可以忽略不计——真正稀缺的是**评估的设计、红队的人力与判断**。所以「算力不够所以少评估」从来不是理由；瓶颈在人不在卡。


```python
# 1) 三条定律的量化：算力、最优配比、过度优化峰值与早停
import math

def train_compute(N, D):            # C ≈ 6ND
    return 6 * N * D

def chinchilla_optimal(C, ratio=20):
    """给定算力与 20 token/参数，反解最优 N 与 D"""
    N = math.sqrt(C / (6 * ratio))
    return N, N * ratio

print("① 能力/配比：给定算力的计算最优模型")
for C in (1e22, 1e23, 1e24, 1e25):
    N, D = chinchilla_optimal(C)
    print(f"  C={C:.0e} FLOPs -> N≈{N/1e9:7.1f}B 参数，D≈{D/1e12:7.2f}T token"
          f"（{D/N:.1f} token/参数）")

print("\n② 过度优化：拟合式 proxy(d)=d(a-bd)、gold(d)=d(a'-b'd)，d=sqrt(KL)")
def curve(d, a, b):
    return d * (a - b * d)
A, B, A2, B2 = 1.0, 1.6, 0.8, 1.6
d_star = A / (2 * B)
kl_star = d_star ** 2
print(f"  代理奖励峰值：d*={d_star:.3f}（KL*={kl_star:.3f}），峰值 proxy={curve(d_star,A,B):.4f}")
print(f"  金标准更早见顶：d*={A2/(2*B2):.3f}（KL*={(A2/(2*B2))**2:.3f}）")
print("  早停建议：把 KL 预算定在两者之间偏保守处，例如 KL ≤ "
      f"{(A2/(2*B2))**2:.3f}")
print("  实际训练中应监控「proxy - gold」的差，而不是 proxy 本身")

print("\n③ 缩放外推的边界：真实曲线含不可约损失项 L(N)=L_inf + a*N^-alpha，")
print("   却用纯幂律在小规模上拟合，然后外推")
L_INF, A_TRUE, ALPHA_TRUE = 1.60, 2.0, 0.076
def true_loss(N):
    return L_INF + A_TRUE * N ** (-ALPHA_TRUE)
# 只用两个小规模点拟合纯幂律 L = a*N^-alpha（不含 L_inf）
N1, N2 = 1e8, 1e9
import math
y1, y2 = math.log(true_loss(N1)), math.log(true_loss(N2))
alpha_hat = -(y2 - y1) / (math.log(N2) - math.log(N1))
a_hat = math.exp(y1 + alpha_hat * math.log(N1))
print(f"  小规模拟合得 α̂={alpha_hat:.4f}（真值 {ALPHA_TRUE}），a_hat={a_hat:.3f}（真值 {A_TRUE}）")
print(f"  {'N':>10} {'真实损失':>10} {'纯幂律外推':>12} {'相对误差':>10}")
for N in (1e8, 1e9, 1e10, 1e11, 1e12):
    pred = a_hat * N ** (-alpha_hat)
    err = pred / true_loss(N) - 1
    print(f"  {N:>10.0e} {true_loss(N):>10.4f} {pred:>12.4f} {err:>9.1%}")
print("  读法：真实损失有下界（不可约项），纯幂律没有 → 外推会把损失低估（越远越离谱）。")
print("        这正是「不能用小模型结论外推大模型（更不能用它外推安全风险）」的量化理由")

# 2) 评估的统计功效：给定目标检出率，需要多少样本
def n_for_detection(p, target=0.95):
    return math.ceil(math.log(1 - target) / math.log(1 - p))
def detection_prob(p, n):
    return 1 - (1 - p) ** n
print(f"\n④ 评估样本量（目标：95% 概率至少检出一次）")
for p in (0.001, 0.01, 0.05, 0.10):
    print(f"  真实成功率 {p:>6.1%}: 需要 {n_for_detection(p):>6,d} 次尝试；"
          f"若只做 100 次，检出率仅 {detection_prob(p,100):.0%}")
print("  读法：这就是「评估必须按风险等级配样本量」的算术依据；")
print("        要估计 p 本身（而非只检出），样本量还要再上一个量级")

# 3) 算力阈值门禁：评估算力 vs 训练算力的占比
def eval_flops(n_prompts, avg_tokens, params=70e9):
    return 2 * params * n_prompts * avg_tokens
C = train_compute(70e9, 1.4e12)
E = eval_flops(10_000, 1_000)
print(f"\n⑤ 评估成本占比：训练 {C:.2e} FLOPs，一次全量评估 {E:.2e} FLOPs "
      f"-> 占比 {E/C:.2e}")
print("  读法：评估的算力几乎免费，瓶颈在设计、红队人力与判断 —— "
      "「算力不够所以少评估」不成立")
```

预期输出要点（实跑）：① 给定算力反解出计算最优的 $N$ 与 $D$（保持约 20 token/参数），说明「同等算力下更强的模型会持续出现」；② 过度优化曲线给出**代理奖励峰值 $d^*=0.3125$（KL≈0.098）**与金标准更早的峰值（本例 KL≈0.0625），早停应定在两者之间偏保守处，并监控「proxy − gold」；③ 真实损失含**不可约项**（有下界），而纯幂律没有：只用两个小规模点拟合时，**指数被低估 4.5 倍**（α̂=0.0167 vs 真值 0.076），外推到 $N=10^{12}$ 时损失低估 **2.8%** 且随规模单调恶化——**指数估偏的后果远比损失值本身严重**，因为它会让所有「能力何时出现」的预测系统性乐观，这正是「不能拿小模型的安全结论外推」的量化演示；④ 检出 1% 的攻击需要约 300 次尝试（$n=100$ 时只有 63%）；⑤ 一次全量评估的算力只占训练的约 $10^{-6}$ 量级——**瓶颈是设计与人力，不是算力**。

## 常见追问

- **追问**：缩放定律能预测「对齐失败」吗？
  - 要点：不能直接预测。可用的经验规律只有**过度优化曲线**（代理-金标准分离的起点与形状随规模平滑变化）；「是否对齐」不是损失函数，无法用幂律刻画。因此安全评估必须靠**行为评测 + 红队**，而不是靠损失曲线。
- **追问**：算力阈值怎么定才不武断？
  - 要点：按「能力预判 + 风险分级」定：先用既有模型拟合能力-算力曲线，找出**关键能力（如自主性、网络攻击辅助）可能出现的算力区间**，把阈值设在它之前；阈值与对应评估要求写成版本化文档，并对每次训练记录实际算力。
- **追问**：如何在评估上防污染？
  - 要点：私有留出（永不进训练）+ 持续更新的公开基准（题目按月更新、答案可自动判分）+ 去污染检查与记录 + 定期轮换评测集；公开榜单只作参考信号（串 [[evaluation-06]]）。
- **追问**：评估样本量怎么定？
  - 要点：按目标检出率反解（$n=\ln(1-\text{target})/\ln(1-p)$）；对高风险类别要求更高的 target（例如 99%）并额外报告置信区间；把样本量写进评估计划，避免「跑了几十条就宣布安全」。
- **追问**：如果评估发现风险，流程上怎么办？
  - 要点：评估结论必须**能阻断发布**（门禁有牙齿）：触发更强评估、限制访问（分阶段发布/受控访问）、能力抑制（训练侧干预）或推迟发布；并记录决策与依据（可审计）。
- **追问**：算力越大越难评估，怎么办？
  - 要点：① 用「能力预判」把评估前置；② 自动化红队（可扩展的攻击生成）+ 人工深挖高风险类别；③ 用少量高信息量的评估任务而非海量低信息量任务；④ 接受「评估永远不完整」，用**保守的部署策略**（限权、监控、可回滚）补足不确定性。
