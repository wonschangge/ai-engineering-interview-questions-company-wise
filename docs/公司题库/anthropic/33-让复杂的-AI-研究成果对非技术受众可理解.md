## 一句话答案

> 让研究「可被理解」不是**降低精度**，而是**换一个承载信息的结构**。我的做法有五步：
> ① **先问受众要做什么决策**——听不懂往往不是智力问题，而是**内容与决策无关**：给董事会的应该是「要不要上/风险多大/需要什么资源」，给用户的是「这对我有什么用/我该怎么做」，给同行才是方法与证据。**受众的决策决定该讲什么，而不是研究里有什么就讲什么**；
> ② **一句话主张 + 一个数字 + 一个类比**（三条腿缺一不可）：主张要能被复述；数字要给量级与不确定性；类比要**标注它的失效边界**（类比是脚手架，不是论证）；
> ③ **用具体案例替代抽象机制**：把「注意力机制如何聚合上下文」换成「它像查字典时同时看很多个词条，按相关度加权」，再补一句「但它不会真的'查表'，只是数学上的相似」；
> ④ **把不确定性当内容而不是免责声明**：「这个结论在当前测试集上成立，换到你的场景可能不同——我们已知的失效场景是……」。**丢掉不确定性的科普是误导**；
> ⑤ **测试理解，而不是测试表达**：给 5–10 个目标受众读一遍，让他们**用自己的话复述主张**并回答两个问题（这改变了什么？什么情况下不成立？）；复述错误率高的地方就是需要重写的地方。
> 一句话判据：**好的科普让受众能做出更好的决定，而不只是「感觉懂了」**。

## 面试官在考什么

- **是否从受众决策出发**：能不能说出「同一份研究，对三类受众要写三个版本」，并给出各自的**核心问题**。
- **是否能舍弃**：科普的难点在**删**——保留什么、删什么、把什么放到附录；能否明确说出「这一版不讲方法细节，因为受众不据此决策」。
- **类比的质量**：能否给出**带边界的类比**（「像……但不一样的地方是……」），而不是只给一个漂亮比喻（漂亮比喻最容易制造错误直觉）。
- **不确定性的传递**：能否把置信区间、样本量、适用范围翻译成受众能用的语言（例如「这个数字在 ±X% 内可信；在我们的测试里样本是 2,000 条」）。
- **对「简化导致误解」的警惕**：可引用的例子是「涌现能力」——很多被报道的「突然学会」其实是**指标选择**造成的表象（改用连续指标后消失）；把这类反例讲给受众，比讲机制更能防止误读。
- **可测量**：是否用**理解度测试**（复述正确率、误解率）替代「我觉得讲清楚了」；以及有没有具体格式（1 页简报 / 5 分钟口头 / FAQ）。
- **诚实与边界**：会不会为了「好懂」而夸大能力或淡化风险；能否区分「我们知道的」「我们推测的」「我们不知道的」。

**常见错误答案**

- 把论文摘要翻译一遍就当成科普（术语换中文，结构没变）。
- 用大量比喻堆砌，却不给数字与边界。
- 只说结论不说适用范围（「模型会撒谎」这类惊悚化表述）。
- 假定受众「只要结论」，于是把不确定性全部删掉。
- 不做任何理解度验证，靠自我感觉判断「讲清楚了」。

## 原理与推导

### 1. 三类受众与各自的决策

| 受众 | 他们的决策 | 该讲 | 不该讲 | 合适格式 |
| --- | --- | --- | --- | --- |
| 决策者（高管/客户） | 要不要投入/上线/采购 | 影响、成本、风险、时间线、需要的决定 | 方法细节、指标定义 | 1 页简报 + 3 张图 |
| 使用者（员工/用户） | 我该怎么用它 | 能做什么、不能做什么、出错时怎么办 | 机制、训练细节 | FAQ + 示例 |
| 同行/评审 | 结论是否可信 | 方法、数据、局限、可复现性 | 过度简化 | 论文/技术报告 |

**关键**：把这份表**写在动笔之前**。多数「讲不清楚」的根因是**没决定受众**，于是想同时满足所有人。

### 2. 「一句话 + 一个数字 + 一个类比」的三条腿

- **一句话主张**：主语 + 动作 + 对象，且**可被否定**（「模型在长文档中段的信息利用率下降」而不是「模型很厉害」）；
- **一个数字**：给量级与不确定性（"在 2,000 条样本上，中段位置的正确率比首尾低约 20 个百分点，95% 区间约 ±4 个百分点"）；
- **一个类比**：形式为「像 X，但在 Y 上不同」（「像读书时容易忽略中间几页，但不同之处是它并非'跳过'，而是注意力权重被稀释」）。

**为什么必须带 Y**：类比的作用是**建立初始直觉**，而它必然在某处失真；把失真点说出来，才能防止受众把类比当机制。

### 3. 不确定性的翻译表

| 技术表述 | 面向决策者的表述 |
| --- | --- |
| $p<0.05$，效应量 5pp | 「这个提升不太可能是偶然（约 5% 的可能是噪声），幅度约 5 个百分点」 |
| 95% CI [1pp, 9pp] | 「真实提升大概在 1–9 个百分点之间，最可能是 5 个左右」 |
| 样本量 300 | 「我们测了 300 个案例；要发现更小的差异需要更多样本」 |
| 分布外失效 | 「在我们测过的场景之外，这个结论没有保证」 |
| 评估集污染风险 | 「这个分数可能被'见过类似题目'抬高了，所以别只看分数」 |

**纪律**：**不把「没有显著差异」说成「没有差异」**（功效不足时尤其危险，串 [[anthropic-27]]）。

### 4. 常见失真模式（科普的反模式）

| 反模式 | 后果 | 修正 |
| --- | --- | --- |
| 惊悚化 | 「模型会撒谎/会自我复制」 | 加范围与条件：「在我们的测试设定下，出现了 X 行为」 |
| 拟人化 | 「它想/它害怕」 | 换成行为描述：「在某些提示下它会输出 X」 |
| 单一数字崇拜 | 只报分数最高的那一项 | 报分布与基线，说明指标选择的影响 |
| 抹掉不确定性 | 受众按点估计做决策 | 给区间与样本量 |
| 类比代替机制 | 受众形成错误模型 | 标注类比的失效边界 |

**可引用的最佳反例**：所谓「涌现能力」在改用连续指标后往往消失——这说明**指标本身会制造结论**（串 [[anthropic-27]] 的代码演示）。这是讲给非技术受众时最值得说的一件事，因为它直接教会受众「看到跃变曲线要先问指标怎么定义的」。

### 5. 理解度测试（把「讲清楚」变成可测量）

1. 选 5–10 名目标受众（不是同事——同事已被同化）；
2. 让他们读/听后回答三问：**主张是什么**、**什么情况下不成立**、**你会因此做什么决定**；
3. 统计**复述正确率**与**误解类型**（哪一种误解最多）；
4. 只重写误解最集中的那一段，再测一次（小样本迭代）。

**样本量直觉**：若某段落的误解率是 30%，在 $n=10$ 人里**至少一人误解**的概率约 97%——所以 10 人足够发现「高频误解」，但不足以精确估计误解率（要精确到 ±5% 需要数百人，串 [[anthropic-27]]）。**小样本用于发现，大样本用于测量。**

### 可运行代码

```python
# 科普写作的两个可测量工具：可读性代理指标 + 理解度测试功效
import math, re, random
from dataclasses import dataclass
from typing import Dict, List, Tuple

# ---------- 1) 可读性代理：平均句长、术语密度、数字（含不确定性）密度 ----------
JARGON = {"注意力机制", "稀疏自编码器", "KL 散度", "梯度下降", "交叉熵", "同分布",
          "对齐", "涌现", "上下文窗口", "微调", "推理"}

def readability(text: str) -> Dict[str, float]:
    sents = [s for s in re.split(r"[。！？\n]+", text) if s.strip()]
    chars = sum(len(s) for s in sents)
    jargon_hits = sum(text.count(j) for j in JARGON)
    number_hits = len(re.findall(r"\d+(?:\.\d+)?\s*(?:%|个百分点|条|倍|ms|秒)", text))
    uncertainty_hits = len(re.findall(r"(?:±|约|大致|区间|可能在|不确定|置信)", text))
    return {
        "平均句长": chars / len(sents) if sents else 0,
        "每千字术语数": jargon_hits / chars * 1000 if chars else 0,
        "每千字数字数": number_hits / chars * 1000 if chars else 0,
        "每千字不确定性词": uncertainty_hits / chars * 1000 if chars else 0,
    }

ABSTRACT = ("本文提出一种基于检索增强的生成框架，通过混合检索与重排序机制提升上下文相关性，"
            "并在多任务评测上验证了该方法的有效性。实验表明，该框架在知识密集型任务上优于基线，"
            "注意力机制与稀疏自编码器的结合进一步改善了对齐表现。")
PLAIN = ("这项改造让答案更常引用到正确的文档。"
         "我们测了 300 个问题。"
         "错误率从 30% 降到约 16%。"
         "误差大约 ±4 个百分点。"
         "它像给助手换了一副更准的眼镜。"
         "但不一样的地方是：文档过期时，它照样会引错页面。"
         "所以引用要连日期一起看。")

print("① 可读性代理指标（同一份研究的两种写法）")
rows = [("论文摘要式", readability(ABSTRACT)), ("科普改写版", readability(PLAIN))]
keys = list(rows[0][1].keys())
print(f"  {'版本':<12} " + " ".join(f"{k:>12}" for k in keys))
for name, r in rows:
    print(f"  {name:<12} " + " ".join(f"{r[k]:>12.1f}" for k in keys))
print("  读法：科普版把平均句长与术语密度压下来，同时把数字与不确定性词提上去 ——")
print("        好的科普不是「更少信息」，而是「换一种信息结构」")

# ---------- 2) 理解度测试：小样本能发现什么问题、不能测量什么 ----------
def detect_prob(p_misunderstand: float, n: int) -> float:
    """n 个读者里至少一人误解的概率（用于说明小样本的用途）"""
    return 1 - (1 - p_misunderstand) ** n

def ci_width(p_hat: float, n: int) -> float:
    """误解率估计的 95% 置信区间半宽（Wald 近似）"""
    return 1.96 * math.sqrt(p_hat * (1 - p_hat) / n)

print("\n② 理解度测试的样本量：小样本用来「发现」，大样本用来「测量」")
print(f"  {'误解率':>8} {'n=5 至少一人误解':>18} {'n=10':>8} {'n=30':>8}")
for p in (0.1, 0.3, 0.5):
    print(f"  {p:>8.0%} {detect_prob(p, 5):>18.1%} {detect_prob(p, 10):>8.1%} "
          f"{detect_prob(p, 30):>8.1%}")
print(f"\n  {'观测误解率':>10} {'n=10 的 ±CI':>14} {'n=30':>10} {'n=300':>10}")
for p_hat in (0.1, 0.3, 0.5):
    print(f"  {p_hat:>10.0%} {ci_width(p_hat, 10):>13.1%} {ci_width(p_hat, 30):>10.1%} "
          f"{ci_width(p_hat, 300):>10.1%}")
print("  读法：n=10 时只要某段有 30% 误解率，就有 97% 概率被我们发现（够用）；")
print("        但要把误解率估准（±5% 以内）需要数百人 —— 所以先小样本找问题段落，")
print("        再用大样本测量改善幅度")

# ---------- 3) 类比质量检查：是否标注了失效边界 ----------
@dataclass
class Analogy:
    text: str
    has_boundary: bool
    maps_to_mechanism: bool     # 是否容易被误解为真实机制
def analogy_score(a: Analogy) -> Tuple[float, str]:
    score = 0.4
    score += 0.4 if a.has_boundary else 0.0
    score += 0.2 if not a.maps_to_mechanism else 0.0
    verdict = ("可用" if score >= 0.8 else
               "需补边界" if not a.has_boundary else "易误导，换一个")
    return score, verdict
ANALOGIES = [
    Analogy("像查字典时同时看很多词条，按相关度加权", False, True),
    Analogy("像查字典按相关度加权，但它不会真的查表，只是数学上的相似", True, True),
    Analogy("像给助手换了一副更准的眼镜；但文档过期时它照样引错页面", True, False),
]
print("\n③ 类比质量检查（是否标注失效边界、是否会被当成真实机制）")
for a in ANALOGIES:
    sc, verdict = analogy_score(a)
    print(f"  {sc:.1f}  {verdict:<12} {a.text}")
print("  读法：漂亮比喻最容易制造错误直觉 —— 把「不一样的地方」说出来，才是有用的类比")

# ---------- 4) 三版受众的骨架（同一份研究的三种承载结构） ----------
@dataclass
class Brief:
    audience: str
    decision: str
    claim: str
    number: str
    boundary: str
BRIEFS = [
    Brief("决策者", "要不要投这笔改造", "检索改造能把错误率降到约一半",
          "30% -> 16%（±4pp，n=300）", "只在我们测过的三类问题上验证过"),
    Brief("使用者", "怎么用才不出错", "带引用的回答更可信",
          "带引用时错误率约为不带引用的一半", "引用也可能指向过期文档，请核对日期"),
    Brief("同行", "结论是否可信", "混合检索 + 重排在知识密集型任务上优于基线",
          "全部指标与置信区间见附表", "存在评测集污染风险，外部效度有限"),
]
print("\n④ 三个版本的骨架（注意：主张、数字、边界三列都必须填）")
for b in BRIEFS:
    print(f"  [{b.audience}] 决策={b.decision}")
    print(f"      主张：{b.claim}")
    print(f"      数字：{b.number}")
    print(f"      边界：{b.boundary}")
print("  读法：任何一版如果不写「边界」，就等于把研究结论放大成普适承诺 —— ")
print("        这是科普最常见的伦理问题，也是最容易修的一处")
```

预期输出要点（实跑）：① 可读性代理显示科普版**平均句长与术语密度显著下降，而数字与不确定性词密度上升**（说明科普不是「删信息」，而是换结构）；② 理解度测试的样本量对照给出一个实用结论：**n=10 足以发现「某段 30% 的人误解」这类问题（97% 概率），但要把误解率估准到 ±5% 需要数百人**——先发现、后测量；③ 类比质量检查把「未标注失效边界」的比喻判为「需补边界」或「易误导」，直接把「漂亮比喻最容易制造错误直觉」变成可检查的规则；④ 三版骨架强制每一版都填「主张 / 数字 / 边界」三列，任何一版缺「边界」就是不可交付的。

## 常见追问

- **追问**：怎么给完全不懂技术的受众讲「对齐」？
  - 要点：先给**他们要做的决定**（「我们要不要让这个助手自动发邮件」），再给一句话主张（「它可能被恶意邮件诱导去做不该做的事」）、一个数字（"在我们测的 300 次攻击里，若不加限制有约七成会成功；加了收件人限制与审批后降到约 2%「）、一个带边界的类比（」像新员工会照着一封伪造的内部通知去办事——但不一样的是，它不会'怀疑'，所以必须靠流程限制"）。**全程不谈 RLHF**。
- **追问**：简化到什么程度算过度？
  - 要点：判据是**受众的决定是否被误导**。若简化让他们做出与完整信息下**不同**的决定，就是过度简化；反之（简化但决定相同）是成功的。这也是为什么必须做理解度测试，并专门问「你会因此做什么决定」。
- **追问**：怎么讲不确定性而不让受众觉得「你们自己也不确定，那我不做了」？
  - 要点：把不确定性**与行动绑定**：「结论在这个范围内可信 → 建议先在小范围上线并设回滚」；给出「什么情况下要停下」的判据。**不确定性 + 行动方案**比「确定性的乐观」更有说服力，也更诚实。
- **追问**：受众只想要一个数字怎么办？
  - 要点：给数字，但**随数字附三条**：口径（怎么算的）、样本量、适用范围。如果对方坚持只要数字，就在脚注里保留这三条——**不让数字脱离口径传播**是底线。
- **追问**：内部同事也需要科普吗？
  - 要点：需要，而且更难——同事会用「专业直觉」填补你没说的部分，导致**不同的心智模型**。做法：给同事的版本要显式写「这次我们**没有**改什么」和「哪些旧结论仍然成立」。
- **追问**：怎么评估一篇科普的长期效果？
  - 要点：看**决策质量**而不是阅读量：受众是否能说出边界、是否在后续讨论中引用正确口径、误解型提问是否减少；把常见误解固化成 FAQ 条目（下一次直接命中）。
