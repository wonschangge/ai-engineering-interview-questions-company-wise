## 一句话答案

> 文件共享系统的本质是**三套独立可伸缩的东西 + 一个权限模型**：
> ① **内容存储**（blob store）：按**内容哈希寻址**（content-addressed），天然去重、天然幂等、天然支持「同一文件多处引用只存一份」；
> ② **元数据服务**（metadata）：文件树/命名空间、版本、权限、共享关系——**这是唯一需要强一致的部分**，用关系库或强一致的 KV 存；
> ③ **分发层**（CDN/边缘）：读多写少的文件走边缘缓存，热文件不重复回源；
> ④ **权限模型**：主体（用户/组/链接）× 客体（文件/文件夹）× 动作（读/写/分享），加上**链接分享**（带过期、密码、下载次数、可撤销）——权限判定必须在**元数据层的唯一入口**做（不能靠客户端）。
> 再叠加三个工程要点：
> - **分块上传 + 断点续传**：大文件切成固定块并行上传，失败只重传该块（Range 请求的标准语义可引用的口径见 RFC 9110）；
> - **增量同步**：客户端与服务端各自维护版本向量/变更游标，只传差异块（不是「重新下载整个文件」）；
> - **不可变版本 + 墓碑删除**：每次修改产生新版本（内容寻址天然支持），删除是逻辑删除 + 后台回收，避免「边读边删」的竞态。
> 一句话判据：**内容层用哈希、元数据层用事务、分发层用缓存、权限层用单一入口**——四件事各自独立伸缩，才不会互相拖累。

## 面试官在考什么

- **是否区分内容与元数据**：绝大多数设计失误都源于把两者混在一起（例如把权限信息写进对象存储的路径里）。内容不可变、可去重、可最终一致；元数据可变、需强一致、需事务。
- **去重的量化**：内容寻址带来多少节省？能否给出估算（重复文件比例、块级去重收益、以及去重的**代价**：跨用户去重会带来侧信道泄露风险——这是一个高级要点）。
- **权限与共享的正确性**：链接分享如何撤销、权限变更如何**快速生效**（缓存 TTL 与主动失效）、如何防止越权（IDOR 类漏洞）、以及共享链接的**枚举攻击**（可猜测 id 导致泄露）。
- **同步与冲突**：两个设备同时改同一文件怎么办（版本 + 冲突副本，而不是静默覆盖）；大目录的增量同步如何做（游标 + 分页，可引用的分页约定见 AIP-158）。
- **大文件与网络现实**：分块大小、并行度、断点续传、校验（块级哈希 + 整文件哈希）、客户端限速（避免占满用户带宽）。
- **成本与分层**：热/温/冷分层（对象存储的存储类别）、生命周期策略、以及 CDN 回源成本。
- **与 LLM 产品的连接**：如果这是聊天产品的附件系统，还要考虑**索引管道**（上传 → 解析 → 分块 → 向量化）与权限过滤检索（串 [[anthropic-22]] 与 [[rag-08]]）。

**常见错误答案**

- 「存到 S3 + 挂个 CDN 就完了」——忽略元数据、权限、同步与去重。
- 用可猜测的自增 id 做分享链接——枚举即可拖库。
- 权限只在 UI 层做检查（后端不校验）。
- 把去重做到**跨租户**（节省了空间，却引入了「某人上传同一文件即可推断他人是否拥有该文件」的侧信道）。
- 增量同步靠「客户端上报 mtime」——时钟不可靠，必须用服务端版本号。

## 原理与推导

### 1. 架构分层

```
客户端（桌面/移动/Web）
  │ ① 分块上传（并行 + 断点续传 + 块级校验）
  ▼
接入层：鉴权 → 权限预检 → 配额（存储/流量）→ 限流
  │
  ▼
元数据服务（强一致）：命名空间、版本、权限、共享链接、变更游标
  │            └─ 权限判定唯一入口（所有读写都经它）
  ▼
内容存储（对象存储，内容哈希寻址）：块对象 + 清单（manifest）
  │
  ▼
分发层：CDN/边缘缓存（读取路径）＋ 预览/缩略图服务（异步生成）
  │
  ▼
异步管道：病毒扫描 → 文本抽取 → 索引/向量化 → 缩略图
```

**关键设计决策**：**上传路径与读取路径分离**——上传先写内容存储（拿到哈希），再在元数据服务里登记一个新版本（事务内）；读取先查元数据拿权限与清单，再从内容层或 CDN 取块。这样内容层永远不需要知道「谁有权限」。

### 2. 内容寻址与去重

- **文件 → 分块**（例如 4 MiB 固定块或内容定义分块 CDC）→ 每块计算哈希 → 清单（有序哈希列表）；
- **块级去重**：相同块只存一份（全局块存储），因此「同一文件复制 100 份」只占 1 份空间；文件小幅修改只产生 1 个新块（CDC 下更明显）；
- **去重粒度与安全的取舍**：

| 策略 | 节省 | 风险 |
| --- | --- | --- |
| 全局去重（跨用户） | 最大 | **侧信道**：上传已知文件可探测他人是否拥有该文件（「确认攻击」） |
| 租户内去重 | 较大 | 低 |
| 不做去重 | 无 | 存储成本高 |

**工程折中**：默认**租户内去重**；全局去重只用于「非敏感/公共」内容，或者要求上传者证明拥有完整内容（例如提供整文件哈希 + 足够长的随机盐）。

### 3. 权限模型

| 主体 | 客体 | 动作 | 说明 |
| --- | --- | --- | --- |
| 用户 | 文件/文件夹 | read/write/share/delete | 直接 ACL |
| 组/团队 | 文件夹 | read/write | 继承式（子文件继承父文件夹权限） |
| 匿名（链接） | 文件 | read（可选 write） | 链接即凭证：需不可枚举 + 可撤销 + 可过期 |

**继承与覆盖**：文件夹权限向下继承，子节点可**收紧**（不能放大）。判定顺序：显式拒绝 > 显式允许 > 继承允许 > 默认拒绝。

**链接分享的实现要点**：
- **不可枚举**：链接 id 用 128 位随机（不是自增 id、不是文件哈希——哈希会泄露内容），
- **可撤销**：链接是元数据里的一个实体（不是「把文件设成公开」），撤销即失效；
- **可过期/可限次数/可加密码**；
- **权限缓存**：CDN 与边缘必须尊重撤销——用**短 TTL + 主动失效**（或签名 URL，有效期即权限窗口）。

**签名 URL** 是分发层的标准做法：内容层只认签名（含资源 id、过期时间、权限范围），签名由元数据层在校验权限后签发——这样 CDN 不需要理解业务权限模型。

### 4. 同步与冲突

- **服务端权威版本号 + 客户端游标**：客户端持 `cursor`（上次同步到的变更位置），服务端返回增量变更（新增/修改/删除），客户端应用；分页用 `page_token`（串 [[anthropic-25]]）。
- **冲突检测**：写入时带 `base_version`，若服务端当前版本 ≠ `base_version` → 冲突 → **保留两个版本**（生成「冲突副本」）并让用户选择，而不是静默覆盖（数据丢失是共享系统最不可接受的故障）。
- **时钟不可信**：不要用客户端 mtime 判断新旧；一律用服务端单调版本号。

### 5. 大文件与网络

| 参数 | 取值建议 | 理由 |
| --- | --- | --- |
| 块大小 | 4–16 MiB | 太小 → 元数据与请求开销大；太大 → 重传代价高 |
| 并行上传 | 4–8 块 | 受客户端带宽与丢包影响 |
| 校验 | 每块哈希 + 整文件哈希 | 断点续传必须能验证「已传部分」正确 |
| 断点续传 | 服务端记录已接收块（会话 id） | 依赖 Range 语义（RFC 9110） |
| 重试 | 指数退避 + 抖动，块级重试 | 移动网络下抖动是必需的（串 [[anthropic-08]]） |

### 6. 分层存储与成本

| 层 | 访问频率 | 存储类别 | 取回成本 |
| --- | --- | --- | --- |
| 热 | 天级 | 标准对象存储 + CDN | 低 |
| 温 | 月级 | 低频访问 | 中 |
| 冷/归档 | 年级 | 归档类 | 高（分钟–小时级取回） |

**生命周期策略**：按最后访问时间自动下沉；**注意合规**（保留期限、法务保留 hold）与**用户预期**（「我的文件还在吗」）——下沉不应影响元数据可见性。

## 数值与代码验证

### 表 1：容量与去重收益（示例：100 万用户、人均 2,000 个文件、平均 1.5 MB）

| 项 | 算式 | 结果 |
| --- | --- | --- |
| 逻辑数据量 | $10^6\times2000\times1.5\text{ MB}$ | 3.0 PB |
| 无去重物理占用 | 同上（+ 版本开销） | 3.0 PB |
| 块级去重（假设 35% 重复率） | $3.0\times(1-0.35)$ | 1.95 PB |
| 3 副本/纠删码后 | 1.95 PB × 1.3（纠删码） | **约 2.5 PB** |
| 元数据（每文件 1 KB） | $2\times10^9\times1\text{ KB}$ | 2 TB（可分片） |

### 表 2：上传与同步的网络成本（1 GB 文件修改 1% 时）

| 方案 | 传输量 | 说明 |
| --- | --- | --- |
| 全量重传 | 1 GB | 原始方案 |
| 固定块增量（4 MiB 块） | 1 个块 = 4 MiB | 但「插入一个字节」会导致后续所有块变化 |
| **内容定义分块（CDC）** | 1–2 个块 ≈ 8 MiB | 插入/删除只影响局部，**增量同步的正确选择** |
| 只传元数据（改名/移动） | 若干 KB | 内容哈希未变，无需传内容 |

**读法**：CDC 相比固定块的价值在「编辑影响面局部化」——这是增量同步质量的核心。

### 可运行代码

```python
# 文件共享系统的四件事：块级去重与成本、CDC 增量、权限判定、签名 URL 的权限窗口
import hashlib, hmac, os, random, time
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Tuple

# 1) 内容寻址 + 块级去重：同一文件多份引用只存一次
class BlobStore:
    def __init__(self, block_size=4 * 1024 * 1024):
        self.block_size = block_size
        self.blocks: Dict[str, bytes] = {}
        self.logical_bytes = 0
        self.written_bytes = 0
    def put_file(self, data: bytes, cdc: bool = False) -> List[str]:
        chunks = cdc_chunks(data) if cdc else [data[i:i + self.block_size]
                                               for i in range(0, len(data), self.block_size)]
        hashes = []
        for c in chunks:
            h = hashlib.sha256(c).hexdigest()[:16]
            hashes.append(h)
            self.logical_bytes += len(c)
            if h not in self.blocks:                 # 去重：只有新块才真正写入
                self.blocks[h] = c
                self.written_bytes += len(c)
        return hashes
    def ratio(self) -> float:
        return self.written_bytes / self.logical_bytes if self.logical_bytes else 1.0

def cdc_chunks(data: bytes, min_size=2048, avg_size=4096, max_size=16384):
    """内容定义分块：滚动哈希遇到掩码边界就切（示意实现）"""
    MASK = avg_size - 1
    chunks, start, h = [], 0, 0
    for i, b in enumerate(data):
        h = ((h << 1) + b + 0x9E3779B1) & 0xFFFFFFFF
        size = i - start + 1
        if size >= min_size and (h & MASK) == 0 or size >= max_size:
            chunks.append(data[start:i + 1]); start = i + 1
    if start < len(data):
        chunks.append(data[start:])
    return chunks or [b""]

store = BlobStore()
rnd = random.Random(11)
base = bytes(rnd.getrandbits(8) for _ in range(200_000))
print("① 块级去重（固定块 4 MiB 太大，这里调小到 8 KiB 便于演示）")
s2 = BlobStore(block_size=8192)
for _ in range(5):
    s2.put_file(base[:])                      # 同一文件上传 5 次
print(f"  同一文件上传 5 次：逻辑 {s2.logical_bytes/1024:.0f} KiB -> "
      f"物理 {s2.written_bytes/1024:.0f} KiB（去重率 {s2.ratio():.1%}）")

# 2) CDC vs 固定块：在文件开头插入 1 字节后有多少块变化
def changed_blocks(old: bytes, new: bytes, mode: str) -> Tuple[int, int]:
    if mode == "fixed":
        bs = 8192
        a = [old[i:i+bs] for i in range(0, len(old), bs)]
        b = [new[i:i+bs] for i in range(0, len(new), bs)]
    else:
        a, b = cdc_chunks(old, 2048, 8192, 32768), cdc_chunks(new, 2048, 8192, 32768)
    ha = [hashlib.sha256(x).hexdigest()[:12] for x in a]
    hb = [hashlib.sha256(x).hexdigest()[:12] for x in b]
    sa, sb = set(ha), set(hb)
    return len(sb - sa), max(len(ha), len(hb))    # 新增块数 / 总块数

inserted = base[:1] + b"\x00" + base[1:]
for mode, label in (("fixed", "固定块 8 KiB"), ("cdc", "内容定义分块")):
    changed, total = changed_blocks(base, inserted, mode)
    print(f"\n② 开头插入 1 字节（{label}）：{total} 块中 {changed} 块变化 "
          f"-> 需重传 {changed/total:.1%}")
print("  读法：固定块在插入点之后「全线错位」，CDC 只影响局部 1–2 块 —— "
      "这就是增量同步必须用 CDC 的原因")

# 3) 权限判定：唯一入口 + 继承 + 显式拒绝优先
@dataclass
class Ace:
    subject: str          # "user:alice" / "group:eng" / "link:<token>"
    action: str           # read / write / share
    allow: bool
@dataclass
class Node:
    node_id: str
    parent: Optional[str] = None
    acls: List[Ace] = field(default_factory=list)

TREE: Dict[str, Node] = {}
def add_node(nid, parent=None, acls=()):
    TREE[nid] = Node(nid, parent, list(acls))
add_node("root")
add_node("eng", "root", [Ace("group:eng", "read", True)])
add_node("secrets", "eng", [Ace("group:eng", "read", False), Ace("user:bob", "read", True)])

def effective(node_id: str, subject: str, action: str, groups: Dict[str, List[str]]) -> bool:
    """从根到叶收集 ACE；显式拒绝优先于允许；默认拒绝"""
    chain, cur = [], node_id
    while cur:
        chain.append(TREE[cur]); cur = TREE[cur].parent
    chain.reverse()
    subjects = {subject} | {f"group:{g}" for g in groups.get(subject, [])}
    decision = None
    for node in chain:
        for ace in node.acls:
            if ace.action == action and ace.subject in subjects:
                decision = ace.allow          # 后出现的（更靠近叶子）覆盖
    return bool(decision)

groups = {"user:alice": ["eng"], "user:bob": ["eng", "security"]}
print("\n③ 权限判定（显式拒绝优先 + 就近覆盖）")
for subject, node in (("user:alice", "eng"), ("user:alice", "secrets"),
                      ("user:bob", "secrets"), ("user:carol", "eng")):
    ok = effective(node, subject, "read", groups)
    print(f"  {subject:<12} 读 {node:<8} -> {'允许' if ok else '拒绝'}")

# 4) 签名 URL：把「权限窗口」交给内容层，CDN 无需理解业务权限
SECRET = b"demo-signing-key"
def sign(resource: str, expires_at: int, scope: str = "read") -> str:
    msg = f"{resource}|{expires_at}|{scope}".encode()
    return hmac.new(SECRET, msg, hashlib.sha256).hexdigest()[:32]
def verify(resource: str, expires_at: int, sig: str, scope: str = "read", now: Optional[int] = None) -> str:
    now = now or int(time.time())
    if now > expires_at:
        return "expired"
    if not hmac.compare_digest(sig, sign(resource, expires_at, scope)):
        return "bad_signature"
    return "ok"
now = int(time.time())
url_sig = sign("file/abc123", now + 300)
print("\n④ 签名 URL（内容层只认签名，权限撤销 = 缩短有效期 + 元数据层拒绝续签）")
print(f"  有效期内: {verify('file/abc123', now + 300, url_sig, now=now)}")
print(f"  过期后:   {verify('file/abc123', now + 300, url_sig, now=now + 301)}")
print(f"  被篡改:   {verify('file/abc999', now + 300, url_sig, now=now)}")
print("  读法：签名把「谁有权」转成「这张凭证在何时之前有效」——CDN 不需要查权限库；")
print("        撤销通过「短 TTL + 主动失效」实现，TTL 就是权限的暴露窗口")

# 5) 冲突检测：base_version 不匹配则生成冲突副本，绝不静默覆盖
@dataclass
class Version:
    v: int
    content_hash: str
class Conflict(Exception): pass
def write(node: str, base_version: int, new_hash: str, server_version: Dict[str, Version]):
    cur = server_version.get(node, Version(0, ""))
    if cur.v != base_version:
        raise Conflict(f"服务端版本 {cur.v} ≠ 客户端基线 {base_version} -> 生成冲突副本")
    server_version[node] = Version(cur.v + 1, new_hash)
    return f"写入成功，新版本 v{cur.v + 1}"
sv: Dict[str, Version] = {}
print("\n⑤ 冲突检测")
print(" ", write("doc1", 0, "h1", sv))
print(" ", write("doc1", 1, "h2", sv))
try:
    write("doc1", 0, "h3", sv)          # 另一个设备基于旧版本写入
except Conflict as e:
    print("  Conflict:", e)
print("  读法：宁可让用户选，也不要静默覆盖 —— 共享系统的第一原则是不丢数据")
```

预期输出要点（实跑）：① 同一文件上传 5 次，逻辑 977 KiB 只占物理 195 KiB（**去重率 20%**，即节省 80%）；② 在文件开头插入 1 字节，**固定块方案全部 25 块都变化（100%）**，而**CDC 只有 1 块变化（4%）**——这是增量同步必须用内容定义分块的直接证据；③ 权限判定显示 `user:alice` 能读 `eng` 但**被 `secrets` 上的显式拒绝挡住**，而 `user:bob` 因显式允许可读；④ 签名 URL 在有效期内通过、过期与篡改都被拒（权限暴露窗口 = TTL）；⑤ 冲突检测在 `base_version` 不匹配时抛错并生成冲突副本，而不是覆盖。

## 常见追问

- **追问**：跨租户去重的侧信道到底怎么泄露？
  - 要点：攻击者上传一个「猜测内容」的文件；若系统返回「已存在（去重）」，就证明**别人已有该文件**。这可以用于确认（例如确认某公司是否持有某份机密文档）。缓解：租户内去重、要求证明拥有完整内容、对「秒传」接口做权限与限流约束。
- **追问**：撤销共享链接后，已经分发的签名 URL 怎么办？
  - 要点：签名 URL 的有效期就是**最大暴露窗口**，所以 TTL 要短（分钟级）；对高敏感资源用「短 TTL + 每次访问回源校验 + 主动失效缓存」；接受「已下载的副本无法收回」这一事实（要写进产品说明）。
- **追问**：大目录（十万文件）首次同步怎么做？
  - 要点：游标 + 分页（`page_token`）+ 只返回元数据；客户端按需拉取内容（懒加载）；对超大目录提供「按需同步/选择性同步」（否则首次同步要下 TB 级数据）。
- **追问**：怎么防止上传恶意文件？
  - 要点：异步病毒扫描（**在可分享之前完成**，而不是「扫描后置」）、内容类型嗅探（不要信扩展名）、预览渲染隔离（在沙箱里渲染 PDF/Office，防解析器漏洞）、对可执行文件默认禁止分享。
- **追问**：附件要接 RAG，怎么处理权限？
  - 要点：索引时把**权限元数据一起写入**，检索时按用户权限过滤（**检索前过滤**，不是检索后再删——后者会泄露「存在但你看不到」的信息并浪费算力）；权限变更要触发索引侧的可见性更新（串 [[rag-08]]）。
- **追问**：成本怎么压？
  - 要点：① 去重（租户内）；② 生命周期下沉（按最后访问时间）；③ CDN 命中率（热文件）；④ 缩略图/预览按需生成并缓存；⑤ 纠删码替代多副本（跨区容灾用 1.3–1.5× 而非 3×）。
