# Anthropic 面试题库

Anthropic 的面试有一个很鲜明的特征：**它把「你会怎么做工程判断」当成主要考点**。同一个问题常常在一次面试里被追加两三次需求（限流器要加突发、要加权重；爬虫要从同步改成异步；调度器要加优先级与重试），
看的是你在**需求演进时如何不把代码和设计搞烂**；系统设计题则几乎都会落到「p99 与利用率怎么平衡」「幻觉投诉的前 48 小时做什么」这类**真实约束**上。

三十七道题里，实现题十道（含三道 SQL）、模型与推理七道、系统设计与应用八道、Agent 与安全六道、评估与行为六道。
这个比例本身就是信息：**Anthropic 不太考偏题怪题，但会反复追问「你的依据是什么、代价是什么、怎么验证」。**

## 这家公司的面试怎么准备

**第一，接受「需求会追加」这件事。** 01、05、07 三道实现题都是同一个模式：先给一个能跑的版本，然后追加两三次需求。准备方式是**刻意练习「改需求时只动该动的地方」**——接口稳定、算法可替换，是这类题的核心评分点。

**第二，所有系统设计题都要能算账。** 这个题库里几乎每道设计与架构题都有一条可算的判据：roofline 拐点（295 FLOPs/byte）、KV 每 token 字节数（320 KiB）、batching 平坦区上界（由 KV 读取决定）、准入控制对成功数的影响（+27%）、缓存带来的相对成本（0.13）。**「我觉得」在这类题里没有分，「按这台机器的常数算下来是」才有分。**

**第三，安全题要落到机制，不要停在态度。** 28、30、31 三题的共同要求是：把「我重视安全」翻译成**可执行的机制**（权限白名单、出网控制、分级发布、回滚清单、门禁条目带阈值与样本量与否决权）。这也是这家公司面试最明显的取向。

**第四，行为题要用数字和机制说话。** 34、36 两题考的是**决策密度与复盘质量**，不是经历大小；35、37 考的是**判断是否可讨论、可被证据修正**。这几题共同的失分点是「只有立场、没有可检验的内容」。

**第五，有一类问题会反复出现：不确定性的表达。** 从 08（限流与退避）、17（p99 与利用率）到 27（统计功效）、31（金丝雀判据），面试官反复在测同一件事——**你会不会在样本不足时宣称结论**。这个题库里相关题目都给了可运行的统计口径，值得逐条跑一遍。
