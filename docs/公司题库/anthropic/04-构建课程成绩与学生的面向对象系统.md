## 一句话答案

> 这类「面向对象建模」题考的不是继承层次画得多漂亮，而是**你能否先钉住领域不变量，再让结构服务于变化**。四步：
> ① **分清实体与值对象**：`Student`/`Course` 是实体（有身份、生命周期）；`Grade`（分值 + 权重 + 类型）、`Term`、`StudentId` 是值对象（不可变、按值相等）。
> ② **把关联建模成关联实体**：选课是 `Enrollment`（学生 × 课程 × 学期），它承载成绩与状态；**不要让成绩挂在学生或课程上**（否则重修、转学分、同一课程多学期都会打架）。
> ③ **把会变的规则抽成策略**：评分方案（加权/取最高/替换重修）、GPA 换算、舍入规则都是策略对象，而不是 `if school == 「x」` 的分支。
> ④ **不变量集中在构造与唯一入口**：分数范围 $[0,100]$、权重之和为 1、先修课满足、容量不超——在 `__post_init__` 或工厂方法里校验，而不是散落在调用点。
> 一句话原则：**用组合表达「有什么」，用策略表达「怎么算」，用不变量守住正确性**；继承只用于真正同质的子类型（例如 `LetterGrade` 与 `NumericGrade` 作为成绩的两种表示）。

## 面试官在考什么

- **建模顺序**：会不会先问清语义（成绩是百分制还是等级制？重修怎么算？GPA 是否按学分加权？）再动笔。上来就写三个类并互相引用的，通常在追问「重修」时崩掉。
- **实体 vs 值对象的意识**：能否说出「两个学号相同的学生是同一实体，但两条成绩记录值相等就是重复」。
- **不变量的处理**：分数边界、权重归一化、容量限制、时间区间不重叠（学期/选课时间）——这些必须被显式校验，且**失败要给出可诊断的错误**。
- **扩展点识别**：新增「等级制转百分制」「不同 GPA 算法」「课程替换」时，改动应该局限在**新增一个策略类 + 配置**，而不是改动核心实体。
- **精度与舍入**：分数与 GPA 用**十进制定点**（可引用 Python `decimal` 的定位）；舍入策略（四舍五入 vs 银行家舍入）必须显式，因为成绩申诉常常就发生在 89.5 这种边界上。
- **可测试性**：能否给出关键测试用例（边界分数、空选课、重复重修、权重不为 1）。

**常见错误答案**

- 用继承表达角色（`Student` → `GraduateStudent` → `PhDStudent`）——角色会变、会叠加，应该用组合或属性。
- 把成绩直接挂在 `Student` 上（`student.grades[course] = 90`）——无法表达多学期与重修历史。
- 用二进制浮点存分数并直接比较（`0.1 + 0.2 != 0.3`）——成绩系统里这是真实事故源。
- 不校验权重之和，GPA 计算时静默按未归一化权重求和。
- 把持久化逻辑写进实体（`student.save()`）——实体与存储耦合，无法测试、无法替换存储。

## 原理与推导

### 1. 领域模型（实体 / 值对象 / 关联）

| 概念 | 类别 | 身份 | 关键字段 |
| --- | --- | --- | --- |
| `Student` | 实体 | `StudentId` | 姓名、入学学期、状态 |
| `Course` | 实体 | `CourseCode` | 名称、学分、先修课、容量 |
| `Enrollment` | 关联实体 | `(StudentId, CourseCode, Term)` | 状态、成绩、尝试次数 |
| `Grade` | 值对象 | 按值 | 分值（Decimal）、类型、权重 |
| `GradingScheme` | 策略 | 按名注册 | 权重、舍入、换算规则 |
| `Transcript` | 聚合视图 | 按学生 | 由 Enrollments 派生（不落库） |

**关键决定**：`Transcript`（成绩单）是**派生视图**而不是数据源——数据源永远是 `Enrollment` 集合。这条决定让「重修」「替换」「审计」都变成对关联的查询，而不是对成绩单的修补。

### 2. 不变量清单（必须显式校验）

1. `0 <= score <= 100`（或等级制枚举内）；
2. `sum(weights) == 1`（用 Decimal 精确比较，或在方案构造时归一化）；
3. 同一 `(student, course, term)` 至多一条 `Enrollment`；
4. 选课容量 `len(enrollments(course, term)) <= course.capacity`；
5. 先修课必须已通过；
6. 学期区间不重叠、且 `enroll_term >= student.enroll_term`；
7. 舍入规则与显示精度在方案里声明（避免各处 `round()`）。

### 3. GPA 计算：策略 + 精度

加权 GPA：

$$\text{GPA}=\frac{\sum_i w_i\cdot g(s_i)\,c_i}{\sum_i w_i\,c_i}$$

其中 $s_i$ 是课程的百分制成绩、$g(\cdot)$ 是百分制到绩点的换算（各校不同）、$c_i$ 是学分、$w_i$ 是权重（重修替换时可设为 0 或 1）。**三个变化点**——$g$ 的换算表、重修策略、舍入规则——都应该可替换。

**精度纪律**：金额/分数用 `Decimal`；舍入显式声明（`ROUND_HALF_UP` vs `ROUND_HALF_EVEN`）；对外显示与内部存储精度分离（内部保留 2 位，显示按方案裁剪）。边界案例：89.45 在两位精度下按 `ROUND_HALF_UP` 是 89.5 → 若绩点表以 90 为 A 档，这位学生的申诉就会发生在这里——所以**舍入与分档必须在同一处定义**。

### 4. 扩展点与设计取舍

| 变化需求 | 差的设计 | 好的设计 |
| --- | --- | --- |
| 新增等级制 | 在各处 `if` 判断 | `Grade` 的两个子类型 + `to_numeric()` 策略 |
| 不同 GPA 算法 | 复制一份计算函数 | 注入 `GpaPolicy` |
| 重修替换 | 在成绩单上覆盖 | `Enrollment.attempt` + `RetakePolicy` 生成派生权重 |
| 转学分 | 伪造一条选课 | `Enrollment.source = TRANSFER` + 校验规则放宽 |
| 换存储 | 改实体方法 | `Repository` 接口 |

**过度抽象的反例**：给 `Grade` 引入泛型化的「可加权可换算可审计值」接口，只有两种实现——面试里要主动指出「这里不值得抽象」，这比多写两个接口更能体现判断力。

## 数值与代码验证

### 表 1：两种舍入策略的差异只出现在「恰好半值」处

| 原始分（3 位小数） | `ROUND_HALF_UP` | `ROUND_HALF_EVEN` | 差异原因 |
| --- | --- | --- | --- |
| 89.445 | 89.45 | **89.44** | 丢弃位恰为 5，且前一位 4 是偶数 → 银行家舍入不进位 |
| 89.455 | 89.46 | 89.46 | 丢弃位恰为 5，前一位 5 是奇数 → 进位（两者一致） |
| 89.444 | 89.44 | 89.44 | 丢弃位 < 5，无差异 |
| 89.450 | 89.45 | 89.45 | **已是两位小数，`quantize` 不触发任何舍入** |

**读法**：两种策略的差异只在「恰好半值且前一位为偶数」时出现（第一行）；而 89.45 这种本身就只有两位小数的分数，**任何舍入模式都不会改变它**——所以成绩分档争议通常来自「计算过程中产生三位以上小数」（例如加权求和 $0.4\times89.4+0.6\times89.475=89.445$），而不是来自最后一步。工程结论：**把精度与舍入写进评分方案，并且在加权求和的输出处显式 quantize**。

### 表 2：不变量与测试用例对照

| 不变量 | 测试用例 | 期望 |
| --- | --- | --- |
| 分数范围 | `Grade(-1)` / `Grade(101)` | 抛错，错误信息含合法范围 |
| 权重和为 1 | `Scheme([(0.3, 「作业」), (0.3, 「考试」)])` | 抛错或自动归一化（策略声明） |
| 选课唯一 | 同学期同课程两次选课 | 抛错，提示已存在 |
| 容量上限 | 容量 2 的第 3 人 | 抛错，提示容量已满 |
| 先修课 | 未修先修课直接选课 | 抛错，列出缺失先修课 |

### 可运行代码

```python
# 领域模型 + 不变量 + GPA 策略 + 精度处理（可直接跑）
from dataclasses import dataclass, field
from decimal import Decimal, ROUND_HALF_UP, ROUND_HALF_EVEN, getcontext
from typing import Dict, List, Optional, Sequence

getcontext().prec = 28
TWO = Decimal("0.01")

class DomainError(ValueError):
    pass

@dataclass(frozen=True)
class StudentId:
    value: str
    def __post_init__(self):
        if not self.value or not self.value.isalnum():
            raise DomainError(f"学号必须是字母数字：{self.value!r}")

@dataclass(frozen=True)
class Grade:
    """值对象：百分制成绩（Decimal，避免二进制浮点误差）"""
    score: Decimal
    def __post_init__(self):
        if not (Decimal(0) <= self.score <= Decimal(100)):
            raise DomainError(f"分数必须在 [0,100]，得到 {self.score}")

@dataclass(frozen=True)
class Enrollment:
    """关联实体：学生 × 课程 × 学期（成绩挂在这里，不挂在学生或课程上）"""
    student: StudentId
    course: str
    term: str
    credits: Decimal
    grade: Optional[Grade] = None
    attempt: int = 1

class GpaPolicy:
    """百分制 -> 绩点的换算策略（可替换）"""
    TABLE = [(Decimal(90), Decimal("4.0")), (Decimal(85), Decimal("3.7")),
             (Decimal(82), Decimal("3.3")), (Decimal(78), Decimal("3.0")),
             (Decimal(75), Decimal("2.7")), (Decimal(72), Decimal("2.3")),
             (Decimal(68), Decimal("2.0")), (Decimal(64), Decimal("1.5")),
             (Decimal(60), Decimal("1.0"))]
    def point(self, score: Decimal) -> Decimal:
        for cut, pt in self.TABLE:
            if score >= cut:
                return pt
        return Decimal("0.0")

class RetakePolicy:
    """重修策略：全部计入 / 只取最高 / 只取最新"""
    def __init__(self, mode: str = "highest"):
        if mode not in {"all", "highest", "latest"}:
            raise DomainError(f"未知重修策略：{mode}")
        self.mode = mode
    def select(self, attempts: Sequence[Enrollment]) -> List[Enrollment]:
        graded = [e for e in attempts if e.grade is not None]
        if not graded or self.mode == "all":
            return list(graded)
        key = (lambda e: e.grade.score) if self.mode == "highest" else (lambda e: e.attempt)
        best = max(graded, key=key)
        return [best]

class GradingScheme:
    """评分方案：权重 + 舍入规则；权重必须和为 1（Decimal 精确比较）"""
    def __init__(self, weights: Dict[str, Decimal], rounding: str = "half_up"):
        total = sum(weights.values(), Decimal(0))
        if total != Decimal(1):
            raise DomainError(f"权重之和必须为 1，得到 {total}")
        self.weights = dict(weights)
        self.rounding = {"half_up": ROUND_HALF_UP, "half_even": ROUND_HALF_EVEN}[rounding]
    def final(self, components: Dict[str, Decimal]) -> Grade:
        missing = set(self.weights) - set(components)
        if missing:
            raise DomainError(f"缺少评分项：{sorted(missing)}")
        raw = sum(components[k] * w for k, w in self.weights.items())
        return Grade(raw.quantize(TWO, rounding=self.rounding))

class Course:
    def __init__(self, code: str, credits: Decimal, capacity: int, prereqs: Sequence[str] = ()):
        self.code, self.credits, self.capacity, self.prereqs = code, credits, capacity, list(prereqs)

class Registrar:
    """聚合根：守住选课不变量，并派生成绩单（GPA 不在实体里硬编码）"""
    def __init__(self, gpa: GpaPolicy, retake: RetakePolicy):
        self.courses: Dict[str, Course] = {}
        self.enrollments: List[Enrollment] = []
        self.gpa, self.retake = gpa, retake

    def add_course(self, c: Course) -> None:
        self.courses[c.code] = c

    def _passed(self, sid: StudentId, code: str) -> bool:
        return any(e.student == sid and e.course == code and e.grade and e.grade.score >= 60
                   for e in self.enrollments)

    def enroll(self, sid: StudentId, code: str, term: str) -> Enrollment:
        if code not in self.courses:
            raise DomainError(f"课程不存在：{code}")
        c = self.courses[code]
        if any(e.student == sid and e.course == code and e.term == term for e in self.enrollments):
            raise DomainError(f"{sid.value} 已在 {term} 选过 {code}")
        missing = [p for p in c.prereqs if not self._passed(sid, p)]
        if missing:
            raise DomainError(f"缺少先修课：{missing}")
        current = [e for e in self.enrollments if e.course == code and e.term == term]
        if len(current) >= c.capacity:
            raise DomainError(f"{code} 在 {term} 已满（容量 {c.capacity}）")
        attempt = 1 + sum(1 for e in self.enrollments if e.student == sid and e.course == code)
        e = Enrollment(sid, code, term, c.credits, attempt=attempt)
        self.enrollments.append(e)
        return e

    def set_grade(self, sid: StudentId, code: str, term: str, score: Decimal) -> Enrollment:
        """Enrollment 是不可变值对象，改分 = 替换列表里的那一条（保留审计友好的不可变语义）"""
        for i, e in enumerate(self.enrollments):
            if e.student == sid and e.course == code and e.term == term:
                self.enrollments[i] = Enrollment(e.student, e.course, e.term, e.credits,
                                                 grade=Grade(score), attempt=e.attempt)
                return self.enrollments[i]
        raise DomainError(f"未找到选课记录：{sid.value} {code} {term}")

    def transcript(self, sid: StudentId) -> List[Enrollment]:
        mine = [e for e in self.enrollments if e.student == sid]
        by_course: Dict[str, List[Enrollment]] = {}
        for e in mine:
            by_course.setdefault(e.course, []).append(e)
        out = []
        for code, attempts in by_course.items():
            out.extend(self.retake.select(attempts))
        return sorted(out, key=lambda e: (e.term, e.course))

    def gpa_of(self, sid: StudentId) -> Decimal:
        rows = [e for e in self.transcript(sid) if e.grade is not None]
        if not rows:
            return Decimal("0.00")
        num = sum(self.gpa.point(e.grade.score) * e.credits for e in rows)
        den = sum(e.credits for e in rows)
        return (num / den).quantize(TWO, rounding=ROUND_HALF_UP)

# ---- 演示与断言 ----
reg = Registrar(GpaPolicy(), RetakePolicy("highest"))
reg.add_course(Course("CS101", Decimal(4), capacity=2))
reg.add_course(Course("CS201", Decimal(3), capacity=5, prereqs=["CS101"]))
a, b, c = StudentId("S1"), StudentId("S2"), StudentId("S3")

reg.enroll(a, "CS101", "2026F"); reg.enroll(b, "CS101", "2026F")
try:
    reg.enroll(c, "CS101", "2026F")
except DomainError as e:
    print("容量不变量：", e)
try:
    reg.enroll(c, "CS201", "2026F")
except DomainError as e:
    print("先修不变量：", e)
try:
    Grade(Decimal("101"))
except DomainError as e:
    print("范围不变量：", e)
try:
    GradingScheme({"作业": Decimal("0.3"), "考试": Decimal("0.3")})
except DomainError as e:
    print("权重不变量：", e)

scheme = GradingScheme({"作业": Decimal("0.4"), "考试": Decimal("0.6")})
edge = Decimal("89.4") * Decimal("0.4") + Decimal("89.475") * Decimal("0.6")
print("加权求和产生三位小数：", edge)
print("  half_up   ->", scheme.final({"作业": Decimal("89.4"), "考试": Decimal("89.475")}).score)
print("  half_even ->",
      GradingScheme({"作业": Decimal("0.4"), "考试": Decimal("0.6")}, rounding="half_even")
      .final({"作业": Decimal("89.4"), "考试": Decimal("89.475")}).score)
print("  已是两位小数的 89.45 不会被任何模式改变：",
      GradingScheme({"作业": Decimal("1.0")}, rounding="half_even").final({"作业": Decimal("89.45")}).score)

# 重修取最高：先录首次成绩，再重修；成绩单只保留最高
reg.set_grade(a, "CS101", "2026F", Decimal(58))     # 首次不及格
e2 = reg.enroll(a, "CS101", "2027F")                # 重修（attempt=2）
reg.set_grade(a, "CS101", "2027F", Decimal(92))     # 重修通过
reg.enroll(a, "CS201", "2027F")                     # 先修课此时已满足
print("重修后成绩单：",
      [(e.course, str(e.grade.score), f"attempt={e.attempt}") for e in reg.transcript(a)])
print("GPA（只取最高分，CS101 4 学分 + CS201 3 学分）：", reg.gpa_of(a))
```

预期输出要点（本机实跑结果）：四条不变量各抛出可读错误（容量已满、缺少先修课、分数越界、权重和为 0.6）；加权求和产生三位小数 `89.445`，`half_up` 得 **89.45**、`half_even` 得 **89.44**——这就是分档争议的真实来源；而本身已是两位小数的 `89.45` 在两种模式下都是 `89.45`（`quantize` 不触发舍入）；重修后成绩单里同一课程只保留最高分（`attempt=2`、92 分），GPA 按学分加权得 **4.00**（未出成绩的课程不计入 GPA）。这三点正是「值对象不可变 + 策略可替换 + 精度显式」三个设计决定的直接回报。

## 常见追问

- **追问**：重修、转学分、免修怎么统一处理？
  - 要点：都用 `Enrollment` 的**来源与尝试属性**表达（`source ∈ {NORMAL, TRANSFER, EXEMPT}`、`attempt`），由策略决定它们在 GPA 中的权重；不要新增平行的数据结构。
- **追问**：并发选课怎么保证不超容量？
  - 要点：聚合根内串行 + 数据库层的唯一约束/条件更新（`UPDATE ... WHERE enrolled < capacity`）或乐观锁（版本号）；只在应用层加锁在多实例下无效。
- **追问**：成绩变更要不要审计？
  - 要点：要。成绩是**强审计对象**：append-only 变更日志（谁、何时、旧值、新值、原因），当前值由日志派生或加版本号；这也是「成绩单是派生视图」这一设计的延伸。
- **追问**：为什么不用继承做角色（本科生/研究生/博士生）？
  - 要点：角色会变、可叠加（助教 + 学生），继承会把变化固化到类型层次里；用组合（`roles: set[Role]`）或策略更合适。
- **追问**：怎么测试这类系统？
  - 要点：不变量驱动的用例（上表 2）+ 属性测试（随机选课序列后校验不变量）+ 策略的可替换测试（同一输入在两种重修策略下结果不同）；可引用的方法论背景见 TDD 条目。
- **追问**：如果需求是「每 10 分钟加一条」，你怎么避免代码失控？
  - 要点：与 [[anthropic-07]] 同一答案——把变化点收敛到策略与配置（评分方案、换算表、重修策略、存储），核心实体只守住不变量。
