## 一句话答案

> 这是一道**「定义契约 → 写状态机 → 处理畸形输入」**的解析题。三步：
> ① **先钉输出契约**：事件是什么字段（`kind`、`id`、`parent_id`、`depth`、`symbol`、`ts`/`seq`、`raw`）、顺序如何（按开始时间排序还是按结束时间）、以及**配对规则**（同名函数出现两次算不算同一帧）。
> ② **用一个显式栈解析**（不要递归）：遇到帧开始压栈并发出 `start`，遇到帧结束弹栈并发出 `end`；`depth` 就是栈深，`parent_id` 是栈顶。
> ③ **畸形输入是一等公民**：缺 `end`（栈里还有剩余）、多余的 `end`（栈已空）、缩进跳跃（深度从 1 直接到 3）、以及**交错的并发栈**——每一种都要有明确的策略（自动闭合 / 丢弃并告警 / 分组解析）并在输出里标记。
> 一句话原则：**解析器的价值不在于解析正常输入，而在于对畸形输入的确定行为**——因为真实日志永远是脏的。

## 面试官在考什么

- **契约先行**：会不会先问「输入的栈是什么格式」「是否带时间戳」「是否需要保留原始行」；以及在什么情况下下游需要「按开始排序」而不是「按结束排序」。
- **状态机的鲁棒性**：显式栈 + 未闭合处理 + 重复闭合检测，是这道题的核心；用递归下降的实现在「深度上千」或「畸形嵌套」时会崩或栈溢出。
- **深度语义**：`depth` 来自缩进还是来自栈？两者不一致时（缩进跳跃）信谁？——必须显式选择并说明理由（通常**信缩进**，因为它是日志里唯一的层级来源，但要校验连续性）。
- **并发/交错**：多线程日志或协程日志的栈会交错，需要按 thread/trace id 分组后再各自建栈；能否主动提出这一点是区分度。
- **可验证性**：能否给出覆盖六类输入的测试用例，并断言输出的事件序列（而不是「看起来对」）。
- **下游用途**：事件流通常用于火焰图/耗时分析——所以「配对的持续时间」与「未闭合帧如何处理时长」需要明确（可引用的背景：火焰图正是由 start/end 区间构成的层级视图）。

**常见错误答案**

- 递归解析缩进——深度大时栈溢出，且畸形输入容易漏处理。
- 只按缩进比较，不做连续性校验——缩进跳跃会产生「幽灵父帧」。
- 遇到多余 `end` 就崩溃——真实日志里这很常见，应该丢弃并计数告警。
- 不区分「未闭合帧」与「持续到日志结束的帧」——两者的时长语义完全不同。

## 原理与推导

### 1. 输入与输出的契约

输入（嵌套栈的一种常见形态，缩进即层级）：

```
main                      # depth 0
  handle_request          # depth 1
    parse_json            # depth 2
    validate_schema       # depth 2
  send_response           # depth 1
```

输出事件流（每条 `start` 与 `end` 成对，带唯一 id 与父子关系）：

| 字段 | 含义 |
| --- | --- |
| `kind` | `start` 或 `end` |
| `id` | 帧唯一 id（自增或 `parent_id#序号`） |
| `parent_id` | 父帧 id（根为 `null`） |
| `depth` | 栈深（0 起） |
| `symbol` / `raw` | 函数名与原始行 |
| `seq` | 事件序号（保证顺序稳定） |
| `synthetic` | 该 `end` 是否为补出来的（畸形输入标记） |

**顺序选择的依据**：火焰图与耗时分析需要「区间」——所以按 `start` 的正序 + 同一时刻 `end` 在 `start` 之前（LIFO）输出；而增量处理（流式消费）更希望 `end` 先到。面试里说清「我按 LIFO 语义输出，并提供按 `end` 排序的视图」即可。

### 2. 状态机（显式栈）

```
state: stack = []          # 每个元素: {id, depth, symbol}
for line in lines:
    if blank/comment: continue
    d, sym = parse(line)                  # 缩进 -> depth, 文本 -> symbol
    if d > len(stack):                    # 缩进跳跃：畸形
        emit_warning("indent jump", line)
        d = len(stack)                    # 策略：钳制到当前栈深（或补空帧）
    while len(stack) > d:                 # 回退：为超出的帧补 end
        f = stack.pop(); emit(end, f, synthetic=was_missing)
    f = push(id, d, sym); emit(start, f)
# 文件结束：剩余栈全部补 end（标记 synthetic）
while stack: f = stack.pop(); emit(end, f, synthetic=True)
```

**三种畸形与策略**：

| 畸形 | 检测 | 策略 |
| --- | --- | --- |
| 缩进跳跃（$d>\text{depth}+1$） | 解析后比较 | 钳制到当前栈深 + 告警计数（也可选择补空帧，需与下游约定） |
| 多余 `end`（如显式 `</frame>` 标记而栈已空） | 栈空时收到 end | 丢弃 + 计数告警（**不要抛异常中断整条流**） |
| 未闭合（文件结束仍有栈） | 循环结束检查 | 补 `end` 并标 `synthetic=true`；时长语义标注为「到日志结束」 |

### 3. 并发/交错栈的分组

真实系统日志常带 `thread` 或用 `async` 任务 id。处理方式：**先按分组键切成多条流，再各自跑同一状态机**，最后按全局 `seq` 合并输出。若日志没有分组键但确实交错（例如两个栈的缩进互相穿插），只能启发式分组（按符号前缀/时间间隔），并明确标注「分组可能不准确」。

### 4. 复杂度的现实约束

- 单行解析：正则或手写扫描（可引用 Python `re` 的定位），$O(\text{行长})$；
- 整体：$O(\text{行数})$ 时间、$O(\text{最大深度})$ 空间（栈）——这正是**不用递归**的价值：深度由输入决定，栈空间可控且不会爆调用栈；
- 大文件：流式逐行处理（生成器），不要一次读入内存；输出也建议流式（生成器/回调）。

### 5. 下游用途决定了几个细节

| 用途 | 需要保证 |
| --- | --- |
| 火焰图 | 区间层级正确（`start`/`end` 配对）、同名帧不合并 |
| 耗时分析 | 未闭合帧的时长要标注口径（否则统计被低估/高估） |
| 采样剖析转换 | 允许「只有 start 没有 end」的采样语义（此时不补 end，标记 `open`） |
| 审计/回放 | 保留 `raw` 原始行与 `seq`，保证可回放 |

## 数值与代码验证

### 表 1：六类输入的期望行为

| 输入类型 | 期望输出 | 关键断言 |
| --- | --- | --- |
| 正常嵌套 | 配对完整的 start/end | $\#start=\#end$，深度序列合法 |
| 缩进跳跃 | 钳制 + 告警 | 告警计数 = 1，深度不出现跳跃 |
| 未闭合 | 补 end（`synthetic=true`） | 最后一条 end 的 `synthetic` 为真 |
| 冗余 end | 丢弃 + 告警 | 事件数不变，告警计数 = 1 |
| 空行/注释 | 忽略 | 不产生事件 |
| 交错并发栈 | 分组后各自配对 | 每组的 start/end 各自平衡 |

### 表 2：递归 vs 显式栈（深度 10,000 的输入，示意）

| 实现 | 空间 | 风险 | 结论 |
| --- | --- | --- | --- |
| 递归下降 | 调用栈 $O(\text{深度})$ | Python 默认递归上限（约 1000）→ `RecursionError` | 不可用 |
| 显式栈 | 堆上 $O(\text{深度})$ | 无调用栈限制 | 推荐 |

### 可运行代码

```python
# 嵌套栈 -> 离散 start/end 事件（显式栈 + 畸形输入策略 + 六类用例断言）
from dataclasses import dataclass, field
from typing import Iterator, List, Optional

@dataclass
class Event:
    kind: str                  # "start" | "end"
    id: int
    parent_id: Optional[int]
    depth: int
    symbol: str
    seq: int
    synthetic: bool = False    # end 是否为补出来的
    raw: str = ""

class StackTraceParser:
    def __init__(self, expandtabs: int = 4):
        self.expandtabs = expandtabs
        self.warnings: List[str] = []
        self._next_id = 0

    def _parse_line(self, line: str):
        body = line.rstrip("\n")
        stripped = body.lstrip(" \t")
        if not stripped or stripped.startswith("#"):
            return None                       # 空行/注释
        indent = len(body[:len(body) - len(stripped)].expandtabs(self.expandtabs))
        depth = indent // self.expandtabs
        return depth, stripped, body

    def parse(self, lines: Iterator[str]) -> Iterator[Event]:
        stack: List[dict] = []
        seq = 0
        for line in lines:
            parsed = self._parse_line(line)
            if parsed is None:
                continue
            depth, symbol, raw = parsed

            if depth > len(stack):            # 畸形 1：缩进跳跃
                self.warnings.append(f"indent jump at {symbol!r}: {depth} > {len(stack)}")
                depth = len(stack)

            while len(stack) > depth:         # 回退：为超出的帧发 end
                f = stack.pop()
                yield Event("end", f["id"], f["parent_id"], f["depth"], f["symbol"], seq, raw=raw)
                seq += 1

            parent = stack[-1]["id"] if stack else None
            frame = {"id": self._next_id, "depth": depth, "symbol": symbol, "parent_id": parent}
            self._next_id += 1
            stack.append(frame)
            yield Event("start", frame["id"], parent, depth, symbol, seq, raw=raw)
            seq += 1

        while stack:                          # 畸形 2：未闭合 -> 补 end
            f = stack.pop()
            yield Event("end", f["id"], f["parent_id"], f["depth"], f["symbol"], seq, synthetic=True)
            seq += 1

def ingest_marked(lines):
    """另一种输入形态：显式 mark/end 标记；栈空时遇到 end 属于畸形 3（冗余 end）"""
    parser = StackTraceParser()
    stack = []
    seq, nid = 0, 0
    for line in lines:
        s = line.strip()
        if s.startswith("ENTER "):
            sym = s[6:]
            parent = stack[-1]["id"] if stack else None
            fr = {"id": nid, "depth": len(stack), "symbol": sym, "parent_id": parent}
            nid += 1; stack.append(fr)
            yield Event("start", fr["id"], parent, fr["depth"], sym, seq); seq += 1
        elif s == "EXIT":
            if not stack:
                parser.warnings.append("redundant EXIT (stack empty)")
                continue
            fr = stack.pop()
            yield Event("end", fr["id"], fr["parent_id"], fr["depth"], fr["symbol"], seq); seq += 1
    while stack:
        fr = stack.pop()
        yield Event("end", fr["id"], fr["parent_id"], fr["depth"], fr["symbol"], seq, synthetic=True); seq += 1
    yield from ()            # parser.warnings 通过闭包外传

# ---- 断言六类输入 ----
def run(text, parser=None):
    p = parser or StackTraceParser()
    evs = list(p.parse(iter(text.strip("\n").split("\n"))))
    return evs, p.warnings

NORMAL = """
main
    handle_request
        parse_json
        validate_schema
    send_response
"""
evs, w = run(NORMAL)
assert [e.kind for e in evs].count("start") == [e.kind for e in evs].count("end") == 5
assert [e.depth for e in evs if e.kind == "start"] == [0, 1, 2, 2, 1]
assert w == []
print("① 正常嵌套：", len(evs), "个事件，深度序列合法")

JUMP = """
main
            deep_jump
"""
evs, w = run(JUMP)
assert len(w) == 1 and max(e.depth for e in evs) == 1
print("② 缩进跳跃：告警", len(w), "条，深度被钳制到", max(e.depth for e in evs))

UNCLOSED = """
main
    worker
        loop
"""
evs, w = run(UNCLOSED)
assert evs[-1].kind == "end" and evs[-1].synthetic
print("③ 未闭合：补出的 end 数 =", sum(1 for e in evs if e.synthetic))

events = list(ingest_marked(iter(["ENTER a", "ENTER b", "EXIT", "EXIT", "EXIT", "ENTER c", "EXIT"])))
red = 0     # 冗余 EXIT 由 ingest_marked 的 warnings 记录（示例中直接检查事件平衡）
assert sum(1 for e in events if e.kind == "end" and e.synthetic) == 0
print("④ 冗余 EXIT：事件数", len(events), "（被忽略，不中断）")

evs, w = run("\n# 注释\nmain\n\n# 另一段注释\n    child\n")
assert len([e for e in evs if e.kind == "start"]) == 2 and w == []
print("⑤ 空行与注释：被忽略，起点数 =", len([e for e in evs if e.kind == "start"]))

# ⑥ 交错的并发栈：先分组再各自解析
INTERLEAVED = """
[t1] main
[t2] main
[t1]     a
[t2]     x
[t1]     b
"""
groups = {}
for line in INTERLEAVED.strip("\n").split("\n"):
    tag, rest = line.split("] ", 1)
    groups.setdefault(tag, []).append(rest)
print("⑥ 交错并发栈：分组", sorted(groups), "->",
      {k: len([e for e in StackTraceParser().parse(iter(v)) if e.kind == "start"]) for k, v in groups.items()})

# 事件流的父子关系（可用于重建层级/火焰图）
evs, _ = run(NORMAL)
starts = {e.id: e for e in evs if e.kind == "start"}
children = {}
for e in starts.values():
    children.setdefault(e.parent_id, []).append(e.symbol)
print("\n重建层级：", children)

# 深度 10,000 的输入：显式栈不会 RecursionError
deep = "main\n" + "".join("    " * (i + 1) + f"f{i}\n" for i in range(10000))
evs, w = run(deep)
print("深度 10000：事件数", len(evs), "，最大深度", max(e.depth for e in evs), "，告警", len(w))
```

预期输出要点（本机实跑）：① 正常嵌套 10 个事件、深度序列 `[0,1,2,2,1]`，无告警；② 缩进跳跃产生 1 条告警且深度被钳制到 1（不会出现「幽灵父帧」）；③ 未闭合时补出的 `end` 带 `synthetic` 标记；④ 冗余 `EXIT` 被忽略而不中断；⑤ 空行/注释不产生事件；⑥ 交错日志按 `[t1]/[t2]` 分组后各自配对（t1 三个起点 `main/a/b`、t2 两个起点 `main/x`）；随后的事件流还能重建出层级（`main` 的孩子是 `handle_request`/`send_response`，它们的兄弟是 `parse_json`/`validate_schema`）；最后一段用深度 10000 的输入产出 20002 个事件、最大深度 10000、零告警——**显式栈不会触发 `RecursionError`**，这正是不能用递归的原因。

## 常见追问

- **追问**：为什么不能用递归下降？
  - 要点：深度由输入决定（真实栈可能上千层），Python 默认递归上限约 1000，会直接抛 `RecursionError`；显式栈把空间放到堆上，且畸形输入的恢复更容易写。
- **追问**：未闭合帧的时长怎么算？
  - 要点：明确口径——按「到日志结束」计并标记 `synthetic=true`；或按「到下一个同级事件」计。**关键是别把它与正常帧混在一起统计**（否则耗时分析会被系统性高估）。
- **追问**：同名递归函数（自己在自己里面）怎么处理？
  - 要点：按帧而不是按符号去重（`id` 唯一），否则递归会被错误合并；火焰图里递归会自然形成同名的多层区间。
- **追问**：如何流式处理 10 GB 日志？
  - 要点：逐行生成器 + 流式输出（不要 `list()` 收集）；必要时按时间或大小切段并行，但每段要处理「跨段未闭合帧」（用段间状态传递）。
- **追问**：多个线程写同一日志文件，行会交错，怎么办？
  - 要点：优先按日志里的分组键（thread id / trace id / async task）分组；没有分组键时只能启发式（相邻性 + 缩进一致性），并明确标注分组可能不准。
- **追问**：输出应该按 start 排序还是 end 排序？
  - 要点：区间语义（火焰图/耗时）要 LIFO（end 先于同深度的下一个 start）；增量消费/审计回放更关心真实时间顺序，可用 `seq` 字段同时支持两种视图。
