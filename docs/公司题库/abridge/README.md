# Abridge 面试题库

这一家的题有一个统一的前提：**输出会被医生签署，而签署意味着法律责任。**
所以**"延迟"、"召回"、"格式"这三件在别处是工程指标的事，在这里都是临床与合规问题。**

**第一件事是"截止时间不是几秒，而是就诊时长"。**
**"在医生离开诊室之前就绪"意味着预算约 900–1,200 秒**——
**所以这不是低延迟推理问题，而是增量生成问题**：
**串行方案在音频结束后还要等 115–230 秒，而增量方案收尾只要 5–10 秒。**
**而 EHR 的"签名后不可改"正是这个产品目标的制度原因。**

**第二件事是"成本结构与直觉相反"。**
**90,000 个格子的 token 成本只有 \$405**，而**人工复核是 450 小时（约 \$45,000）**；
**所以在 5,000 份文档的规模上，"优化推理"是最后一位的杠杆。**
**同理，PHI 的约束里"自托管 \$0.28 vs BAA API \$0.11"说明成本上有理由用外部 API——前提是它提供 BAA。**

**第三件事是"漏报与误报不对称，但方向随场景翻转"。**
**医嘱草稿场景要"精确率优先"**（**误改一处会让医生核对全部**）；
**而检索场景要"宁可误报"**（**漏报成本是误报的约 20 倍**）。
**同一家公司里两种相反的取舍，判据是"下游后果"。**

准备这一家时，建议把**"预算约等于就诊时长"**、**"肯定陈述 vs 字符串出现"**、**"一致率是天花板"**这三条练熟。
它们分别解释了"架构该怎么定"、"检测该怎么做"、"质量该怎么测"。

## 准备建议

1. **先建立"预算约等于就诊时长"的直觉**（02）。**这一条决定了整个架构是"增量生成"而不是"批量推理"**，也解释了为什么 EHR 的"签名后不可改"与产品目标是一致的。
2. **02 与 11 是"时间轴的两端"**：**02 讲"什么时候要就绪"、11 讲"音频本身有多难"**。**合起来看才知道为什么需要"流式 + 重解"两遍。**
3. **03 的三条反噬值得单独记**：**chart 过期会让 ASR"听出"未提及的药**——**这正好制造了 08 的安全事件**。**改进手段会引入新的失效模式，两题必须联动设计。**
4. **08 与 09 是"检测与被检测"**：**08 的第 1 层检测正是 09 建的溯源**。**一个基础设施服务产品与安全两个目的，这是它值得投入的理由。**
5. **06 与 07 是"质量与信任"**：**06 讲"怎么测质量"、07 讲"编辑率为什么不能代替它"**。**两者的共同点是都要按维度拆开，不能用一个聚合数字。**
6. **01 与 04 共享"编码空间"这个约束**：**诊断码与医嘱码合计几十万条**。**所以两题都得出同一个结论：模型给名字、系统给编码。**
7. **05 的"幂等"是最工程化的一题**：**确认丢失 1% + 重试 3 次 = 2.97% 重复**。**这个数字在分布式系统里是常识，但在这里的后果是护士要手工清理病历。**
8. **10 是唯一一道"合规优先于技术"的题**：**BAA 是前置条件**。**准备时要把"先问能不能、再问怎么做"这个顺序讲出来。**
