# Hugging Face 面试题库

这一家的题有一个共同点：**它们问的是"为什么这么决定"，而不是"这个模型怎么训"。**
十一道题里有九道在问一个取舍——**取舍的答案通常不是"哪个更好"，而是"当时哪个是瓶颈"。**

**第一件事是"决定的对错取决于阶段"。**
"每个模型一个自包含文件"在**成长期是对的（把加模型的成本压到一个文件）、在成熟期是错的**——
**N=200、M=20 时"重复式"是 4,000 个接触点、"模块化"只有 220（差 18 倍）**，
而**一个优化要 24 个月才覆盖 82% 的模型**。
**所以回答这类问题要先问"现在哪个是瓶颈"。**

**第二件事是"实测常常推翻直觉"。**
三道题上我都被实测纠正过：**safetensors 与 torch.save 在"整读"时几乎无差别（1.00×/1.13×）**，
真正的差别在 mmap 惰性访问（**94 倍**）；
**"块越小去重率越高"是错的**——去重率被约掉了，**块大小只在插入/删除时才决定**（**50 GB vs 1 MB**）；
**Unigram 在小语料上只学到 61 个词元**，因为它的似然剪枝撑不起大词表。
**这些都不是"查文档能查到"的结论。**

**第三件事是"账要算全"。**
**"8B 模型 = 16 GB"只是第一行**：**全量微调的完整账是 128 GB（5.3 倍于 24 GB）**，
而**最大的一项是优化器状态（64 GB）**；
**100 TB 原始快照最后只剩 3.6 TB**，而**保留率是连乘的**；
**serverless 的盈亏平衡低到"1B 模型每月 8,640 次"**。

准备这一家时，建议把**"每参数字节数"**、**"保留率连乘"**、**"长尾分位"**这三条算术练熟。
它们分别解释了"显存够不够"、"语料还剩多少"、"该给谁保持热副本"。

## 准备建议

1. **先建立"每参数字节数"的直觉**：**bf16 权重 2、梯度 2、Adam 两阶 8、master 4 = 16 字节/参数**（07）。**这一个数字能推出 128 GB，也能解释为什么"4 bit + LoRA"要各解决一半。**
2. **02 与 03 共享同一套机制**：**mmap + 惰性访问**。02 讲权重文件、03 讲数据集文件，**而"整读无差别、惰性访问差 94 倍"这个结论对两者都成立**。
3. **04 与 07 是"加载"与"训练"两面**：04 讲放置（device_map）、07 讲账。**两者的共同点是"要自己算 KV 与激活，工具不算"。**
4. **05 与 06 必须一起看**：**tokenizer 定义特殊 token、template 使用它们**。**两者共同定义"模型看到的输入"，缺一不可。**
5. **09 的"块大小不影响原地修改的去重率"值得单独记**：**这是一个容易算错的点**（我自己先算错了）。真正的论据在插入/删除场景。
6. **10 的长尾分布是"设计前提"**：**前 1% 吃 60.6%**。**任何"给每个模型都保持热副本"的设计都会因为这一条而失败。**
7. **01 与 11 是一对**：01 讲"约定为什么存在"、11 讲"怎么守住约定"。**review 的依据是约定，不是个人偏好。**
8. **08 的"看被删样本"是最容易忽略的一条**：**大家只看保留了什么，而 filter 的判断体现在被删的东西上。**
