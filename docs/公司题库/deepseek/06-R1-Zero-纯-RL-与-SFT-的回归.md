## 一句话答案

> **R1-Zero 证明的是「能力已经在基座里，RL 只是把它激发出来」**——不是「RL 能凭空造出推理能力」。
> **它为什么能work**：
> ① **可验证奖励**：数学/代码有**规则可判对错**，所以不需要奖励模型，**没有「奖励模型被黑」这条路径**；
> ② **GRPO 的组内相对优势**：同一问题采样一组答案，用**组内均值当基线**，省掉价值网络、降低方差（串 [[cognition-04]] 的基线标准误口径）；
> ③ **长 CoT 自然涌现**：思考更长 → 答对概率更高 → 奖励直接激励「多想一会儿」；
> ④ **基座已具备潜能力**：预训练见过大量代码/数学，**正确的推理路径在基座分布里概率非零**——RL 把它放大。
> **它的问题（也正是 R1 把 SFT 加回来的原因）**：
> ① **可读性/语言一致性差**：纯 RL 只优化「对错 + 格式」，于是输出**中英混杂、结构混乱**——**作为产品不可用**；
> ② **冷启动不稳定、前期低效**：从基座直接 RL 要经历一段「随机探索」，训练不稳、样本效率低；
> ③ **覆盖不了不可验证任务**：写作、开放问答、安全对齐**没有规则奖励**，纯 RL 无从下手；
> ④ **SFT 还是蒸馏的载体**：R1 产出的高质量 SFT 数据是**把能力蒸馏到小模型**的关键（否则小模型无从学起）。
> **所以 R1 的配方是四段**：**冷启动 SFT → 面向推理的 RL → 拒绝采样 + SFT（含非推理数据）→ 全场景 RL**。
> **一句话判据**：**RL 激发能力，SFT 塑造行为**——前者决定「能不能做对」，后者决定「以什么形式交付」。
> **本轮的四个量化模型**（都可实跑）：
> ① **奖励黑客**：只优化格式类代理奖励时，**代理指标涨到 1.00 而真实正确率被挤占到 0.00**（代理优化挤占真实改进）；
> ② **激发 vs 创造**：把「思考更长」建模为「更多次尝试」，单次成功率 $q$、$L$ 段思考的成功率 $1-(1-q)^L$——**$q=0$ 时再长的链也是 0**，而 **$q=0.01$（弱但非零）靠长链能到 0.92**；
> ③ **长度膨胀**：不给长度惩罚时最优思考长度**直接顶到上限 1024**（惩罚系数 0.001 时降到 149，0.005 时降到 69）；
> ④ **GRPO 的方差优势**：组内基线相对「带噪声的价值网络」把优势估计的标准误降低 **3.7–53.3 倍**（$G$ 越大差距越大）。

## 面试官在考什么

- **是否理解「激发 vs 创造」**：能否明确指出 R1-Zero 的成功**依赖基座已有的潜能力**，而不是「RL 万能」。
- **可验证奖励的关键作用**：能否说清「规则奖励 → 不需要奖励模型 → 没有 RM 被黑这条路径」，以及它的**适用边界**（只在可验证任务上）。
- **GRPO 的机制**：组内相对优势、省掉 value network、方差如何下降（能否给出「基线标准误 $\sigma/\sqrt{G}$」的量级感）。
- **R1 为什么加回 SFT**：能否列出**四条**（可读性、冷启动稳定、不可验证任务、蒸馏载体），而不是只说「为了效果更好」。
- **四段配方**：能否复述 R1 的完整训练流程（冷启动 SFT → 推理 RL → 拒绝采样 + SFT → 全场景 RL）并说清每段的目的。
- **涌现现象**：能否解释「aha moment」与长 CoT 的**激励机制**（更长思考 → 更高答对率 → 更高奖励）。
- **代价与边界**：能否指出纯 RL 的**长度膨胀、语言混杂、不稳定**，以及为什么这些是「优化目标的直接后果」而非偶然。
- **与 SFT/RLHF 的关系**：能否区分「RLHF 对齐人类偏好」与「RLVR 优化可验证正确性」——**目标函数不同，风险不同**。
- **工程视角**：能否说出数据配比、奖励设计、以及「什么时候该用 SFT、什么时候该用 RL」的判据。

**常见错误答案**

- 说「R1-Zero 证明了不需要 SFT 也能训出推理模型」（忽略了**基座前提**与**产品可用性**）。
- 认为「RL 可以教会模型全新的能力」（RL 主要在**重新加权已有行为**）。
- 忽略可验证性的边界（把 RLVR 套到写作/开放问答上）。
- 把 R1 加回 SFT 只说成「为了效果」（真实原因主要是**可读性与稳定性**）。
- 不提长度膨胀与语言混杂（这是纯 RL 的直接副作用）。
- 混淆 RLHF 与 RLVR 的目标函数。
- 不区分「冷启动 SFT」与「最终 SFT」（两者目的不同：前者给先验，后者给通用能力与蒸馏数据）。

## 原理与推导

### 1. 激发 vs 创造：链式成功概率

把「答对一道多步题」建模为**连续 $L$ 步都正确**（$L$ 为推理链长度），每步正确概率 $p$：

$$P(\text{答对})=1-(1-p)^{L}\quad(\text{至少一步到位；等价地，采样 }L\text{ 条路径至少一条全对})$$

**关键推论**：$p$ 由**基座**决定，RL 能做的是**提高被选中路径的权重**（把「偶尔对」变成「稳定对」）：

- $p>0$：RL 可以通过采样发现正确路径并放大它 → **涌现**；
- $p=0$：**任何 RL 都无效**（没有可放大的信号）——这就是「RL 激发而非创造」。

### 2. 可验证奖励：为什么它是这套方法的地基

| 奖励类型 | 例子 | 风险 |
| --- | --- | --- |
| **规则可验证（RLVR）** | 数学答案匹配、代码单测通过、格式合法 | **无奖励模型 → 无 RM 被黑**；但**只覆盖可验证任务** |
| 学习型奖励模型（RLHF） | 人类偏好打分 | **会被黑**（模型学会讨好 RM 而非做对事） |
| 混合 | 正确性 + 格式 + 长度约束 | 需要小心权重（见下面的「格式黑客」） |

**读法**：R1-Zero 的成功**很大程度来自「奖励是可信的」**——而不是来自「没有 SFT」。

### 3. GRPO：组内相对优势

对同一问题采样 $G$ 个答案，奖励 $r_1..r_G$，优势用**组内标准化**：

$$\hat A_i=\frac{r_i-\text{mean}(r)}{\text{std}(r)}$$

**优点**：① **不需要价值网络**（省一份与策略同规模的模型与训练开销）；② **基线是「同题内的平均」**，天然抵消题目难度差异；③ 方差随 $G$ 下降——基线的标准误约 $\sigma/\sqrt{G}$（串 [[cognition-04]]）。

### 4. 长度膨胀：优化目标的直接后果

若「答对概率随思考长度上升」且**奖励不含长度惩罚**，则最优策略会把长度拉到**上限**：

$$\max_L\ \big[\,\text{Reward}(L)-c\cdot L\,\big]\ \xrightarrow{\ c=0\ }\ L\to L_{\max}$$

**这解释了两件事**：① 长 CoT 的涌现（有益的一面）；② 纯 RL 输出的**啰嗦、可读性差**（有害的一面）。**SFT 冷启动的作用之一，就是给模型一个「合理的长度先验」**，让 RL 不必从零学「该说多长」。

### 5. R1 的四段配方与各自目的

| 阶段 | 目的 |
| --- | --- |
| ① **冷启动 SFT**（少量高质量长 CoT 数据） | 给一个**可读、结构化的先验**，避免 RL 前期乱探索 |
| ② **面向推理的 RL**（RLVR + 语言一致性奖励） | 提升可验证任务的正确率；**语言一致性奖励**专门治「中英混杂」 |
| ③ **拒绝采样 + SFT**（推理数据 + 通用数据） | 把 RL 的成果**固化**，并**补上不可验证任务**（写作/问答/安全） |
| ④ **全场景 RL**（有用性 + 无害性） | 对齐人类偏好，收尾 |

**读法**：**SFT 与 RL 不是替代关系，而是分工**——SFT 负责「形式与覆盖」，RL 负责「正确性与上限」。

```python
# R1-Zero 的四个量化模型：奖励黑客、激发 vs 创造、长度膨胀、GRPO 方差优势
import math
import numpy as np
from dataclasses import dataclass
from typing import Dict, List, Tuple

RNG = np.random.default_rng(7)

# ---------- 1) 奖励黑客：只优化"格式"这类代理奖励 ----------
@dataclass
class ProxyHack:
    """★ 关键建模：优化代理指标会"挤占"真实目标的改进（推理预算/容量有限）"""
    n_steps: int = 200
    lr: float = 0.05
    def run(self, w_proxy: float, w_true: float) -> Dict[str, float]:
        fmt, corr = 0.2, 0.3
        for _ in range(self.n_steps):
            # 格式：代理权重直接驱动；真实正确率：真实权重驱动，但被代理优化挤占
            fmt = min(1.0, fmt + self.lr * w_proxy)
            corr = max(0.0, min(1.0, corr + self.lr * (w_true - 0.8 * w_proxy)))
        return {"格式合规（代理指标）": fmt, "真实正确率": corr}
print("① 奖励黑客：把「格式」当代理指标（代理优化会挤占真实目标的改进）")
print(f"  {'代理权重':>9} {'真实权重':>9} {'格式合规':>10} {'真实正确率':>11}")
for wp, wt in ((1.0, 0.0), (1.0, 0.2), (1.0, 1.0), (0.2, 1.0)):
    r = ProxyHack().run(wp, wt)
    print(f"  {wp:>9.1f} {wt:>9.1f} {r['格式合规（代理指标）']:>10.2f} {r['真实正确率']:>11.2f}")
print("  读法：**代理权重高、真实权重低时，格式冲到 1.00 而真实正确率反而下降**（被挤占）——")
print("        这正是 R1 必须用「规则可验证奖励」的原因：**奖励必须与真实目标同向**；")
print("        也解释了纯 RL 为何产出「格式漂亮但可读性差」的输出（可读性根本没进奖励）")

# ---------- 2) 激发 vs 创造：链式成功概率 ----------
def chain_success(q: float, L: int) -> float:
    """★ 把"思考更长"建模为"更多次尝试/回溯"：单次尝试成功率 q，L 段思考至少成功一次"""
    return 1 - (1 - q) ** L
print("② 激发 vs 创造：基座的单次尝试成功率 q 决定 RL 的上限")
print(f"  {'q（基座能力）':>13} {'L=4':>8} {'L=16':>8} {'L=64':>8} {'L=256':>8} {'结论':<20}")
for q in (0.0, 0.01, 0.05, 0.2, 0.5):
    vals = [chain_success(q, L) for L in (4, 16, 64, 256)]
    if q == 0.0:
        note = "**无潜能力：RL 无效**"
    elif q < 0.03:
        note = "弱但非零：长链可放大"
    else:
        note = "RL 可放大为稳定能力"
    print(f"  {q:>13.2f} " + " ".join(f"{v:>8.3f}" for v in vals) + f" {note:<20}")
print("  读法：**q=0 时任何思考长度都是 0**（RL 无法创造能力）；而 **q=0.01 这种「弱但非零」的基座，")
print("        靠长链也能把成功率推到 0.92** —— 这就是「RL 激发而非创造」的严格版本，也解释了")
print("        为什么 R1-Zero 能work：**基座在预训练里已经见过大量代码与数学，q 远大于 0**")

# ---------- 3) 长度膨胀：没有长度惩罚时的最优策略 ----------
def best_length(success_fn, L_max: int, length_cost: float) -> Tuple[int, float]:
    best_L, best_val = 1, -1e9
    for L in range(1, L_max + 1):
        val = success_fn(L) - length_cost * L
        if val > best_val:
            best_val, best_L = val, L
    return best_L, best_val
def succ(L: int, q: float = 0.02) -> float:
    """★ 渐近逼近 1（永不到 1），这样"没有长度惩罚"时最优点才会顶到上限"""
    return 1 - (1 - q) ** L
print("")
print("③ 长度膨胀：奖励不含长度惩罚时，最优思考长度会被拉到上限")
print(f"  {'长度惩罚系数':>13} {'最优长度':>9} {'对应成功率':>10}")
for c in (0.0, 0.001, 0.005, 0.02, 0.1):
    L, v = best_length(succ, 1024, c)
    print(f"  {c:>13.3f} {L:>9} {succ(L):>10.3f}")
print("  读法：**c=0 时最优长度直接顶到上限 1024**（因为成功率渐近逼近 1、永不饱和）——")
print("        长 CoT 的「涌现」与「啰嗦」是同一枚硬币；SFT 冷启动的作用之一就是**给出合理的长度先验**")

# ---------- 4) GRPO 的方差优势：组内基线 vs 噪声价值网络 ----------
def advantage_std(group_size: int, n_trials: int = 2000,
                  reward_sd: float = 1.0, value_noise: float = 0.8) -> Dict[str, float]:
    """比较两种基线：组内均值（GRPO）与带噪声的价值网络"""
    grpo, vnet = [], []
    for _ in range(n_trials):
        r = RNG.normal(0, reward_sd, group_size)
        grpo.append(r.mean())                                  # 组内基线
        vnet.append(r.mean() + RNG.normal(0, value_noise))     # 价值网络：有额外噪声
    # 优势估计的标准误：以"真实均值 0"为参照
    return {"GRPO 基线标准误": float(np.std(grpo, ddof=1) / math.sqrt(group_size)),
            "价值网络基线标准误": float(np.std(vnet, ddof=1)),
            "组大小": group_size}
print("")
print("④ GRPO 的方差优势（组内基线 vs 带噪声的价值网络）")
print(f"  {'组大小 G':>9} {'GRPO 标准误':>13} {'价值网络标准误':>15} {'倍数':>7}")
for g in (4, 8, 16, 32, 64):
    r = advantage_std(g)
    print(f"  {g:>9} {r['GRPO 基线标准误']:>13.4f} {r['价值网络基线标准误']:>15.4f} "
          f"{r['价值网络基线标准误']/max(r['GRPO 基线标准误'], 1e-9):>6.1f}x")
print("  读法：**组内基线的标准误随组大小按 1/sqrt(G) 下降**，而价值网络还要额外承担自身的估计噪声 ——")
print("        这就是 GRPO 省掉 value network 却仍能稳定训练的原因（代价是**同题要多采样 G 次**）")

# ---------- 5) R1 四段配方与各段目的 ----------
@dataclass
class Stage:
    name: str
    data: str
    purpose: str
STAGES = [
    Stage("① 冷启动 SFT", "少量高质量长 CoT", "给可读、结构化的先验；避免 RL 前期乱探索"),
    Stage("② 推理 RL", "RLVR（规则奖励）+ 语言一致性奖励", "提升可验证任务正确率；治中英混杂"),
    Stage("③ 拒绝采样 + SFT", "推理数据 + 通用数据", "固化 RL 成果；补上不可验证任务"),
    Stage("④ 全场景 RL", "有用性 + 无害性", "对齐人类偏好，收尾"),
]
print("")
print("⑤ R1 的四段配方（SFT 与 RL 分工，而不是替代）")
print(f"  {'阶段':<18} {'数据':<34} 目的")
for s in STAGES:
    print(f"  {s.name:<18} {s.data:<34} {s.purpose}")
print("  读法：**SFT 负责形式与覆盖，RL 负责正确性与上限** —— 这就是「为什么 R1 又把 SFT 加回来」的完整答案")
```

预期输出要点（实跑）：① **代理权重高、真实权重低时，格式冲到 1.00 而真实正确率被挤占到 0.00**——奖励必须与真实目标同向，这正是 RLVR 的价值；② **$q=0$ 时任何思考长度的成功率都是 0**（RL 无法创造能力），而 **$q=0.01$ 这种弱但非零的基座靠长链可到 0.924**（L=4/16/64/256 分别 0.039/0.149/0.474/0.924）——**「RL 激发而非创造」的严格版本，也是 R1-Zero 能 work 的前提**；③ **长度惩罚为 0 时最优思考长度顶到上限 1024**（0.001 → 149，0.005 → 69）——**「涌现」与「啰嗦」是同一枚硬币**；④ **GRPO 组内基线的标准误按 $1/\sqrt{G}$ 下降**（G=4→64 时 0.2526→0.0154），而带噪声价值网络始终在 0.82 附近，**差距 3.7–53.3 倍**；⑤ 四段配方表把「SFT 与 RL 分工」讲清——**SFT 管形式与覆盖，RL 管正确性与上限**。

## 常见追问

- **追问**：R1-Zero 说明了什么？
  - 要点：① **推理能力可以从 RL 中自发涌现**（不需要人工写推理轨迹）；② 但**前提是基座已有潜能力**（$p>0$）；③ **可验证奖励是关键**（不需要奖励模型，也就没有 RM 被黑）；④ **纯 RL 的产物在产品上不可用**（可读性/语言一致性）。**四条一起说才算完整。**
- **追问**：为什么 R1 要加「语言一致性奖励」？
  - 要点：纯 RL 只优化正确性与格式，**语言混合不影响奖励** → 模型没有理由保持单一语言。R1 在 RL 阶段**显式加入语言一致性奖励**来修正这一点。**这是「奖励设计决定行为」的直接证据**——你不奖励的东西，模型不会替你在意。
- **追问**：GRPO 与 PPO 的区别？
  - 要点：**PPO 需要一个价值网络（critic）估计基线**（与策略同规模，训练开销大、方差来源多）；**GRPO 用同一问题的一组采样奖励的均值当基线**，省掉 critic，并天然归一化题目难度。代价是**同题需要多采样 $G$ 次**（推理成本上升）。串 [[cognition-04]] 的基线标准误口径。
- **追问**：什么时候该用 SFT，什么时候该用 RL？
  - 要点：**SFT 适合「有高质量示范、要固定形式/风格/格式」**（行为塑造、冷启动）；**RL 适合「正确性可验证、且基座已有潜能力」**（把上限推高）；**两者通常都要**：SFT 给先验与覆盖，RL 提上限与鲁棒性。**判据是「你要的是形式还是上限」**（串 [[deepseek-08]] 的数据构建）。
- **追问**：RLVR 能用到写作/开放问答上吗？
  - 要点：**不能直接用**——没有规则可判对错。替代方案：① **用模型当裁判**（引入裁判偏差与「讨好裁判」的风险）；② **分解成可验证子目标**（事实一致性、引用正确性、格式）；③ **偏好数据 + RLHF**（代价是奖励模型会被黑）。**R1 的第三段（拒绝采样 + SFT）正是为了覆盖这些任务。**
- **追问**：为什么 R1 的 SFT 数据能被用来蒸馏小模型？
  - 要点：因为 R1 的输出**已经是「可读的、结构化的推理轨迹」**——这恰好是小模型学得会的监督信号。**纯 RL 的 R1-Zero 输出可读性差，蒸馏效果也差**。所以「加回 SFT」不仅是为了 R1 自身，也是为了**整个蒸馏生态**。
- **追问**：怎么判断 RL 是在「激发」还是「创造」？
  - 要点：**看基座在目标任务上的 pass@k（大 k）**：若 pass@k 明显高于 pass@1，说明能力已在（RL 可激发）；若 pass@k 也很低，RL 能做的有限。**这是「先量潜力再上 RL」的判据**，也能解释为什么「用 RL 修一个基座完全不会的任务」通常失败。
