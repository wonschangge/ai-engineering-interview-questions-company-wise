## 一句话答案

> **低精度出问题的四个地方，按危害排序**：
> ① **离群值把普通值压扁**（最致命）：激活/权重是**重尾**的——少数通道幅度是其他的几十倍。**逐张量缩放**下，为了不让离群值溢出，scale 被撑大，**普通值只剩几位有效精度**。本机实测：4/128 通道有 40× 离群值时，**非离群通道的 SQNR 只有 19.3 dB**（约 3 位有效），而**逐块（1×128）缩放下是 54.7 dB**——**差 35 dB**；
> ② **累加精度**：FP8 的矩阵乘**必须用 FP32 累加器**。本机模拟：4096 项归约时**低精度累加的相对误差约 0.21，而 FP32 累加约 4.8e-6（差约 4.4 万倍）**，且误差随归约长度增长（256 项 0.042 → 4096 项 0.211）；
> ③ **敏感算子被降精度**：**嵌入/输出头、归一化、残差、路由门控、优化器状态、主权重**——这些「FLOPs 占比小但影响大」的部分**必须留在高精度**；
> ④ **数值范围**：E4M3 的最大值只有 **448**、最小正规数约 $2^{-6}$——**溢出成 inf/NaN、下溢成 0**，而这两个都会在反向传播里放大。
> **稳定化的六条手段**：
> | # | 手段 | 作用 |
> | --- | --- | --- |
> | ① | **细粒度（分块）缩放**：按 1×128 的块各自算 scale | 把离群值的影响**限制在块内**（实测 +18.4 dB，普通通道 +35 dB） |
> | ② | **混合精度提升**：敏感算子保 BF16/FP32（归一化、输出头、路由、优化器状态） | 用少量吞吐换稳定（Amdahl：**15% 的算子保 BF16 只损失约 13% 的理想加速**） |
> | ③ | **FP32 累加器** | 长归约的误差不随长度爆炸 |
> | ④ | **周期性「提升」**（每 N 层用一次高精度） | 限制误差沿层数累积 |
> | ⑤ | **损失尖峰处理**：监控 + 检查点回滚 + 跳过该批数据 | **尖峰概率 1%/步就吃掉约一半训练进度**，所以这是必备能力而非应急 |
> | ⑥ | **通信也用 FP8**（all-gather/reduce），但**缩放因子要一起传** | 带宽减半；代价是实现复杂（缩放因子同步） |
> 一句话判据：**「FP8 训练难」的本质不是「8 位不够」，而是「分布是重尾的」**——所以解决方案的核心是**让缩放粒度跟上分布的粒度**（分块缩放），而不是简单地「用更少的位」。

## 面试官在考什么

- **能否指出离群值才是真问题**：不是「8 位精度不够」，而是**重尾分布 + 粗粒度缩放**的组合；能否给出量化（普通通道 SQNR 从 19.3 dB 提到 54.7 dB）。
- **是否知道分块缩放**：1×128 的块级 scale 是 V3 的关键工程；能否解释**为什么块越小越好、但开销越大**（scale 数量与通信/存储开销）。
- **累加精度的约定**：能否说清「**输入 FP8、累加 FP32**」是硬件约定，以及为什么低精度累加会让长归约崩掉。
- **哪些必须保高精度**：能否列出**嵌入/输出头、归一化、残差、路由、优化器状态、主权重**，并给出理由（小 FLOPs、大影响）。
- **Amdahl 视角**：能否算出「保 BF16 的算子占比 → 吞吐损失」，说明这个交易划算。
- **损失尖峰的工程处理**：能否说出**监控指标（梯度范数、损失突增）+ 检查点回滚 + 跳过数据**这套机制，并量化其成本。
- **数值范围**：能否说出 E4M3/E5M2 的取舍（范围 vs 精度）以及 inf/NaN 的传播风险。
- **通信侧**：能否想到「激活也用 FP8 传输」能省一半带宽，但**缩放因子必须同步**（否则两端解码不一致）。
- **诚实**：承认 FP8 训练**需要更多工程与调参**（缩放粒度、提升策略、回滚机制），不是「开个开关」。

**常见错误答案**

- 只说「用 FP8 省显存和算力」，不讲离群值与缩放粒度。
- 认为「低精度累加没关系」（长归约下误差爆炸）。
- 把归一化/输出头也降到 FP8（这些地方最容易崩）。
- 不做尖峰处理（没有回滚能力，一次尖峰可能毁掉几天训练）。
- 用逐张量缩放处理重尾分布（本机实测普通通道只剩 19 dB）。
- 忽略缩放因子的通信开销（FP8 传输不只是「少传一半字节」）。
- 认为「FP8 训练已经成熟，直接开就行」（忽略调参与监控成本）。

## 原理与推导

### 1. FP8 的两种格式与范围

| 格式 | 指数位 | 尾数位 | 最大值 | 特点 |
| --- | --- | --- | --- | --- |
| **E4M3** | 4 | 3 | 448 | 精度更好，**范围小**（前向权重/激活常用） |
| **E5M2** | 5 | 2 | 57344 | 范围大，精度更差（**反向梯度常用**） |

**3 位尾数**意味着相对量化步长约 $2^{-3}=12.5\%$ 的**分辨率**——这已经很低了，**如果 scale 再被离群值撑大，普通值的有效精度会进一步塌陷**。

### 2. 离群值：为什么逐张量缩放会崩

设数据中比例 $\rho$ 的通道幅度是普通值的 $M$ 倍。逐张量缩放取

$$s=\frac{\max|x|}{448}\approx\frac{M\cdot x_{\text{typ}}}{448}$$

于是**普通值**被映射到 $\frac{x_{\text{typ}}}{s}=\frac{448}{M}$ 这个量级——**当 $M=40$ 时，普通值只用到 11 个量化格**，有效精度约 3–4 位。

**分块缩放**（每 128 个元素一个 scale）把离群值的影响**限制在它所在的块内**，其余块各自用满量程：

$$\text{SQNR}_{\text{block}}\gg\text{SQNR}_{\text{tensor}}\quad(\text{本机实测：非离群通道 }19.3\to54.7\ \text{dB})$$

**代价**：scale 数量增加 $d/128$ 倍（需要额外存储与通信），且块太小会让缩放本身的开销占比上升。

### 3. 累加精度：长归约的误差

矩阵乘 $C_{ij}=\sum_k A_{ik}B_{kj}$ 的归约长度是 $K$。若累加也在低精度，**每次加法都引入相对误差 $\epsilon$**，误差按随机游走累积：

$$\text{相对误差}\approx\epsilon\sqrt{K}\ \text{（随机）到}\ \epsilon K\ \text{（最坏）}$$

**本机实测**：FP32 累加在 4096 项时约 **4.8e-6**，低精度累加约 **0.211**——**差约 4.4 万倍**，且低精度累加的误差随归约长度单调增长（256 → 4096 项时 0.042 → 0.211）。所以「**输入 FP8、累加 FP32**」不是可选优化，而是**数值正确性的底线**。

### 4. 哪些必须保高精度（以及代价）

| 组件 | 精度 | 理由 |
| --- | --- | --- |
| 嵌入 / 输出头 | BF16 | 直接决定词表上的分布；量化误差直接变错词 |
| 归一化（RMSNorm/LN） | BF16（内部 FP32） | 它缩放整个向量，误差会被放大到所有下游 |
| 残差累加 | BF16/FP32 | 残差是「信息的载体」，误差会沿层累积 |
| **路由门控** | FP32/BF16 | 错路由 = 用错专家（串 [[deepseek-04]]） |
| **优化器状态 / 主权重** | FP32 | 更新量很小，低精度会让更新「被舍入掉」 |
| 专家 GEMM / 注意力 GEMM | **FP8**（分块缩放） | FLOPs 主体，收益最大 |
| 通信（激活） | FP8（缩放因子同传） | 带宽减半 |

**Amdahl 视角的代价**（FP8 相对 BF16 假设 2× 吞吐）：

$$\text{有效加速}=\frac{1}{(1-f)/2+f}\quad\Rightarrow\ f=15\%\ \text{时}\ 1.74\times\ (\text{损失 13\% 的理想加速})$$

**读法**：**「保高精度的算子」恰好是 FLOPs 占比小的那批**——所以这个交易非常划算。

### 5. 损失尖峰：规模训练的必备机制

即使数值都做对，**大规模训练仍会出现偶发损失尖峰**（可能与数据、数值、优化器状态有关）。工程处理：

$$\text{有效吞吐}=\frac{1}{1+p\cdot C_{\text{rollback}}}$$

**例**：$p=0.5\%$/步、回滚 100 步 → **有效吞吐 0.667（损失 33%）**；$p=2\%$ → **0.333**。

**机制**：① **监控**（损失突增、梯度范数异常、激活最大值）；② **自动回滚**到最近的健康检查点；③ **跳过**导致尖峰的数据批；④ **保留**这些批用于事后分析。

**读法**：**「能回滚」不是应急预案，而是吞吐的一部分**——没有它，一次尖峰可能浪费数天的算力。

```python
# FP8 训练的五个量化模型：分块缩放、离群鲁棒性、Amdahl 代价、累加精度、尖峰回滚
import math
import numpy as np
from dataclasses import dataclass
from typing import Dict, List, Tuple

RNG = np.random.default_rng(0)
E4M3_MAX = 448.0            # E4M3 的最大可表示值
BLOCK = 128                 # 分块缩放的块大小（V3 用 1x128）

def quant_e4m3(x: np.ndarray, scale: np.ndarray) -> np.ndarray:
    """模拟 E4M3：除以 scale、四舍五入到整数格、截断到 [−448, 448]，再乘回 scale"""
    q = np.clip(np.round(x / scale), -E4M3_MAX, E4M3_MAX)
    return q * scale

def sqnr_db(x: np.ndarray, xq: np.ndarray) -> float:
    err = x - xq
    return 10 * math.log10(float((x ** 2).sum()) / max(float((err ** 2).sum()), 1e-30))

def scales_tensor(x: np.ndarray) -> np.ndarray:
    return np.full_like(x, np.abs(x).max() / E4M3_MAX)

def scales_block(x: np.ndarray, block: int = BLOCK) -> np.ndarray:
    n_ch, n = x.shape
    pad = (-n) % block
    xp = np.pad(x, ((0, 0), (0, pad))) if pad else x
    s = np.abs(xp).reshape(n_ch, -1, block).max(axis=2, keepdims=True) / E4M3_MAX
    s = np.repeat(s, block, axis=2).reshape(n_ch, -1)
    return s[:, :n]

# ---------- 1) 逐张量 vs 逐块缩放 ----------
n_ch, n_tok, n_out = 128, 4096, 4
base = RNG.normal(0, 1.0, (n_ch, n_tok))
out_ch = RNG.choice(n_ch, n_out, replace=False)
base[out_ch] *= 40.0                     # 4/128 的通道有 40× 离群值
print("① 逐张量 vs 逐块（1x128）缩放（128 通道中 4 个有 40× 离群值）")
q_t = quant_e4m3(base, scales_tensor(base))
q_b = quant_e4m3(base, scales_block(base))
bulk = np.delete(base, out_ch, axis=0)
print(f"  整体 SQNR：逐张量 {sqnr_db(base, q_t):.1f} dB | 逐块 {sqnr_db(base, q_b):.1f} dB "
      f"（+{sqnr_db(base, q_b) - sqnr_db(base, q_t):.1f} dB）")
print(f"  **非离群通道** SQNR：逐张量 {sqnr_db(bulk, np.delete(q_t, out_ch, axis=0)):.1f} dB | "
      f"逐块 {sqnr_db(bulk, np.delete(q_b, out_ch, axis=0)):.1f} dB")
print("  读法：**逐张量缩放时，离群值把普通通道的有效精度压到约 3 位（19.3 dB）**；")
print("        分块缩放把影响限制在块内，普通通道回到 54.7 dB —— 这是 FP8 训练最关键的工程手段")

# ---------- 2) 离群幅度的鲁棒性 ----------
print("")
print("② 离群幅度扫描：逐张量 vs 逐块（4 个离群通道）")
print(f"  {'离群幅度':>8} {'逐张量 SQNR':>12} {'逐块 SQNR':>10} {'差距':>8}")
for m in (1, 5, 20, 100, 400):
    x = RNG.normal(0, 1.0, (n_ch, n_tok))
    x[out_ch] *= m
    st = sqnr_db(x, quant_e4m3(x, scales_tensor(x)))
    sb = sqnr_db(x, quant_e4m3(x, scales_block(x)))
    print(f"  {m:>8} {st:>12.1f} {sb:>10.1f} {sb - st:>8.1f}")
print("  读法：**逐张量随离群幅度增大而显著退化（49.8 → 37 dB），逐块几乎不变（≈54.8 dB）** ——")
print("        这就是「让缩放粒度跟上分布粒度」的量化证据")

# ---------- 3) 精度提升的 Amdahl 代价 ----------
def effective_speedup(f_bf16: float, fp8_speed: float = 2.0) -> float:
    """f 比例的 FLOPs 保 BF16，其余用 FP8（假设 FP8 相对 BF16 快 2×）"""
    return 1.0 / ((1 - f_bf16) / fp8_speed + f_bf16)
print("")
print("③ 把敏感算子留在 BF16 的代价（FP8 相对 BF16 假设 2× 吞吐）")
print(f"  {'BF16 占比':>10} {'有效加速':>9} {'相对理想 2× 的损失':>18}")
for f in (0.0, 0.05, 0.15, 0.30, 0.50):
    sp = effective_speedup(f)
    print(f"  {f:>10.0%} {sp:>9.2f}x {1 - sp / 2.0:>17.0%}")
print("  读法：**归一化/输出头/路由/优化器状态这些「小 FLOPs、大影响」的算子保 BF16，")
print("        只损失约 13% 的理想加速** —— 这是典型的「用少量吞吐买稳定」的交易")

# ---------- 4) 累加精度：长归约的误差 ----------
def accumulate_error(n_terms: int, mantissa_bits: int, trials: int = 120) -> float:
    """模拟点积：每步把中间和量化到指定尾数位（FP32=23、BF16=8）"""
    errs = []
    for _ in range(trials):
        a = RNG.normal(0, 1, n_terms); b = RNG.normal(0, 1, n_terms)
        exact = float(np.dot(a.astype(np.float64), b.astype(np.float64)))
        s = 0.0
        for i in range(n_terms):
            s += float(a[i]) * float(b[i])
            if s != 0:
                m, e = np.frexp(s)
                q = 2 ** (-mantissa_bits)
                s = float(np.ldexp(round(m / q) * q, e))
        errs.append(abs(s - exact) / max(abs(exact), 1e-12))
    return float(np.mean(errs))
print("")
print("④ 累加精度：归约长度对相对误差的影响")
print(f"  {'项数':>7} {'FP32 累加(23 位)':>17} {'低精度累加(8 位)':>17}")
for n in (256, 1024, 4096):
    print(f"  {n:>7} {accumulate_error(n, 23):>17.2e} {accumulate_error(n, 8):>17.2e}")
print("  读法：**低精度累加让误差随归约长度增长（256 项 0.042 -> 4096 项 0.211，比 FP32 大约 4.4 万倍）** ——")
print("        所以「输入 FP8、累加 FP32」是数值正确性的底线，不是可选优化")

# ---------- 5) 损失尖峰与回滚 ----------
def effective_throughput(p_spike: float, rollback_steps: int = 100) -> float:
    return 1.0 / (1 + p_spike * rollback_steps)
print("")
print("⑤ 损失尖峰与回滚的代价（每次回滚 100 步并跳过该批数据）")
print(f"  {'尖峰概率/步':>12} {'有效吞吐':>9} {'训练进度损失':>13}")
for p in (0.0, 0.001, 0.005, 0.01, 0.02):
    tp = effective_throughput(p)
    print(f"  {p:>12.3f} {tp:>9.3f} {1 - tp:>12.0%}")
print("  读法：**尖峰概率 1%/步就吃掉约一半训练进度** —— 所以「监控 + 自动回滚 + 跳过坏数据」")
print("        是吞吐的一部分，而不是偶发故障的应急手段")
```

预期输出要点（实跑）：① **逐张量缩放时，离群值把非离群通道的 SQNR 压到 19.3 dB（约 3 位有效），分块缩放回到 54.7 dB**——这是 FP8 训练最关键的工程手段；② 离群幅度从 1 增到 400 时，**逐张量 SQNR 从 49.8 掉到约 37 dB，逐块始终约 54.8 dB**；③ Amdahl 视角：**15% 的算子保 BF16 只损失约 13% 的理想加速**——「小 FLOPs、大影响」的算子保高精度非常划算；④ **低精度累加在 4096 项归约时相对误差约 0.211（FP32 约 4.8e-6，差约 4.4 万倍）**，且随归约长度增长——所以必须 FP32 累加；⑤ **尖峰概率 1%/步就吃掉约一半训练进度**（回滚 100 步），所以回滚机制是吞吐的一部分；⑥ 精度分配表给出「哪些保 BF16/FP32、哪些用 FP8」的完整清单。

## 常见追问

- **追问**：为什么用 1×128 的块而不是更小/更大？
  - 要点：**块越小，越能隔离离群值**（精度更好），但**scale 的数量与开销上升**（存储、通信、kernel 复杂度）；块越大则反之。**1×128 是与硬件（tensor core 的 K 维对齐、向量化访存）匹配的折中点**。实践中还会**按通道方向**再叠一层（例如 128×128 的二维分块）来进一步隔离。
- **追问**：为什么反向传播常用 E5M2 而前向用 E4M3？
  - 要点：**梯度分布更「宽」**（动态范围大、离群更极端），所以需要**更大的指数范围**（E5M2 最大值 57344 vs E4M3 的 448），代价是尾数更少（2 位）。**前向的激活/权重分布相对集中，用精度更高的 E4M3。**
- **追问**：FP8 训练会不会掉质量？
  - 要点：**做对了几乎不掉**（V3 报告 FP8 与 BF16 的损失曲线基本重合），但**前提是分块缩放 + 敏感算子提升 + FP32 累加**。**掉质量通常来自「缩放粒度太粗」或「把归一化/输出头也降精度」**，而不是 FP8 本身。
- **追问**：缩放因子怎么算、怎么传？
  - 要点：① **算**：通常用当前块的 `amax`（绝对值最大）除以 448，可加「延迟更新 + 历史平滑」避免抖动；② **传**：通信 FP8 激活时，**scale 必须与数据一起传**（否则接收端解码不一致），并保证两端**用同一套 scale 语义**；③ **存**：检查点要保存 scale（否则恢复后数值不一致）。
- **追问**：损失尖峰一般怎么定位？
  - 要点：① **记录尖峰前的数据批**（用于事后分析）；② 检查**梯度范数、激活 amax、优化器状态**是否异常；③ 检查**学习率与 warmup**；④ 若与特定数据相关，**跳过该批**并抽样人工看；⑤ 若与数值相关，**提升相关算子的精度**或收紧 scale。**关键是「能回滚 + 能取证」**。
- **追问**：FP8 训练和 FP8 推理是一回事吗？
  - 要点：**不是**。① 训练要处理**梯度与优化器状态**（范围更宽、更需要高精度累加）；② 训练有**反向传播**（E5M2 的用武之地）；③ 训练的**缩放因子要动态更新**（激活分布随训练变化），推理可以离线标定。**推理侧的 FP8 简单得多**（串 [[deepseek-05]]）。
- **追问**：671B 规模下 FP8 的收益到底有多大？
  - 要点：① **显存**：权重与激活减半（但优化器状态仍 FP32，所以总显存收益小于 2×）；② **算力**：tensor core 的 FP8 吞吐是 BF16 的约 2×（本机 Amdahl 算例显示保 15% 高精度后有效 1.74×）；③ **通信**：激活通信减半。**三者叠加才是 FP8 的真实价值**，而不是只看算力。
