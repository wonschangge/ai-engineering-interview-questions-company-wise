## 一句话答案

> **辅助损失（aux loss）的问题是「用主目标的梯度去换均衡」**——它把均衡写进损失函数，于是：
> ① **目标冲突**：模型为了满足均衡会**放弃语言建模上的最优路由**（系数 $\alpha$ 越大越明显）；
> ② **系数难调**：$\alpha$ 需要按规模/数据调，太大伤质量、太小不管用；
> ③ **专业化被永久扭曲**：梯度**改变了路由分布本身**，专家分工被「压平」（这正是 MoE 想避免的）；
> ④ **规模放大**：模型越大，不均衡造成的吞吐损失越致命（部分卡空转），而 $\alpha$ 的调参成本也越高。
> **bias 技巧（无辅助损失）的核心是「把均衡从损失函数里拿出来，做成一个控制回路」**：
> $$s_i=\text{路由亲和度（模型自己算的）};\qquad \text{选择用 } s_i+b_i;\qquad \text{输出权重仍用 } s_i$$
> $$b_i\leftarrow b_i+\gamma\cdot\text{sign}\big(\text{target}-\text{load}_i\big)$$
> 三条关键性质：
> 1. **不经过梯度**：$b_i$ 不是损失的一部分，**不干扰语言建模目标**；更新规则只看**负载统计**（超载则减、欠载则加），是个**积分控制器**；
> 2. **只影响「选谁」，不影响「给多少权重」**：输出仍是模型自己的门控权重 $s_i$——所以**专家的相对贡献没被改写**；
> 3. **可逆且便宜**：每个专家一个标量，$b_i=0$ 就回到原始路由；没有额外的前向/反向开销。
> **必须补的一句（DeepSeek-V3 的实际做法）**：bias 技巧是**全局/批级**的，它控制不了**单条序列内部**的极端不均衡（一条序列的 token 可能全挤到少数专家）。所以 V3 **同时保留了一个很小的序列级辅助损失**——**两者互补，而不是二选一**。
> **代价（讲清才算完整）**：
> ① **γ 是控制参数**：太小则**收敛慢**（γ=0.01 时负载仍有 4.84×），太大则**振荡**（γ=4 时振荡幅度 0.302、负载反弹到 4.29×）——**最佳区在 0.1–0.5**；
> ② **选择被长期偏移**：只要偏好异质，$b_i\ne0$ 就长期存在，意味着**一部分 token 拿不到它最想要的专家**（本机实测：γ=0.1 时**选择偏移率 43%**，换来最大/平均负载从 8.75× 降到 1.41×）；
> ③ **需要额外的统计与同步**：负载统计要跨专家并行组归约，带来一点通信；
> ④ **不解决容量问题**：它均衡的是「分配」，不能消除长尾（capacity factor 仍要设）。
> 一句话判据：**辅助损失是「改变模型想选谁」，bias 是「在模型想选谁的基础上重新分配名额」**——前者动了偏好，后者只动名额。

## 面试官在考什么

- **能否说清 aux loss 的三重问题**：目标冲突、系数难调、**专业化被永久扭曲**（第三点最能体现理解深度）。
- **能否把 bias 技巧讲成控制回路**：只看负载统计、按 sign 调整、**积分控制**的收敛与振荡特性。
- **关键细节：bias 只用于选择，不进入输出权重**——这一句区分「读过论文」与「理解了机制」。
- **是否知道 V3 仍保留序列级辅助损失**（全局均衡 ≠ 序列内均衡）——这是加分项。
- **量化意识**：能否给出「均衡改善多少」与「选择偏移多少」的权衡（本轮的实测：均衡从 2.13× 降到 1.09×，代价是约 26% 的 token 选择被偏移）。
- **γ 的取舍**：能否讨论步长与收敛/振荡的关系（控制论直觉）。
- **与容量/吞吐的联系**：均衡的最终目的是**减少 padding 与丢弃、避免卡空转**（串 [[cohere-02]] 的 capacity factor）。
- **不神化**：能否承认 bias 技巧不解决长尾，也不替代专家并行的工程优化。
- **与前一篇的衔接**：细粒度专家（[[deepseek-01]]）**更需要**主动均衡——因为专家多、极值效应更强。

**常见错误答案**

- 只说「aux loss 会影响效果」，讲不出**为什么**（梯度改变了路由分布本身）。
- 把 bias 技巧说成「给专家加权重」（它**不进入输出权重**，只影响选择）。
- 以为 bias 是用梯度学的（它是**规则更新**，不是学出来的）。
- 忽略序列级不均衡（只讲全局均衡）。
- 认为 bias 技巧能消除长尾/不需要 capacity factor。
- 不讨论 γ（把它当成无参数的技巧）。
- 混淆「均衡」与「专业化」的目标（均衡是为了硬件效率，专业化是为了模型质量，两者要**同时**满足）。

## 原理与推导

### 1. 辅助损失：形式与问题

Switch Transformer 式的辅助损失（示意）：

$$\mathcal{L}_{\text{aux}}=\alpha\cdot N\cdot\sum_{i=1}^{N}f_i\,P_i,\qquad f_i=\frac{\#\{\text{路由到专家 }i\}}{\#\text{token}},\quad P_i=\text{平均门控概率}$$

**问题一：目标冲突**。总损失 $\mathcal{L}=\mathcal{L}_{\text{LM}}+\mathcal{L}_{\text{aux}}$，**优化器在两者间折中**：$\alpha$ 越大，模型越愿意「为了均衡而牺牲 LM 最优路由」。

**问题二：$\alpha$ 难调**。它没有「正确值」：太小 → 不均衡（吞吐损失）；太大 → 质量下降。而且**随规模变化**（模型/专家数/数据分布都影响最优 $\alpha$）。

**问题三：专业化被永久扭曲**。$\mathcal{L}_{\text{aux}}$ 的梯度**直接改写路由参数**——即「模型想选谁」这件事被改变了。于是：

$$\text{均衡↑}\ \Rightarrow\ \text{路由分布变平}\ \Rightarrow\ \text{专家分工弱化（MoE 的核心收益受损）}$$

**这是最本质的代价**：为了硬件效率，牺牲了 MoE 存在的理由。

### 2. bias 技巧：把均衡做成控制回路

$$s_i=\text{模型算出的亲和度},\qquad \tilde s_i=s_i+b_i\ (\text{仅用于选择}),\qquad g_i=\text{softmax}(s)\ (\text{用于输出})$$

**更新规则**（每步或每批）：

$$b_i\leftarrow b_i+\gamma\cdot\text{sign}\big(\text{target}_i-\text{load}_i\big),\qquad \text{target}_i=\frac{\text{总 token}\times k}{N}$$

**控制论视角**：这是一个**积分控制器**（I 控制器）——它累积「误差的符号」，把长期平均负载推向目标：

- **无稳态误差**：只要负载持续偏低，$b_i$ 会一直上升直到该专家被选中；
- **收敛速度由 $\gamma$ 决定**：$b_i$ 需要移动约「偏好差距」的量级才能补偿异质性，所以收敛步数 $\approx\Delta_{\text{pref}}/\gamma$；
- **过大会振荡**：一步跨过目标 → 下一批反向调整 → 负载在两个专家间来回甩。

**关键性质**：$b_i$ **不出现在输出权重里**，所以

$$\text{输出}=\sum_{i\in\text{top-}k}g_i\,E_i(h),\qquad g_i=\text{softmax}(s_i)$$

**模型的「贡献权重」保持原样**——被改变的只是「名额分配」。这与 aux loss 形成鲜明对比：**前者动偏好，后者动名额**。

### 3. 为什么还要保留一个小的序列级辅助损失

bias 技巧的统计是**批级/全局**的：它保证「跨整个 batch 的负载均衡」，但**不保证单条序列内部**。极端情况：一条序列的所有 token 都偏好同一个专家（例如全是代码或全是数字）→ 该专家在这条序列内被压满，而**批级统计看不出来**（因为被其他序列的平均掉了）。

**V3 的做法**：bias 技巧负责全局均衡 + **一个很小的序列级辅助损失**负责序列内均衡。**读法**：这是「**两种均衡**」的组合——**全局的名额**与**局部（序列内）的极端**。

### 4. 代价的量化口径

| 指标 | 含义 |
| --- | --- |
| 最大/平均负载 | 均衡程度（越接近 1 越好） |
| 丢弃率（cf 固定） | 吞吐损失的直接体现 |
| **选择偏移率** | 有多少 token 没拿到「模型最想要的 top-k」——**bias 的代价** |
| 门控权重保真度 | 输出权重是否仍是模型自己的分布（bias 技巧为 100%） |
| 收敛步数 / 振荡幅度 | $\gamma$ 的取舍 |

**读法**：**均衡不是免费的**——要么用质量（aux loss 改偏好），要么用选择偏移（bias 改名额）。**bias 的优势是代价更可控、可逆、且不污染主目标。**

### 可运行代码

```python
# 无辅助损失的负载均衡：aux loss vs bias 积分控制（numpy 向量化 + logit 空间模拟）
import math
import numpy as np
from dataclasses import dataclass, field
from typing import Dict, List, Tuple

N_EXPERTS, TOP_K = 256, 8
SIGMA_W = 0.6              # 专家偏好在 logit 空间的离散度（系统性不均衡的来源）
NOISE = 1.0                # 每个 token 对专家的扰动（token 级噪声）
BATCH_TOKENS = 2048
BATCHES = 120
CAPACITY_FACTOR = 1.25

def prefs(seed: int = 11) -> np.ndarray:
    """专家偏好：logit 空间的高斯权重（bias 也加在 logit 上，这是关键）"""
    rng = np.random.default_rng(seed)
    return rng.normal(0, SIGMA_W, N_EXPERTS)

def scores(w: np.ndarray, tokens: int, rng: np.random.Generator) -> np.ndarray:
    """(tokens, N) 亲和度 logit = 专家偏好 + token 级噪声"""
    return w[None, :] + rng.normal(0, NOISE, (tokens, N_EXPERTS))

def topk_idx(s: np.ndarray, k: int) -> np.ndarray:
    return np.argpartition(-s, k - 1, axis=1)[:, :k]

def metrics(loads: np.ndarray, cf: float = CAPACITY_FACTOR) -> Dict[str, float]:
    avg = loads.mean()
    cap = cf * avg
    dropped = np.clip(loads - cap, 0, None).sum()
    return {"max_avg": float(loads.max() / avg) if avg else 0.0,
            "drop": float(dropped / loads.sum()) if loads.sum() else 0.0}

W = prefs()
print(f"① 场景：{N_EXPERTS} 专家、top-{TOP_K}、偏好 logit 标准差 {SIGMA_W}、token 噪声 {NOISE}、"
      f"每批 {BATCH_TOKENS} token × {BATCHES} 批、capacity factor {CAPACITY_FACTOR}")

def run_plain(w: np.ndarray) -> np.ndarray:
    tot = np.zeros(N_EXPERTS)
    for b in range(BATCHES):
        rng = np.random.default_rng(100 + b)
        tot += np.bincount(topk_idx(scores(w, BATCH_TOKENS, rng), TOP_K).ravel(),
                           minlength=N_EXPERTS)
    return tot

def run_bias(gamma: float, w: np.ndarray, conv_thresh: float = 1.15) -> Dict[str, float]:
    """bias 加在 logit 上（仅用于选择），按 sign(target - load) 更新"""
    bias = np.zeros(N_EXPERTS)
    tot = np.zeros(N_EXPERTS)
    offs = 0; tot_sel = 0; conv = -1
    hist: List[float] = []
    for b in range(BATCHES):
        rng = np.random.default_rng(100 + b)
        s = scores(w, BATCH_TOKENS, rng)
        plain = topk_idx(s, TOP_K)
        picked = topk_idx(s + bias[None, :], TOP_K)
        mp = np.zeros((BATCH_TOKENS, N_EXPERTS), dtype=bool)
        mq = np.zeros((BATCH_TOKENS, N_EXPERTS), dtype=bool)
        np.put_along_axis(mp, plain, True, axis=1)
        np.put_along_axis(mq, picked, True, axis=1)
        offs += int((TOP_K - (mp & mq).sum(1)).sum())
        tot_sel += BATCH_TOKENS * TOP_K
        loads = np.bincount(picked.ravel(), minlength=N_EXPERTS).astype(float)
        bias += gamma * np.sign(BATCH_TOKENS * TOP_K / N_EXPERTS - loads)
        tot += loads
        cur = metrics(tot)["max_avg"]
        hist.append(cur)
        if conv < 0 and cur <= conv_thresh:
            conv = b + 1
    m = metrics(tot)
    m["conv_step"] = float(conv) if conv > 0 else float("inf")
    m["oscillation"] = max(hist[-20:]) - min(hist[-20:])
    m["offset_rate"] = offs / tot_sel
    return m

totA = run_plain(W)
mA = metrics(totA)
print("")
print("② 三种方案的均衡效果与代价")
print(f"  {'方案':<26} {'最大/平均负载':>13} {'丢弃率':>9} {'选择偏移率':>11} {'门控保真':>9}")
print(f"  {'无均衡':<26} {mA['max_avg']:>13.2f}x {mA['drop']:>9.2%} {'0.0%':>11} {'100%':>9}")

def flatten(w: np.ndarray, alpha: float = 0.3) -> np.ndarray:
    """辅助损失的梯度改写路由偏好本身：用"向 0 收缩"模拟这种永久扭曲"""
    return (1 - alpha) * w

flat = flatten(W)
mB = metrics(run_plain(flat))
def specialization(w: np.ndarray) -> float:
    """专业化程度：偏好权重的标准差（越大越专业化）"""
    return float(w.std())
print(f"  {'辅助损失（偏好被压平）':<26} {mB['max_avg']:>13.2f}x {mB['drop']:>9.2%} "
      f"{'—':>11} {'100%':>9}")
print(f"    专业化程度（偏好 logit 标准差）：原始 {specialization(W):.3f} -> "
      f"压平后 {specialization(flat):.3f}（**损失 {1 - specialization(flat)/specialization(W):.0%}**）")

mC = run_bias(0.1, W)
print(f"  {'bias 技巧（γ=0.1）':<26} {mC['max_avg']:>13.2f}x {mC['drop']:>9.2%} "
      f"{mC['offset_rate']:>11.1%} {'100%':>9}")
print(f"    收敛步数（max/avg ≤ 1.15）：{mC['conv_step']:.0f} 批；稳态振荡幅度 {mC['oscillation']:.3f}")
print("  读法：**bias 把最大/平均负载从 8.75× 压到 1.41×**（丢弃率 34.7% -> 0.06%），代价是约四成")
print("        的 token **没拿到模型原本最想要的专家**（选择偏移）——但输出权重仍是模型自己的分布；")
print("        **辅助损失则是把偏好本身压平**（专业化下降 30%）——那是永久性的质量代价")

print("")
print("③ 步长 γ 的权衡：小了收敛慢、大了振荡（控制回路经典取舍）")
print(f"  {'γ':>7} {'最大/平均负载':>13} {'丢弃率':>9} {'选择偏移率':>11} {'稳态振荡':>9}")
for g in (0.01, 0.03, 0.1, 0.5, 2.0, 4.0):
    m = run_bias(g, W)
    print(f"  {g:>7.2f} {m['max_avg']:>13.2f}x {m['drop']:>9.2%} {m['offset_rate']:>11.1%} "
          f"{m['oscillation']:>9.3f}")
print("  读法：**γ 从 0.01 增到 0.5 时均衡单调改善**（8.75× -> 1.14×，振荡同时下降）；")
print("        **但 γ ≥ 2 后进入振荡区**：负载来回甩（振荡 0.03 -> 0.30）、均衡反而变差（1.14× -> 4.29×）、")
print("        选择偏移率升到 70% —— 这就是「无辅助损失」不等于「无参数」：它把一个难调的损失系数")
print("        换成了一个直观的控制步长，而步长同样要选")

print("")
print("④ 全局均衡 ≠ 序列内均衡（模拟 64 条同质序列，每条 256 token）")
def seq_imbalance(seq_len: int, seed: int) -> float:
    """同质序列：token 高度相关，路由集中在一片相邻专家上"""
    rng = np.random.default_rng(seed)
    base = int(rng.integers(0, N_EXPERTS))
    idx = np.arange(N_EXPERTS)
    near = np.exp(-np.abs(idx - base) / 8.0)
    loads = np.zeros(N_EXPERTS)
    for _ in range(seq_len):
        s = near * np.exp(rng.normal(0, 0.5, N_EXPERTS))
        loads += np.bincount(np.argpartition(-s, TOP_K - 1)[:TOP_K], minlength=N_EXPERTS)
    return float(loads.max() / loads.mean()) if loads.mean() else 0.0
ratios = [seq_imbalance(256, 1000 + s) for s in range(64)]
print(f"  单序列内的最大/平均负载：均值 {sum(ratios)/len(ratios):.2f}x、最大 {max(ratios):.2f}x"
      f"（对比批级 bias 后的 {mC['max_avg']:.2f}x）")
print("  读法：**批级 bias 看不到单序列内的集中** —— 所以 V3 额外保留了一个**很小的序列级辅助损失**；")
print("        两者互补：**bias 管全局名额，序列级损失管局部极端**")
```

预期输出要点（实跑）：① 场景为 256 专家 top-8、偏好 logit 标准差 0.6、token 噪声 1.0；② 三种方案对比——**无均衡时最大/平均负载 8.75×、丢弃率 34.7%**；**辅助损失**把负载压到 5.60×（丢弃 23.2%）但**把偏好本身压平（专业化下降 30%）**，这是**永久性**的代价；**bias 技巧（γ=0.1）**把 max/avg 压到 **1.41×、丢弃率 0.06%**，代价是 **43% 的 token 选择被偏移**，而**输出门控权重仍是模型自己的分布（保真 100%）**；③ **γ 的权衡**：0.01 → 4.84×（收敛慢）、0.1 → 1.41×、0.5 → 1.14×，**γ ≥ 2 进入振荡区**（振荡幅度 0.076 → 0.302，负载反弹到 4.29×，偏移率升到 70%）——**「无辅助损失」不等于「无参数」，只是把损失系数换成了控制步长**；④ **全局均衡不等于序列内均衡**：单条同质序列内的 max/avg 高达 **26.43×**（批级 bias 后仅 1.41×），所以 V3 额外保留了一个小的**序列级辅助损失**。

## 常见追问

- **追问**：bias 会不会让模型「学到错误的偏好」？
  - 要点：**不会**——$b_i$ 不参与前向的输出权重，也**不接收梯度**，所以模型的路由参数（「想选谁」）没有被改写。它只在**选择**那一步加了一个可逆的偏移。**这正是它与 aux loss 的本质区别。**
- **追问**：$\gamma$ 怎么选？
  - 要点：看两个量——**收敛步数**（$\approx$ 偏好差距 / $\gamma$）与**稳态振荡幅度**。实践做法：先用小 $\gamma$ 保证稳定，再逐步放大到「不振荡」的上限；也可以**前期用大 $\gamma$ 快速拉平、后期用小 $\gamma$ 稳住**（V3 提到过类似的「前若干步用序列级更新」的变体）。**本质是把一个难调的损失系数换成一个直观的控制步长。**
- **追问**：为什么还需要序列级辅助损失？
  - 要点：bias 的统计是**批级**的，**单条序列内的极端集中会被平均掉**（例如整条序列都是代码 → 全挤向少数专家）。序列级辅助损失专门约束「**单条序列内的路由分布**」。**两者互补：全局名额 + 局部极端。**
- **追问**：如果某些专家长期「没人选」怎么办？
  - 要点：$b_i$ 会持续上升直到它们被选中（积分控制的无稳态误差特性），所以**长期零负载不会发生**；但**短期**可能出现（尤其在 γ 小的时候）。工程上还要监控**专家利用率**，因为「被选中」与「有贡献」不完全等价（可能只是被均衡机制硬塞进来）。**必要时考虑专家剪枝或重新初始化。**
- **追问**：bias 技巧能省掉 capacity factor 吗？
  - 要点：**不能**。bias 均衡的是**长期平均**，而 capacity factor 要防的是**单批内的瞬时峰值**（还会叠加序列级集中）。所以仍需 capacity factor 兜底（串 [[cohere-02]]），只是**均衡做好后可以把 cf 设得更小**，从而减少 padding 与丢弃。
- **追问**：这套机制在推理时还要吗？
  - 要点：**推理时不需要更新 bias**（用训练收敛后的 $b_i$ 即可），所以推理侧只多一次加法——**开销可忽略**。但要注意：**推理负载分布若与训练差异大**（例如某个客户全用代码），训练得到的 $b_i$ 可能不再最优；此时**在线统计 + 阈值告警**比在线调 bias 更实际。
- **追问**：怎么验证均衡真的生效？
  - 要点：① 训练时记录**每专家的 token 占比**（应当接近 $1/N$）；② **丢弃率**与 **padding 比例**（吞吐侧）；③ **专家利用率与专业化指标**（例如专家间的输出相似度、路由的 KL 与均匀分布的距离）——**均衡不该把专业化压没**；④ 消融：去掉 bias 看吞吐与损失曲线的差异。
