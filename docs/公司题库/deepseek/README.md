# DeepSeek 面试题库

这一家的题有一个很集中的主题：**在资源约束下把大模型训出来、并且服务出去**。
十道题里七道直接落在「约束下的工程选择」上——**显存换质量**（MoE）、**显存换时间**（DualPipe）、
**精度换吞吐**（FP8）、**算力换标注**（RLVR）、**验证换多样性**（合成数据过滤）。
另外两道是服务与行为，也都在讲「口径与取舍」。

准备这一家时，建议把**「这是一次交换，代价是什么」**当成口头禅：
每讲一个技术优势，就补一句它的代价与适用边界——这正是这家公司的面试官想听的思维方式。

## 这家公司的面试怎么准备

**第一，一切都要能落到「交换」上。** 这一家的技术选择几乎都是资源之间的重新定价：
MoE 用显存换算力、DualPipe 用显存换时间、FP8 是唯一两头都省、RLVR 用算力换标注。
**能主动说出代价与边界，比只讲优势更贴合这家公司的语境。**

**第二，数字要能脱口而出。** 这一家的面试里高频出现的锚点：
组合数 $\binom{N}{k}$、激活比例、KV 每 token 字节、气泡公式 $\frac{PP-1}{m+PP-1}$、
$pN$（期望命中次数）、以及「每 token 激活算力」这类量级。
本仓库的十篇都给了实跑数字，可以直接用来做记忆锚点。

**第三，把「实测与引用」分清楚。** 这一家的技术报告里有大量结论无法在小规模复现
（例如 MTP 的表示收益、R1 的训练曲线）。**本文档的做法是：能实测的就实测，不能的就明确标注「未复现，仅引用」**——
这种诚实本身就是面试加分项，因为它表明你知道**结论的适用边界**。

**第四，行为题也要有结构。** 第 10 题示范了怎么回答「这怎么可能」这类**半技术半叙事**的问题：
**拆口径 → 分层归因 → 主动交底 → 给出可证伪的验证路径**。这套结构可以迁移到任何「评价一个说法」的场合。
