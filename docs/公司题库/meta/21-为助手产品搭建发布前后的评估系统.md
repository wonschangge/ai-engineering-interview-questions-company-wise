## 一句话答案

> 把评估系统当成一个**有版本、有门禁、有成本预算的产品**，而不是一堆脚本。它由五块组成：
> ① **评测矩阵**——能力（推理、代码、多语言、长上下文、工具调用）× 场景（问答、写作、助手任务、多轮）× 语言 × 风险等级，每一格都要有样本与判分方式；
> ② **发布门禁**——**硬门**（安全红线、格式合法率、工具调用成功率、越狱成功率上限）一票否决；**软门**（能力指标不退化）要求**统计显著**而不是小数点比较；
> ③ **回归集**——**每一起线上事故变成一条永久测试用例**（这是评测集增长最可靠的来源，也避免同一个 bug 反复出现）；
> ④ **人在环**——分层抽样 + 盲评 + 一致性检验；LLM-as-judge 只能作为**加速器**，必须用人工标注校准它的偏差（位置、长度、自偏好）；
> ⑤ **在线层**——A/B 与护栏指标、长期 holdout，用来发现离线测不到的退化（串 [[evaluation-05]]）。
> 一句话纪律：**离线是回归网，在线是判据，人评是仲裁**；三者缺一，发布就会变成赌博。

## 面试官在考什么

- **门禁的可运营性**：每次发布都要在有限时间（例如数小时）与有限算力内跑完，所以要有**分层抽样**（全量跑红线集 + 抽样子集跑能力集）与清晰的通过/阻断规则。
- **统计意识**：是否知道小样本下「差 1 个百分点」通常不显著，会要求置信区间或重复采样；也应当主动提出「用配对比较（同一批 prompt 两个模型各跑一次）」来降方差。
- **污染与过拟合评测集**：模型迭代多轮后团队会不自觉地对评测集过拟合（反复调 prompt 直到指标好看）。要能说出私有留出、定期轮换、以及持续更新的公开基准（可引用 LiveBench 的设计口径：题目按月更新、答案有客观 ground truth 可自动判分、规避众包与 LLM judge 的主观偏差，发布时最强模型低于 70%），以及污染检测的手段与局限（可引用 Deng et al. 的 TS-Guessing 探针：ChatGPT 与 GPT-4 仅凭上下文就能以 52% 与 57% 的精确匹配率猜出 MMLU 中被遮住的错误选项，这是较强的记忆证据，但**不是答题准确率**）。
- **Agent 类能力怎么评**：单轮问答的准确率无法覆盖多轮工具调用；可引用 τ-bench 的口径——在真实域名（零售、航空）里让模型与模拟用户多轮交互、用数据库最终状态判定任务是否真的完成，并报告 **pass^k**（同一任务重复 $k$ 次全部成功的比例），用来衡量**一致性**而不是最好一次的表现。
- **红队与安全的闭环**：安全评估不是一次性的，而是「攻击 → 发现 → 转成回归用例 → 门禁」的循环（串 [[meta-22]]）。
- **成本与时间的显式预算**：能不能给出「一次发布评测需要多少 GPU 小时、多少人评小时」的量级。

**常见错误答案**

- 「跑一遍公开榜单就行」——公开榜单既不覆盖你的产品场景，也不能防止过拟合（且可能被污染）。
- 「指标涨了就发布」——没有硬门与护栏，安全与格式回归会在线上暴露。
- 「用 GPT-4 当 judge 就够了」——judge 有位置偏差、长度偏好、对自家输出的偏好；不校准的 judge 会系统性偏移。
- 「评测集固定不变以便对比」——固定集合会被迭代过拟合；要有轮换与私有留出的组合。

## 原理与推导

### 1. 评测矩阵与优先级

| 维度 | 取值示例 | 判分方式 | 优先级 |
| --- | --- | --- | --- |
| 能力 | 数学推理、代码、多语言、长上下文、指令跟随 | 精确匹配/单测/模型判分 | 高（能力回归） |
| 场景 | 单轮问答、多轮助手、带工具的任务 | 规则 + 人工 + 数据库状态 | 高（产品核心） |
| 风险 | 越狱、有害内容、隐私、未成年保护 | 攻击成功率/分类器判定 | **最高（硬门）** |
| 语言 | 主要语种 + 长尾语种 | 分语种报告，禁止平均 | 中 |
| 系统 | 延迟、成本、格式合法率、拒答率 | 直接测量 | 高（硬门） |

**分语种、分场景报告、禁止平均**是这一节的纪律：一个跨语言平均值会掩盖某个语种的严重退化。

### 2. 门禁的三类门与判定规则

1. **硬门（一票否决）**：安全红线攻击成功率不得超过基线；格式合法率、工具调用成功率不得低于阈值；拒答率不得异常上升。
2. **软门（统计判定）**：能力指标与基线做**配对比较**；只有在置信区间不重叠（或预设的等价性检验失败）时才判定回归。
3. **构建门（流程）**：评测集本身有版本号，任何改动需评审（否则「指标涨了」可能只是题变了）。

配对比较的直观理由：同一批 prompt 上，两模型的差异方差远小于跨批次的方差，所以**同样样本量下配对设计的检出力更高**。

### 3. 样本量与噪声：别把噪声当回归

对二项比例，用 Wilson 区间近似：

$$\hat p\pm z_{1-\alpha/2}\sqrt{\frac{\hat p(1-\hat p)}{n}}$$

$n=200$、$\hat p=0.70$ 时，95% 区间约为 $[0.633,0.762]$（宽度约 13 个百分点）——**这意味着一两百条样本根本区分不了 2–3 个百分点的差异**。工程结论：能力门禁要么用足够大的样本（数百到数千），要么用配对比较/多次采样，要么把判定阈值设得比噪声大。

### 4. 人评与 LLM-judge 的校准

- **抽样设计**：按场景与风险分层；对高风险场景全量人评，对低风险场景按比例抽样。
- **盲评与一致性**：不告诉评审哪个是哪个模型；计算评审者之间一致性（Cohen's κ 或 Krippendorff's α）；一致性太低说明评分标准不清，要先改标准。
- **judge 校准**：先让人工标注一批（例如 500 条）作为校准集，测 judge 与人工的一致率与偏差方向；位置偏差用交换顺序两次判定来抵消；长度偏好用长度分桶检查。
- **judge 的适用边界**：适合「有明确标准、答案可读性/遵循度」类判定；**不适合**需要外部事实核验、需要执行代码、或高风险安全判定（那些要用规则、单测、分类器、人审）。

### 5. 在线层与闭环

- **A/B 与护栏**：主指标（任务成功率、用户满意度）与护栏（延迟、成本、拒答率、负反馈、安全事件率）同时看；预注册分析口径（串 [[evaluation-09]]）。
- **长期 holdout**：保留一小部分流量长期使用旧版本，用于测量长期效应（留存、信任）。
- **事故转用例**：每起线上事故都要产出「最小可复现 prompt + 判定断言」，进入回归集；这是评测集最有价值的增长方式。
- **污染与过拟合防护**：私有留出集不参与任何调参；公开集只作参考；对训练数据做去污染并保留记录（串 [[alibaba-08]]、[[evaluation-06]]）。

## 数值与代码验证

### 表 1：一次发布的评测预算（示例）

| 项 | 规模 | 资源 | 时间 |
| --- | --- | --- | --- |
| 红线集（安全） | 5,000 条攻击 prompt × 2 轮 | 8×H100 | 1.5 h |
| 能力集（抽样） | 12,000 条 prompt | 8×H100 | 2 h |
| Agent 任务（τ-bench 式） | 300 个任务 × pass^4（每任务 4 次） | 8×H100 | 3 h |
| 人评 | 800 条分层抽样 × 2 位评审 | 人工 | 40 人·小时 |
| 在线灰度 | 1% 流量 × 3 天 | 生产 | 3 天 |

口径：规模与时间为构造示例（8×H100 节点的推理吞吐按仓库统一常数估算）；**人评 40 人·小时**是常被低估的一项——发布节奏快时它才是真正的瓶颈。

### 表 2：样本量与可检测差异（二项比例，双侧 α=0.05、power=80%）

| 样本量 $n$ | $\hat p=0.5$ 可检测的绝对差异 | $\hat p=0.9$ 可检测的绝对差异 |
| --- | --- | --- |
| 200 | ≈ 14 个百分点 | ≈ 8 个百分点 |
| 1,000 | ≈ 6.3 个百分点 | ≈ 3.7 个百分点 |
| 5,000 | ≈ 2.8 个百分点 | ≈ 1.6 个百分点 |
| 20,000 | ≈ 1.4 个百分点 | ≈ 0.8 个百分点 |

读法：**要检测 1 个百分点的退化，在 $\hat p=0.9$ 处也需要两万条量级的样本**。这就是为什么发布门禁要么样本足够，要么改用配对比较与重复采样。

### 可运行代码

```python
# 1) 用 Wilson 区间判断「版本 B 是否真的比 A 差」，并演示配对比较的收益
import math, random
random.seed(31)

def wilson(k, n, z=1.959964):
    if n == 0: return (0.0, 1.0)
    p = k / n
    d = 1 + z*z/n
    c = p + z*z/(2*n)
    r = z * math.sqrt(p*(1-p)/n + z*z/(4*n*n))
    return ((c - r)/d, (c + r)/d)

def verdict(kA, nA, kB, nB):
    loA, hiA = wilson(kA, nA); loB, hiB = wilson(kB, nB)
    if hiB < loA: return "B 显著更差（阻断）"
    if loA < hiB and loB < hiA: return "差异不显著（放行，需记录）"
    return "B 显著更好"

for nA, nB, pA, pB in [(200, 200, 0.70, 0.67), (2000, 2000, 0.70, 0.67),
                       (2000, 2000, 0.70, 0.60)]:
    kA, kB = int(nA*pA), int(nB*pB)
    loA, hiA = wilson(kA, nA); loB, hiB = wilson(kB, nB)
    print(f"n={nA:>5} A={kA/nA:.3f}[{loA:.3f},{hiA:.3f}]  B={kB/nB:.3f}[{loB:.3f},{hiB:.3f}]"
          f"  -> {verdict(kA, nA, kB, nB)}")

# 配对比较：同一批 prompt 上两模型的差异（方差更小）
P = 2000
base_p, delta = 0.70, -0.03
pair_diff = [random.random() < delta for _ in range(P)]        # 每条 prompt 上 B 是否比 A 差
k = sum(pair_diff)
lo, hi = wilson(k, P)
print(f"\n配对设计：{P} 条 prompt 中 B 比 A 差 {k} 条 -> 差值比例 {k/P:.3f} [{lo:.3f},{hi:.3f}]"
      f"，{'显著' if lo > 0 else '不显著'}")
print("对比上面同规模的非配对结果：配对设计用同样样本量得到更紧的区间（检出力更高）")

# 2) 门禁实现：硬门 + 软门 + 构建门
GATES = {
    "safety_jailbreak_rate": ("hard_max", 0.02),      # 攻击成功率上限 2%
    "tool_call_success":     ("hard_min", 0.95),      # 工具调用成功率下限
    "format_valid":          ("hard_min", 0.99),
    "capability_math":       ("soft", 0.0),           # 与基线配对比较，不显著退化即可
}
def run_gates(metrics, baseline):
    fails = []
    for k, (kind, thr) in GATES.items():
        if kind == "hard_max" and metrics[k] > thr:
            fails.append(f"{k}={metrics[k]:.3f} > {thr}（硬门）")
        if kind == "hard_min" and metrics[k] < thr:
            fails.append(f"{k}={metrics[k]:.3f} < {thr}（硬门）")
        if kind == "soft" and metrics[k] < baseline[k] - 0.03:
            fails.append(f"{k}={metrics[k]:.3f} 低于基线 {baseline[k]:.3f} 超过 3pp（软门）")
    return fails

baseline = {"capability_math": 0.62}
for name, m in [("候选版（合格）", {"safety_jailbreak_rate": 0.011, "tool_call_success": 0.962,
                                 "format_valid": 0.994, "capability_math": 0.63}),
                ("候选版（越狱超标）", {"safety_jailbreak_rate": 0.031, "tool_call_success": 0.97,
                                   "format_valid": 0.995, "capability_math": 0.65})]:
    fails = run_gates(m, baseline)
    print(f"\n{name}: {'阻断' if fails else '通过'}")
    for f in fails:
        print("   ✗", f)

# 3) Agent 能力的 pass^k：一致性比最好一次更重要
def pass_pow_k(p_single, k):
    return p_single ** k
print("\npass^k（单次成功率 -> 连续 k 次全成功的概率）")
for p in (0.90, 0.70, 0.50):
    print(f"  单次 {p:.2f}: pass^1={pass_pow_k(p,1):.3f}  pass^4={pass_pow_k(p,4):.3f}"
          f"  pass^8={pass_pow_k(p,8):.4f}")
print("单次 90% 的任务在 pass^8 口径下只剩约 43% —— 这就是 agent 类能力必须报 pass^k 的原因")
```

预期输出要点：第 1 段显示 **$n=200$ 时 3 个百分点的差异完全不显著**（放行），样本增到 2000 仍不显著，而 10 个百分点的差异才显著——这就是「别把噪声当回归」；配对设计在同样样本量下给出更紧的区间；门禁段演示越狱率超标被硬门阻断（即使能力指标更好）；`pass^k` 段量化一致性衰减（单次 90% → pass^8 约 43%）。

## 常见追问

- **追问**：评测集多久更新一次？怎么防过拟合？
  - 要点：公开集持续更新（LiveBench 式按月更新）；内部集分层——**固定核心集**（用于跨版本对比）+ **轮换集**（定期换新，防止调参过拟合）+ **私有留出**（永不参与调参，只用于对外声称）。
- **追问**：LLM-as-judge 能信吗？
  - 要点：作为加速器可信，作为最终判据不可信。做法：人工校准集测一致率与偏差、交换顺序抵消位置偏差、长度分桶检查长度偏好、以及对高风险判定改用规则/分类器/人审。
- **追问**：离线指标涨、线上没涨，怎么办？
  - 要点：先查分布对齐（离线 prompt 与线上分布是否一致）、再看在线指标是否够灵敏（样本量、代理指标）、最后看链路（延迟/拒答/安全拦截是否吃掉了收益）。这与 [[evaluation-05]] 的七类原因同源。
- **追问**：安全评测为什么要独立成硬门？
  - 要点：安全退化与能力提升往往同时发生（更听话的模型更容易被诱导），用软门的「平均分」会被能力增益掩盖；独立硬门保证安全不退化是不可交易的。
- **追问**：Agent 类任务怎么判定成功？
  - 要点：看**最终状态**而不是回复文本（可引用 τ-bench 的做法：以数据库最终状态判定任务是否真的完成），并报告 pass^k 而不是取最好一次。
- **追问**：怎么让评测集持续增长而不腐化？
  - 要点：把线上事故、红队发现、用户反馈都转成带断言的用例；要求每个用例有 owner 与来源标注；定期清理重复与失效用例（用例本身也要有维护成本）。
