## 一句话答案

> 端到端 = **接入与规整 → 多模态表示 → 分层分类（类目树 + 属性抽取 + 政策标签）→ 置信度路由（自动通过 / 人审 / 打回补信息）→ 反馈闭环**。
> 但真正的题眼不在模型，而在三件事：
> ① **分类体系（taxonomy）本身在漂移**——类目会新增、合并、改名，模型必须支持增量而不必全量重训；
> ② **长尾**——头部几个类目占绝大多数样本，尾部类目样本极少但业务上同样重要（甚至是政策风险最高的那批）；
> ③ **误分类代价极不对称**——把普通商品误判成违禁品，损失是一个卖家的体验；把违禁品误判成普通商品，损失是合规事故。所以最终形态一定是**按类目分别标定阈值的代价敏感路由**，而不是统一的 0.5 阈值。
> 一句话总结：这是「多模态分类 + 层级体系 + 主动学习人审预算」的组合题，答题时必须把三个成本（模型成本、人审成本、误分类成本）都算出来。

## 面试官在考什么

- **端到端的完整性**：有没有覆盖「卖家填写 → 图片/文本规整 → 分类与属性抽取 → 政策判定 → 人审 → 上线后反馈」全链路，而不是只讲分类模型。
- **层级分类的处理方式**：是训练一个扁平分类器（类目数上千、长尾极重），还是**逐层分类**（先大类后子类）、或用层次化 softmax；能不能说出各自的取舍（扁平模型能共享统计强度但尾部更差；逐层模型每层样本更均衡但错误会级联）。
- **多模态融合**：标题/描述是文本，图片是视觉，价格/位置是结构化字段。会不会提到 early fusion（把图片 patch 与文本 token 一起送进一个 Transformer，可引用 LayoutLMv3 的统一文本-图像掩码预训练思路）与 late fusion（各模态分别编码后拼接，工程上更易增量更新）的取舍。
- **零样本/少样本能力**：新类目出现时怎么办——可引用 CLIP 式的图文对比学习：用类目名或类目描述做文本查询、与图片嵌入比对，可以在**没有该类目标注样本**时给出可用初值（这正是 Marketplace 新类目冷启动的实用手段）。
- **代价敏感与路由**：能否给出基于代价矩阵的阈值推导（而不是拍一个 0.9），并说清人审预算（每天能审多少条）如何决定自动通过率。
- **政策与体验的分层**：政策标签（违禁、仿品、成人、诈骗）与商品类目是两套目标，代价矩阵不同、需要分开建模；可引用的工程做法来自 *A Holistic Approach to Undesired Content Detection in the Real World*：把分类器与政策规则结合、并按危害类别分别评估，而不是只看总体准确率。

**常见错误答案**

- 「用一个大模型把所有类目一次分完」——忽略长尾（尾部类目样本不足）与类目体系漂移（新增类目要重训）。
- 「统一用 0.9 阈值」——忽略代价不对称与人审预算；阈值必须按类目与危害等级分别标定。
- 「只做图片分类」——商品标题里往往含关键信息（品牌、型号、违禁词），只做视觉会漏掉大量政策风险。
- 「准确率 99% 就够了」——在 1% 的违禁品基率下，99% 准确率可能意味着漏掉一半违禁品或误杀大量正常商品；要看分层的精确率/召回率与代价。

## 原理与推导

### 1. 流水线的五个阶段

| 阶段 | 输入 | 输出 | 关键工程点 |
| --- | --- | --- | --- |
| 接入与规整 | 卖家填写字段、图片 | 规范化的字段 + 图片变体（缩略图、多分辨率） | 去重、EXIF 清理、图片质量检测（模糊/截图/水印） |
| 多模态表示 | 标题、描述、图片、结构化字段 | 文本嵌入 + 视觉嵌入 + 结构化特征 | 嵌入离线预计算并缓存；支持增量更新 |
| 分层分类 | 上述表示 | 类目路径 + 属性 + 政策标签 | 类目树分层、长尾处理、政策头独立 |
| 代价敏感路由 | 各头概率 + 代价矩阵 | 自动通过 / 人审 / 打回 | 阈值按类目标定；人审队列按优先级排序 |
| 反馈闭环 | 人审结论、用户举报、卖家申诉 | 新标签 + 阈值重标定 | 主动学习采样；申诉结果必须回灌 |

### 2. 层级分类与长尾

设类目树深度 3、叶子类目数千。三种做法：

1. **扁平多分类**：一个 softmax 覆盖全部叶子。优点是共享统计强度；缺点是尾部类目梯度被头部淹没。
2. **逐层分类**：每层一个分类器（先 20 个大类，再各层子类）。每层样本更均衡、易于增量新增类目（只在对应父节点下加一个子类头）；缺点是**错误级联**——父层错了，子层再准也没用（可用 beam search 保留多个父候选缓解）。
3. **混合**：头部类目用扁平模型（数据足），尾部与新增类目用**检索式分类**（用类目描述的文本嵌入与商品嵌入做最近邻，可引用 CLIP 式的图文对齐思路），无需训练即可覆盖新类目，再逐步积累样本转入监督模型。

长尾的常用手段：重采样/重加权、logit adjustment（按类先验校正 logits）、以及把尾类归入「相似类目检索」而不是硬分类。

### 3. 多模态融合的两种形态

- **Early fusion**：把图片的 patch token 与文本 token 拼成一个序列送进同一个 Transformer，让跨模态注意力直接建模「图片里的文字 ↔ 标题里的品牌」。可引用的依据是 LayoutLMv3 的统一文本-图像掩码预训练（在同一 Transformer 上同时做文本与图像掩码）。代价是推理成本高、图片分辨率受限。
- **Late fusion**：视觉塔与文本塔分别编码，再拼接/交叉注意力融合。工程上更常见：**两个塔可以独立更新与缓存**，图片嵌入离线算好（Marketplace 里同一张图可能被多次复用），延迟可控。

实际系统通常是 late fusion 为主 + 关键字段（如品牌/型号的 OCR 文本）单独抽取，作为强特征喂给融合层。

### 4. 代价敏感阈值：把「该不该自动通过」算出来

设某类目自动通过的阈值为 $t$，则

$$\text{ExpectedCost}(t)=c_{\text{FP}}\cdot \underbrace{\text{FP}(t)}_{\text{误杀正常商品数}}+c_{\text{FN}}\cdot \underbrace{\text{FN}(t)}_{\text{漏放违规数}}+c_{\text{H}}\cdot \underbrace{\text{HR}(t)}_{\text{送人审数}}$$

其中 $c_{\text{FP}}$ 是误杀代价（卖家体验 + 申诉成本），$c_{\text{FN}}$ 是漏放代价（合规/信任损失，通常高几个数量级），$c_{\text{H}}$ 是单条人审成本。**人审预算**给出约束 $\text{HR}(t)\le B$，于是最优阈值是「在预算约束下最小化 $c_{\text{FP}}\text{FP}+c_{\text{FN}}\text{FN}$」。

这个式子有两个直接推论，面试里说出来就是区分度：
- **不同类目要有不同阈值**（$c_{\text{FN}}/c_{\text{FP}}$ 的比值不同）；
- **人审预算变化会改变阈值**（预算减半，自动通过率必须提高，漏放风险随之上升——这是一个必须向业务显式说明的权衡）。

### 5. 反馈闭环与主动学习

- **采样策略**：不要随机抽人审，优先抽「模型不确定」（熵高/接近阈值）与「分布上新」（与已审样本距离远）的样本——这就是主动学习的收益来源。
- **申诉回灌**：卖家申诉成功 = 标签错误的高置信度来源，必须回灌并触发阈值重标定。
- **漂移监控**：类目分布、政策命中率、误杀率分群监控；类目体系变动（新增/合并）要有专门的迁移流程（串 [[consumer-ml-13]]）。

## 数值与代码验证

### 表 1：代价敏感路由的算例（某类目，日新增 100 万条，人审预算 2 万条/天）

| 阈值 $t$ | 自动通过率 | 漏放违规（$c_{\text{FN}}=100$） | 误杀正常（$c_{\text{FP}}=1$） | 送人审 | 期望日成本 |
| --- | --- | --- | --- | --- | --- |
| 0.50 | 88% | 320 条 → 32,000 | 6,000 条 → 6,000 | 114,000（**超预算**） | 38,000 |
| 0.80 | 93% | 480 条 → 48,000 | 3,000 条 → 3,000 | 67,000（**超预算**） | 51,000 |
| 0.95 | 97% | 900 条 → 90,000 | 1,200 条 → 1,200 | 28,800（超预算） | 91,200 |
| 0.995 | 99.3% | 2,400 条 → 240,000 | 500 条 → 500 | **6,500（在预算内）** | 240,500 |

口径：数字为构造示例（基率 0.8% 违规、$c_{\text{FN}}/c_{\text{FP}}=100$）。**读法**：在给定人审预算下，阈值被人审容量顶到 0.995 附近，代价几乎全部来自漏放——这正是「预算决定风险敞口」的量化表达，也是面试里应当主动指出的结论：**要么加人审预算，要么提升模型在该类目的召回，二者必选其一**。

### 表 2：三种分类架构的取舍

| 架构 | 新类目上手 | 尾部类目效果 | 推理成本 | 错误级联 |
| --- | --- | --- | --- | --- |
| 扁平多分类 | 需重训 | 差 | 低（一次前向） | 无 |
| 逐层分类 | 易（加子头） | 中 | 中（多层前向） | 有（父层错则全错） |
| 头部监督 + 尾部检索 | 极易（零样本） | 好 | 中（含向量检索） | 无 |

### 可运行代码

```python
# 1) 代价敏感阈值：在人工审核预算约束下最小化期望代价
import random, math
random.seed(23)
N, VIOLATION_RATE = 1_000_000, 0.008
C_FN, C_FP, C_HUMAN, BUDGET = 100.0, 1.0, 0.5, 20_000

# 合成打分：违规样本分数偏高但不完美（用 Beta 分布近似一个中等质量的分类器）
items = []
for _ in range(N):
    bad = random.random() < VIOLATION_RATE
    score = random.betavariate(6, 2) if bad else random.betavariate(2, 6)
    items.append((score, bad))

def evaluate(t):
    fp = fn = 0
    for score, bad in items:
        if score < t:                    # 自动通过
            if bad:
                fn += 1
        else:                            # 送人审
            if not bad:
                fp += 0                  # 人审拦下的正常商品：算误杀
                fp += 1
    human = sum(1 for score, _ in items if score >= t)
    cost = C_FN * fn + C_FP * fp + C_HUMAN * human
    return fp, fn, human, cost

print(f"{'阈值':>7} {'送人审':>9} {'漏放':>7} {'误杀':>7} {'期望成本':>12} {'预算':>6}")
best = None
for t in (0.5, 0.8, 0.9, 0.95, 0.98, 0.99, 0.995, 0.999):
    fp, fn, human, cost = evaluate(t)
    ok = "✓" if human <= BUDGET else "✗超"
    print(f"{t:>7.3f} {human:>9,} {fn:>7,} {fp:>7,} {cost:>12,.0f} {ok:>6}")
    if human <= BUDGET and (best is None or cost < best[1]):
        best = (t, cost)
print(f"\n预算内最优阈值 = {best[0]}（期望成本 {best[1]:,.0f}）；"
      f"若不限预算，最优阈值会降到 {min(((t, evaluate(t)[3]) for t in (0.5,0.8,0.9,0.95,0.98,0.99,0.995)), key=lambda x: x[1])[0]}")
print("结论：人审预算把阈值顶高，漏放成为主要代价来源 -> 要降风险必须加预算或提升召回")

# 2) 长尾：类目分布与「头部覆盖多少样本」
import math as m
K = 3000
weights = [1.0 / (i + 1) ** 1.1 for i in range(K)]      # Zipf 式长尾
tot = sum(weights)
cum, head80 = 0.0, None
for i, w in enumerate(weights, 1):
    cum += w
    if head80 is None and cum / tot >= 0.8:
        head80 = i
print(f"\n长尾分布（K={K}, Zipf α=1.1）：前 {head80} 个类目覆盖 80% 样本"
      f"（占类目数的 {head80/K:.1%}），尾部 {K-head80} 个类目共享剩余 20% 样本"
      f"（平均每类 {0.2*tot/(K-head80)/ (tot/K) * 100:.2f}% 的头部平均样本量）")

# 3) 逐层分类的错误级联 vs 扁平分类（示意）
p_top, p_child_given_top, p_flat = 0.97, 0.95, 0.90
print(f"\n逐层：顶层 {p_top:.2f} × 子层 {p_child_given_top:.2f} = {p_top*p_child_given_top:.4f}（端到端）")
print(f"扁平：{p_flat:.4f}（无级联但尾部类目样本少）")
print("若用 beam=3 保留多个父候选，顶层召回可达 ~0.995，端到端提升到"
      f" ~{0.995*p_child_given_top:.4f}（代价是子层推理量 ×3）")
```

预期输出要点：阈值表显示**人审预算把最优阈值顶到 0.99 以上**，此时期望成本几乎全来自漏放——这就是「预算决定风险敞口」；长尾段给出「前 10% 类目覆盖 80% 样本」的量级（Zipf 场景的典型结论），说明为什么尾部必须用检索/零样本方案而不是硬训分类头；最后一段量化逐层分类的错误级联，并给出 beam 缓解的代价（推理量 ×3）。

## 常见追问

- **追问**：新类目上线，没有标注数据怎么办？
  - 要点：用类目名/描述做文本查询，与商品图文嵌入做检索式分类（CLIP 式的零样本路径），先给可用初值；同时用主动学习优先采样该类目样本，几天内积累足够数据后切到监督模型。
- **追问**：类目体系变更（合并/改名）怎么处理？
  - 要点：把类目映射做成**可配置的映射表**（旧 label → 新 label），训练时按新体系重映射历史标签；对合并类目要注意先验变化并重标定阈值，不要直接复用旧阈值。
- **追问**：怎么防卖家对抗（故意错填类目逃避审核）？
  - 要点：不要只依赖卖家自填字段——用图片与标题独立判定；把「自填与模型判定不一致」本身作为一个强特征；对反复错填的账号做账号级风险累计（串 [[consumer-ml-11]] 的对抗性对手）。
- **追问**：人审队列怎么排序？
  - 要点：按「期望代价 × 不确定性」排序：$(\text{危害等级}\times\text{违规概率})\times\text{不确定度}$，并保证新类目与分布外样本有固定配额（否则人审只审头部）。
- **追问**：如何评估这个流水线？
  - 要点：分层评估——类目分类看**逐层与逐类的精确率/召回率**（不看总体准确率）、政策判定看按危害类别的召回与误杀率、路由看「自动通过率 × 错误率」与预算利用率、端到端看卖家申诉率与买家举报率（串 [[system-design-05]]）。
- **追问**：图片质量差（模糊、暗光、截图）怎么办？
  - 要点：把质量检测作为前置门（低质量直接要求重传或降权），而不是让分类器硬扛；对低质量图片启用额外的文本/结构化信号，并降低自动通过率（不确定性路由）。
