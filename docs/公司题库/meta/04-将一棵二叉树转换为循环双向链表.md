## 一句话答案

> 先钉口径再写代码：递归中序 + 一个 prev 指针 + dummy 哨兵，全程只有两个动作——把当前节点接到 prev 之后（`cur.left = prev; prev.right = cur`），以及遍历结束后把首尾闭合一次（`first.left = last; last.right = first`）。时间 $O(n)$、额外空间 $O(h)$、零新节点，指针写入恒为 $2n+2$ 次。
> 题面只说「二叉树」，而「转成循环双向链表」的经典形式是 BST 转**有序**链表：只有 BST 才能靠中序拿到有序序列，实测任意二叉树 `{1,2,3,4,5}` 的中序是 `[4,2,5,1,3]`，并不是有序的，「排序」这个隐含要求只在 BST 前提下成立。要问清的三件事：① 是不是 BST、按中序还是别的次序；② 是否允许原地改写 left/right（left 当 prev、right 当 next）；③ 额外空间有没有 $O(1)$ 的要求。契约：返回 head，head.left 指向尾节点、尾节点的 right 指回 head，空树返回 None，单节点自环。
> 破坏性必须写进契约：转换完成后原树不可再用——`left` 链已成环，任何以 None 为终止条件的旧遍历都会无界增长。下游消费循环链表的终止条件是 `while cur is not head`，这是环形结构与哨兵链表（[[coding-06]]）共有的性质。
> 深树不要靠递归：CPython 默认 `recursionlimit=1000`，实测递归版最大只能处理深度 996 的树；把它调到 $10^6$ 换来的是 SIGSEGV，不是更大的深度。生产上默认写显式栈的迭代中序。

## 面试官在考什么

- **第一分钟的口径澄清**：Meta 的技术初筛是 45 分钟 2 道编程题（README.zh-CN.md 的公开流程），这题的正确性完全取决于「BST 还是任意二叉树、按什么次序、能不能原地改、空间要不要 $O(1)$」这四个回答。不澄清就动笔，写出来的答案很可能整体作废。
- **哨兵与闭合时机**：能不能说清 dummy 哨兵为什么能把「空树 / 第一个节点 / 最后一个节点 / 单节点」四个特判压成零特判，以及为什么环只能闭合一次、必须放在遍历结束之后。
- **复杂度三项**：只答 $O(n)$ 一定被追问。要同时给出时间（$\Theta(n)$，$2n+2$ 次指针写入）、额外空间（$O(h)$ 递归帧或显式栈）、以及 $O(1)$ 额外空间是否可达（Morris，代价是什么）。
- **破坏性与终止条件**：这是最容易被抓住的生产问题——接口命名是否区分原地改写与拷贝、调用方是否知道原树失效、下游遍历有没有从 `while cur` 改成 `while cur is not head`。
- **能不能上生产**：深树（递归上限实测 996）、内存按字节记账、环形引用的回收、以及「加需求」环节（可撤销版本、泛型比较器、多叉树前序展平）。

常见错误答案：

- 默认题面里的二叉树是 BST，却不声明这个前提，把「链表要有序」当成题面给的约束。任意二叉树上中序不产生有序序列（实测 `[4,2,5,1,3]`），此时「有序」这个验收标准根本不存在。
- 深树用 `sys.setrecursionlimit` 兜底。实测把上限提到 $10^6$ 后，对深度 20000 的链式树递归，子进程 returncode 是 -11（SIGSEGV）、深度 200000 同样：把一个可捕获的 `RecursionError` 换成了不可捕获的段错误（C 栈耗尽）。
- 在遍历中途闭合环，或者把闭合写进接入语句。当前节点的 `right` 还是前进指针（或右子树的入口），提前写它会丢掉右子树或让遍历绕回头部；闭合必须留到 last 确定之后。

## 原理与推导

### 1. 先把契约钉死：问什么、返回什么

四个问题按顺序问，答完再动笔：

| 要问的 | 为什么影响答案 |
| --- | --- |
| 是不是 BST、按哪个次序展平？ | 「有序」只在 BST + 中序下成立；任意二叉树必须由面试官指定次序（中序只是次序之一，不等于排序） |
| 允许原地改写 left/right 吗？ | 原地改写零新节点但破坏原树；拷贝版保留原树但要多分配 $n$ 个节点 |
| 额外空间有 $O(1)$ 要求吗？ | 有就上 Morris（临时线索），没有就用递归或显式栈，代码短、常数小 |
| 返回什么？空树怎么算？ | 返回 head；head.left = 尾节点，尾的 right = head；空树返回 None |

契约写成一句可验收的话：**返回的链表从 head 出发沿 right 走 $n$ 步回到 head，沿 left 走 $n$ 步也回到 head，且 head.left 就是尾节点。** 有了这句话，验收断言才能写成代码（见数值节）。

### 2. 只有中序能给出有序序列（且仅在 BST 前提下）

BST 的定义要求左子树所有值小于根、右子树所有值大于根，中序的访问顺序恰好是「左子树 → 根 → 右子树」，因此输出非降序；前序、后序、层序都不保序（前序先输出根，根后面的元素可以比它小也可以比它大）。关键推论：**「把二叉树转成有序循环双向链表」= 「对 BST 做中序展平」**，两句话是同一件事的两种说法，而「有序」这个要求是由 BST 这个前提白送的，不是遍历算法给的。题面只写「二叉树」时，正确动作是把这个前提问出来，而不是默默假设。实测把一棵普通二叉树 `{1,2,3,4,5}` 做中序展平，得到 `[4,2,5,1,3]`，有序性直接不成立。

### 3. 机制只有两个动作：接入与闭合

**接入**（每个节点一次）是 `cur.left = prev; prev.right = cur; prev = cur`；**闭合**（全部结束后一次）是 `first.left = last; last.right = first`。两个动作之外没有任何一步操作。

**安全性不变量：只写已经消费完的指针。** 中序遍历下降到某个节点后，它的 `left` 已经不会再被读（左子树遍历完了），可以安全改写成 prev；它的 `right` 还要用来前进，所以必须先用 `nxt = cur.right` 存下来，之后才轮到它作为「前驱」被写。这就是「先取 nxt、再改指针」那一行的来历——不是风格问题，是原地改写的正确性条件。

**计数是确定的：$2n+2$。** 每个节点在接入时写 2 次（自己的 left、前驱的 right），闭合再写 2 次。实测 n = 1、2、7、1000 时指针写入分别是 4、6、16、2002，与 $2n+2$ 完全一致；n = 200000 时是 400002 次。

7 节点平衡 BST 走查（值取 0..6）：中序是 `[0,1,2,3,4,5,6]`，返回值就是这串，`head.left` 是 6（尾）。哨兵 dummy 的 right 指向 0，dummy 的 left 从未被使用。

### 4. 哨兵把四个边界砍成一个

不用哨兵就要处理四种情况：空树（直接返回 None）、第一个节点（没有 prev，必须先把它记成 head）、最后一个节点（它的 next 不是新节点而是 head）、单节点（自己指自己）。用 dummy 之后 prev 永远不为 None，接入语句一条 `if` 都不用加，第一个节点只是「dummy 的 next」，最后一个节点由遍历结束后的 `last` 决定。这套写法与 [[coding-06]] 的哨兵完全同源：哨兵的收益不在省一次判断，而在于**把「边界」变成「普通情况」**，从而让主循环只有一条路径、没有分支。

### 5. 闭合时机：为什么必须在遍历结束之后

两个真实的错误形态：

- **提前闭合**：把 `first.left = last` 写在还知道不了 last 的地方（例如第一个节点处写 `first.left = first`），此时「尾」还不是尾，环的长度与方向都是错的；**把闭合混进接入语句**：例如每次接入后都写 `cur.right = first`。当前节点的 `right` 还是右子树的入口，抹掉它就把右子树丢了；如果是在递归版里对第一个节点写 `node.right = node`，递归会沿着这个自环无限下降。

正确纪律：整个遍历结束、`prev` 就是尾节点之后，才写 `first.left = last` 与 `last.right = first` 这两次；闭合是 $O(1)$ 的收尾动作，不属于循环体。

### 6. 复杂度三项要一起说，Morris 的代价要按形状讲

- **时间 $\Theta(n)$**：每节点一次弹出、一次接入（2 次指针写入）、一次取 nxt，共 $2n+2$ 次写入；没有查找、没有搬移、没有数据复制。指针写入次数是确定的，与树的形状无关。
- **额外空间 $O(h)$、输出空间 $O(1)$**：递归版是递归帧，迭代版是显式栈，$h$ 是树高；平衡树 $h \approx \log_2 n$（n = 200000 时约 18），退化树 $h = n$。但栈峰值并不等于 $h$，它等于最长一条「一路向左」链的节点数：实测 n = 200000 时左斜树 200000 项（按 CPython 列表 8 B/指针算的下界是 1.53 MiB，这 1.53 MiB 是真实内存，不能用「$O(1)$ 空间」一句话带过）、平衡树 17 项、右斜树只有 1 项（push 完立刻 pop，同样是 $h = n$ 的形状却一点都不占栈）。输出侧不新建节点，这是与「先中序收集到数组、再新建链表」写法的本质差异。
- **Morris 是唯一的 $O(1)$ 额外空间方案**：把前驱节点的 `right` 临时改成指向当前节点的「线索」，第二次经过这个前驱时再把线索还原。它的额外空间只有几个指针变量，代价是每个有左子树的节点要做一次前驱查找（每条边最多被走两次，因此均摊仍是 $O(1)$），以及每个这样的节点多两次临时线索写入（设线索、还原线索），所以 Morris 的指针写入次数比迭代版更多而不是更少。
- **Morris 是不是更快，取决于树的形状**：平衡树上实测 111.7 ms，是显式栈 36.1 ms 的 3.09 倍（几乎每个节点都要下到左子树最右端找前驱）；右斜树上 20.0 ms，反而比显式栈 38.0 ms 快，因为没有左子树就没有前驱查找，只剩接入。所以取舍按「树的形状 + 是否有内存上限」答，而不是背一句「Morris 更好」。

### 7. 破坏性与环形终止条件

- 原地复用 left/right 的直接后果是**原树失效**，而失效的方式比「指针乱了」更隐蔽：`left` 链在环上首尾相连，任何以 None 为终止条件的遍历都不会结束。实测：对转换后的原 root 跑旧的中序遍历（`while stack or cur is not None`），内层 `while cur is not None: stack.append(cur); cur = cur.left` 沿成环的 left 链无界增长；对链表头套用同一个旧遍历同样失败，因为它的 left 也是环。这里实测的是受控地址空间上限下的形态——3 GiB 与 12 GiB 都是未捕获的 `MemoryError`（退出码 1）；不设上限时它会一直涨到被 OOM killer 用 SIGKILL 收掉（退出码 137）。
- 两条工程结论：① 接口命名与文档要区分 `flatten_inplace` 与 `to_linked_copy`，调用方要么先深拷贝、要么明确接受树失效，转换后不得再对原树做任何遍历；② 下游消费循环链表的终止条件必须从 `while cur` 换成 `while cur is not head`（或先取 head 引用做比较），并全仓库搜一遍同类遍历代码。环形结构没有 None 终止点，这是它与 [[coding-06]] 哨兵链表共有的性质。

### 8. 内存与所有权：按字节报，并且环形引用计数不归零

- Python 里带 `__slots__` 的三字段节点是 56 B（实测 `sys.getsizeof`）。
- 原地改写的额外分配只有哨兵对象与解释器开销：n = 100000 时实测 8416 B（另一轮 8472 B），tracemalloc 峰值 9288 B（另一轮 9400 B）。
- 「先中序收集、再新建链表」同样 n 下 tracemalloc 峰值 5,600,160 B = 5.34 MiB（其中 5,600,000 B 就是 56 B × 100000 个新节点，余下 160 B 是哨兵与解释器开销），是原地改写的约 600 倍。这就是原地复用两个指针换来的收益，也是能否通过内存上限验收的关键。
- 更隐蔽的一条是循环引用：环形链表在 CPython 里引用计数永远不归零，只能靠 gc 的代际回收。实测关闭 gc 后丢掉 5 万个双节点环（共 100000 个节点），常驻内存增长 5,600,160 B ≈ 5.34 MiB——其中 5,600,000 B 就是 56 B × 100000 个节点，一个都没被引用计数回收（余下 160 B 是解释器与测量开销）；`gc.collect()` 后回落到 168 B。所以在 C++/Rust 手写版本或关闭 gc 的长驻进程里，这份结构就是内存泄漏（`shared_ptr` 的环、`Rc` 的环同理）。生产实现要么用侵入式链表（节点就是树节点本身，不新增所有权），要么在释放前显式拆环（`head.left.right = None; head.left = None`）。
- 常数对照要说清量级：5.34 MiB 只相当于 LLaMA-3-70B 每 token KV cache（320 KiB）的 17 个 token；H100 的 3.35 TB/s 带宽搬完这 5,600,000 B（十进制 5.6 MB = 5.34 MiB）只要约 1.67 μs。所以原地改写的真实动机不是省这 5 MiB，而是**避免一次 $O(n)$ 拷贝、保持节点引用稳定**——这个判断比数字本身更能说明你在生产里怎么权衡。

### 9. 收口：把「写对」升级成「能上生产」

- 递归版必须配树深上限校验加迭代兜底，或者干脆默认迭代：失败要给正常出口，而不是崩溃（工程标准与 [[coding-12]] 相同）。验收证据必须是可复现的断言，不是肉眼看输出：环的正反向遍历一致、节点计数等于 $n$、BST 有序性、以及深树与斜树（n = 200000）不依赖递归——「用压力测试证明边界正确」的做法与 [[coding-09]] 同源。
- Meta 场景：这类原地展平的真实原型是把层级结构（嵌套模块树、表达式树、执行计划）按某种序遍历成线性序列。同一手法在推理栈里就是编译期看到整张图后把连续小算子融成一个 kernel、省的是带宽（[[inference-serving-11]] 里 TensorRT-LLM 的那条收益线）——H100 的 bf16 dense 峰值 989 TFLOPs 与 3.35 TB/s 带宽给出约 295 FLOPs/byte 的 roofline 拐点，融合减少的正是中间张量的读写次数。此时遍历次序决定数值语义与内存复用顺序；而原结构若要在多轮迭代里复用就不能破坏，得保留副本，或用 node 到 index 的 side table 表达顺序。
- 按 2026 年流程里那轮 AI 辅助编程的三阶段扩展问题：探索并修 bug（给一棵别人写坏的树，找出环没闭合或 prev 没接上）、实现新功能（改成 $O(1)$ 空间的 Morris 版）、扩展改进（可撤销版本、泛型比较器、多叉树前序展平），全程保持 [[coding]] 专题的四件套：参考实现、可复现实测输出、边界用例与断言、生产化差距。

| `recursionlimit=10**6` | 20000 | -11 | SIGSEGV（C 栈耗尽） |
| `recursionlimit=10**6` | 200000 | -11 | SIGSEGV |
| 显式栈迭代 | 200000 | 0 | 转换 + 环校验全部通过 |

探针不计 `convert` 与模块帧的固定开销，所以**真实可用树深只会比 996 更小**。表 1 里递归版在右斜树上的 `RecursionError` 就是这个墙（实测 n = 200000 时 `maximum recursion depth exceeded`）。

**表 5：环形结构的回收（CPython 引用计数）**

| 操作 | 常驻增长 |
| --- | --- |
| 关闭 gc，丢掉 5 万个双节点环（100000 节点） | 5,600,160 B ≈ 5.34 MiB（其中 5,600,000 B 就是 56 B × 100000，一个都没回收） |
| `gc.collect()` 之后 | 168 B |

**其余实测结论**

- 边界：空树返回 `None`；单节点 `head.left is head and head.right is head`（自环）；平衡 BST n = 7 输出 `[0,1,2,3,4,5,6]`、`head.left` 是 6；非 BST `{1,2,3,4,5}` 输出 `[4,2,5,1,3]`（有序性为 False）。
- 环校验三断言全部通过（`head.left` 是尾、尾的 `right is head`、反向遍历等于正向的逆序），`right/left` 逐节点互逆，节点计数等于 $n$；深树用显式栈：右斜树与左斜树 n = 200000 转换加校验都通过（左斜树栈峰值 200000 项 ≈ 1.53 MiB，右斜树只有 1 项）；Morris 版对平衡树 n = 200000 与 n = 10000 的校验也都通过（线索全部被还原，右指针没有残留）。

```python
class Node:
    __slots__ = ('val', 'left', 'right')
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right


def flatten(root):
    # 显式栈迭代中序：原地改写，返回 head；空树返回 None。转换后原树失效。
    if root is None:
        return None
    dummy = Node(0)                       # 哨兵：真正的头是 dummy.right
    prev, stack, cur = dummy, [], root
    while stack or cur is not None:
        while cur is not None:
            stack.append(cur); cur = cur.left
        cur = stack.pop()
        nxt = cur.right                   # 先存右子：它马上要被改
        cur.left = prev                   # 只写已消费的指针：自己的 left
        prev.right = cur                  # 以及前驱的 right
        prev, cur = cur, nxt
    first, last = dummy.right, prev
    first.left = last                     # 环只闭合一次，放在遍历结束之后
    last.right = first
    return first


def flatten_morris(root):
    # O(1) 额外空间：借用前驱的 right 当回溯线索，第二次经过时还原。
    if root is None:
        return None
    dummy = Node(0)
    prev, cur = dummy, root
    while cur is not None:
        if cur.left is None:
            nxt = cur.right
        else:
            pred = cur.left
            while pred.right is not None and pred.right is not cur:
                pred = pred.right
            if pred.right is None:
                pred.right = cur; cur = cur.left; continue   # 设线索后下降
            pred.right = None; nxt = cur.right               # 还原线索
        cur.left = prev; prev.right = cur; prev = cur; cur = nxt
    first, last = dummy.right, prev
    first.left = last; last.right = first
    return first


def check(dll, n, ordered=True):
    # 验收断言：环、双向互逆、节点数、反向一致；BST 再加有序性。
    fwd, cur = [], dll
    while True:
        fwd.append(cur.val)
        assert cur.right.left is cur, 'right/left 必须互逆'
        cur = cur.right
        if cur is dll:
            break
        assert len(fwd) <= n, '绕回 head 之前长度就超过 n'
    assert len(fwd) == n, '节点数必须等于 n'
    back, cur = [], dll
    while True:
        back.append(cur.val); cur = cur.left
        if cur is dll:
            break
    assert back == [fwd[0]] + fwd[:0:-1], '反向遍历必须与正向一致'
    if ordered:
        assert fwd == sorted(fwd) == list(range(n)), 'BST 展平必须保持有序'
    return fwd


def make_bst(values):
    # 迭代构造平衡 BST，避开构造阶段的递归。
    if not values:
        return None
    mid = len(values) // 2
    root = Node(values[mid])
    work = [(root, 0, mid - 1, 'left'), (root, mid + 1, len(values) - 1, 'right')]
    while work:
        parent, lo, hi, side = work.pop()
        if lo <= hi:
            m = (lo + hi) // 2
            node = Node(values[m]); setattr(parent, side, node)
            work += [(node, lo, m - 1, 'left'), (node, m + 1, hi, 'right')]
    return root


assert flatten(None) is None                               # 空树
single = flatten(Node(7))
assert single.left is single and single.right is single    # 单节点自环
assert check(flatten(make_bst(list(range(7)))), 7) == list(range(7))
tree = Node(1, Node(2, Node(4), Node(5)), Node(3))
assert check(flatten(tree), 5, ordered=False) == [4, 2, 5, 1, 3]       # 非 BST：不有序
deep = Node(0); cur = deep
for i in range(1, 200000):
    cur.right = Node(i); cur = cur.right
assert check(flatten(deep), 200000) == list(range(200000))             # 深链只走迭代版
for fn in (flatten, flatten_morris):
    assert check(fn(make_bst(list(range(10000)))), 10000) == list(range(10000))
```

## 常见追问

- **追问**：这题到底给的是 BST 还是任意二叉树？
  - 要点：先问，再按回答分叉。BST + 中序是「有序链表」，可以用有序性做验收断言；任意二叉树必须由面试官指定遍历次序，中序只是其中一种，此时**不能**用有序性验收，只能验收环、互逆与节点数。实测普通二叉树 `{1,2,3,4,5}` 的中序是 `[4,2,5,1,3]`，用它来说明「排序」是 BST 白送的前提，比口头解释有说服力。
- **追问**：能不能不新建节点、也不用递归？
  - 要点：能。显式栈的迭代中序不新建任何节点，额外空间 $O(h)$；要连栈也不要就用 Morris，把前驱的 right 临时当线索、第二次经过时还原。标准库层面的同类思路可以看 `collections.OrderedDict` 这类「顺序 + 指针」容器（参考资料 1 是延伸阅读）。现场要能说清 Morris 的两处临时写入与它们必须被还原。
- **追问**：为什么 $O(1)$ 空间的 Morris 反而更慢？
  - 要点：因为前驱查找的常数被树的形状放大。平衡树上几乎每个节点都要下到左子树最右端去找前驱，实测 n = 200000 时 111.7 ms，是显式栈 36.1 ms 的 3.09 倍；右斜树上没有左子树就没有前驱查找，Morris 20.0 ms 反而比显式栈 38.0 ms 快。$O(1)$ 空间是真的，但它买的是「内存上限」，不是「速度」。
- **追问**：转换后原树还能用吗？下游遍历要怎么改？
  - 要点：不能。left 链已成环，旧中序遍历的内层下降循环永不终止——实测在 3 GiB 与 12 GiB 地址空间上限下都以未捕获的 `MemoryError` 退出（退出码 1），不设上限会被 OOM killer 用 SIGKILL 收掉（137）。契约上区分 `flatten_inplace` 与 `to_linked_copy`，下游把终止条件从 `while cur` 改成 `while cur is not head`，并全仓库搜一遍同类遍历。环形结构没有 None 终止点，这与 [[coding-06]] 的哨兵链表是同一条性质。
- **追问**：深树（链式 $10^5$）怎么办？
  - 要点：递归的墙是默认 `recursionlimit=1000`，实测递归版最大只到深度 996；`sys.setrecursionlimit(10**6)` 不是解法——深度 20000 与 200000 的子进程 returncode 都是 -11（SIGSEGV），风险从 Python 栈搬到 C 栈。正确做法是显式栈迭代版：实测右斜树 n = 200000（深度 200000）转换加校验全部通过，左斜树同样通过（栈峰值 200000 项 ≈ 1.53 MiB）。
- **追问**：要加可撤销、泛型比较器、多叉树，各要改什么？
  - 要点：可撤销要多留一份「原指针」记录（节点上不增加字段的话，就用 side table 或者转换前先拷贝一份 left/right）；泛型比较器只影响「哪些树算 BST」的校验，不影响展平本身；多叉树要先定次序（前序展平最常见），并且要显式约定 first-child / next-sibling 的复用方式——那本质上就是「把多叉树先转成二叉表示再展平」。
