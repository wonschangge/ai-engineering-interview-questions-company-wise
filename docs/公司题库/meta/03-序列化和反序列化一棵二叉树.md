## 一句话答案

> 先讲三条不变量，再写编码：n 个节点恰好写 2n+1 个 token（n 个值 + n+1 个空哨兵）；解析游标单调不减；结束时消费掉的 token 数必须等于输入长度，多一个、少一个都报错。
> 编码选前序（DFS）+ 空哨兵：递归定义 serialize(u) = [u.v] + serialize(u.l) + serialize(u.r)，空树写成单个哨兵，时间 $\Theta(n)$、序列化栈 $O(h)$、输出 $O(n)$；它不要求节点值互不相同，这正是「前序 + 中序还原」那条常见路线站不住的地方（要求值唯一）。
> 时间预算按[题库总导读](../../../README.zh-CN.md)的 Meta 一节：技术初筛是 45 分钟内 2 道编程题，本题只分到约 20 分钟。答题顺序固定：一分钟澄清三件事（值域：节点能否为 null、是否可能含分隔符；协议边界：进程内字符串还是跨进程落盘的字节流；是否允许递归）→ 讲三条不变量 → 写前序带哨兵版 → 当场跑空树/单节点/深链/全相同值/含分隔符 → 再谈 N 叉与流式扩展。

## 面试官在考什么

- **格式自洽**：能不能先把「编码与解码互为逆映射」说清楚，再动笔；$2n+1$ 这个计数能不能当场归纳出来，而不是背题解。
- **边界齐全**：空树、单节点、单侧链（深度 $n$）、值全相同、负数与极大值、值里含分隔符、截断输入，一个都不能省。
- **往返怎么证明**：必须逐节点比较结构与值，或者再序列化一次做字节级比较。只比中序遍历值会漏——实测 5 个节点全为 7 的完全树与链式树中序都是 `[7, 7, 7, 7, 7]`，中序比较在这里零信息。
- **复杂度与演进**：除了 $O(n)$，还要说得清输出字节数、递归深度风险，以及反序列化里三个环节（切分、整数解析、对象构造）各占多少；再往前一步是值域外的字符有没有退路、头部要不要长度与校验和、能不能改成流式——Meta 的编程轮是「先实现、再加需求」，2026 年部分流程还有一轮 AI 辅助编程（探索并修复问题 → 实现新功能 → 扩展并改进系统），这些就是加需求环节的入口。

常见错误答案：

- 用「前序 + 中序」还原，却默认值互不相同。只给一条中序还原不出唯一的树，前序 + 中序也只是在**值唯一**时成立；本题题面没有任何唯一性承诺。
- 说「BFS 输出更啰嗦」而不区分口径。不裁剪尾部哨兵时 BFS 的 token 数与前序**完全相同**，都是 $2n+1$；只有裁掉尾部哨兵后才更短，而那时编码不再是定长位图。
- 用堆式数组下标（左 $2i$、右 $2i+1$）当通用编码。数组长度按 $2^h$ 增长，链式树上 $n=64$ 就越过 int64 上限。
- 深树只给递归版，或者用 `sys.setrecursionlimit` 兜底。实测把上限提到 30 万后对链式 $n=10^5$ 递归序列化，进程直接 SIGSEGV。

## 原理与推导

### 1. 先定三条不变量，再写编码

任何序列化格式都是 token 串与树之间的双射。把不变量写在代码前面，代码才有验收标准（写法与 [[coding-10]] 一致）：

1. **计数**：$n$ 个节点恰好产生 $2n+1$ 个 token。归纳一下：空树是 1 个 token；非空树是 `值 + 左子树 + 右子树`，即 $1 + (2n_l+1) + (2n_r+1) = 2(n_l+n_r+1)+1 = 2n+1$。
2. **游标单调不减**：解析只前进、不回退，每一步消费恰好一个 token；游标回退就是死循环的入口。
3. **边界闭合**：每棵子树的 token 区间要么被完整消费、要么抛错；结束时 `consumed == len(tokens)`。多一个 token 必须报错，而不是静默忽略。

空树的唯一编码是**单个哨兵**；空串不是合法编码，这一点要主动交代，否则接口语义会漂（实测把空串当空树、把「token 用尽」当空孩子，都会让错误在上层变成「静默拿到一棵小树」）。

### 2. 前序 + 空哨兵：$2n+1$ 个 token 的来历

$$T(n) = 1 + T(n_l) + T(n_r),\quad T(0) = 1 \;\Longrightarrow\; T(n) = 2n+1$$

- **序列化**：显式栈，先压右孩子再压左孩子，弹出顺序就是前序；空指针写一个哨兵 token。
- **反序列化**：一次切分（或单遍扫描）得到 token 流，用「游标 + 帧栈」重建：帧里记「下一个该填左孩子还是右孩子」。读到哨兵就跳过，读一个 token 恰好做一次决策，所以是单遍、$O(n)$。
- **空间**：序列化栈与反序列化帧栈都是 $O(h)$；输出 $O(n)$ 字节。

这套编码不需要值域任何假设，也不需要值互不相同——它是本题最短的正解。

### 3. 为什么单靠中序不行

两个节点、值为 1 和 2 的树，两种挂法：

| 树 | 结构 | 中序 | 前序 + 哨兵 |
| --- | --- | --- | --- |
| A | 1 是根，2 是右孩子 | `[1, 2]` | `1,#,2,#,#` |
| B | 2 是根，1 是左孩子 | `[1, 2]` | `2,1,#,#,#` |

中序相同、结构不同。值全相同时更极端：任何形状的中序都是同一串值，中序比较彻底失效。所以往返验收只有两条路——逐节点比较（值 + 左 + 右），或者对还原出的树再序列化一次做字节比较；两条都要用**迭代**实现，递归比较器在链式 $n=10^5$ 的树上自己先抛 RecursionError。「前序 + 中序还原」本身是经典解法（值不重复时前序提供根、中序划出左右子树区间），但它要求值**互不相同**才能唯一定位根的位置；题面没承诺唯一，可以答，但必须先声明前提。

### 4. BFS 与堆式下标：两个常见写法的真实口径

**BFS（层级）写法正确，但收益要说清。** token 数与前序**完全相同**：$n$ 个值 + $n+1$ 个哨兵，实测链式 $n=10^4$、随机 $n=10^4$、完全树 $n=16383$ 三棵树上不裁剪时都是 $2n+1$。差别在空间形状：

- 队列里只放真节点时，链式树的队列长度恒为 1（实测最大 1），而前序的显式栈是 $O(h)=O(n)$；
- 完全树（16383 节点）的队列最大 8192，而前序栈只有 14 层。宽树伤 BFS 的内存，深树伤 DFS 的栈，两个方向都要能说。
- 只有裁掉尾部哨兵后 BFS 才更短，而且省下的是 token 数不是字节数：完全树从 32767 token 降到 16383（token **0.500×**，字节只到 0.727×——裁掉的全是 1 B 哨兵加 1 B 分隔符，每个 token 只省 2 B），链式与随机树的 token 数几乎不变（0.9999× / 0.999×，字节 1.000×）。代价是形状长度随内容变化，二进制紧凑编码做不成定长位图——前序带哨兵的形状恰好 $2n+1$ bit。

**堆式数组下标只对近完全树可用。** 左链（每层只挂左孩子）时最深叶的下标是 $2^{n-1}$：$n=32$ 是 2147483648（10 位）；$n=63$ 是 $2^{62}$（19 位），刚好卡在 int64 里；$n=64$ 是 $2^{63}=9223372036854775808$，越过 int64 上限 9223372036854775807；$n=1000$ 是 $2^{999}$，301 位十进制（约 $10^{300.7}$）。现场口径：明确说「不做数组下标编码」，理由是数组长度按 $2^h$ 增长而链式树上 $h = n$——$n=64$ 就撑爆 int64，不是「$n$ 很大才出事」。

### 5. 值域：转义与长度前缀，两条退路都要能写

只要值可能含分隔符（字符串节点、含逗号或井号的值、路径、base64），按单个分隔符切分就会静默错切：

- 裸 `join` 三个值 `['a,b', 'c#d', 'e\f']` 得到 `a,b,c#d,e\f`，切出 4 个 token——值被切开，反序列化**不报错**，只是树错了。这是最危险的一类 bug：错误发生在编码层，症状出现在下游。
- **转义救不了 `split`**。把逗号转义成 `\,` 之后再 `split(',')`，仍然切在转义逗号上（`'a\,b'` → `['a\\', 'b']`）。转义必须配**单遍状态机**，切分与反转义在同一次扫描里完成，否则等于没转义。这是这道题最容易被抓住的实现细节。
- **长度前缀**（netstring 风格的 `长度:载荷`）同样要单遍扫描，但载荷零改写：`,` 与 `#` 原样出现，解析器按长度整段跳过，不需要逐字符判断；代价是每个值多一个 `长度:` 前缀（5–19 字符的值平均多 2.67 B：长度 1 位多 2 B、2 位多 3 B，表 5 的 1.205× 就是这笔账），而且解析要先扫到冒号才知道载荷边界。截断输入要有受控出口：单遍扫描时判断「转义符恰好在末尾」立刻报错，长度前缀在「声明 N 字节、实到 M < N」时报错。

结论口径沿用 [[coding-04]]：底层符号表必须给表外字符留退路，否则一个制表符就让往返破掉；序列化里的对应物是「值域外的字符必须有明确退路」，没有退路的格式等于有损格式。

### 6. 深树：递归上限与 C 栈

- `sys.getrecursionlimit()` 默认 1000（本机实测 1000）。实测递归序列化在链长 998 时正常，**999 就抛 RecursionError**——链式 $n=10^5$ 必然踩中。
- `sys.setrecursionlimit` 不是解法。实测把上限提到 300000 后再对链式 $n=10^5$ 递归序列化，子进程 returncode 为 -11、输出 `Fatal Python error: Segmentation fault`，两次复现。风险从 Python 栈搬到 C 栈：从受控异常变成进程崩溃，服务里就是整条请求线挂掉。
- 正确做法是显式栈的迭代版：序列化先压右再压左，反序列化用「游标 + 帧栈」，实测链式 $n=10^5$ 迭代序列化 44.13 ms、反序列化 129.39 ms（wall 5 次中位）。递归版仍然值得写（约 10 行、语义清楚），现场两版都给，并说明切换条件：深度可能超过几百就用迭代版；校验器也要迭代，否则「验证往返」这一步先崩。立场与 [[coding-09]] 的「永不假设输入形状」一致：深度、规模与值域都是不可信输入。

### 7. 复杂度与常数项

- **时间 $O(n)$ 均摊**：序列化每节点一次 append + 一次 `join`；反序列化一次切分 + 一次整数解析 + 一次对象分配。
- **别依赖字符串原地拼接优化**：`s += tok` 在 CPython 上有优化，但那是实现细节，换解释器或换拼接形态就退化。一律 `list.append` + `str.join`。
- **别对每个 token 重新扫描或切片**：每次重切全文（`int(s.split(',')[i])`）是 $O(n^2)$，列表反复切片（`toks = toks[1:]`）也是 $O(n^2)$，只是常数不同；改用一次切分 + 游标或迭代器。
- **别把「token 用尽」当成结束信号**：这是截断输入静默变成半棵树的根源，用不变量 3 兜住。
- **内存要按字节记账**（口径同 [[coding-06]]）：token 列表里每个 `str` 对象要占 50–53 B（4 字符的值 53 B、哨兵 `'#'` 50 B；链式 $n=10^5$ 的 token 平均 51.9 B），而它的载荷只有 1–5 B。实测链式 $n=10^5$（值 0–99999，输出 788,891 B = 0.75 MiB）的序列化中间态 7.44 MiB，膨胀约 9.9×。要压峰值就边生成边写出，不要先攒一个 token 列表。

## 数值与代码验证

口径：Python 3.10.12；值域 $[0, 10^4)$ 的随机形状树（`seed = n`）；前序 + `#` 哨兵、逗号分隔；32 核机器跑批时 load average 约 14–19，wall 时间抖动可达 2×，所以耗时一律取 CPU 时间 9 次最小值（附 wall 5 次中位数）。单位口径：KB/MB/TB 按 $10^3$ 换算，KiB/MiB/GiB 按 $2^{10}$ 换算。复算脚本 `.work/lane-a/numbers-for-doc.py`、`.work/lane-a/verify-meta-03.py`、`.work/lane-a/verify-meta-03b.py`、`.work/lane-a/verify-meta-03c.py`、`.work/lane-a/meta03_reverify.py`（都在仓库根 `.work/` 下，未纳入版本控制）。

**其余实测结论**

- 往返：$10^4$ 棵随机树逐节点一致 10,000/10,000，再序列化字节一致 10,000/10,000；链式 $n=10^5$ 的迭代版往返一致，递归版抛 RecursionError，`setrecursionlimit(300000)` 后 SIGSEGV（两次复现），递归比较器在同样的树上也抛 RecursionError。
- 增量：同一份序列化结果按 chunk = 1、2、3、4096 喂入，以及 2000 次随机多段切分，token 序列全部一致（2000/2000）。
- 截断：切在 token 边界 → 受控的 `ValueError: token 用尽`；切在数字中间 → `int()` 抛的 `ValueError`（信息不可读，说明要加长度/节点数头部提前校验）；把「token 用尽」当空孩子的宽容解码器则**不报错**：300 节点的随机树（`seed = 300`）截到 50% 会静默返回 152 个节点的半棵树，空输入静默返回 None。
- 协议开销：头部 `v1:<字节数>:<crc32>:` 加 CRC 共 19 B，在 $n=10^5$ 的 688,862 B 上占 0.0028%；但头部是防恶意 payload 的关键——声称 $10^9$ 个节点的输入若被信任并预分配，裸指针数组就要 14.90 GiB，按每节点 56 B 的对象算是 52.2 GiB。
- 量级对照：688,862 B 约等于 LLaMA-3-70B 每 token 320 KiB 的 KV cache 的 2.10 个 token；同一份 payload 在 H100 的 3.35 TB/s 带宽下搬运只要约 0.21 μs，而把它变成 Python 对象要 121.1 ms（$n=10^6$ 是 6.89 MB 对 1519.2 ms）——差了近六个数量级，瓶颈是每节点一次对象分配，不是带宽。

```python
NULL, SEP = '#', ','


class Node:
    __slots__ = ('v', 'l', 'r')

    def __init__(self, v, l=None, r=None):
        self.v, self.l, self.r = v, l, r


def serialize(root):
    """前序 + 空哨兵：n 个节点写 2n+1 个 token。"""
    out, stack = [], [root]
    while stack:                       # 先压右再压左，弹出顺序就是前序
        x = stack.pop()
        if x is None:
            out.append(NULL)
        else:
            out.append(str(x.v))
            stack.append(x.r)
            stack.append(x.l)
    return SEP.join(out)


def deserialize(s):
    if s == '':
        raise ValueError('空串不是合法编码：空树的编码是单个哨兵')
    toks = s.split(SEP)                # 一次切分，之后只用游标前进
    n = len(toks)
    i = 0
    tk = toks[i]
    i += 1
    if tk == NULL:                     # 空树
        if i != n:
            raise ValueError(f'多余 token：消费 {i}/{n}')
        return None
    root = Node(int(tk))
    stack = []                         # 帧 = [节点, 下一个要填的孩子]（0 左 1 右）
    stack.append([root, 0])
    while stack:
        if i >= n:                     # 不变量 3：token 用尽就是截断输入
            raise ValueError(f'token 用尽：消费 {i}/{n}')
        tk = toks[i]
        i += 1
        child = None if tk == NULL else Node(int(tk))
        frame = stack[-1]
        if frame[1] == 0:
            frame[0].l = child
            frame[1] = 1
        else:
            frame[0].r = child
            stack.pop()
        if child is not None:
            stack.append([child, 0])
    if i != n:                         # 不变量 3：多余 token 必须报错
        raise ValueError(f'多余 token：消费 {i}/{n}')
    return root


def same(a, b):                        # 迭代比较：递归比较器在深链上同样会 RecursionError
    stack = [(a, b)]
    while stack:
        x, y = stack.pop()
        if x is None or y is None:
            if x is not y:
                return False
        elif x.v != y.v:
            return False
        else:
            stack += [(x.l, y.l), (x.r, y.r)]
    return True


chain = Node(0)                        # 单侧链，深度 10 万
cur = chain
for i in range(1, 100000):
    cur.r = Node(i)
    cur = cur.r

assert deserialize(serialize(None)) is None                        # 空树
assert deserialize(serialize(Node(7))).v == 7                      # 单节点
assert serialize(Node(7, Node(7), Node(7))) == '7,7,#,#,7,#,#'     # 值全相同
assert same(deserialize(serialize(chain)), chain)                   # 深链走迭代版
for bad in ('', '1,#', '9', '#,9'):                                # 截断 / 多余 token
    try:
        deserialize(bad)
        raise AssertionError(f'{bad!r} 应当报错')
    except ValueError:
        pass

import random
rng = random.Random(0)
for _ in range(10000):                 # 批量往返：逐节点 + 字节级双重比较
    root = Node(rng.randrange(-50, 10 ** 4))
    slots = [(root, 'l'), (root, 'r')]
    for _ in range(rng.randrange(1, 30)):
        p, side = slots.pop(rng.randrange(len(slots)))
        c = Node(rng.randrange(-50, 10 ** 4))
        setattr(p, side, c)
        slots += [(c, 'l'), (c, 'r')]
    s = serialize(root)
    assert same(deserialize(s), root) and serialize(deserialize(s)) == s
```

## 常见追问

- **追问**：空树怎么编码？空串合法吗？
  - 要点：空树写成**单个哨兵**（`'#'`），所以序列化结果永远非空；空串、`','`，以及 `'#'` 之后还有内容，都属于非法编码，解码器要显式报错。宽容解码（空串当空树、token 用尽当空孩子）会让截断输入静默变成半棵树——实测 300 节点的随机树（`seed = 300`）截到 50% 会得到 152 个节点且不报错。
- **追问**：值里可能含分隔符（字符串节点、路径、base64）怎么办？
  - 要点：两条退路都要能写。转义（转义符自身也要转义）必须配单遍状态机，因为 `split` 会切在转义逗号上；长度前缀（`长度:载荷`）载荷零改写、可以整段跳过，代价是每值多一个 `长度:` 前缀（5–19 字符的值平均多 2.67 B）。$10^5$ 个脏值下转义 1.308×、长度前缀 1.205×，而裸切分虽然「1.000×」但数据已经损坏。截断（转义符在末尾、声明长度不足）都要有受控报错。
- **追问**：为什么不直接用 JSON 或 pickle？
  - 要点：pickle 是语言私有的，且反序列化会执行任意代码，不能作为跨信任边界的格式；JSON 直接表达树要引入嵌套对象或专门的约定，体积更大也没有「n 个节点 2n+1 个 token」这种可断言的结构。生产里跨语言与 schema 演进交给 Thrift / Protobuf，本题考的正是自己设计格式时的不变量与边界。
- **追问**：树很深（链式 $10^5$）怎么办？
  - 要点：递归版的墙是 `sys.getrecursionlimit()` 默认 1000，实测链长 998 通过、999 抛 RecursionError；`setrecursionlimit` 把风险搬到 C 栈，实测 30 万上限 + 链式 $10^5$ 直接 SIGSEGV。正确做法是显式栈迭代版（序列化先压右再压左，反序列化用游标 + 帧栈），栈深度都是 $O(h)$；实测链式 $10^5$ 迭代序列化 44.13 ms、反序列化 129.39 ms。
- **追问**：怎么证明实现是对的？
  - 要点：不能只比中序——5 个节点全为 7 的完全树与链树中序相同；要逐节点比结构与值，或再序列化做字节比较。必测用例：空树、单节点、单侧链、值全相同、负数与极大值、值含分隔符，再加 $10^4$ 棵随机树批量往返。增量解析的证明照 [[coding-09]]：对同一份结果用固定长度 1/2/3/4096 与 2000 次随机切分喂入，断言还原的树逐节点一致。
- **追问**：改成 N 叉树、流式、带版本号各要改什么？
  - 要点：N 叉树要在编码里显式带子节点个数或终止标记（否则子树边界又变成猜的）；流式反序列化要点名任意 chunk 边界、buffer 上界、截断与取消的出口（口径见 [[coding-09]]；边收边建时的并发上限、重试与错误隔离见 [[coding-08]]）；版本号 + 节点数上界 + 校验和放在头部，长度与节点数用于**预分配之前**的校验（声称 $10^9$ 个节点的 payload 会直接吃掉十几 GiB）。不能上线的四条也要主动交代：内存里是语言对象而不是字节布局、没有 schema 演进、没有完整性校验、截断输入会返回半棵树。
