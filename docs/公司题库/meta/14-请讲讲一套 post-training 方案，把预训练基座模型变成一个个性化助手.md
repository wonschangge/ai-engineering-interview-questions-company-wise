## 一句话答案

> 分两层交付。**全局层**（所有用户共享一份）：SFT 装助手人格、输出格式、工具调用习惯与安全边界，偏好优化（RLHF / DPO / GRPO 任选其一）定取舍与安全兜底；这一层是一次性成本，摊到数亿用户后可忽略。**个性化层**（每用户不同）：个人**事实**（时区、联系人、日程、明确说过的偏好设置）一律不进权重，走分层记忆与权限感知检索；个人**行为**（语气、详略、语言、常用表达）优先用推理期机制（记忆注入、个性化重排、best-of-n 个性化打分器），最多按画像分桶训少量共享 adapter，绝不给每个用户做全量微调。
> 顺序是：① 评测基线与红线集 → ② 记忆加 RAG 补事实 → ③ SFT 定行为与格式 → ④ 偏好优化定取舍与安全 → ⑤ 参数级个性化与蒸馏降本。顺序反了就会追着变化的需求反复重训。可发布物（权重、adapter、system prompt、记忆 schema 与检索配置）都要带版本号与一键回退。

## 面试官在考什么

- **会不会分两层、会不会把「事实」与「行为」切开**。候选人的默认反射往往是「训一个更懂我的模型」，而正确答案是先问这条信息会变吗、要不要引用与删除、能不能用检索解决。
- **报不报得出每阶段的输入、产出与量级**。SFT 是 12,725 条人工示范 prompt、16 个 epoch；RM 是 33,207 条 prompt、$K=4\!\sim\!9$、只训 1 个 epoch；RL 是 256k episodes、约 31k 唯一 prompt。没有量级就说明没有真做过。
- **懂不懂偏好优化的机制与代价**。Bradley-Terry 只有分数差有辨识性、KL 是分布锚点而不是防过拟合、$\beta=0.02$ 的量级、四模型同场 252 GB、长度偏置从哪来——这些决定了同一套流水线在规模化时会不会翻车。
- **有没有把个性化当成本与工程问题**。per-user LoRA 的 4.19M 参数、训练态 67.1 MB 与推理态 8.39 MB 是两个口径；adapter 常驻显存、版本爆炸、多 LoRA 路由、按用户隔离，这些比训练超参更接近 Meta 的真实约束。
- **有没有上线门禁与回滚**。离线回归、人评口径、影子流量、按用户随机化的灰度、holdback、护栏自动停机，以及「个性化关闭」对照组的设置。

常见的错误答案：

- 把 RLHF 三段从头复述一遍就交卷，不讲个性化那一层怎么落地，也不讲 SFT 装什么、不装什么——那是把机制题当流水线背诵题。
- 说「给每个用户微调一份权重」，或把用户个人数据直接混进 SFT 数据与共享 RM 的训练集——前者在数亿用户规模上不成立，后者是隐私事故加评测污染。

## 原理与推导

### 1. 两层结构：共享底座加上每用户适配

| 层 | 装什么 | 机制 | 更新频率 | 回滚粒度 |
| --- | --- | --- | --- | --- |
| 全局层 | 助手人格与语气、格式与结构化输出、工具调用习惯、拒答与安全边界、多语言与地区覆盖 | SFT → 偏好优化 → 安全兜底 | 版本级（周/月） | 切回上一版权重加 system prompt |
| 个性化·事实 | 时区、关系与称呼、日程、明确说过的设置 | 分层记忆加权限感知检索，不训练 | 秒级（写入即可用） | 删除单条记忆、关闭注入 |
| 个性化·行为 | 语气、详略、语言、常用表达 | 提示或软提示 → 分桶共享 adapter → 在线重排 | 天级 | 换 adapter 版本、关闭个性化 |

个人事实进权重是最贵的错法：要写、要标注、要重训，更新周期以周计，而且拿不到引用、权限与删除能力——用户改一次时区就要重训一轮模型。**SFT 该装的是形式，记忆该装的是内容。**

### 2. 阶段一 SFT：装行为，不装个人事实

InstructGPT 的口径：12,725 条人工示范 prompt、训 16 个 epoch；SFT 的权重同时被冻结成后续 RL 的参考模型 $\pi_{SFT}$。「一份检查点两个角色」这个细节决定了 KL 项从哪来：初始策略与参考锚点是同一份权重，KL 衡量的就是 RL 阶段相对 SFT 走了多远。

数据量级用 LIMA 校准：65B 模型只用 1000 条精选 prompt/response 做监督微调、不做 RL 与偏好建模，受控人类研究里它被评「与 GPT-4 相当或更优」的比例是 43%（对 Bard 58%、对 DaVinci003 65%）；论文结论是知识几乎全部在预训练阶段获得、指令微调只教输出形式。这条结论直接给出本题最重要的数据取舍：

- **该进 SFT**：助手人格与语气、markdown 与结构化输出（含工具调用的 schema 与错误恢复）、拒答与安全边界、多语言与地区覆盖。
- **不该进 SFT**：任何用户私有事实。写进权重就等于放弃更新、引用与删除三种能力。
- **成本用合成数据摊薄**：Self-Instruct 自举生成指令并过滤后微调，在 Super-NaturalInstructions 上取得 33 个百分点绝对提升，与用私有数据加人工标注的 InstructGPT-001 相当；但必须配过滤、去重与去污染，否则模板化数据会把输出风格带偏。

上线前先排工程变量：微调前后 chat template、特殊 token、system prompt、解码默认值、推理精度、adapter 是否真的加载。任何一项变了，线上观感都会像「模型变笨」，要先排掉这些再谈权重（排查清单见 [[finetuning-07]]）。

### 3. 阶段二偏好优化：一份全局 RM 加一次偏好训练

RM 的口径（InstructGPT）：33,207 条 prompt，同一 prompt 采 $K=4\!\sim\!9$ 条回答由人排序，拆成 $\binom{K}{2}$ 个偏好对（$K=9$ 时 36 个），只训 1 个 epoch，且同一 prompt 的对必须放进同一个 batch element——打散等于让一个 completion 被反复推，单遍数据就过拟合。Bradley-Terry 只有分数差有辨识性（分数整体平移不改变损失），所以进 RL 前必须做尺度与零点对齐。

RL 的目标是「多拿奖励」与「别走远」的兑换：

$$J(\theta) = \mathbb{E}_{x \sim D,\ y \sim \pi_\theta(\cdot \mid x)}\left[ r_\phi(x,y) - \beta \, \mathrm{KL}\!\left(\pi_\theta(\cdot \mid x) \,\big\|\, \pi_{SFT}(\cdot \mid x)\right) \right]$$

口径：$\beta=0.02$（消融最优区间 0.01–0.02，$\beta=0$ 与 $\beta=2$ 都明显变差）、clip 0.2、256k episodes 约 31k 唯一 prompt（复用 8.3 次）、batch 512 拆 8 个 minibatch、只做 1 个 inner epoch、不打折扣的 GAE、序列级奖励只在终止步给一次。四个模型同场，按 7B 算的显存是 $112+112+14+14=252$ GB：policy 与 value 是训练态 16 B/param，reward 与 reference 是推理态 2 B/param。

替代路径要讲清边界：DPO 从 KL 约束目标的闭式最优策略 $\pi^* \propto \pi_{SFT}\exp(r/\beta)$ 反解出奖励，模型数从 4 降到 2、不需要 rollout，代价是离线数据没有探索（见 [[finetuning-02]]）；GRPO 用组内相对优势去掉 value network，省一份 16 B/param（见 [[finetuning-03]]）；奖励能被规则验证时走 RLVR。

**个性化为什么不能共用这一份 RM**：单一全局 RM 学的是全体标注者的平均口味，会把多数人的偏好强加给每个用户。最典型的症状是长度偏置——偏好数据里更长的回答更容易被选中，RM 于是把「长」当成质量代理，策略越写越长，而 KL 只约束分布、不约束长度。所以输出长度、拒答率、重复率必须列成监控曲线，并在数据与奖励两侧同时做长度平衡。设计规则可以压缩成一句：**通用有用、无害与格式固化进全局 RM 与 RL；个人口味留在推理期**（个性化重排、best-of-n 的个性化打分器、写进记忆），最多用很小的适配器学风格。

对齐税要报得出数：PPO-ptx 在同一个 minibatch 里混预训练梯度，系数 27.8、每个 episode 配 8 倍预训练样本；算力账是 SFT 4.9 加 PPO-ptx 60 petaflop/s-days，相对 GPT-3 预训练的 3,640 只占 1.78%（SFT 单独 0.135%），但人工标注与四模型并行的工程成本不在这笔账里。超参极敏感，$\beta$、clip、学习率、batch、采样温度要一起调，任何一项错了都表现为「RM 分数涨、人评掉」。

### 4. 阶段三个性化层：事实走记忆，行为才考虑参数

事实层直接复用记忆的分层设计（[[agents-07]]）：按内容分工作记忆、情节记忆、语义记忆、程序记忆；按存储层分上下文窗口、摘要、向量库、结构化库、对象存储。语义记忆必须做到「唯一有效版本 + 显式删除 + 新事实覆盖旧事实」，四类读写模式不能塞进一个向量库。权限过滤要发生在召回阶段而不是生成阶段（[[rag-08]]）；跨用户泄漏、保留期限与删除权是红线；把用户私有数据混进共享 adapter 或共享 RM 的训练数据，既是隐私事故也是评测污染。

行为层有三条路，代价差一个数量级：

| 路线 | 训练成本 | 推理成本 | 适用场景 |
| --- | --- | --- | --- |
| 提示或软提示 | prefix tuning 只学约 0.1% 参数就能与全量微调相当（GPT-2、BART）；prompt tuning 要过百亿参数才追平（T5） | 每次前向多带 $T$ 个虚拟 token，占上下文与 KV cache，且与 prefix cache 天然冲突 | 少量显式偏好设置、短期试验 |
| per-user LoRA | $r=8$ 只适配 q、v 时 4,194,304 可训练参数（7B 的 0.0599%），训练态 67.1 MB | bf16 adapter 8.39 MB；合并进权重后推理零额外延迟 | 稳定且量大的风格差异，能接受离线训练与版本管理 |
| 在线无梯度适应 | 0 | 检索与重排的 token 与延迟 | 唯一真正「每用户」的机制：当天生效、可回滚、可解释 |

两个口径必须分开写：**训练态 16 B/param**（bf16 权重副本 2 + 梯度 2 + fp32 master 与 Adam 状态 12）和**推理态 2 B/param** 不是一回事。7B 全量微调训练态 104.31 GiB，LoRA 那份 67.1 MB，差了约 1669 倍（这份对照只算可训练参数的状态开销：全量那 104.31 GiB 已含 14 GB 的 bf16 底座，LoRA 这 67.1 MB 之外还要另加同一份冻结底座）；但服务侧只关心推理态，一份 adapter 只有 8.39 MB——把训练口径当成服务成本会得出完全错误的结论。真正卡住「每用户一份权重」的是版本爆炸与自己算的并发账：adapter 要常驻显存，1000 并发挂 $r=16$、q/k/v/o 的 adapter（33.55 MB 一份）就是 33.55 GB。生产上只能按画像或聚类分桶出少量共享 adapter，或走请求级多 LoRA 路由（[[finetuning-06]]、[[system-design-10]]）。

软提示还有一笔隐藏成本：$T$ 个虚拟 token 每一层都要占 KV。$T=20$ 的前缀在 8B 上是 2.5 MiB/序列（128 KiB/token），在 70B 上是 6.25 MiB/序列（320 KiB/token）；它对所有用户都一样，所以可以用 prefix cache 复用，但也正因为要复用，个体差异化的软提示反而破坏缓存命中——这是高频助手请求不划算的原因。

### 5. 个性化适配的遗忘与回归

优化新任务一步必然抬高旧任务损失：

$$\Delta L_{old} \approx -\eta \left\langle \nabla L_{old}, \nabla L_{new} \right\rangle$$

只要目标里没有旧任务约束、参数容量又被共享，遗忘就是几何必然，与模型大小无关。

实证口径（1B–7B 持续指令微调，Luo 等）：遗忘普遍存在；在该区间内模型越大遗忘越严重（这是相对跌幅口径，不能外推到 100B 级）；3b 档 decoder-only 的 BLOOMZ 遗忘少于参数档接近的 encoder-decoder mT0（FG 均值 17.76% 对 21.77%）；混入通用指令数据能显著缓解——在持续任务数据里加 1 万条通用指令后，LLAMA-7b 的 MMLU-human 从只训指令数据的 26.8% 回到 30%（初始 34.72%；相对初始的跌幅从 22.81% 收到 13.59%，补回 40.40%，仍残留 59.60%）。

四层缓解按「改数据 / 改参数 / 改目标 / 改流程」给：数据层回放配比 5%–10%（总算力 1.053×–1.111×，旧数据每个 epoch 只被过 0.0526–0.1111 遍）；参数层用 LoRA 这类隔离把底座冻结；目标层用 KL 约束到参考模型或软目标蒸馏；流程层把通用能力回归集写进验收门禁。

个性化场景的特殊风险要单独点出：如果按用户或按场景周期性重训，遗忘与回归成本按周期复利。所以优先选「冻结底座加参数隔离」，或干脆不进权重。每次适配后都要跑同一套通用能力回归集（固定评测集、固定解码参数），用回归分数与目标任务指标两条曲线一起调约束强度，从 $\rho=5\%$ 起步，回归掉超阈值就加大配比或降学习率，别把约束强度拍出来（[[finetuning-07]]）。

### 6. 评测与上线门禁

离线侧固定评测集与解码参数，同时报绝对跌幅与相对跌幅；人评用 1–7 Likert（InstructGPT 口径里 Likert 只用于人评，不用于 RM 训练）。「RM 分数涨不等于人评涨」有实证：标注者之间一致率只有 72.6%±1.5%（留出标注者之间 77.3%±1.3%），6B RM 在训练标注者上的预测精度 72.4%±0.4%、在留出组上 69.6%±0.9%，已经贴着人类一致率——此时再堆 RM 容量收益有限，该改的是标注指南与数据分布。

门禁按分层写：红线集一票否决、核心能力集不许显著退化、目标能力集必须显著提升、成本与延迟守预算；阈值与最小可检测差异事前写死，输出允许「数据不够」这第三种结论，judge 版本必须与 prompt、模型版本一起锁（[[evaluation-04]]）。

在线侧走四级阶梯：离线回归 → 影子流量（用户看旧输出，用来把能力变化与工程开销拆开）→ 1%–5% 按用户或会话随机化的灰度 A/B（带护栏，护栏破了自动停机）→ 放量并保留约 1% holdback（[[evaluation-09]]）。

个性化特有的口径必须写进实验设计：按用户分群（新用户、重度用户、不同语言与地区）分别报，看长会话多轮指标而不是单轮，设「个性化关闭」作为对照组，护栏里加安全性（有害内容与越狱）、隐私（跨用户泄漏）与助手指标（拒答正确率、工具调用成功率、满意度）。还要防个性化自己的 Goodhart——点击与停留上升可能来自一味附和用户的讨好行为，必须配人工评估与对抗集。

### 7. 成本账与执行顺序

微调收益写成可算的盈亏平衡 $N^* = C_{\text{一次性}} / \Delta c$：400 美元的纯训练算力对每次省 0.0045 美元是 8.9 万次请求回本（每月 10 万次约 27 天）；加上 1000 条乘 \$5 的人工标注后一次性成本 5400 美元，回本点涨到 120 万次；若微调后仍要保留 1000 token 示例，每次只省 0.003 美元，回本点 13.3 万次；把知识烧进权重（每周重训一次、每月 1600 美元）要每月 26.7 万次才持平，而且仍然拿不到引用与权限（口径与算式见 [[finetuning-08]]：输入按 \$3/1M token、训练按 \$2/GPU·小时）。延迟侧：去掉 1500 token 示例在 1 万 token/s 的 prefill 吞吐下省 150 ms；RAG 的 rerank（100 个候选乘 512 token，按 100 万 token/s）约 51.2 ms，且 p99 抖动比均值更值得关注。

把账接回 Meta 的规模：全局 SFT 与偏好优化是数亿用户共享的一次性成本——按 64.9 petaflop/s-days、H100 bf16 989 TFLOPs、40% MFU 与 \$2/GPU·小时估算约 3,937 GPU·小时，摊到 3 亿用户每人约 \$0.000026（算力口径估算，标注与工程成本另计，放大 100 倍也只是每人约 \$0.0026）。个人事实走检索每次多约 2000 token 即 \$0.006，在 70B 上还要多 625 MiB 的 KV。而 per-user 训练的一次性成本只能服务一个用户——哪怕只给 1% 的用户（300 万）每月刷一次、每次按 0.05 美元算，也是每月 15 万美元，外加 25.2 TB 的 adapter 落盘与 300 万份需要回归、灰度与回滚的产物。**全局层的一次性成本能摊到数亿用户，per-user 训练永远摊不薄**，所以「个性化」在 Meta 这道题里应该是推理时机制加少量共享适配器，而不是训练问题。

执行顺序写成五步：① 先建评测基线与红线集；② 提示加记忆与 RAG 补事实；③ SFT 定行为与格式；④ 偏好优化定取舍与安全（DPO 或 RLHF/GRPO 按数据与算力选）；⑤ 最后才做参数级个性化与蒸馏降本。反面清单收尾：把个人知识烧进权重（更新、引用、权限三件事同时丢）、给每个用户做全量微调、跳过 SFT 直接上 RL（既没有好的参考锚点，也训不出有用 RM）、用 RM 分数当对齐成功的证据、没有回归集就上线个性化、不设回退开关。

### 可运行实验：一步更新必然抬高旧任务损失

旧任务 $y=x$、新任务 $y=-x$，单参数线性模型，两个任务的梯度方向完全相反（$\cos=-1$）：

```python
import torch, torch.nn as nn

X = torch.linspace(-1, 1, 64).unsqueeze(1)          # 旧任务 y=x；新任务 y=-x
m = nn.Linear(1, 1)
nn.init.constant_(m.weight, 0.5); nn.init.constant_(m.bias, 0.0)
yA, yB, mse = X.clone(), -X.clone(), nn.MSELoss()

def grad(y):
    m.zero_grad(); mse(m(X), y).backward()
    return [p.grad.clone() for p in m.parameters()]

gA, gB = grad(yA), grad(yB)
dot = sum((a * b).sum() for a, b in zip(gA, gB))
nA = sum((a * a).sum() for a in gA).sqrt()
nB = sum((b * b).sum() for b in gB).sqrt()
print(f"<gA,gB>={dot:.4f}  cos={dot / (nA * nB):.4f}")   # 预期 -0.3548 / -1.0000

eta, L_A0 = 0.1, mse(m(X), yA).item()
m.zero_grad(); mse(m(X), yB).backward()                 # 只对新任务走一步 SGD
with torch.no_grad():                                   # 只有参数更新不需要梯度
    for p in m.parameters():
        p -= eta * p.grad
L_A1 = mse(m(X), yA).item()
print(f"L_A {L_A0:.6f} -> {L_A1:.6f}  一阶预测 {L_A0 - eta * dot:.6f}")
```

本机输出（CPU）：

```text
<gA,gB>=-0.3548  cos=-1.0000
L_A 0.085979 -> 0.125123  一阶预测 0.121462
```

$\Delta L_{old} \approx -\eta\langle g_A, g_B\rangle = +0.0355$，真实一步是 $+0.0391$（比一阶项多的 0.0037 是二阶项 $\tfrac{1}{2}\eta^2 \Delta\theta^{\top} H \Delta\theta$，精确值 0.00366）。**一阶项已经为正，所以这不是学习率太大造成的，而是负内积的必然结果**——这正是必须把 $L_{old}$ 加回目标函数（回放）、或隔离参数（PEFT）的原因。符号与量级结论可外推，具体幅度不能。

### 回放配比的实际效果（本机重跑共享 trunk 玩具，设置同 [[mistral-07]]）

结构：trunk（Linear(32→16)+ReLU）加两个头；旧任务 8 类、类均值铺满 32 维，新任务 4 类、只落在 6 维子空间；先在旧任务上训 600 步得基线，再冻结旧头、用 800 步、lr 3e-3 微调 trunk 与新头，每步按配比 $\rho$ 额外混入旧任务样本。本机复跑该设置（完整脚本在 [[mistral-07]]），并补上 $\rho=0.25$ 一档与新任务的 loss 列——acc 与 loss 都在 2000 条留出样本上测（同一个玩具在训练集上的 loss 是另一条曲线）：

| 回放配比 $\rho$ | 旧任务 acc | 旧任务相对跌幅 | 新任务 acc | 新任务 loss（留出） |
| --- | --- | --- | --- | --- |
| 0（只训新任务） | 0.5190 | 48.02% | 0.7935 | 0.5588 |
| 0.05 | 0.9760 | 2.25% | 0.8005 | 0.5545 |
| 0.10 | 0.9725 | 2.60% | 0.7995 | 0.5548 |
| 0.25 | 0.9885 | 1.00% | 0.7945 | 0.5474 |

基线：旧任务 0.9985、新任务 0.2005（4 类随机约 0.25）。读法有三条：① 回放把旧任务相对跌幅从 48.02% 压到 2.25%，**这个玩具里塑性代价落在噪声内**（新任务 loss 0.5588 → 0.5545）；② 5% 到 10% 之间没有单调关系，说明「从 5% 起步、按两条曲线调」比拍一个配比更重要；③ 这只是 H=16 的刻意受限 trunk，48.02%、2.25% 这类幅度不能外推到真实模型。

塑性代价的真实量级要看最坏情形。[[finetuning-07]] 的对抗式玩具（两任务梯度 $\cos=-1$）里，配比从 5% 提到 10% 会把新任务 loss 从 0.1959 推到 0.3797，即 $0.3797/0.1959=1.94$ 倍，同时旧任务损失倍数从 8.1× 降到 6.4×。**回放不是免费的，只是在非对抗分布上很便宜。**

## 常见追问

- **追问**：为什么不给每个用户训一套权重，哪怕只用 LoRA？
  - 要点：训练成本不是瓶颈（4.19M 参数、训练态 67.1 MB），服务侧才是：adapter 要常驻显存，1000 并发挂 $r=16$ 的 adapter 就是 33.55 GB；数亿用户各一份权重意味着数亿个需要回归、灰度与回滚的产物。事实类需求本来就不该进权重（更新、引用、权限三件事同时丢），行为类需求先用推理期机制验证收益，只有稳定且量大的风格差异才值得分桶共享 adapter。
- **追问**：个性化偏好为什么不能训一个 RM 来打分？
  - 要点：单个用户的偏好对太少（几十到几百条），训不出稳定 RM；全局 RM 是平均口味，会把多数人的偏好强加给个人。长度偏置是最典型的副作用：偏好数据里更长更易被选中，RM 把长度当成质量代理，策略越写越长，而 KL 只约束分布不约束长度。个性化打分该放在推理期（重排、best-of-n 打分器，用少量个人历史在线校准），并把长度作为显式约束扣掉。
- **追问**：事实与行为的边界怎么划？
  - 要点：「我的时区是 UTC+8」「下周三出差」「我女朋友叫某名字」是事实，必须可更新、可删除、可引用，走记忆与检索；「回答短一点」「用中文、别用 emoji」「先说结论」是行为，优先走 system prompt 或记忆里的偏好项，只有稳定且提示词表达不了时才考虑 adapter。判据就一条：这条信息会随现实变化吗、需要引用或删除吗——会变的都是事实。
- **追问**：个性化功能怎么上线？
  - 要点：按四级阶梯走，并加个性化专属口径——离线回归（固定 harness）→ 影子流量把工程开销与能力变化拆开 → 按用户随机化的 1%–5% 灰度（同一个人要么全开要么全关，避免会话内抖动），保留约 1% holdback，设「个性化关闭」对照组；按新用户、重度用户、语言与地区分群，看长会话多轮指标；护栏含越狱与有害内容、跨用户泄漏、拒答正确率与工具调用成功率；防讨好型 Goodhart（点击涨但满意度掉）。
- **追问**：什么时候该微调、什么时候走 RAG 或纯提示？
  - 要点：缺知识（事实、时效、权限、需要引用）走 RAG；缺行为（格式、术语、语气、拒答边界）才微调；两者都不缺就是提示工程加少量示例。算盈亏平衡：\$400 的训练费对每次省 \$0.0045 是 8.9 万次请求回本，加上标注成本后 120 万次（[[finetuning-08]]）。
- **追问**：跳过 SFT 直接上 RL 行不行？
  - 要点：不行。RL 需要两个锚：参考模型与 RM。没有 SFT，采样出来的回答只是网页续写，标注者比较的是两段噪声，RM 学不到有用信号，KL 也没有好的锚点。InstructGPT 的顺序是 SFT（12,725 条、16 个 epoch）先给出 $\pi_{SFT}$，偏好数据与 RL 都建立在它之上；预算不够时先砍 RL 的规模，而不是砍 SFT。
