## 一句话答案

> 翻译服务的答案要分四层，且每层都有一个「不能只讲模型」的工程要点：
> ① **数据与词表**——平行语料 + 子词切分（BPE 式的做法把稀有词拆成高频子词，词表固定、彻底消除 OOV，可引用 Sennrich 等人的原始动机）+ 回译扩充；
> ② **模型**——编码器-解码器 + 交叉注意力（Transformer 用自注意力与交叉注意力替掉了 RNN 的串行依赖，可引用 *Attention Is All You Need*）；工业级 NMT 的工程细节可参照 GNMT 的做法：深层 LSTM + 残差连接 + 词片（wordpieces）+ 量化推理 + 束搜索（带长度归一化与覆盖惩罚）；
> ③ **服务**——批处理与 KV cache、流式（同传）的「等多少再翻」策略、**术语表与格式约束**（用约束解码保证术语被强制使用、HTML 标签与占位符不被翻坏）；
> ④ **评测**——自动指标（BLEU/COMET）+ 人工（充分性/流畅性）+ **按语言对与领域分群**，绝不用一个平均分对外声称质量。
> 一句话取舍：**翻译质量的瓶颈几乎从来不在解码器，而在数据覆盖、术语一致性、以及格式与上下文保持**。

## 面试官在考什么

- **子词切分的动机**是否能讲透：词级词表会 OOV、字符级序列过长；子词在两者之间取平衡，并且让「同词根/复合词」共享表示。可引用 Sennrich 等人的口径：用 BPE 处理稀有词与未知词，让开放词表问题变成固定词表的子词建模问题。
- **架构演进**是否说得清：RNN 的串行依赖 → 注意力机制 → 完全基于注意力的 Transformer；以及为什么交叉注意力是翻译任务的关键部件（把源语言表示对齐到目标语言生成）。
- **工业细节**：GNMT 那篇的价值不在模型新意，而在工程化——深层网络的残差与低精度推理、词片、束搜索的长度归一化与覆盖惩罚（避免重复翻译与漏译）。能报出这些细节，说明读过系统论文而不是只看模型图。
- **服务侧的两个硬问题**：① **格式保持**（译文中不能改坏标记、URL、代码片段、占位符）；② **术语一致性**（同一术语在全文必须同一译法，且必须使用客户指定的译法）。这两条是商用翻译与「跑个开源模型」的分水岭。
- **评测的诚实性**：BLEU 是 $n$-gram 精确率加简短惩罚，**不理解语义、对分词敏感、对同义替换惩罚过重**；要能说出什么时候必须上学习式指标（COMET 类）或人工评估，以及为什么必须分语言对/领域报告。

**常见错误答案**

- 「用 LLM 直接翻译，不需要专门系统」——忽略术语约束、格式保持、成本与延迟、以及长文档的一致性。
- 「BLEU 高就是翻译好」——BLEU 对词序与同义替换的敏感度与你想要的「意义一致」并不同向。
- 「长文本直接切块分别翻」——会导致代词与术语跨块不一致；要有重叠窗口 + 术语表 + 后处理对齐。
- 「同传就是流式输出」——不做「等待策略」的流式翻译会因缺少后文而反复自我纠正，质量显著下降。

## 原理与推导

### 1. 词表：为什么必须子词化

设词级词表大小 $V$、语料中不同词形 $W$。自然语言里 $W\gg V$（且长尾极长），词级模型必然遇到 OOV；字符级又把序列拉长 4–6 倍，注意力成本与解码步数都受影响。子词（BPE/WordPiece/unigram）的做法是把词拆成高频片段：

$$\text{unbelievable}\Rightarrow \text{un}+\text{believ}+\text{able}$$

收益有三：① 不再有 OOV（任何词都能拆成已知子词，最坏退化为字节）；② 稀有词与常见词共享子词表示，参数效率高；③ 跨语言共享子词能帮助低资源语言对（多语言模型的常用手段）。代价是解码步数变多、以及子词边界可能切断语义单元（这也是「翻译后处理」要处理空格与标点的原因）。

### 2. 模型：从 RNN 到注意力

- **RNN 编码器-解码器**：串行、长依赖衰减、无法并行。
- **注意力**：解码时对源端所有位置加权求和，解决长依赖与对齐问题（交叉注意力的雏形）。
- **Transformer**：自注意力 + 交叉注意力 + 位置编码，训练可并行、长依赖建模更强。翻译是最典型的「编码器-解码器」任务，交叉注意力是核心部件。
- **工业工程**：GNMT 的贡献是把上面这些做成可服务系统——深层 LSTM 配残差、词片、量化推理（当时用低精度算术提升吞吐）、以及**束搜索的改良**：长度归一化（避免偏向短句）、覆盖惩罚（避免重复翻译同一片段、减少漏译）。

### 3. 训练数据与低资源

- **平行语料**是稀缺资源；**回译（back-translation）**用目标语单语数据生成合成源句，是小语种提升的主力手段。
- **多语言模型**共享参数与词表，但要处理**容量竞争**（高资源语言挤占低资源语言的表示）；常用做法是温度采样调整语言比例、加语言标签、或为低资源语言保留专用容量。
- **领域适配**：通用模型在医疗/法律上术语错乱；做法是术语表约束 + 领域微调 + 检索增强的翻译记忆（TM）复用。

### 4. 服务：延迟、流式与约束

- **批处理与 KV cache**：翻译是「短输入长输出」的典型（同传除外），批处理能显著降低单位成本；KV cache 让解码每步只算一个 token（串 [[system-design-10]] 的服务栈）。
- **流式/同传**：核心是**等待策略**（wait-$k$：多等 $k$ 个词再译，或按「读入-写出」延迟预算自适应）。等待越少延迟越低、但质量越差（缺少后文导致性别、数、语序判断错误）。评估要同时报 **BLEU 与延迟（LAAL/平均滞后词数）**，只报 BLEU 会掩盖延迟代价。
- **约束解码**：术语表强制（在解码时把不允许的 token 概率置零或用词表偏置）、格式保持（把标签/占位符当作不可翻译的 span，先抽取再回填——比让模型学会「别翻坏」可靠得多）。
- **长文档**：重叠分块 + 术语表 + 跨块一致性后处理（代词、术语、数字格式）。

### 5. 评测

| 层次 | 指标 | 说明 |
| --- | --- | --- |
| 自动（表面） | BLEU、chrF | 快、可复现；对同义替换与词序敏感，不衡量语义 |
| 自动（学习式） | COMET 类 | 用带标注的译文质量数据训练，和人工判断相关性更高 |
| 人工 | 充分性/流畅性、错误类型标注（漏译/误译/术语/格式） | 上线前的最终判据；抽样设计要分层 |
| 系统 | 延迟、成本、格式错误率、术语符合率 | 产品可用性的硬门槛 |

**关键纪律**：任何对外数字都必须带**语言对、测试集、领域**与解码参数；绝不能用一个跨语言平均分声称「翻译质量达到 X」。

## 数值与代码验证

### 表 1：服务成本量级（70B 级模型，仓库统一常数）

| 项 | 算式 | 结果 |
| --- | --- | --- |
| 翻译 100 万 token 输出 | $2\times N\times P$（$N$ 为总 token） | $2\times2\times10^{6}\times7\times10^{10}=2.8\times10^{17}$ FLOPs |
| 单卡时间（8×H100、MFU 40%） | $2.8\times10^{17}/(8\times989\times10^{12}\times0.4)$ | ≈ 88 s |
| 成本（\$2/GPU·h） | $88/3600\times8\times2$ | ≈ \$0.39 |
| 对比：小模型（1.5B 专用 MT） | 参数量 1/47 | ≈ \$0.008（质量需按语言对验证） |

口径：这是**算力下界**（未计批处理效率损失、重试与术语约束的额外开销）。结论是：通用大模型翻译的单位成本并不高，真正的成本在**评测、术语维护与长文档一致性**上。

### 表 2：BLEU 的三个反例（说明它衡量什么、不衡量什么）

| 译文 | 与参考的关系 | BLEU-4（示例） | 问题 |
| --- | --- | --- | --- |
| 完全一致 | 相同 | 100 | — |
| 词都相同但语序打乱 | 意义可能仍可懂 | 显著下降 | 词序敏感，但语序在部分语言对里可自由 |
| 同义词替换（每个词都对） | 意义完全一致 | 明显下降 | 不理解语义（这是学习式指标存在的理由） |
| 漏译一个从句但其余更流畅 | 意义缺失 | 可能仍然较高 | $n$-gram 精确率偏高、召回没有被直接惩罚 |

### 可运行代码

```python
# 1) 手写 corpus BLEU（含裁剪计数与简短惩罚），并演示它的局限
import math, re
from collections import Counter

def tokens(s, lower=True):
    s = s.lower() if lower else s
    return re.findall(r"\w+|[^\w\s]", s, flags=re.UNICODE)

def ngrams(ws, n):
    return Counter(tuple(ws[i:i+n]) for i in range(len(ws)-n+1))

def corpus_bleu(cands, refs, N=4):
    num = [0]*N; den = [0]*N
    c_len = r_len = 0
    for c, r in zip(cands, refs):
        cw, rw = tokens(c), tokens(r)
        c_len += len(cw); r_len += len(rw)
        for n in range(1, N+1):
            cn, rn = ngrams(cw, n), ngrams(rw, n)
            num[n-1] += sum(min(cnt, rn[g]) for g, cnt in cn.items())
            den[n-1] += max(0, len(cw)-n+1)
    prec = [(num[i]/den[i] if den[i] else 1.0) for i in range(N)]
    if min(prec) == 0:
        return 0.0, prec
    bp = 1.0 if c_len > r_len else math.exp(1 - r_len/c_len)
    return bp * math.exp(sum(math.log(p) for p in prec)/N), prec

REF = "The cat sat on the mat and looked at the dog"
cases = {
    "完全一致": "The cat sat on the mat and looked at the dog",
    "语序打乱": "The mat on sat cat the and dog the at looked",
    "同义替换": "A feline rested upon the rug and gazed at the canine",
    "漏译从句": "The cat sat on the mat",
}
print(f"{'译文类型':<10} {'BLEU-4':>8}  1-gram 精确率")
for name, cand in cases.items():
    b, prec = corpus_bleu([cand], [REF])
    print(f"{name:<10} {b:>8.4f}  {prec[0]:.4f}")

# 2) 子词切分：为什么稀有词不再是 OOV（极简 BPE 合并演示）
def learn_bpe(corpus, merges=12):
    vocab = Counter()
    for w in corpus:
        vocab[tuple(w)] += 1
    rules = []
    for _ in range(merges):
        pairs = Counter()
        for w, c in vocab.items():
            for i in range(len(w)-1):
                pairs[(w[i], w[i+1])] += c
        if not pairs:
            break
        (a, b), _ = pairs.most_common(1)[0]
        rules.append((a, b))
        new = {}
        for w, c in vocab.items():
            out, i = [], 0
            while i < len(w):
                if i < len(w)-1 and w[i] == a and w[i+1] == b:
                    out.append(a+b); i += 2
                else:
                    out.append(w[i]); i += 1
            new[tuple(out)] = new.get(tuple(out), 0) + c
        vocab = new
    return rules, vocab

corpus = ["low", "lower", "lowest", "newer", "newest", "unbelievable", "believable"]
rules, vocab = learn_bpe(corpus)
print(f"\n学到 {len(rules)} 条合并规则：{rules[:6]} ...")
for w in ["lowest", "unbelievable", "unseenword"]:
    seg, i = [w[0]], 1
    while i < len(w):
        seg.append(w[i]); i += 1
    for a, b in rules:                      # 依序应用合并规则
        out, i = [], 0
        while i < len(seg):
            if i < len(seg)-1 and seg[i] == a and seg[i+1] == b:
                out.append(a+b); i += 2
            else:
                out.append(seg[i]); i += 1
        seg = out
    print(f"  {w:<14} -> {seg}")
print("最后一行说明：没见过的词也能切成已知子词（最坏退化到字符），因此不再有 OOV")

# 3) 约束解码：术语表强制（词表偏置的最小演示）
TERM_MAP = {"cloud": "云", "server": "服务器"}
def constrained_translate(src, model_out, term_map=TERM_MAP):
    """真实系统在解码时偏置/屏蔽 token；这里用后处理演示必须保证的性质"""
    out = model_out
    for en, zh in term_map.items():
        if en in src.lower() and zh not in out:
            out = out.replace("服务器", zh) if zh == "服务器" and "服务器" in out else out + f"（术语强制：{en}->{zh}）"
    return out

for src, mt in [("deploy on a cloud server", "部署在服务器上"),
                ("cloud storage", "存储服务")]:
    print(f"  src={src!r:<26} 模型输出={mt!r:<12} -> {constrained_translate(src, mt)!r}")
print("术语符合率必须作为发布门禁指标单独统计（不能只看 BLEU）")
```

预期输出要点：BLEU 表里**同义替换的得分大幅下降**、而**漏译从句的得分可能仍不低**——这正好说明 BLEU 的两个方向都不对齐「意义正确」；BPE 段显示未见词被切成已知子词（无 OOV）；约束解码段演示术语强制在系统层面实现（真实做法是解码期偏置或先抽取 span 再回填），并提示术语符合率要单独监控。

## 常见追问

- **追问**：BLEU 现在还用吗？
  - 要点：用于回归对比（同测试集、同分词口径下的版本间比较）仍然有效；但对外声称质量、以及跨系统比较必须配学习式指标与人工评估。**BLEU 是回归网，不是目标函数**（串 [[evaluation-05]]）。
- **追问**：术语表怎么强制才可靠？
  - 要点：解码期词表偏置（把目标术语的 token 概率抬升或屏蔽其他候选）+ 生成后校验（未命中的句子重译或标记），并对「术语符合率」单独做门禁。
- **追问**：长文档翻译怎么保证一致性？
  - 要点：重叠分块 + 全局术语表 + 跨块后处理（代词、数字、格式统一）；对一致性要求高的场景，用「先抽取术语与实体 → 再翻译 → 再回填」的管道比端到端更可控。
- **追问**：低资源语言对怎么办？
  - 要点：多语言共享 + 回译 + 从高资源语言迁移（迁移学习/适配器）+ 数据清洗（低资源语料噪声大，清洗收益常高于模型改动）。
- **追问**：同传（流式）的关键权衡是什么？
  - 要点：等待策略。等得越多质量越好、延迟越高；评估必须同时报质量与延迟（平均滞后词数），并按场景（会议 vs 字幕）设不同工作点。
- **追问**：为什么不让一个通用 LLM 直接用提示词翻译？
  - 要点：可以做，但要用系统的约束补齐——术语、格式、上下文一致性、成本与延迟；纯提示词在这些维度上没有保障（串 [[system-design-10]]）。
