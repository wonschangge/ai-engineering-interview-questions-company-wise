## 一句话答案

> 把「已排序」翻译成只作用在相邻词对上的约束：两词的第一个不同位置给出唯一一条有向边（前词的字符指向后词的字符），该位置之后一律不建边。$N$ 个词只做 $N-1$ 次比较，总代价不超过全部字符数 $C$，所以时间 $O(C)$、空间 $O(k+E)$，其中 $k$ 是输入里实际出现的不同字符数，$E \le N-1$。
> 三条无解路径在建图阶段就要分开：前缀悖论（长词在前、它的前缀词在后，如 `[abc, ab]`）立刻返回空串；环（Kahn 输出节点数少于 $k$）返回空串；相邻词完全相同只算重复，跳过而不是报错。
> 唯一性与确定性是加分项：Kahn 每一步入度为零的候选数恰为 1 才唯一；即使题目只要求任意合法顺序，也要用最小堆固定 tie-break，否则同一输入在不同进程会给出不同结果。

## 面试官在考什么

- 能否把自然语言的「已排序」翻译成图约束：只比相邻、只取第一个差异位置、前缀关系单独处理。这是本题的第一道分水岭，也是 2 到 3 分钟口头陈述的全部内容。
- 复杂度是否真的算过：$N$ 个词、平均长 $L$、总字符数 $C = N \cdot L$，$N-1$ 次比较给出时间 $O(C)$；哈希邻接表给出空间 $O(k+E)$。
- 三条无解路径是否分得清、各自返回什么：前缀悖论、环、重复词。Meta 的编程轮几乎一定会在主循环写完后补一个 `[abc, ab]` 或 `[a, b, a]`。
- 图规模口径是否写死正确：$k$ 是输入里实际出现的字符数而不是固定 26；边数 $E \le \min(N-1,\; k(k-1))$。
- 工程确定性：邻接表去重与入度累加必须一致，输出顺序不能依赖哈希迭代顺序；无解要有正常出口（返回空串），不是抛异常。
- 自证能力：能否给出一个可检验的不变量，而不是只跑两个手挑的例子。

常见错误答案：

- 两两比较所有词对来建边。$N=10^4$、平均长 10 时是约 $5 \times 10^7$ 对、最坏约 $5 \times 10^8$ 次字符比较，比相邻链式的约 $10^5$ 次贵 5,000 倍（约三个数量级）；而且全序的传递性保证相邻约束已经充分。
- 把字母表写死成 26 个小写字母。输入含大写、数字或非 ASCII 直接出错；反过来输入只用到 3 个字符时，写死 26 会凭空输出 23 个不存在的字符，判题立刻错。
- 只比较首字符，或者把第一个差异之后的字符也拿去建边。前者丢约束，后者引入假边，可能把本来合法的词表判成有环。

## 原理与推导

### 1. 把「已排序」翻译成相邻约束

题目保证存在一个字符全集上的全序 $<_O$，使词表按字典序（逐字符比较、前缀更小）非降。对相邻两词 $w_1, w_2$：

- 找到第一个满足 $w_1[i] \ne w_2[i]$ 的位置 $i$，得到唯一一条边 $w_1[i] \to w_2[i]$，含义是 $w_1[i] <_O w_2[i]$；
- 位置 $i$ 之后的字符对顺序没有任何信息，一律不建边；
- 找不到差异时只有三种情况：$w_1$ 是 $w_2$ 的真前缀（合法，无边，如 `[ab, abc]`）、两词完全相等（重复词，无边）、$w_2$ 是 $w_1$ 的真前缀（长词在前，无解）。

只比较相邻而不是两两比较，依据是全序的传递性：$w_1 \le w_2 \le \dots \le w_N$ 只要逐对成立就整体成立。这一点讲清楚，$O(C)$ 的结论就顺理成章。

### 2. 为什么时间上限是全部字符数 $C$

$N$ 个词做 $N-1$ 次相邻比较，每次最多走到较短词的长度，所以字符比较次数不超过 $\sum_i |w_i| = C$。建图、拓扑排序、输出都与 $k+E$ 同阶，整体 $O(C)$。写成 $O(N \cdot L)$ 也行，但要说明 $L$ 是平均词长、$C$ 是全部字符数——面试里把 $C$ 说成 $N$ 是常见口误。

| 口径（$N=10^4$、平均长 10） | 比较对数 | 最坏字符比较 | 同量级实测 |
| --- | --- | --- | --- |
| 只比相邻 | 9,999 | 99,990（约 $10^5$） | 392,345（$n=10^5$、长 8 的随机词表） |
| 两两比较 $\binom{N}{2}$ | 49,995,000（约 $5 \times 10^7$） | 499,950,000（约 $5 \times 10^8$） | 不跑：同规模已贵 5,000 倍 |

$499{,}950{,}000 \mathbin{/} 99{,}990 = 5{,}000$，即 $10^{3.7}$，口语里说「贵三个数量级」。这就是「不改题意就先分胜负」的那一步。

### 3. 三条无解路径与各自的返回值

| 情形 | 判定时机 | 返回值 | 例子 |
| --- | --- | --- | --- |
| 前缀悖论：相邻对 $(w_1, w_2)$ 中 $w_2$ 是 $w_1$ 的真前缀（长词在前） | 建图阶段，立刻短路 | 空串 | `[abc, ab]` |
| 环：拓扑排序输出的节点数 $< k$ | 拓扑阶段结束 | 空串 | `[z, x, z]`、`[a, b, a]` |
| 相邻词完全相同 | 建图阶段跳过 | 不视为错误 | `[abc, abc]` |

前缀悖论必须短路而不是继续建图：任何全序下前缀词都更小，所以 `[abc, ab]` 不可能对应任何全序，此时图里甚至一条边都没有（第一个差异不存在），继续走下去会返回一个看似合法的顺序，把错误判成正确。反方向 `[ab, abc]` 完全合法且不产生任何约束，必须跳过。

还有第四类输入：合法但顺序不唯一（有解、拓扑序不止一个）。它不是无解。按 LeetCode 269 口径可以返回任意一个合法顺序；生产系统通常要求确定性输出，两者要分开谈。

### 4. Kahn 还是 DFS

| 维度 | Kahn（入度 + 队列） | DFS（后序逆序） |
| --- | --- | --- |
| 无解检测 | 输出节点数 $< k$ 即为环，天然顺带 | 需要三色标记 |
| 唯一性检测 | 每步入度为零的候选数是否恒为 1 | 需要额外统计 |
| 代码量 | 略长（入度数组 + 队列） | 更短 |
| 栈深度 | 无递归 | 递归深度 = 图的最长链 $\le k$ |

DFS 的递归深度是 $k$ 而不是 $N$：词表十万级但字符集只有 26 个小写字母时深度不超过 26，不会爆栈；字符集本身上千上万（CJK、Unicode）时才会，需要改成显式栈的迭代式 DFS。这一点区分「背过模板」和「想过规模」。

唯一性的判据要记住是充要条件：拓扑序唯一等价于 Kahn 过程中每一步入度为零的节点数恰好为 1。用最小堆实现队列时，堆长度恒为 1 是同一件事的另一种写法。

### 5. 图规模口径：$k$ 不是 26

$k$ 是输入里实际出现的不同字符数，$E \le \min(N-1, k(k-1))$，空间 $O(k+E)$。写死 26 只在小写字母且要求输出全部字母时成立，面试里通常直接判错。邻接矩阵的规模：

| 字符集 $k$ | 矩阵格数 | 每格 1 字节 | 位图 |
| --- | --- | --- | --- |
| 26 | 676 | 676 B | 84 B |
| 1,000 | 1,000,000 | 1 MB | 122 KiB |
| Unicode BMP 65,536 | 4,294,967,296 | 4 GiB | 512 MiB |

所以：小写字母可以用 676 字节的布尔矩阵；换成 Unicode 或千级字符集必须改成哈希邻接表或位图。注意 $k$ 小时图会接近满图——$k=26$ 时 $k(k-1)=650$，占 676 格的 96%，这也是「写死 26 的矩阵够用」的根本原因。

### 6. 两个经典 bug

**bug 1：邻接表用 set 去重，入度却按出现次数累加。** 重复边把入度抬高，Kahn 少输出节点，被误判成有环。可复现的例子是 `[mx, my, nx, ny]`：正解是 `mnxy`，错误实现输出 `mxn` 并报环。

**bug 2：多个入度为零的节点按哈希迭代顺序取。** Python 的 `set` 与 `dict` 的迭代顺序受字符串哈希随机化影响，同一份输入在不同进程可能给出不同顺序（[[coding-06]] 里分片哈希必须用稳定哈希是同一条教训）。实测：`[mx, my, nx, ny, qz, rw]` 在 4 个不同的 `PYTHONHASHSEED` 下，无堆版本给出 3 种不同结果（`xmzwynqr`、`xwzmynqr`、`wzxmynqr`），全部合法但不一致；改用 `heapq` 后稳定输出 `mnqrwxyz`。

修法是两条：邻接表用 set 去重、入度只在「新边」上加一次；候选节点用最小堆或排序后的列表取，保证输出确定。

### 7. 正确性证明与自证口径

**引理（充分性）**：若逐对检查相邻词后 ① 没有前缀悖论 ② 边图无环，则任取一个拓扑序 $O$，输入词表在字典序 $<_O$ 下已经有序。

证明：看任意相邻对 $(w_1, w_2)$。若存在第一个差异位置 $i$，则图里有边 $w_1[i] \to w_2[i]$；$O$ 是拓扑序，所以 $w_1[i] <_O w_2[i]$，于是 $w_1 <_O w_2$。若不存在差异位置，由 ① 可知 $w_2$ 不是 $w_1$ 的真前缀，所以在「两词无差异」的前提下只剩 $w_1$ 是 $w_2$ 的前缀或两者相等，仍有 $w_1 \le_O w_2$。每个相邻对都 $\le_O$，由传递性整表有序。必要性显然（有序列表的每个相邻对都满足约束）。所以「相邻检查 + 无环」是充要条件，$O(C)$ 的建图不会漏判。

**不变量（反排序）**：把推断出的顺序做成 rank 表，再用这个比较器重排原始词表，结果必须与输入逐字相同。它同时覆盖前缀悖论（重排会把前缀词排到前面）与环（rank 表根本构造不出来），代价是一次 $O(C \log N)$ 的排序。这是能当场说出口、也能写进断言的最强检验。

**随机对拍**：随机生成 $k$ 个字符的一个全序，再按该全序随机生成词表（混入重复词、前缀词与 1 字符词），跑 1 万组与暴力校验对齐——实测 10,000 组全部通过，其中 1,919 组（19.2%）合法但不唯一。这套「不变量 + 随机对拍 + 边界枚举」的验收方式与 [[coding-09]] 的切分压力测试同源。

**边界枚举**至少包含：$n=1$、单词只有 1 个字符、相邻词完全相同、词表里出现非 ASCII 字符。

### 8. 返回契约与「字符」的粒度

- **任意合法解还是唯一解**：LeetCode 269 口径接受任意合法顺序、无解返回空串；要求唯一时用第 4 节的每步候选数判据。生产系统另有一条硬要求——即使只需要任意解，也要固定 tie-break，让同一输入永远给出同一输出，否则缓存键、索引与评测都对不上。
- **大小写敏感**：`A` 与 `a` 是两个节点；要合并就先统一 casefold，而且必须在建图前统一做一次。
- **Unicode 规范化**：NFC 的 `é` 是 1 个码位（U+00E9），NFD 的 `é` 是 2 个码位（`e` 加上组合符 U+0301）。实测词表里一个词用 NFC、另一个用 NFD 时，建图得到 5 个节点并推出一条伪边 `é → e`；先对所有词做一次 NFC 规范化则回到 3 个节点，输出正确的 `abé`。规范化必须建图前做且只做一次，两侧不一致等于承认两套字符集。
- **失败出口**：无解返回空串或结构化错误（附带冲突边），不要抛异常；调用方必须有正常分支，这正是 [[coding-12]] 的「失败也要有正常出口」。这类粒度 bug 的共同点是**不报错**，只静默地让下游对不上，与 [[coding-04]] 里 tokenizer 训练与服务偏斜是同款。

### 9. Meta 语境与加需求路径

按题库导读的公开信息，Meta 的技术初筛是 45 分钟内 2 道编程题，onsite 还有两轮编程，所以本题实际只有 20 分钟出头：2 到 3 分钟讲清「相邻建边 + 三条无解路径 + $O(C)$」，然后动手，边界用例留到最后；2026 年部分流程还有一轮分三阶段的 AI 辅助编程（探索并修复、实现新功能、扩展并改进系统），所以扩展题要提前想好：

- **词表涨到十万到百万级**：图的规模不变（$k$ 由字符集决定），瓶颈变成读入与内存——先去重、只保留相邻的不同词、流式两两比较，建图仍是 $O(k+E)$；
- **要求顺序唯一**：在 Kahn 里统计每步候选数，或在建图后检查是否存在「可从多个前驱到达」的节点；
- **比较器化后缓存与并发复用**：把顺序固化成 rank 表（字符到整数），比较代价 $O(\min(|w_1|, |w_2|))$；只读结构可跨线程并发复用，进程间一致就必须持久化 rank 表，不能依赖哈希顺序；
- **合并多来源有序列表**：用同一条反排序不变量对合并结果做冲突检测。

真实系统里这个算法对应的是「从已有排序语料恢复隐式排序键」：搜索引擎词表与实体词典的 collation 顺序、tokenizer 词表的 rank 顺序。BPE 的 merge 表就是一份有顺序的规则表——同一集合、只换顺序，同一条文本的切分就会变（实测 `abab` 得到 `['abab']` 或 `['a', 'ba', 'b']`），切分一变 embedding 就对不上（见 [[coding-04]]）。

随机对拍：10,000 组全部通过（0 失败），其中 1,919 组不唯一；每种情况的输出都通过反排序不变量校验。

```python
import heapq
import unicodedata


def alien_order(words, normalize=None):
    """返回 (顺序, 状态, 是否唯一)；状态为 ok / empty / prefix / cycle。"""
    if normalize:
        words = [unicodedata.normalize(normalize, w) for w in words]
    if not words:
        return '', 'empty', True

    nodes = {}
    for w in words:
        for ch in w:
            nodes.setdefault(ch, None)

    adj = {ch: set() for ch in nodes}
    indeg = {ch: 0 for ch in nodes}

    for w1, w2 in zip(words, words[1:]):          # 只比相邻：N-1 次
        for a, b in zip(w1, w2):                  # 至多到较短词的长度
            if a != b:
                if b not in adj[a]:               # 去重后才抬入度
                    adj[a].add(b)
                    indeg[b] += 1
                break
        else:
            if len(w1) > len(w2):                 # 长词在前 -> 前缀悖论
                return '', 'prefix', False
            # 完全相等：无约束，跳过

    heap = [ch for ch in nodes if indeg[ch] == 0]
    heapq.heapify(heap)                           # 最小堆：输出确定
    out, unique = [], True
    while heap:
        if len(heap) > 1:
            unique = False                        # 同一步有多个候选 -> 不唯一
        ch = heapq.heappop(heap)
        out.append(ch)
        for nxt in sorted(adj[ch]):
            indeg[nxt] -= 1
            if indeg[nxt] == 0:
                heapq.heappush(heap, nxt)

    if len(out) != len(nodes):                    # 输出少于节点数 -> 有环
        return '', 'cycle', False
    return ''.join(out), 'ok', unique


def resort_same(words, order):
    """反排序不变量：用推断顺序重排后必须与输入逐字相同。"""
    rank = {ch: i for i, ch in enumerate(order)}
    return sorted(words, key=lambda w: [rank[c] for c in w]) == list(words)


print(alien_order(['wrt', 'wrf', 'er', 'ett', 'rftt']))   # ('wertf', 'ok', True)
print(alien_order(['abc', 'ab']))                          # ('', 'prefix', False)
print(alien_order(['a', 'b', 'a']))                        # ('', 'cycle', False)
print(alien_order(['a', 'a']))                             # ('a', 'ok', True)
print(alien_order(['mx', 'my', 'nx', 'ny']))               # ('mnxy', 'ok', False)
print(alien_order(['éa', 'éb'], normalize='NFC'))          # ('abé', 'ok', False)
print(alien_order(['éa', 'e\u0301b']))                     # ('abée\u0301', 'ok', False)：5 节点，缺规范化
print(resort_same(['wrt', 'wrf', 'er', 'ett', 'rftt'], 'wertf'))   # True
```

## 常见追问

- **追问**：为什么不能两两比较所有词对？
  - 要点：$N=10^4$、平均长 10 时是约 $5 \times 10^7$ 对、最坏 $5 \times 10^8$ 次字符比较，比相邻链式的约 $10^5$ 次贵 5,000 倍；而且全序的传递性保证 $N-1$ 个相邻约束就是充要条件（第 7 节的引理）。多出来的比较只会引入冗余边和更长的运行时间。
- **追问**：怎么判断推断出的顺序是否唯一？
  - 要点：Kahn 过程中每一步入度为零的候选数恰为 1（等价地，最小堆长度恒为 1）是充要条件。约束稀疏时很难唯一：随机对拍里 19.2% 的合法输入不唯一，`['abc']` 这种没有任何边的输入自然给出 3 种候选。追问通常会跟一句「如果不唯一，你的返回还有意义吗」——意义在于它仍然是合法解，但生产系统必须再固定 tie-break 并显式声明「任意解」的契约。
- **追问**：发现环以后工程上怎么处理？
  - 要点：无解要有正常出口——返回空串或结构化错误（带上冲突边、涉及的词对），不要抛异常让调用方崩。上层可以降级到默认 collation 或标记该数据源不可信并告警，这正是 [[coding-12]] 里 agent loop 的「失败也要有正常出口」。
- **追问**：字符集不是 26 个小写字母呢？
  - 要点：$k$ 由输入决定，邻接结构改成哈希表；$k=10^3$ 的布尔矩阵是 1 MB，Unicode BMP 写满要 4 GiB（位图也要 512 MiB），所以真实系统用稀疏邻接表。另外，真实语言的词典顺序不是码位序（德语变音、瑞典语的 å 等），需要 ICU collation；本题推断的只是这份语料隐含的顺序，不等于语言规范。
- **追问**：词表涨到百万级，瓶颈在哪里？
  - 要点：瓶颈在读入、去重与内存，不在图——$n=10^6$ 时建图加拓扑实测约 1 s，图仍然只有 26 个节点；先去重、相邻相同词直接跳过、流式两两比较能把内存压到常量级。如果输入是压缩存储（前缀共享的 trie 或排序文件），相邻比较可以边读边做，不需要一次性展开全部词。
- **追问**：怎么证明你的实现是对的？
  - 要点：反排序不变量（重排后与输入逐字相同）加随机对拍加边界枚举，三者缺一不可：不变量覆盖前缀悖论与环，随机对拍覆盖组合爆炸的边角，边界枚举覆盖 $n=1$、单字符词、重复词、非 ASCII 与 NFC/NFD。线上还可以把不变量做成 golden 校验，每条新语料入库前跑一次。
