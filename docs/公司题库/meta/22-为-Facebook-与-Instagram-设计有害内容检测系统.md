## 一句话答案

> 答案的骨架是**四层 + 一个闭环**：
> ① **上传期（ingest）**——高召回拦截：多模态分类器（图像/视频/文本/音频/元数据）+ 政策规则，宁可误拦。目标是把最坏内容挡在扩散之前。
> ② **展示期（impression）**——按**观看者**动态判定：同一条内容对成年人和未成年人、对不同地区与法规，合规要求不同；这一层做降权、加警示、限制分发，而不是简单删除。
> ③ **人审与申诉**——按「危害等级 × 不确定性」排序的队列 + 误杀补偿（申诉通道、快速复核）；可引用 *A Holistic Approach to Undesired Content Detection in the Real World* 的工程做法：**把分类器与政策规则结合，并按危害类别分别评估**，发布门禁看的是分层的召回与误杀，而不是总体准确率。
> ④ **对抗闭环**——对手会针对你的检测器演化（变体词、谐音、图文不一致、对抗扰动），所以要有红队 → 新数据 → 重训 → 回归用例的循环（威胁分类可参照 NIST AI 100-2 的术语框架：规避、投毒、隐私、滥用四类）。
> 一句话纪律：**在 1% 的违规基率下，「99% 准确率」听起来很好，但决定体验与合规的是分层的召回率与误杀率**——这必须算出来给业务看。

## 面试官在考什么

- **代价不对称**能否量化：漏放一条极端有害内容的代价 vs 误杀一条正常内容的代价，差几个数量级；由此推出「不同危害类别、不同地区要有不同阈值」。
- **多模态的工程现实**：图像分类、视频抽帧（关键帧 + 音频轨 + OCR）、文本（帖子正文、评论、图片内文字）、以及**元数据与行为信号**（新账号、批量上传、异常传播速度）。只讲文本分类会被追问视频与图文不一致。
- **基率问题**：能否指出准确率在低基率下的欺骗性（见下文算例），并改用分层精确率/召回率与代价加总。
- **对抗演化**：是否知道隐式仇恨与变体表达（可引用 ToxiGen 的动机：隐式和对抗性的仇恨言论检测比显式表达难得多，需要专门的数据构造），以及检测器一旦固定就会被绕过。
- **LLM 在链路里的位置**：可引用 Llama Guard 的做法——用一个 LLM 做输入输出的安全分类器（按政策分类学给出判定），适合覆盖细粒度政策与多轮对话场景；但**不能替代**低延迟的线上分类器与规则，定位应是「政策解释能力强、成本较高的补充层」。
- **人审的现实约束**：审核员的心理负担、地区法律差异、申诉时效，这些是系统设计的一部分，不是「运营细节」。

**常见错误答案**

- 「训练一个多标签分类器，阈值 0.5」——忽略基率、代价不对称与分层要求。
- 「用 LLM 审核所有内容」——成本与延迟不可行；且 LLM 也会被越狱诱导（串 [[safety-03]]）。
- 「准确率 99.9%，已经很好」——在极低基率下，99.9% 准确率可能仍意味着高误杀或高漏放，必须算。
- 「删掉就完了」——删帖会激化对抗（用户换号、改图重发），且误杀直接伤害创作者；分层处置（降权/加警示/限制分发）往往比删除更有效。

## 原理与推导

### 1. 政策 → 可判定类别 → 阈值

把政策文档拆成机器可判定的类别是关键的第一步。每个类别 $c$ 有自己的：

- 代价比 $\lambda_c=c_{\text{FN}}/c_{\text{FP}}$（暴力/未成年相关远高于垃圾信息）；
- 处置动作集合（删除、降权、加警示、限制分发、送人审）；
- 地区与年龄适用范围。

给定分类器输出的概率 $\hat p_c$，阈值 $t_c$ 应最小化

$$\mathbb{E}[\text{cost}]=\sum_c\big(c_{\text{FN},c}\,\text{FN}_c(t_c)+c_{\text{FP},c}\,\text{FP}_c(t_c)\big)\quad\text{s.t.}\ \sum_c \text{HR}_c(t_c)\le B$$

其中 $B$ 是人审预算。**这个约束式就是「人审预算决定风险敞口」的数学形式**，也是面试里最容易被忽略的一句话。

### 2. 分层检测架构

| 层 | 内容 | 延迟 | 处置 |
| --- | --- | --- | --- |
| L0 规则与哈希 | 已知违规内容的哈希/感知哈希匹配、关键词与正则 | <1 ms | 直接拦（几乎零误杀） |
| L1 轻量分类器 | 图像/文本多标签分类（小模型） | 10–50 ms | 高置信直接处置 |
| L2 重型多模态 | 视频抽帧 + 音频 + OCR + 跨模态一致性 | 秒级（异步） | 降权/送审 |
| L3 LLM 政策层 | 按政策分类学给出判定与解释 | 秒级 | 争议案例、申诉复核辅助 |

**关键设计**：L0 负责「已知的坏东西」，L1 负责「高频易判」，L2/L3 负责「难判与争议」。上传是异步的（用户等待发布），所以 L2 可以慢一点，但不能慢到内容已经被广泛传播——必要时先限制分发再判定。

### 3. 基率谬误：为什么 99% 准确率什么都说明不了

设违规基率 $\pi$、分类器召回 $r$、误杀率 $f$（正常内容被误判的比例）。在 $N$ 条上传中：

$$\text{漏放}=\pi N(1-r),\qquad \text{误杀}=(1-\pi)N f$$

取 $\pi=0.01$、$N=10^8$、$r=0.99$、$f=0.001$：漏放 $=10^6$ 条、误杀 $=99{,}000$ 条。**准确率高达 99.9%**，但每天漏放百万条、误杀近十万条——两个数字都必须报出来，且要分危害类别报。

### 4. 对抗演化与数据飞轮

对手的策略会随检测器变化（NIST AI 100-2 把这类威胁归为**规避攻击**：在推理期修改输入以躲开检测）。工程上的应对：

1. **红队常态化**：专门的对抗团队持续构造变体（谐音、字符替换、图文错配、对抗扰动），产出攻击样本（串 [[safety-10]]）。
2. **数据飞轮**：红队样本 + 用户举报 + 人审结论 → 训练数据；但要注意**举报偏差**（某些群体被过度举报），需按群体监控误杀率。
3. **检测器轮换**：不对外暴露阈值与规则细节（减少针对性优化），并定期更新模型，让「找到的绕过方法」失效。
4. **多信号融合**：内容信号 + 行为信号（新账号、异常传播、批量相似内容）能显著提高对抗鲁棒性——因为对手可以改内容，但很难改传播行为。

### 5. 处置、申诉与公平性

- **分层处置**：删除 > 限制分发 > 加警示/插页 > 降权；选择取决于置信度与危害等级。低置信度内容「限流 + 观察」比直接删除更稳。
- **申诉与回灌**：申诉成功 = 高置信度误杀标签，必须回灌并触发阈值重标定；申诉时效是体验指标。
- **公平性监控**：误杀率与召回率要按语言、方言、群体、地区分群报告；差异过大本身就是发布阻断项（这与「总体指标好看」并不冲突——总量会被头部掩盖）。
- **未成年人保护**：默认更严格的分发限制与更高的召回阈值（宁可误拦），并对私信/评论做额外过滤（串 [[meta-18]]）。

## 数值与代码验证

### 表 1：基率对结论的支配作用（$N=10^8$ 条上传）

| 违规基率 $\pi$ | 召回 $r$ | 误杀率 $f$ | 漏放条数 | 误杀条数 | 准确率 |
| --- | --- | --- | --- | --- | --- |
| 1% | 99% | 0.1% | 1,000,000 | 99,000 | 99.9% |
| 1% | 99.9% | 0.1% | 100,000 | 99,000 | 99.9% |
| 1% | 99.9% | 0.01% | 100,000 | 9,900 | 99.99% |
| 0.1% | 99% | 0.1% | 100,000 | 99,900 | 99.9% |

**读法**：第一行与第二行只差召回（99% → 99.9%），漏放下降 10 倍而误杀不变；第四行说明基率降 10 倍时，同样误杀率造成的误杀绝对数几乎不变而漏放下降。**结论**：报数字必须同时给基率、召回、误杀与绝对条数，否则读者会得出完全相反的结论。

### 表 2：人审预算与分层处置（示例）

| 处置路径 | 比例 | 人审需求 | 说明 |
| --- | --- | --- | --- |
| 自动删除（L0/L1 高置信） | 0.02% | 无（事后抽检） | 需极低误杀率 |
| 限制分发 + 观察 | 0.30% | 无（抽样复核） | 低置信度的稳妥处置 |
| 送人审 | 0.05% | 全部 | 按危害×不确定性排序 |
| 申诉复核 | 0.01% | 全部（限时） | 时效是体验指标 |

### 可运行代码

```python
# 1) 基率谬误：同一套指标在不同基率下的绝对后果
N = 100_000_000
def report(pi, r, f, n=N):
    missed = pi * n * (1 - r)
    fp = (1 - pi) * n * f
    acc = 1 - (missed + fp) / n
    return missed, fp, acc
print(f"{'基率':>6} {'召回':>6} {'误杀率':>7} {'漏放':>12} {'误杀':>11} {'准确率':>9}")
for pi, r, f in [(0.01, 0.99, 0.001), (0.01, 0.999, 0.001), (0.01, 0.999, 0.0001), (0.001, 0.99, 0.001)]:
    m, fp, acc = report(pi, r, f)
    print(f"{pi:>6.3f} {r:>6.3f} {f:>7.4f} {m:>12,.0f} {fp:>11,.0f} {acc:>9.4%}")

# 2) 按代价与预算选阈值（两个危害类别，代价比不同）
import random
random.seed(41)
CATS = {"极端暴力": {"lam": 500.0, "base": 0.0005},   # 代价比高、基率极低
        "垃圾广告": {"lam": 2.0,   "base": 0.03}}     # 代价比低、基率高
n_eval = 200_000
def make_scores(base, quality=6.0):
    items = []
    for _ in range(n_eval):
        bad = random.random() < base
        s = random.betavariate(quality, 2) if bad else random.betavariate(2, quality)
        items.append((s, bad))
    return items

def cost_at(items, t, lam, c_human=0.5):
    fn = fp = human = 0
    for s, bad in items:
        if s < t:
            if bad: fn += 1
        else:
            human += 1
            if not bad: fp += 1
    return lam * fn + fp + c_human * human, fn, fp, human

print(f"\n{'类别':<10} {'阈值':>6} {'漏放':>7} {'误杀':>7} {'送审':>8} {'代价':>12}")
for cat, cfg in CATS.items():
    items = make_scores(cfg["base"])
    best = min(((t,) + cost_at(items, t, cfg["lam"]) for t in (0.5, 0.8, 0.9, 0.95, 0.99, 0.999)),
               key=lambda x: x[1])
    for t in (0.8, 0.99):
        c, fn, fp, h = cost_at(items, t, cfg["lam"])
        print(f"{cat:<10} {t:>6.3f} {fn:>7} {fp:>7} {h:>8} {c:>12,.0f}")
    print(f"{'  → 最优':<10} {best[0]:>6.3f} {best[2]:>7} {best[3]:>7} {best[4]:>8} {best[1]:>12,.0f}")
print("高代价比类别的最优阈值远高于低代价比类别 —— 阈值必须按类别定，不能统一 0.5")

# 3) 对抗演化：固定检测器 vs 持续重训
def simulate_arms_race(rounds=6, detector_recall=0.95, adapt_rate=0.35, retrain_gain=0.25):
    recall = detector_recall
    evader_share = 0.05
    print(f"\n{'轮次':>4} {'检测召回':>9} {'规避型占比':>11} {'有效拦截率':>11}")
    for t in range(rounds):
        effective = recall * (1 - evader_share) + 0.15 * evader_share      # 规避型只有 15% 被抓住
        print(f"{t:>4} {recall:>9.3f} {evader_share:>11.1%} {effective:>11.3f}")
        evader_share = min(0.9, evader_share * (1 + adapt_rate))
        recall = min(0.995, recall + retrain_gain * evader_share)          # 重训追回一部分
    return recall, evader_share
r, e = simulate_arms_race()
print(f"结论：不重训时有效拦截率会被规避型内容拖垮；持续重训只能维持，无法一劳永逸（最终召回 {r:.3f}）")
```

预期输出要点：第 1 段复现表 1 的结论（准确率都在 99.9% 以上，但漏放从百万级降到十万级只靠召回提升）；第 2 段显示**高代价比类别的最优阈值远高于低代价比类别**（不能统一 0.5），且最优阈值受人审成本项影响；第 3 段演示对抗演化——**规避型内容占比上升会持续侵蚀有效拦截率**，重训只是维持而非根治。

## 常见追问

- **追问**：视频怎么处理？
  - 要点：抽帧（首帧 + 均匀采样 + 场景切分点）+ 音频轨（语音转文本 + 音频事件）+ OCR（画面文字）+ 元数据；异步处理，但在判定完成前先限制分发；重点是**跨模态一致性**（图文不符本身就是信号）。
- **追问**：为什么不能只靠 LLM 做审核？
  - 要点：成本与延迟不可接受（每条都过大模型）、LLM 自身可被越狱、以及政策判定需要稳定可复现（同一输入同一结论）。LLM 的定位是政策解释与争议案例辅助（Llama Guard 式的用法），不是全量第一道关。
- **追问**：怎么衡量审核系统的公平性？
  - 要点：按语言/地区/群体分别报召回与误杀率，并要求差异在可接受范围内；同时监控举报来源的分布（某些群体被过度举报会放大误杀）。
- **追问**：误杀创作者内容怎么补偿？
  - 要点：分级处置（能限流就不删）、快速申诉与限时复核、误杀率作为发布门禁、以及对重复误杀的政策做根因分析（往往是政策定义模糊而不是模型差）。
- **追问**：新危害类别（例如新型诈骗）怎么快速上线？
  - 要点：先用规则与关键词 + 检索近邻（少量标注即可用），同时启动人审标注与主动学习；把「新类别的冷启动流程」本身产品化（政策 → 标注指南 → 少量样本 → 规则+模型混合 → 门禁）。
- **追问**：如何评估对抗鲁棒性？
  - 要点：维护对抗测试集（每轮红队产出）、报告**在对抗样本上的召回**（而不是只在自然分布上），并监控上线后规避型内容的占比变化（这是对手在适应的直接信号）。
