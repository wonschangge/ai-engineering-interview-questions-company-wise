## 一句话答案

> 这是一道**双案例题**，两段的评分点完全不同：
> **第一段（模糊中推动成果）**考的是你能不能把「说不清」变成「可判定」——重述问题为条件式、枚举选项（含不做）、把定性偏好翻译成判据与权重、**先用最小可逆的动作获取信息**、写决策记录、按预设时间点复盘。成果必须带**可核查的增量**（相对谁、多少、是否显著）。
> **第二段（判断错误）**考的是**归因的诚实度与机制化**——说清当时的假设、哪条假设错了、为什么当时没发现（缺了什么验证）、代价多大、以及你因此改了什么**流程**（不是「以后会更小心」）。
> 两段的共同点是：**模糊不是靠勇气解决的，是靠信息获取成本与可逆性设计的**。一段好的答案里，决策记录、可逆试验、复盘时间点这三个词至少出现两个。

## 面试官在考什么

- **是否有一套可复用的动作**：把是非题改成条件题、列选项、定判据、找最小可逆步骤、设复盘点。缺了这套动作，「我很果断」就只是运气叙事。
- **判据是否量化**：能不能把「风险高」「体验重要」翻译成可比较的量（成本、延迟、错误率、留存），并**事前**写明权重（事后写权重会被追问「为什么当时是这个权重」）。
- **可逆性意识**：是否优先选择可回滚的方案（灰度、开关、双跑、影子流量），把不可逆承诺推迟到有数据之后。
- **第二段的真实性与代价**：判断错误是否是真实代价（不是「我判断错了但其实没影响」），以及**是否识别出当时缺失的验证信号**。
- **机制化改进**：把教训变成流程（门禁、评审清单、验收窗口、监控），而不是个人品质承诺。
- **与业务的关系**：成果是否落到业务指标，而不是「我们上线了」。

**常见错误答案**

- 第一段讲一个其实不模糊的项目（有既定流程与指标），被追问「哪里模糊」时答不上。
- 第一段只讲结果不讲过程（「我拍板做了 X，后来成功了」）——这是幸存者叙事。
- 第二段挑一个「不是我的错」的案例（需求被砍、数据没给），或代价极小的案例。
- 第二段只讲情绪（「我反思了很久」）而不讲机制改动。

## 原理与推导

### 1. 第一段：把模糊变成可判定的五步

1. **重述**：「要不要做 X」→「在什么条件下做 X、代价上限多少、什么信号出现就停」。
2. **选项枚举**：至少三个（激进/保守/不做），每个标注代价与**可逆性**。
3. **判据与权重**：把偏好翻译成量；能算就算（本文件下一节给了一个算例）。
4. **最小可逆步骤**：优先做「便宜、能获取信息、可撤回」的动作——一周原型、影子流量、小流量灰度、离线回放。
5. **决策记录 + 复盘点**：写下决策、前提假设、预期指标、复盘时间；到点按数据复盘。

### 2. 为什么「可逆性」比「判断准确」更可控

大多数决策的真实成本来自**不可逆部分**（重构系统、公开承诺、招聘、数据不可回滚）。工程上把决策拆成「可逆试验 + 不可逆承诺」两段，就能把不确定性成本降到试验成本：

$$\text{决策风险}\approx\underbrace{c_{\text{试验}}}_{\text{小、可控}}+\underbrace{P(\text{假设被推翻})\times c_{\text{不可逆}}}_{\text{被推迟到有信息之后}}$$

这条式子的实践含义：**先花小钱买信息，再花大钱做承诺**。面试里能这样表述，比「我先做了个 POC」具体得多。

### 3. 第二段：判断错误的六类根因

1. **假设未验证**：默认了用户/系统会如何反应（最典型：低估对手适应性，串 [[alibaba-10]] 的四类反馈回路）。
2. **代理指标错**：优化了一个容易测但不是目标的量（点击 vs 留存）。
3. **分布判断错**：把离线/小流量结论外推到全量；忽略长尾或某个语种/地区。
4. **约束遗漏**：漏掉延迟、成本、合规或上下游依赖。
5. **工程链路**：结论对，但落地链路有损（特征、缓存、重排把效果抹平）。
6. **组织与节奏**：时机不对（大促前上线）、owner 不清、验收窗口太短。

**每一类都要配「当时缺的信号 + 现在的机制」**。例如：假设未验证 → 现在要求「上线前必须有最小可逆验证（影子流量/灰度）并预注册判据」。

### 4. 一个可核查的算例（把「模糊决策」量化）

场景：是否自研一套特征平台（模糊点：收益难估、迁移成本难估）。可判定的形式：

- 判据：年化工程成本节省、迭代速度（新特征上线周期）、迁移期间的效果损失；
- 可逆步骤：先在一个业务线做 4 周试点（可回退），量测「新特征上线周期」与「效果损失」；
- 停止条件：若试点期效果损失 > 2% 或周期改善 < 20%，则不做全量迁移；
- 复盘点：试点结束后 1 周。

这四条写清楚，模糊决策就变成了一份可执行的实验计划。

## 数值与代码验证

### 表 1：两段叙述的必答要素对照

| 要素 | 第一段（模糊中推动） | 第二段（判断错误） |
| --- | --- | --- |
| 背景 | 为什么模糊（信息缺什么） | 当时的假设是什么 |
| 判据 | 事前写明的判据与权重 | 当时用什么信号做判断 |
| 可逆性 | 最小可逆步骤是什么 | 当时缺了哪个可逆验证 |
| 结果 | 可核查增量（相对值 + 显著性） | 代价（时间/成本/体验） |
| 机制 | 决策记录与复盘点 | 改了哪条流程 |

### 表 2：可逆试验 vs 直接承诺的成本对比（示意）

| 方案 | 前期成本 | 不可逆成本 | 信息获取 | 建议 |
| --- | --- | --- | --- | --- |
| 直接全量重构 | 低 | 高（数月工期，难回滚） | 无 | 避免 |
| 影子流量双跑 | 中 | 低 | 高（真实流量对比） | 首选 |
| 单业务线试点 | 中 | 低（可回退） | 中高 | 次选 |
| 离线回放 | 低 | 无 | 中（受历史数据偏差限制） | 辅助 |

**读法**：影子流量双跑之所以首选，是因为它同时具备「信息质量高」与「可逆」两个属性；而离线回放虽然便宜，但受历史数据偏差限制（串 [[consumer-ml-02]]）。

### 可运行代码

```python
# 1) 可逆性设计：把「先试验再承诺」的期望成本算出来
def expected_cost(p_wrong, c_irreversible, c_trial, p_detect=0.8):
    """不做试验：一次性承担错误成本；做试验：先付试验成本，只有漏检才承担不可逆成本"""
    no_trial = p_wrong * c_irreversible
    with_trial = c_trial + p_wrong * (1 - p_detect) * c_irreversible
    return no_trial, with_trial

C_IRR, C_TRIAL = 1_000_000.0, 60_000.0          # 单位：元（示意）
print(f"{'假设错误概率':>12} {'不试验':>14} {'先试验':>14} {'节省':>10}")
for p in (0.1, 0.3, 0.5, 0.7, 0.9):
    a, b = expected_cost(p, C_IRR, C_TRIAL)
    print(f"{p:>12.1%} {a:>14,.0f} {b:>14,.0f} {(a-b)/a:>9.1%}")
print("只要试验能识别出大部分错误假设（本例 p_detect=0.8），先试验几乎总更划算——"
      "这正是「可逆性可以被设计」的量化依据")

# 2) 试点样本量：要检测效果损失 2% 需要多少流量
import math
def n_per_group(p, delta, alpha=0.05, power=0.8):
    z_a, z_b = 1.959964, 0.841621
    return 2*(z_a+z_b)**2*p*(1-p)/delta**2
for p, d in [(0.05, 0.02), (0.05, 0.005), (0.30, 0.02)]:
    print(f"  基线 {p:.0%}，检测绝对差异 {d:.1%} -> 每组需 {n_per_group(p, d):,.0f} 样本"
          f"（即试点期至少要这么多曝光/事件）")

# 3) 判断错误的复盘模板（字段化，可直接用于面试叙述）
TEMPLATE = [
    ("决策", "当时决定了什么（含范围与时限）"),
    ("假设", "结论依赖的三条关键假设（按脆弱度排序）"),
    ("验证", "当时用了什么信号做判断；缺了什么信号"),
    ("结果", "实际发生了什么，代价多大（时间/成本/体验）"),
    ("根因", "六类根因里属于哪一类（假设/代理指标/分布/约束/链路/组织）"),
    ("机制", "现在哪条流程被改了（门禁/清单/验收窗口/监控）"),
]
print("\n复盘模板：")
for k, v in TEMPLATE:
    print(f"  {k:<4} {v}")
```

预期输出要点：第 1 段量化「先试验再承诺」的收益（假设错误概率越高、试验越划算；即使识别率只有 80%，期望成本也大幅下降）；第 2 段提醒**试点也要够样本量**才能检测出 2% 的损失（否则试点结论本身就是噪声）；第 3 段给出可直接用于面试的复盘模板字段——面试里按字段讲，比自由发挥更不容易遗漏关键点。

## 常见追问

- **追问**：如果时间紧到不能做试验，你怎么办？
  - 要点：退而求其次——缩小不可逆范围（先做一部分、加开关、预设回滚条件），并明确写出「我们在什么信号下回滚」。可逆性是可以被设计的，不是有或没有。
- **追问**：你的判据是怎么定的？权重为什么是这个数？
  - 要点：说清来源（业务目标分解、历史基线、成本口径），并承认权重是**假设**——写明「若权重变化到某值，结论会反转」的敏感性。
- **追问**：判断错误那次，你多久才发现的？
  - 要点：诚实说出发现时间与发现方式（哪个信号），并说明现在加了什么**早期信号**（这是机制化改进的核心）。
- **追问**：你怎么在团队里推动一个不受欢迎的结论？
  - 要点：把分歧变成数据问题（先对齐判据再讨论方案）、用最小试验给出证据、并给决策者留可逆路径（而不是要求一次性站队）。
- **追问**：如果复盘发现结论本来是对的，只是执行没做好，怎么算？
  - 要点：区分「决策质量」与「执行质量」——复盘要分开评价，否则团队会学到「不敢做决策」的错误教训。
- **追问**：你怎么知道自己的判断在系统性偏误上有没有问题？
  - 要点：给出具体的防偏误机制：事前写下假设与判据、引入反对意见（红队/pre-mortem）、以及用「若假设被推翻会怎样」的反事实检查（串 [[evaluation-09]] 的预注册思路）。
