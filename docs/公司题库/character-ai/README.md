# Character.AI 面试题库

这一家的题几乎都能化归到一个物理量：**KV cache**。
而它之所以是主因，是因为一个产品事实：**平均会话有 180 条消息**。

**第一件事是"长会话把 KV 变成成本的主因"。**
180 条消息是 5,400 token，每 token 320 KiB，**单对话 1.65 GiB**——
于是一张 80 GB 卡（权重占 35 GB）**只能放 27 个对话**。
而成本 = GPU 时间 / 消息数，**所以"并发"是乘数**：
KV 降 16 倍把每条消息成本降到 1/16，而"缩短单条耗时"的杠杆最多 4 倍。
**这是这一家最核心的算术。**

**第二件事是"prefix cache 决定了 prompt 怎么组装"。**
把每轮重写的摘要放在前面，命中率只有 17%；
追加到最后，命中率 66%——**成本差 2.08 倍、prefill 从 1,450 ms 降到 493 ms**。
所以"把变化的部分放到最后"不是优化技巧，而是**架构约束**。

**第三件事是"要敢说负结果"。**
"自适应更好""int8 一定更省"这类直觉，在这一家的题里都会被算术推翻：
**"换小模型"比"KV 量化"快，但要付质量代价**；
**"原生 int8"买到 0.6 分，而回本只要 1 个月**；
**"长会话漂移"的主因不是模型不行，而是人设被截断（+43.9 个点）**。

准备这一家时，建议把**"KV 是多少、并发是多少、成本怎么算"**这条链练到能背。
它同时解释了 03、04、05、06 四道题。

## 准备建议

1. **先把"KV 算术"练到能背**：320 KiB/token → 1.65 GiB/对话 → 并发 27 → 成本 = GPU 时间 / 消息数。03、04、05、06 四道题都建在这条链上。
2. **01 与 04 是"同一机制的两个尺度"**：01 讲对话内的前缀复用、04 讲跨对话与跨轮次的缓存。两者的判据都是"前缀不变才能复用"。
3. **02 与 08 是一对**：**02 讲"超窗时保留什么"、08 讲"保留得不好会怎样"**（人设漂移）。两者的共同结论是"结构化记忆优于摘要"。
4. **06 的结论要能背**：**prefill 占 67%、并发是乘数**。这两句解释了"为什么 prefix cache 与 KV 降本值得优先做"。
5. **05 的辩护结构可以复用**：**先说"你要量化什么"、再算质量差、最后算回本**。这个三段结构适用于任何"要不要付工程复杂度"的问题。
6. **10 与 12 都有"基率问题"**：10 是 0.1% 基率下的 PPV 8.7%、12 是 14% 基率下的 PPV 73.5%。**同一个公式、两个结论**——值得对照。
7. **09 是这一家最"非技术"的题**，但它的论证是量化的（五个不对称、代理相关性、样本量）。**准备时不要只谈价值观，要给结构。**
8. **07 的核心洞察容易被说反**：**覆盖率由候选池决定，而不是排序函数**。反馈回路的作用是"固化头部"，不是"降低覆盖率"。
