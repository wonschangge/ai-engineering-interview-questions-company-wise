# Cohere 面试题库

这一家的面试有一条很清晰的主线：**「卖给企业」这件事在技术上的全部后果**。
检索要能在**成本约束**下做到可用（所以有 embedding + reranker 的两段式、有 PQ 压缩、有扩容后的排查）；
模型要能**放进客户的机房**（所以有稀疏 MoE 的显存/算力交换、有气隙部署的交付与升级）；
系统要满足**企业的权限、审批、可追溯**（所以有工作流 agent 与企业级清单）；
而这一切都要在**客户没有标注数据**的前提下被证明有效（所以有第 09 题）。

所以准备这一家时，建议把「**企业约束**」当成一根线串起所有题：
**成本 → 权限 → 可追溯 → 可升级 → 可证明**。

## 这家公司的面试怎么准备

**第一，把「成本」当第一约束来回答。** 这一家的题几乎都能往成本上收：检索要压索引（04）、
推理要压显存（02）、交付要压升级与支持的固定成本（08）、agent 要算核验成本（07）。
**能主动把答案落到「单位成本」上，比只谈效果更贴合这家公司的语境。**

**第二，权限与可追溯要当成硬要求。** 第 07 题给出的清单（以调用者身份检索、span 级引用、
对外承诺人工门、数字从权威系统取、副作用幂等）在这一家的面试里可以直接复用。
**「我们做了权限」不是证据，「越权探针全绿」才是。**

**第三，评估要能在没有金标时开展。** 第 05 与第 09 题是同一主题的两面：
**分群报告**（别被聚合值骗）与**造出评估能力**（日志 → 合成 → 小样本标注 → 在线信号 → 滚雪球）。
另外记住 **rule of three**：抽 30 条零缺陷只能支撑「缺陷率低于 10%」。

**第四，随时准备把争论变成实验。** 这一家的场景里「客户坚持某个方向」是常态（串第 06、10 题的追问），
标准动作是**预注册判据 + 小范围对照 + 分群报告**，而不是在立场上争。
