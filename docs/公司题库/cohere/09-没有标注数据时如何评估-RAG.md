## 一句话答案

> **核心思路：没有「标注数据」，但一定有别的东西**——日志、语料、专家、以及「能不能拒答」这类**不需要金标就能构造**的测试集。评估分两段：
> **上线前（离线，无标签）**
> ① **从日志挖查询集**：搜索框日志、历史工单标题、客服 FAQ、内部 IM 提问——**查询本身不需要标注**，只需要**分层抽样**（按意图 × 频次）；
> ② **用杠杆最高的方式造标签**（按性价比排序）：
> - **合成问答对**（从语料里取一段 → 让模型生成问题 → 该段就是金标）：**几乎零成本**，但**只能用于相对比较与覆盖率**（合成问题偏简单，绝对分数不可信）；
> - **SME 小样本标注 + 池化**（几百条查询跑多系统 top-k 的并集，让专家判相关）：**唯一能给出绝对指标的手段**；
> - **LLM 裁判 + 人工校验一致性**（在小样本上算 κ，达标才敢用）；
> - **弱监督**：历史工单里「人最终用的那份文档」、书签、点击；
> ③ **无金标也能测的指标**：
> - **可答性/拒答正确率**——**构造「语料里没有答案」的问题集**（不需要金标，只需要知道语料里没什么）；
> - **依据性（faithfulness）与引用正确率**——每句断言是否有检索到的文段支撑（裁判 + 人工抽检）；
> - **空召回率、覆盖率、重复率、时效分布**（纯语料侧，**完全不需要查询**）；
> ④ **相对比较代替绝对评分**：同一批查询跑两个配置，用**成对偏好**判断哪个更好——**没有绝对金标也能做决策**。
> **上线后（在线，隐式信号为主）**
> ① **隐式信号**：点击/展开引用、复制、**追问与改写（很可能表示没答好）**、转人工、任务完成、放弃率；
> ② **显式反馈**：点赞点踩 + 原因、「这个问题答错了」（带上引用的文档）；
> ③ **每日人工审计抽样**（按意图与低置信信号分层）——**这是把「在线信号」变成「可信结论」的关键**；
> ④ **金标集滚雪球**：每个被确认的失败案例都进回归集 → **评估能力随时间复合增长**（这就是「从零到有标注」的路径）；
> ⑤ **门禁**：把引用率、拒答正确率、审计命中率写成发布门禁（串 [[databricks-07]]）。
> **两个必须算清楚的地方**（本轮的量化部分）：
> - **标注预算怎么花**：几百条判断要按**分层最优分配**（方差大的层多标），而不是平均分；
> - **「没有幻觉」这句话要多少样本**：审计抽样下，**零缺陷时 95% 置信的缺陷率上界 ≈ 3/n**（$n=150$ → 上界 2%）——**算不出来就不要宣称「没有幻觉」**。
> 一句话判据：**「没有标注数据」不等于「无法评估」**——它意味着**你必须先造出评估能力**，而造它的顺序是：日志 → 合成 → 小样本专家标注 → 在线信号 → 滚雪球。

## 面试官在考什么

- **是否把「没有标签」拆开看**：查询可以从日志拿、语料属性不需要标签、「该拒答的问题」可以构造——能否列出**三类不需要金标的评估资产**。
- **合成数据的正确用法**：能否主动指出**合成问答对偏简单**，因此只能用于相对比较与覆盖率，不能当绝对分数（这是最容易犯的错）。
- **LLM 裁判的纪律**：能否坚持「先用人工小样本校验一致性（κ），达标才用」，并报出裁判与人工的一致率。
- **拒答/可答性**：能否想到构造**不可答问题集**（这是无标签评估里最有价值的单点）。
- **相对比较的价值**：能否用成对偏好替代绝对评分做 A/B（离线与在线都适用）。
- **在线信号的陷阱**：能否指出「点击 ≠ 满意」、「追问可能只是好奇」，因此**隐式信号只能用于相对比较**，绝对结论要靠审计抽样。
- **审计抽样的统计学**：能否用**二项分布/rule of three** 说明「抽了 150 条没发现问题」意味着什么（上界 2%，而不是「零幻觉」）。
- **滚雪球机制**：能否给出「失败案例 → 回归集 → 门禁」的闭环，让评估能力随时间增长。
- **诚实**：明确区分「我们知道的」与「我们不知道的」（例如合成数据上的高分不代表性），并给出**下一步补数据的计划**。

**常见错误答案**

- 说「没有标注就先用 LLM 裁判」（不校验裁判一致性）。
- 只用合成问答对，然后报告绝对准确率（虚高）。
- 只测「能不能答对」，不测「该拒答时是否拒答」。
- 把点击率当满意度（不做去偏，不做审计）。
- 不建回归集（每次上线都从零评估）。
- 用「我们抽了 20 条都没问题」来宣称「没有幻觉」。
- 忽略语料侧检查（重复/过期/元数据缺失），而这些**不需要任何标签**。

## 原理与推导

### 1. 无标签下可用的三类资产

| 资产 | 从哪来 | 能测什么 | 不能测什么 |
| --- | --- | --- | --- |
| **查询集** | 日志、工单、FAQ、IM | 覆盖率、空召回率、延迟 | 相关性（缺金标） |
| **语料属性** | 文档库本身 | 重复率、时效、元数据完整度、分块质量 | 检索效果 |
| **构造测试集** | 人为构造 | **拒答正确率**、格式合法性、边界行为 | 真实问题的相关性 |

**读法**：这三类**不需要任何标注**就能立刻开始，且能覆盖相当一部分风险（尤其是「该拒答却胡说」这类最危险的行为）。

### 2. 合成问答对：便宜但偏乐观

生成方式：从语料取一段 $d$ → 让模型生成「这段能回答的问题」 $q$ → 得到 $(q, d)$ 对。

**偏差来源**：$q$ 是**从 $d$ 生成的**，所以 $q$ 与 $d$ 的用词/结构高度相似 → **检索难度系统性低于真实查询**。设真实查询的检索难度为 $\delta_{\text{real}}$、合成为 $\delta_{\text{syn}}$，通常：

$$\delta_{\text{syn}}<\delta_{\text{real}}\ \Rightarrow\ \text{recall}_{\text{syn}}>\text{recall}_{\text{real}}$$

**正确用法**：① **相对比较**（两套配置在同一合成集上的差值仍然有效）；② **覆盖率检查**（语料里有没有相关内容）；③ **回归测试**（同一集合跨版本对比）。**错误用法**：把合成集上的绝对分数当成交付指标。

### 3. 拒答正确率：无标签评估的「甜点」

构造两类集合：

- **可答集**：语料里确有答案 → 期望**回答且引用正确**；
- **不可答集**：**语料里确定没有**（例如问一个不存在的产品特性、超出时间范围的政策）→ 期望**明确拒答/标注未找到**。

$$\text{拒答正确率}=\frac{\#\{\text{不可答问题且被拒答}\}+\#\{\text{可答问题且被回答}\}}{\#\text{全部}}$$

**为什么价值高**：① **不需要金标**（「语料里没有」这件事你自己知道）；② 直接对应**幻觉风险**（企业最在意）；③ 可以**自动化打分**（关键词/裁判判定是否拒答）。

### 4. 审计抽样与「零缺陷」的置信上界

若抽 $n$ 条答案人工审计，**零缺陷**时真实缺陷率的 95% 上界（rule of three）：

$$p_{\text{upper}}\approx\frac{3}{n}$$

| 抽样条数 $n$ | 零缺陷时的缺陷率上界 |
| --- | --- |
| 30 | 10% |
| 150 | **2%** |
| 300 | 1% |
| 600 | 0.5% |

**读法**：**「我们抽了 30 条没问题」只能支撑「缺陷率 < 10%」**——这就是为什么「没有幻觉」这句话需要几百条审计。**分层抽样**（按意图/按低置信信号）能用更少样本覆盖更高风险区域。

### 5. 隐式信号：只能做相对比较

设「追问/改写」是失败信号，但它有误报（用户只是好奇）与漏报（用户懒得追问直接放弃）：

$$\text{precision}=\frac{\text{真失败}}{\text{被标记}},\qquad \text{recall}=\frac{\text{被标记}}{\text{真失败}}$$

只要 **precision/recall 在两个配置间大致稳定**，用它的**相对差**做决策是可信的；但**不能用它估计绝对失败率**。**去偏手段**：用审计样本估计 precision/recall，再对在线指标做校正。

### 6. 金标集滚雪球：从 0 到有标注的路径

$$\text{每月新增金标}\approx\text{审计发现的问题}+\text{用户报告的失败}+\text{主动探索发现}$$

**关键机制**：每个确认失败 → 加入回归集 → 下次发布**自动被门禁拦住**。**评估能力的增长是复利的**：3 个月后通常会有一份几百条的、来自真实分布的回归集——这就是「从无标注到有标注」的现实路径。

### 7. LLM 裁判的样本量膨胀

裁判有噪声（与人工一致率 $\kappa$ 或一致率 $a<1$），这会让**检测同样差异所需样本变大**。粗略地，测量误差使方差增加：

$$\frac{n_{\text{judge}}}{n_{\text{human}}}\approx\frac{1}{a^2}\ \text{（一致率 }a\text{ 时）}$$

**例**：$a=0.85$ → 需要约 $1/0.85^2\approx1.38$ 倍样本；$a=0.7$ → 约 2 倍。**所以「用裁判省标注」的真实代价是「需要更多样本」**——但通常仍然划算。

### 可运行代码

```python
# 无标注数据的 RAG 评估：分层标注分配、合成偏差、裁判噪声、审计抽样上界、滚雪球
import math
from dataclasses import dataclass
from typing import Dict, List, Tuple

# ---------- 1) 标注预算的最优分配（Neyman 分配） ----------
@dataclass
class Stratum:
    name: str
    share: float          # 查询占比
    sd: float             # 层内指标标准差（越大越需要多标）
    def neyman(self, total: int, strata: List["Stratum"]) -> int:
        num = self.share * self.sd
        den = sum(s.share * s.sd for s in strata)
        return max(1, round(total * num / den)) if den else 0

STRATA = [
    Stratum("产品功能咨询", 0.45, 0.20),
    Stratum("价格与合同", 0.15, 0.45),
    Stratum("故障与排障", 0.25, 0.35),
    Stratum("合规与安全", 0.10, 0.50),
    Stratum("其他长尾", 0.05, 0.55),
]
BUDGET = 500
print("① 500 条标注预算怎么分（Neyman 分配：方差大的层多标）")
print(f"  {'意图层':<14} {'查询占比':>8} {'层内方差':>8} {'最优分配':>8} {'均匀分配':>8}")
for s in STRATA:
    print(f"  {s.name:<14} {s.share:>8.0%} {s.sd:>8.2f} {s.neyman(BUDGET, STRATA):>8} "
          f"{round(BUDGET / len(STRATA)):>8}")
print("  读法：**同样 500 条标注，最优分配把资源压到高方差层**（合规/价格/长尾），")
print("        长尾层只占 5% 查询却拿到远超 5% 的预算 —— 这比「每层平均分」更能压住整体估计的方差")

# ---------- 2) 合成问答对的乐观偏差 ----------
@dataclass
class SynthBias:
    """合成问题从文档生成 -> 与文档用词高度重叠 -> 检索更容易"""
    real_overlap: float = 0.35
    synth_overlap: float = 0.78
    base_recall: float = 0.62
    def recall(self, overlap: float) -> float:
        return min(0.99, self.base_recall + 0.42 * (1 - math.exp(-3.0 * overlap)))

b = SynthBias()
print("")
print("② 合成问答对的偏差：为什么它偏乐观")
print(f"  真实查询（词面重叠 {b.real_overlap:.2f}）-> recall@10 约 {b.recall(b.real_overlap):.3f}")
print(f"  合成问题（词面重叠 {b.synth_overlap:.2f}）-> recall@10 约 {b.recall(b.synth_overlap):.3f}")
print(f"  虚高约 {b.recall(b.synth_overlap) - b.recall(b.real_overlap):+.3f}"
      f"（相对 {(b.recall(b.synth_overlap)/b.recall(b.real_overlap)-1):.0%}）")
print("  读法：**合成集适合「相对比较」与「覆盖率检查」，不能当交付指标** ——")
print("        两套配置在合成集上的差值仍有意义，但绝对分数会系统性偏乐观")

# ---------- 3) LLM 裁判的噪声 -> 样本量膨胀 ----------
def n_paired(delta: float, sd_diff: float = 0.35, alpha: float = 0.05,
             power: float = 0.8) -> int:
    return math.ceil((1.96 + 0.84) ** 2 * sd_diff ** 2 / delta ** 2)

print("")
print("③ 用 LLM 裁判替代人工：一致率越低，需要的样本越多")
print(f"  {'与人工一致率':>12} {'样本膨胀':>9} {'检出 0.05 差异所需':>18}")
for a in (1.00, 0.90, 0.85, 0.70):
    infl = 1 / (a ** 2)
    n = n_paired(0.05, sd_diff=0.35 * math.sqrt(infl))
    print(f"  {a:>12.2f} {infl:>8.2f}x {n:>18,}")
print("  读法：**「用裁判省标注」的真实代价是「需要更多样本」**（0.85 一致率约 1.4 倍，0.7 约 2 倍），")
print("        但通常仍比全人工便宜得多 —— 前提是**先用人工小样本校验一致率并报告它**")

# ---------- 4) 审计抽样：零缺陷时的缺陷率上界（rule of three） ----------
print("")
print("④ 审计抽样：抽 n 条零缺陷时，真实缺陷率的 95% 上界 约等于 3/n")
print(f"  {'抽样条数':>9} {'缺陷率上界':>11} {'能支撑的说法':<28}")
for n in (30, 60, 150, 300, 600):
    ub = 3 / n
    note = (f"可以宣称低于 {ub:.1%}" if ub > 0.05 else f"可以宣称低于 {ub:.1%}")
    print(f"  {n:>9} {ub:>10.1%} {note:<28}")
print("  读法：**「抽了 30 条没问题」只能支撑「缺陷率低于 10%」** —— 要宣称「低于 2%」需要约 150 条")
print("        零缺陷；分层抽样（按意图与低置信信号）能用更少样本覆盖更高风险区域")

# ---------- 5) 隐式信号：只能做相对比较 ----------
@dataclass
class Implicit:
    name: str
    precision: float
    recall: float
    true_fail_rate: float = 0.12
    curiosity_rate: float = 0.03
    def observed(self) -> float:
        true_hit = self.true_fail_rate * self.recall
        false_hit = (1 - self.true_fail_rate) * self.curiosity_rate
        return true_hit + false_hit
    def debiased(self) -> float:
        obs = self.observed()
        false_hit = (1 - self.true_fail_rate) * self.curiosity_rate
        return max(0.0, (obs - false_hit) / self.recall)

print("")
print("⑤ 隐式信号（追问/改写）—— 能做相对比较，不能直接读绝对值")
i = Implicit("追问/改写", precision=0.65, recall=0.55)
print(f"  {'真实失败率（未知量）':<24} {i.true_fail_rate:>8.1%}")
print(f"  {'观测到的追问率':<24} {i.observed():>8.1%}  含误报（好奇也会追问）")
print(f"  {'去偏后估计':<24} {i.debiased():>8.1%}  需要审计样本估 precision/recall")
print("  读法：**观测值不是失败率**（本例 9.2% 对真实 12.0%）；但两个配置之间的**相对差**在")
print("        precision/recall 稳定时可比 —— 绝对值要靠审计样本校正")

# ---------- 6) 金标集滚雪球 ----------
print("")
print("⑥ 金标集滚雪球：从 0 到有回归集的路径（每月新增）")
print(f"  {'月份':>5} {'审计发现':>9} {'用户报告':>9} {'主动探索':>9} {'累计金标':>9} {'可检出差异':>11}")
total = 0
for m in range(1, 7):
    audit, user, explore = 18, 6, 4
    total += audit + user + explore
    detectable = math.sqrt((1.96 + 0.84) ** 2 * 0.35 ** 2 / total)
    print(f"  {m:>5} {audit:>9} {user:>9} {explore:>9} {total:>9} {detectable:>10.1%}")
print("  读法：**评估能力是复利的** —— 6 个月后约 170 条真实分布的金标，可检出约 7 个百分点的差异；")
print("        每个确认失败都进回归集，于是**下个版本不会再犯同一个错**（这也是把「无标注」")
print("        逐步变成「有标注」的现实路径）")
```

预期输出要点（实跑）：① **标注预算的最优分配**把资源压到高方差层（合规/价格/长尾），比「每层平均分」更能压住整体方差；② **合成问答对系统性偏乐观**（词面重叠更高 → 召回虚高），所以只能用于相对比较与覆盖率；③ **LLM 裁判的一致率决定样本膨胀**（0.85 → 约 1.4 倍，0.70 → 约 2 倍）——「省标注」的代价是「要更多样本」；④ **审计抽样的 rule of three**：抽 30 条零缺陷只能支撑「缺陷率 < 10%」，要宣称「<2%」需约 150 条；⑤ **隐式信号不能直接读**（观测追问率 9.2% vs 真实失败率 12.0%），但相对差可比，绝对值靠审计校正；⑥ **金标集滚雪球**：每月约 28 条新增，6 个月后约 170 条，可检出约 7 个百分点的差异，且每个确认失败都进回归集。

## 常见追问

- **追问**：客户就是不肯出人标注，怎么办？
  - 要点：① **先做不需要标注的部分**：不可答问题集（拒答）、语料侧体检（重复/过期/元数据）、合成集上的**相对比较**；② **把标注做小**：**200 条分层样本**就足以支撑 launch 决策（并用 rule of three 说明置信区间）；③ **用客户已有的隐式数据**（工单里「最终采用的文档」就是弱标签）；④ **把标注成本转成产品价值**：建好的回归集是客户资产，用于每次升级验收。**要点是：把「要不要标」变成「标多少能支撑什么决策」。**
- **追问**：怎么向客户证明「回答是有依据的」？
  - 要点：① **强制引用**（每句断言带来源，串 [[cohere-07]]）；② **依据性审计**：抽样 N 条答案，逐句检查是否有检索文段支撑（裁判初筛 + 人工确认），**报告「无支撑断言的占比」及其置信上界**；③ **拒答测试**（不可答集）；④ 用**引用可点击率/采纳率**做在线辅助信号。
- **追问**：合成数据能不能用来训练/微调？
  - 要点：能，但要**严格过滤**（去重、去模板化、用更强模型做裁判筛除低质样本），并**保留一部分人工标注做验收**（防止在自己生成的数据上自嗨）。**合成数据适合「扩量」，不适合「定义标准」。**
- **追问**：上线后发现质量不行，但客户说「和演示不一样」，怎么定位？
  - 要点：**用同一套分层查询集做对照**（演示时的查询 vs 客户真实查询），比较：① 空召回率；② 引用命中；③ 拒答率；④ 查询类型分布（**真实查询往往更短、更口语、含错别字/缩写**）。**差异通常在「查询分布」，而不是模型**——据此决定是改检索（同义词/拼写纠错/查询改写）还是改语料。
- **追问**：怎么做 A/B 而不冒风险？
  - 要点：① **影子模式**（新配置只记录不返回）；② **小流量 + 严格门禁**（引用率、拒答正确率、空召回率、延迟）；③ **同一批查询的成对比较**（离线也能做，样本量小得多）；④ **回滚预案与演练**（串 [[databricks-09]] 的灰度与回滚）。
- **追问**：怎么让评估长期有效？
  - 要点：① **金标集滚雪球**（失败 → 回归集）；② **按意图与语言的分布保持同步**（分布漂移了就重采样）；③ **季度重标**（旧标签可能过期，尤其政策类）；④ **指标与门禁挂钩**（每次发布跑分，串 [[databricks-07]]）。
- **追问**：没有金标时怎么设「发布门禁」？
  - 要点：用**无标签可得 + 有明确判据**的组合：① **拒答正确率 ≥ 阈值**（不可答集）；② **空召回率 ≤ 阈值**；③ **引用覆盖率 ≥ 阈值**（有断言就有引用）；④ **格式合法率 = 100%**（schema 校验）；⑤ **审计抽样**上界达标；⑥ **延迟/成本**。**这些都是「不需要金标就能判定」的门禁**，足以拦住大多数严重问题。
