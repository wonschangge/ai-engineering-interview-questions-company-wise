## 一句话答案

> **这道题的考点是「你如何把模糊变成可执行」**——不是项目多大，也不是你多能扛。所以答案不要按时间流水账讲，而按**六段式**组织，
> 其中**第三段（降模糊的动作）与第四段（取舍依据）要占一半时间**：
> ① **背景与约束**（30 秒）：业务问题 + **真实约束**（时间、人、预算、合规、遗留系统）——约束讲得越具体，「模糊」越可信；
> ② **模糊在哪里**（20 秒）：**明确说出模糊的类型**（目标？范围？成功标准？决策权？技术路径？），这一句就能把答案的档次拉开；
> ③ **我做了什么把问题变清晰**（60–80 秒，主体一）：写下 one-pager、**找到真正的决策人**、定义「足够好」、**时间盒探针**（spike）、公开假设清单；
> ④ **关键取舍 2–3 个**（60 秒，主体二）：每个讲**选项 → 依据 → 放弃的代价 → 事后对不对**（依据要有数字或明确推理）；
> ⑤ **结果与口径**（30 秒）：可核查的数字 + **它是怎么算的**（基线、样本、区间）；如果没达标，**如实说并给出原因**；
> ⑥ **如果重来**（15 秒）：一处不同的做法 + 为什么——**主动讲这一段的候选人很少，讲了就是加分**。
> **三个让答案立刻显得专业的动作**：
> 1. **给模糊命名**（「当时的模糊主要是**成功标准**：没人能说清'做出来'是什么意思」）；
> 2. **量化一次决策**（哪怕粗糙：期望值、回本周期、延迟换转化的比率）；
> 3. **说清决策权**（「我确认了 X 是决策人，我对 Y 有最终决定权」）——**端到端负责的标志不是「我全做了」，而是「我知道谁定什么、并且我推动了决定」**。
> **必须避免的三件事**：流水账（听众不知道哪里是关键）、**没有数字的结果**（「效果很好」等于没说）、**把模糊归咎于别人**（「没人告诉我怎么做」是减分句，正确说法是「当时没有任何人知道怎么做，所以我先做了一版可验证的定义」）。
> **关于本文的诚实说明**：行为题必须用**你自己的经历**回答。下面给出的两段叙述是**结构模板与示例**（标注为示例），用来示范「怎么讲」；请把其中的角色、约束、数字替换成你的真实经历——**编造经历在追问下必然露馅**（面试官通常会问「当时谁反对、你怎么说服他的」，细节对不上就完了）。

## 面试官在考什么

- **是否真的端到端**：能否说清「从定义成功标准 → 方案 → 落地 → 上线 → 度量 → 复盘」这条链上你各自做了什么。
- **降模糊的能力**（本题核心）：能否说出**具体动作**（写下来、找决策人、定义足够好、时间盒探针），而不是「我一边做一边摸索」。
- **取舍的依据**：能否给出选项、依据、代价，并且**依据是可检验的**（数据、成本模型、风险对比）。
- **决策权意识**：能否分清「我定的」与「我推动别人定的」——这体现了组织成熟度。
- **结果的真实性**：数字是否有基线、样本、区间；没达标能否如实说（**夸大结果的候选人在追问下会崩**）。
- **沟通与影响**：如何让不情愿的相关方接受方案（尤其是「要砍范围」时）。
- **复盘与学习**：是否有一处**具体的**「如果重来」（不是「我会更早沟通」这种空话）。
- **抗压与边界**：在信息不足时如何避免瘫痪，也不鲁莽（**什么时候决定「先做再说」，什么时候必须先问清**）。
- **与岗位的相关性**：Cohere 的场景（企业交付、客户现场、跨团队）常考察「在客户模糊需求下如何定义可交付物」。

**常见错误答案**

- **流水账**：「第一个月我做了 A，第二个月做了 B……」（没有取舍与判断，听完不知道你强在哪）。
- **假模糊**：其实需求很清楚，只是任务难（面试官会追问「所以到底哪里不明确？」）。
- **没有数字**：「上线后效果显著改善」（等于没有结果）。
- **甩锅**：「没人给我明确需求」（把责任推给组织，而不是展示你怎么创造清晰度）。
- **个人英雄主义**：「全靠我一个人扛下来的」（面试官会担心你无法协作）。
- **只说成功**：没有失败、没有取舍代价（可信度下降）。
- **回答跑题**：问的是「缺少指导的模糊问题」，你讲了「和领导意见不一致」（那是另一道题）。
- **「如果重来」给空话**：「我会更早地沟通」（没有具体动作与后果）。

## 原理与推导

### 1. 先给「模糊」分类（这一步决定你后面讲什么）

| 模糊类型 | 表现 | 降模糊的动作 |
| --- | --- | --- |
| **目标模糊** | 不知道要解决谁的什么问题 | 找业务方访谈，写**问题陈述**（谁、什么场景、现在的损失） |
| **范围模糊** | 不知道做到哪算完 | 定义**最小可交付**与「明确不做」的清单 |
| **成功标准模糊** | 不知道「好」是什么 | 与决策人约定**一个北极星 + 两条护栏**，并写下基线 |
| **决策权模糊** | 不知道谁拍板 | 用 DACI/RACI 明确**谁批准、谁咨询、谁执行** |
| **技术路径模糊** | 多个方案都可能 | **时间盒探针**（3–5 天）验证关键假设，再承诺 |

**读法**：答案里**命名模糊类型**，等于告诉面试官「我不是硬扛，我是有方法的」。

### 2. 什么时候该先调研，什么时候该先动手（可算）

在信息不足时，**先调研**的价值是「避免选错方向」，代价是时间。用**信息的期望价值**（EVPI）判断：

$$\text{EVPI}=\mathbb{E}\big[\text{完美信息下的最优收益}\big]-\text{当前信息下的最优收益}$$

**判据**：若 $\text{EVPI}>\text{调研成本}$，就先做探针；否则**直接选当前最优并保留可逆性**。**关键补充**：优先选**可逆**的路径（花小钱保留换方向的权利），即「**期权思维**」——在模糊环境里，**可逆性本身有价值**。

### 3. 降模糊的五个动作（按性价比排序）

1. **写一页纸**：问题、现状损失、假设、成功标准、不做清单、里程碑。**写下来立刻会暴露「其实没人想清楚」**——这是最便宜的动作；
2. **找决策人**：不是找「最懂的人」，而是找「能拍板的人」；把一页纸给他，问「如果我按这个做，你会反对哪一条」（**反对意见比赞同意见信息量大**）；
3. **定义「足够好」**：给出**可测的门槛**（例如「召回率 ≥ 0.85 且 p95 < 800 ms 就上线试点」），并约定**下一步的判据**；
4. **时间盒探针**：3–5 天验证**唯一最大的不确定性**（不是「做个 demo」，而是「回答某个具体问题」）；
5. **公开假设清单**：把所有假设写在一处并定期更新——**假设被推翻时，方案要跟着变**（这也让复盘有据可依）。

### 4. 叙述的时间预算与评分维度

一段 3 分钟的答案，时间分配大致是：背景 30 秒、模糊 20 秒、动作 70 秒、取舍 60 秒、结果 30 秒、复盘 15 秒。**总时长 3–4 分钟**为宜（超过 5 分钟面试官会打断，且说明你抓不住重点）。

**自评维度**（下面代码里会算一个加权分）：清晰度、降模糊动作、取舍依据、结果口径、复盘深度、诚实度。

### 5. 两段示例叙述（**结构模板，不是真实经历**）

**示例 A：从零定义「企业搜索质量」（B2B 交付场景）**
- 背景：客户买了检索系统但**说不出「好」是什么**，只说「搜不到东西」；我这边只有 3 周、1 名工程师可用。
- 模糊类型：**成功标准模糊**（外加范围模糊）。
- 动作：① 用两天从客户搜索日志里抽 200 条真实查询，**让客户业务方把这 200 条分成 5 类**（他们自己动手，标准就自然浮现）；② 写一页纸定义「好」= 空召回率 < 10% 且前 3 条里有答案的比例 > 80%；③ 明确决策人（客户业务负责人），把「不做」清单写清（**不做多语言、不做个性化**）。
- 取舍：**先修「空召回」而不是先调排序**——依据是 200 条查询里 31% 完全没返回结果，修这个的收益最大且改动最小（同义词 + 拼写纠错），代价是**暂时不解决排序问题**。
- 结果：三周后空召回率 31% → 8%，前三命中率 62% → 84%（**同一批 200 条查询、前后对照**）；排序问题留给第二期。
- 如果重来：**第一周就拉客户业务方参与分类**——我第二周才做，导致第一周的方向偏了（白做了一版同义词表）。

**示例 B：把一个没人负责的线上质量问题收口（平台团队场景）**
- 背景：某类请求的失败率是别的三倍，**三个团队都认为不是自己的问题**；没有明确 owner。
- 模糊类型：**决策权模糊**（外加技术路径模糊）。
- 动作：① 用两天做**归因探针**（把一次失败请求的完整链路指标摊在一张图上）；② 把结论写成一页纸，**给三个团队各发一版**，请他们指出「哪一句不对」；③ 提出一个**临时 owner 机制**：我先当「问题 owner」两周，谁修谁定 —— 拿到管理层同意（明确决策权）。
- 取舍：**先做「止血」（加超时与降级）而不是先做根因重构**——依据是失败率造成的用户可见损失按每千次 0.6 次工单估算，止血能把损失砍掉七成，而重构要 6 周；代价是**留下技术债**（记入 issue 并约定下一季度处理）。
- 结果：两周内该类失败率 3.1% → 0.9%，工单量下降约 65%；重构排在下一季度并按时完成。
- 如果重来：**更早把「临时 owner」写进邮件**——口头约定在第二周被遗忘了一次，导致节奏乱了两天。

**要点**：两段示例都遵循同一结构——**给模糊命名 → 具体动作 → 量化取舍 → 结果有口径 → 复盘有具体动作**。你的版本要把角色、约束、数字换成真实的。

### 6. 面试前怎么准备（story bank）

准备 **5–6 个故事**，每个都写下：一句话标题、约束、模糊类型、2 个取舍、3 个数字、1 个复盘。然后映射到常见维度：

| 维度 | 用哪个故事 |
| --- | --- |
| 端到端负责 | 故事 1（示例 A 型） |
| 处理模糊/缺指导 | 故事 2（本题） |
| 跨团队影响/无授权领导 | 故事 3（示例 B 型） |
| 失败与学习 | 故事 4 |
| 技术深度取舍 | 故事 5 |
| 客户/利益相关方冲突 | 故事 6 |

**关键**：**每个故事都要能压缩到 90 秒，也能展开到 5 分钟**——面试官会根据兴趣决定追问深度。

### 可运行代码

```python
# 行为题的"可算部分"：EVPI（该不该先调研）、可逆性价值、时间预算、答案自评量规
import math
from dataclasses import dataclass, field
from typing import Dict, List, Tuple

# ---------- 1) 什么时候该先调研：信息的期望价值（EVPI） ----------
@dataclass
class Branch:
    name: str
    p_success: float          # 该方向成功的概率（当前认知）
    payoff: float             # 成功时的收益（万美元）
    cost: float = 0.0         # 该方向的投入成本
    def ev(self) -> float:
        return self.p_success * self.payoff - self.cost

def evpi(branches: List[Branch], p_best: float) -> float:
    """完美信息下的期望收益 - 当前信息下最优的期望收益"""
    # 完美信息：以 p_best 的概率得知哪个方向最好（近似：得知后总能选到最好的）
    best = max(b.ev() for b in branches)
    second = sorted((b.ev() for b in branches), reverse=True)[1]
    return p_best * (best - second)

BRANCHES = [
    Branch("方向 A：修检索召回（空召回占 31%）", 0.75, 18.0, 2.0),
    Branch("方向 B：先调排序质量", 0.55, 12.0, 2.0),
    Branch("方向 C：重做数据清洗", 0.40, 9.0, 2.0),
]
P_BEST = 0.75
probe_cost = 0.6          # 3 天探针的成本（万美元）
e = evpi(BRANCHES, P_BEST)
print("① 先调研还是先动手：信息的期望价值（EVPI）")
print(f"  {'方向':<32} {'成功概率':>8} {'收益':>7} {'EV':>7}")
for b in sorted(BRANCHES, key=lambda x: -x.ev()):
    print(f"  {b.name:<32} {b.p_success:>8.0%} {b.payoff:>7.1f} {b.ev():>7.2f}")
print(f"  EVPI（明确知道哪个方向最好值多少钱）= {e:.2f} 万美元；探针成本 {probe_cost:.2f} 万美元")
print(f"  结论：{'先做时间盒探针' if e > probe_cost else '直接选当前最优并保留可逆性'}"
      f"（差额 {abs(e - probe_cost):.2f}）")
print("  读法：**面试里讲「我先花 3 天验证最关键的不确定性」，如果能补一句「因为选错方向的代价是它的几倍」，")
print("        就是完整的决策叙述** —— 而不是「我觉得先看看比较稳」")
print("  注意：EVPI 的近似算法在方向数多于两个时会低估，这里只用于给出量级感")

# ---------- 2) 可逆性（期权）价值：模糊环境里先做小 ----------
@dataclass
class OptionPlan:
    name: str
    upfront: float            # 初期投入（万美元）
    p_pivot: float            # 需要转向的概率
    pivot_cost_small: float   # 小步走时转向成本
    pivot_cost_big: float     # 大步走时转向成本
    payoff: float = 20.0
    def total(self, small_step: bool) -> float:
        """按方案自身选择相应的"转向成本"字段"""
        pivot = self.pivot_cost_small if small_step else self.pivot_cost_big
        return self.upfront + self.p_pivot * pivot
BIG = OptionPlan("一次性大投入（6 周全量）", upfront=8.0, p_pivot=0.45,
                 pivot_cost_small=0.0, pivot_cost_big=9.0)
SMALL = OptionPlan("小步走（2 周试点 + 可扩展）", upfront=3.0, p_pivot=0.45,
                   pivot_cost_small=2.0, pivot_cost_big=0.0)
print("")
print("② 可逆性价值：为什么模糊环境下「先做小」更划算")
print(f"  {'方案':<28} {'初期投入':>9} {'需转向概率':>10} {'期望着总投入':>12}")
print(f"  {BIG.name:<28} {BIG.upfront:>9.1f} {BIG.p_pivot:>10.0%} {BIG.total(False):>12.2f}")
print(f"  {SMALL.name:<28} {SMALL.upfront:>9.1f} {SMALL.p_pivot:>10.0%} {SMALL.total(True):>12.2f}")
print("  读法：**小步走的期望投入更低，而且保留了「扩展」的选择权** —— 在模糊环境里，")
print("        「可逆」本身就是价值；面试时讲清「我为什么先做 2 周而不是直接做 6 周」就是加分")

# ---------- 3) 三分钟答案的时间预算 ----------
@dataclass
class AnswerPlan:
    segments: List[Tuple[str, int]]      # (段落, 秒)
    def total(self) -> int:
        return sum(s for _, s in self.segments)
    def ratio(self, name: str) -> float:
        for n, s in self.segments:
            if n == name:
                return s / self.total()
        return 0.0
PLAN = [("背景与约束", 30), ("模糊在哪里", 20), ("降模糊的动作", 75),
        ("关键取舍", 60), ("结果与口径", 30), ("如果重来", 15)]
ap = AnswerPlan(PLAN)
print("")
print("③ 三分钟答案的时间预算（总长 3–4 分钟；主体占一半以上）")
print(f"  {'段落':<16} {'秒':>5} {'占比':>7}")
for name, sec in PLAN:
    print(f"  {name:<16} {sec:>5} {sec/ap.total():>7.0%}")
print(f"  {'合计':<16} {ap.total():>5} 秒")
print("  读法：**主体（降模糊动作 + 关键取舍）应占一半以上**；若背景讲了两分钟，面试官已经在走神")

# ---------- 4) 自评量规：给一段答案打分 ----------
@dataclass
class Rubric:
    dim: str
    weight: float
    def weighted(self, score: float) -> float:
        return self.weight * score
RUBRIC = [
    Rubric("清晰度（结构/重点）", 0.20),
    Rubric("降模糊动作（命名类型 + 具体动作）", 0.25),
    Rubric("取舍依据（选项/依据/代价/事后）", 0.25),
    Rubric("结果口径（基线/样本/区间）", 0.15),
    Rubric("复盘深度（具体动作）", 0.10),
    Rubric("诚实度（含失败与代价）", 0.05),
]
SAMPLE = {
    "流水账式答案":            [2, 1, 1, 0, 0, 1],
    "有结果但没取舍":           [3, 2, 1, 3, 1, 2],
    "结构完整但复盘空泛":        [3, 3, 3, 3, 1, 3],
    "结构完整 + 具体复盘（目标）":  [3, 3, 3, 3, 3, 3],
}
print("")
print("④ 答案自评量规（0–3 分 × 权重，满分 3.00）")
print(f"  {'版本':<26} {'加权得分':>9} {'主要短板':<22}")
for name, scores in SAMPLE.items():
    total = sum(r.weighted(s) for r, s in zip(RUBRIC, scores))
    if min(scores) == 3:
        weak = "（无明显短板）"
    else:
        weak = min(zip(RUBRIC, scores), key=lambda x: x[1])[0].dim[:20]
    print(f"  {name:<26} {total:>9.2f} {weak:<22}")
print("  读法：**「有结果但没取舍」是最常见的失分形态**（很多人只讲成果不讲判断）；")
print("        **复盘空泛**（「会更早沟通」）在权重只有 10% 的情况下依然明显拉低总分 —— 因为它是")
print("        面试官判断「这个人会不会成长」的直接证据")
```

预期输出要点（实跑）：① **EVPI 判据**显示「先花 3 天验证最关键的不确定性」是**有数字支撑的决策**（本例 EVPI 明显高于探针成本），而不是「我觉得稳一点好」；② **可逆性价值**说明模糊环境下「小步走」的**期望总投入更低且保留扩展选择权**——这正是回答「为什么先做 2 周而不是直接做 6 周」的依据；③ **时间预算**把三分钟答案拆成六段，**主体（降模糊 + 取舍）应占一半以上**；④ **自评量规**显示**「有结果但没取舍」是最常见的失分形态**，而**复盘空泛**即使权重只有 10% 也会明显拉低总分。

## 常见追问

- **追问**：当时到底是谁的决策权？你怎么确认的？
  - 要点：讲清三件事——**谁批准**（预算与范围）、**谁咨询**（受影响团队）、**谁执行**。若当时确实模糊，就讲你**如何把它变清晰**（写下来、发邮件确认、会上明确「这条由 X 定」）。**面试官在验证你是不是只会做事、不会定事。**
- **追问**：如果你的判断错了呢？
  - 要点：不要辩解，讲**你什么时候发现自己错了**（什么信号）、**怎么纠偏**（代价多大）、**学到了什么**。**这类追问是送分题**：能讲清「错在哪、怎么发现、怎么改」的候选人反而比「从没判断错过」的更可信。
- **追问**：有没有人反对？你怎么处理的？
  - 要点：讲**反对的实质理由**（不是「他脾气不好」），以及你**怎么处理**：① 用数据回答（做个小实验）；② 缩小范围（先试点）；③ 承认对方部分对（调整方案）；④ 升级到决策人（最后手段，且要提前告知对方）。**「我用数据说服了他」要配一个具体数据。**
- **追问**：你怎么定义「成功」？
  - 要点：给出**一个北极星 + 两条护栏**，并说明**基线**。例如「前三命中率 > 80%（护栏：p95 < 800 ms、成本不上升）」。若当时确实没有标准，讲你**如何造出标准**（让业务方亲手分类 200 条查询）。
- **追问**：如果重来你会怎么做？
  - 要点：**一处具体的**不同做法 + 后果（「我会第一周就拉业务方参与分类，因为第二周才发现方向偏了，白做了一版同义词表」）。**避免「我会更早沟通」这类空话。**
- **追问**：资源只有一半，你会砍什么？
  - 要点：给出**砍的顺序与理由**（先砍「锦上添花」、再砍「可延后」、最后砍「范围」但**绝不砍质量护栏**）。能说清「不做什么」比说清「做什么」更显成熟。
- **追问**：这是你一个人做的吗？
  - 要点：**诚实说明分工**，并突出你的**独有贡献**（「三个人，我负责定义成功标准与检索侧改动，A 负责数据管道，B 负责前端」）。**「全靠我一个人」是危险答案。**
- **追问**：你怎么知道上线后是有效的？
  - 要点：**前后对照**（同一批查询/同一批用户的基线对比）、**样本与区间**、以及**是否只对某类用户有效**（分层）。若当时做得不够严谨，**如实说并讲你会怎么补**（串 [[cohere-09]] 的审计与 rule of three）。
- **追问**：这件事和 Cohere 的业务有什么关系？
  - 要点：Cohere 的日常是**企业交付与客户现场**：需求模糊、数据不可得、决策权在客户方。把故事里的**「把模糊需求变成可交付物」**这条线接到岗位场景上（串 [[cohere-07]] 的企业级要求）。
- **追问**：如果客户坚持一个你认为错的方向呢？
  - 要点：**把争论转成可检验的实验**（预注册判据 + 小范围对照），这是本仓库反复出现的方法论（串 [[cohere-06]] 的排查、[[databricks-09]] 的迁移评测）。**别在立场上争，在证据上定。**
