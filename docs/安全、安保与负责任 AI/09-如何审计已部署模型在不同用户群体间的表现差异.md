## 一句话答案

> 把「表现差异」先拆成五类**可计算的量**——性能、校准、服务、表征与毒性、可及性——再按固定流水线审计：定义群体与交叉切片 → 确定标签来源 → 先做功效估算 → 受控分层评测（固定解码参数、按层报告指标与置信区间）→ 盲评 → 线上分层监控 → 写进 Model Card / 数据卡披露。核心纪律是：**不看整体平均，只看分层结果加不确定性**，因为整体平均会把小群体的退化完全掩盖。

## 面试官在考什么

- 能否把「公平性」这种口号式的词翻译成指标：每类差异对应哪个可测的量、分母是什么、怎么算置信区间。
- 是否懂统计纪律：交叉切片后样本量骤降，功效不足会同时制造假阳与假阴，这是审计能不能得出结论的前提。
- 是否理解群体标签的来源约束：自报标签、代理特征、社区标注各自的误差与伦理风险。
- 是否知道「有差异」不等于「不公平」，以及审计动作本身（收集与存储敏感标签）会引入新的隐私风险。
- 能否落到行动：数据侧、模型侧、部署侧各改什么，以及如何披露。

常见错误答案：

- 只答「跑一遍 benchmark，看各群体准确率是否接近」——没有交叉切片、没有样本量、没有线上部分。
- 把差异直接判定为歧视，或者反向地认为「模型没看群体标签所以一定公平」（代理特征会让差异照样出现）。

## 原理与推导

### 1. 五类差异，每类一个可计算的指标

审计必须先把目标量化，否则会退化成一句「我们会关注公平性」。

| 差异类别 | 要回答的问题 | 可计算的指标 |
| --- | --- | --- |
| 性能差异 | 某群体的任务成功率是否更低 | 分层后的任务准确率 / F1 / WER / recall@k，及其组间差 |
| 校准差异 | 置信度与拒答阈值在该群体上是否同样可靠 | 分层 ECE、Brier score、risk–coverage 曲线下的覆盖率 |
| 服务差异 | 是否更容易被拒答、答得更短、更多转人工 | 拒答率、平均回复长度、转人工率、首响与解决时长 |
| 表征与毒性差异 | 输出是否更常出现刻板印象或毒性 | 分层毒性率、刻板印象判定率、描述性形容词的情感倾向 |
| 可及性差异 | 语言与无障碍通道是否覆盖 | 支持语种覆盖率、读屏/语音交互的任务成功率 |

前两类是「模型算得准不准」，后三类是「系统对不同人是否一样可用」。只测第一类是最常见的偷懒。

### 2. 群体定义与交叉切片

群体由一组维度构成：性别、年龄段、地区、语言与口音、残障状况、母语非母语程度等。关键在于**必须做交叉切片**：单一维度的边缘分布可能看起来均衡，退化却集中在「某地区 + 老年 + 非母语」这类交叉格中。

设维度集合为 $D_1,\dots,D_m$，审计覆盖的切片就是笛卡尔积的一个子集：

$$
\mathcal{S} \subseteq D_1 \times D_2 \times \cdots \times D_m
$$

切片数量随维度指数增长，因此要显式取舍：先按业务影响排序，选出 $|\mathcal{S}|$ 个必须报告的切片（常见量级是几十到上百），其余维度做滚动审计。切片数直接决定了后面多重比较的校正强度：

$$
\alpha_{\text{per-slice}} = \frac{\alpha}{|\mathcal{S}|}
$$

$|\mathcal{S}|=200$、$\alpha=0.05$ 时单切片阈值降到 $2.5\times10^{-4}$，未校正就报告「显著」几乎必然产生假阳。

### 3. 群体标签从哪来

| 来源 | 误差特征 | 主要风险 |
| --- | --- | --- |
| 自报（可选填的问卷、账户设置） | 覆盖率低、有选择偏差，但语义最准确 | 需要明确的同意与最小化存储 |
| 代理特征（姓氏推族裔、设备与邮编推收入） | 系统性误差大，且误差本身随群体变化 | 把敏感属性推断出来并留存，属于高风险做法 |
| 第三方或社区标注 | 依赖合作方口径，一致性需校准 | 需要与社区约定用途与回传方式 |

原则是：**自报优先，代理特征只作为探索性信号**，且代理特征得出的结论不能用于个体层面的决策。无法获得标签时，宁可报告「该切片无法评估」也不要编造分层结果。

### 4. 功效估算必须在抽样之前做

两个比例之差的最小可检测效应（two-proportion，双侧 $\alpha$、功效 $1-\beta$、两组等量）近似为：

$$
\Delta_{\min} \approx \left(z_{1-\alpha/2} + z_{1-\beta}\right)\sqrt{\frac{2\,p(1-p)}{n}}
$$

反过来，要检出给定差异 $\Delta$ 所需的每组样本量：

$$
n \approx \frac{2\,p(1-p)\left(z_{1-\alpha/2}+z_{1-\beta}\right)^2}{\Delta^2}
$$

这一步的实践含义很直接：$p\approx0.10$、$\alpha=0.05$、功效 80% 时，每组 200 个样本只能可靠检出约 8 个百分点的差异，而 8 个百分点的退化在多数场景里早就被投诉了。所以**先算功效，再决定采多少数据、哪些切片只做定性观察**。

### 5. 受控评测：同一批任务、固定解码参数、按层报告

评测协议上不能留自由度；这里的统计纪律（区间估计、功效、多重比较）与 [[evaluation-04]] 的回归门禁同源，区别只是分组维度从版本换成了人群。

- 固定 temperature、top-p、max tokens、system prompt 与工具版本，否则不同群体的差异可能来自采样温度而不是模型能力。
- 分层抽样：每个切片内的样本数按功效要求配齐，而不是按线上流量比例随机抽（按流量抽会让小群体样本量不够）。
- 按层报告指标 + 置信区间，而不是只报一个总分。分类指标（错误率、拒答率）在小样本下用 Wilson 区间，而非正态近似。
- 盲评：评测者与评审不认识模型身份、不知道预期结论，避免期望效应；人工评分的切片要先做标注者一致性检查。
- 多重比较要么做 Bonferroni / BH 校正，要么把交叉切片的结论显式降级为「探索性」。
- 覆盖检查：只在主流语言/口音或单一地区上评测，等于默认其余切片「没有差异」；未覆盖的切片要显式标注为未评估，而不是当作通过。

### 6. 线上审计与反馈偏差

离线集合永远滞后于线上分布，所以还要按群体分层看线上质量代理指标：追问率、重述率、会话放弃率、转人工率、点踩率，以及分群延迟。它们不是 ground truth，但能触发离线深挖。这些信号的记录、采样与 A/B 口径和 [[evaluation-09]] 一致，区别是全部要再按群体切一层。

反馈数据有选择偏差：愿意点踩/点赞的用户不代表全体，某些群体的反馈意愿与渠道可达性本身就不同。因此反馈要配合无偏的隐式信号（是否完成目标任务）使用，并注意不要用反馈数据去反推敏感属性。

### 7. 文档与透明度

两条被广泛采用的实践构成「可审计性的文档基础」：

- **Model Cards（Mitchell 等，FAT\* 2019）**：随模型发布短文档，给出跨文化、人口统计与表型群体（论文举例包括种族、地理位置、性别、Fitzpatrick 皮肤类型）以及交叉群体（如年龄 × 种族）的分组基准评测，并说明预期用途与评测流程。其动机正是减少模型被用在不适合场景中的情况。
- **Datasheets for Datasets（Gebru 等）**：为数据集记录动机、构成、采集过程与推荐用途。之所以同时要做数据卡，是因为**群体差异常常源自数据**（采集渠道、标注者构成、语种覆盖），只查模型会找不到根因。

组织层面可以用 NIST AI RMF（1.0 于 2023-01-26 发布，自愿采用）的四类功能做治理循环：Map（识别场景与受影响人群）→ Measure（度量上述五类量）→ Manage（排优先级、分配处置）；Govern（职责、流程与复核）在原文中位列四类功能之首，并被说明为贯穿其余三类的基础。

### 8. 缓解与治理

- **数据侧**：补齐覆盖与配平、针对低资源切片定向采集与标注；采集与配比的取舍见 [[finetuning-08]]。
- **模型侧**：对弱切片做定向微调或对齐；要监测通用能力是否被破坏，参见 [[finetuning-07]] 的灾难性遗忘。
- **部署侧**：分群监控与告警、灰度发布、按切片的自动回滚；阈值要按影响面定，而不是套一个通用数字，版本切换与回滚的工程实现见 [[evaluation-08]]。
- **披露**：在系统卡 / Model Card 中写明适用场景、分群结果与已知限制，把「未评估的切片」也写出来。

## 数值与代码验证

以下数字为本地复算，用于说明样本量与不确定性的量级（与源文无关，是通用统计结论）。

Wilson 95% 区间随样本量的变化：

| 观测错误率 | 每组 n | 95% CI | 区间宽度 |
| --- | --- | --- | --- |
| 14.0% | 1000 | [12.0%, 16.3%] | 4.3 pp |
| 9.0% | 1000 | [7.4%, 10.9%] | 3.6 pp |
| 14.0% | 200 | [9.9%, 19.5%] | 9.6 pp |
| 9.0% | 200 | [5.8%, 13.8%] | 8.0 pp |

同样的「14% vs 9%」，n=1000 时两个区间不重叠，n=200 时高度重叠——**同一份数据在样本量不足时无法支撑任何结论**。

最小可检测效应（$p\approx0.10$，双侧 $\alpha=0.05$，功效 80%）：

| 每组样本量 | 可检出差异 |
| --- | --- |
| 200 | 8.4 pp |
| 500 | 5.3 pp |
| 1000 | 3.8 pp |
| 2000 | 2.7 pp |
| 5000 | 1.7 pp |

反解：要检出 5 pp 差异约需每组 565 例，3 pp 约 1570 例，1 pp 约 14130 例。

聚合口径也会骗人：三个切片的准确率为 (0.94, n=10000)、(0.72, n=50)、(0.55, n=20)，微平均（按样本加权）得 0.938，宏平均（按切片等权）得 0.737。只报微平均就等于宣布两个退化最严重的切片不存在。

可运行片段：分层指标 + Wilson 区间 + 功效估算。

```python
import math
from collections import defaultdict

Z = 1.959963985   # 双侧 alpha=0.05
ZB = 0.8416212336 # 功效 80%

def wilson(k, n, z=Z):
    """错误率 k/n 的 Wilson 置信区间（小样本与极端比例下优于正态近似）。"""
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return max(0.0, c - h), min(1.0, c + h)

def mde(n, p=0.10, z=Z, zb=ZB):
    """每组 n 例时能检出的最小差异（绝对值）。"""
    return (z + zb) * math.sqrt(2 * p * (1 - p) / n)

def n_for(delta, p=0.10, z=Z, zb=ZB):
    """要检出 delta 差异所需的每组样本量。"""
    return 2 * p * (1 - p) * ((z + zb) / delta) ** 2

# rows: (切片, 是否错误, 是否拒答, 回复长度)
# 下面是极小规模的演示数据，只用来跑通口径；真实审计每层需要数百例以上（见上表 MDE）。
rows = [
    ("zh-CN/25-34", 1, 0, 210), ("zh-CN/25-34", 0, 0, 190),
    ("zh-CN/25-34", 0, 0, 180), ("zh-CN/25-34", 0, 0, 205),
    ("zh-CN/55+",   1, 1, 120), ("zh-CN/55+",   1, 1,  95),
    ("zh-CN/55+",   0, 0, 150), ("zh-CN/55+",   0, 0, 175),
    ("yue/55+",     1, 1,  60), ("yue/55+",     1, 1,  75),
    ("yue/55+",     1, 1,  55), ("yue/55+",     1, 1,  80),
]

stat = defaultdict(lambda: {"n": 0, "err": 0, "refuse": 0, "len": 0})
for slice_name, err, refuse, length in rows:
    s = stat[slice_name]
    s["n"] += 1
    s["err"] += err
    s["refuse"] += refuse
    s["len"] += length

print(f"{'slice':14s} {'n':>4s} {'err':>7s} {'95% CI (Wilson)':>22s} {'refuse':>7s} {'avg len':>8s}")
for name, s in stat.items():
    lo, hi = wilson(s["err"], s["n"])
    print(f"{name:14s} {s['n']:4d} {s['err']/s['n']:6.1%} "
          f"[{lo:6.1%}, {hi:6.1%}] {s['refuse']/s['n']:6.1%} {s['len']/s['n']:8.0f}")

# 审计前的功效检查：这个切片到底能证明什么？
for n in (50, 200, 1000):
    print(f"n/group={n:5d} -> MDE {mde(n):.1%}")
print(f"检出 3pp 差异需要每组 {math.ceil(n_for(0.03))} 例")

# 多重比较校正
slices = 200
print(f"{slices} 个交叉切片时，单切片显著性阈值 alpha = {0.05 / slices:.6f}")
```

追问这些数字时最容易踩的坑：拿单维度边缘分布当结论、用正态区间代替 Wilson 区间、先看结果再决定切片（相当于隐式的多重比较）。

## 常见追问

- **追问**：拿不到群体标签怎么办？
  - 要点：三条路并行——合成与增强代表性数据（针对低资源语种/口音构造评测集）、用语言与地区等低风险代理做粗分层、与社区合作标注并约定用途。高风险的代理（姓氏推族裔、设备推收入）只用于探索，结论不进个体决策，且要明确标注不确定性。
- **追问**：差异多大算「需要处理」？
  - 要点：没有通用阈值。看三件事——影响面（受影响用户占比）、任务后果（医疗/信贷/招聘等高风险场景零容忍）、差异是否可由任务相关性解释。做法是设**按影响面和后果校准**的处置线，配合人工复核，而不是引用一个行业统一数字。
- **追问**：审计本身会不会造成伤害？
  - 要点：会。收集与长期存储群体标签是新的敏感数据面，交叉切片在小群体上还可能变成事实上的个体识别。因此要最小化收集、限定用途与保留期、聚合上报、访问受控，参见 [[safety-07]]。
- **追问**：怎么区分「性能差异」和「歧视」？
  - 要点：差异是观测事实，是否不公平取决于任务相关性（差异是否与任务目标无关）、可解释性（能否归因到数据覆盖或标注口径）与后果（谁承担代价）。审计的职责是把差异量化并暴露，处置决策要带上领域与法务判断。
- **追问**：线上怎么持续审计？
  - 要点：分群埋点 + 质量代理指标 + 灰度与自动回滚，链路与 [[evaluation-09]] 一致；同时用 [[evaluation-04]] 的统计纪律做门禁，避免把噪声当回归、把回归当噪声。
- **追问**：交叉切片样本量永远不够怎么办？
  - 要点：三级策略——高频切片做完整统计检验；低频切片做定向补采（离线构造而非等线上流量）；确实补不齐的切片合并维度或只报定性观察，并在 Model Card 里写明「该切片未评估」。
