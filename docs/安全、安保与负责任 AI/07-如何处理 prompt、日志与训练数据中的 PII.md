## 一句话答案

> 先把 PII 分层，再谈手段：直接标识（姓名、邮箱、证件号、卡号）、准标识（生日、邮编、性别、机构）、敏感类别（健康与遗传、生物特征、儿童数据）、以及从上下文推断出的属性；真正的风险是**组合可识别性**，不是单个字段。识别必须是组合拳——正则加校验位（Luhn、ISO 7064 MOD 11-2）、NER、上下文规则——再配抽样审计与回归，因为纯正则必漏准标识，模型识别必有误报。三条链路分别定策略：prompt 侧最小化优先（不发 > 发引用 id > 发脱敏正文）、日志侧默认不落原文（哈希、长度、类型计数加受控短存与访问审计）、训练侧能不放就不放（来源授权、去标识、去重），因为权重里没有可靠的「删除」。合规上把目的限制、保留期、DSAR 全链路（缓存、备份、派生数据集都算）、跨境与访问审计做成工程清单，用 NIST AI RMF 的 Map–Measure–Manage–Govern 循环持续校准。

## 面试官在考什么

- **分类能力**：能否把 PII 拆成直接标识、准标识、敏感类别与可推断信息，并指出风险来自准标识的组合而不是某个字段本身。「用正则替换手机号」这种答案在这一层就被淘汰。
- **识别方法的边界**：正则、校验位、NER、上下文规则各自覆盖什么、漏什么；是否知道检测器必须配标注集、抽样复核与回归门禁，而不是上线即合规。
- **三条链路的差异化策略**：prompt 有推理与延迟约束、日志有留存与查询需求、训练数据有不可撤销性，最优解完全不同；只会背一套「脱敏 SOP」说明没做过真实系统。
- **删除的工程现实**：DSAR 要覆盖主库、索引、缓存、备份、评测集、微调集与派生数据集；权重内的删除只有重训（或分片重训）可靠，近似机器遗忘不能当合规承诺。
- **合规到工程**：目的限制、最小必要、保留期、跨境传输、供应商条款、访问审计能不能落成具体字段、任务与验证方式。

常见错误答案：

- 「用正则把手机号和邮箱替换掉就合规了」——漏掉准标识与推断信息，也漏掉 trace、缓存、备份、评测集里的副本，而后者才是泄露的常见来源。
- 「假名化/脱敏之后就不算个人信息了」——多数法域下假名化数据仍是个人信息，只是风险降低；能重识别就按个人信息处理是唯一保守口径。

## 原理与推导

### 1. 四层分类与各自的失效模式

| 层次 | 例子 | 为什么单独处理不够 | 典型失败 |
| --- | --- | --- | --- |
| 直接标识 | 姓名、邮箱、电话、身份证/护照、银行卡、账号、设备 ID、IP、URL | 格式确定，正则加校验位效果好 | 昵称、音译名、罕见病名没有固定格式 |
| 准标识 | 生日、邮编、性别、职位、机构、就诊时间 | 单独不识别，组合起来可唯一定位 | 「去掉姓名的表就安全」的错觉 |
| 敏感类别 | 健康与遗传信息、生物特征、性取向、宗教、儿童数据 | 即使无法识别到个人，泄露本身已构成伤害 | 把「不是个人信息」当成「没有风险」 |
| 可推断信息 | 从行为、上下文与模型输出推断出的属性 | 原文没有标识，结论仍指向个人 | 「我的主治医生是 X」直接暴露病种 |

法域口径不同但方向一致：GDPR 用「特殊类别数据」，HIPAA 用 PHI 加标识符清单，中国 PIPL 用「敏感个人信息」并把不满十四周岁未成年人的个人信息纳入。工程上按最严一档处理，不要按最宽松的一档解释。

### 2. 组合可识别性与「匿名化」的边界

k-匿名的定义是：对每个准标识组合，等价类大小不低于 $k$：

$$k = \min_{q \in QI} \left| \{ r : QI(r) = q \} \right|$$

k-匿名只防「直接定位」，不防敏感属性泄露：整个等价类的敏感值都一样（同质性攻击），或攻击者已知目标的部分信息（背景知识攻击）时，$k$ 再大也没用。l-diversity 要求每个等价类在敏感属性上至少有 $l$ 个良表示的值，t-closeness 要求类内敏感属性分布与全局分布的差距不超过 $t$。三者递进说明：**去标识没有终点，只有风险下界与可证明的流程**。

法规给的同样是流程与举证责任，不是阈值。HIPAA 有两条路：Expert Determination（用统计方法证明重识别风险「very small」并记录方法与结论），以及 Safe Harbor——移除 45 CFR §164.514(b)(2)(i) 列举的 (A) 到 (R) 共 18 类标识符，并满足 (b)(2)(ii) 的「不得实际知道信息仍可用于识别个人」条款；若使用重识别码，代码不得由个人信息派生（§164.514(c)）。GDPR 一侧，假名化（第 4(5) 条）仍属个人信息，只有不可逆的匿名化才脱离适用范围，而「不可逆」要靠重识别风险评估支撑。注意 (B) 项：地理细分小于州一律移除，只有该 3 位邮编单元人口超过 2 万时才可保留 3 位邮编，否则前缀改成 000——这条直接决定准标识泛化的粒度。

### 3. 识别：多信号融合与两段式流水线

| 信号 | 覆盖 | 局限 |
| --- | --- | --- |
| 正则 / 格式模板 | 卡号、证件号、电话、邮箱、IP、URL | 误报高（长数字流水号、日期都可能命中），遗漏无格式标识 |
| 校验位 | Luhn（银行卡）、ISO 7064 MOD 11-2（18 位居民身份号码） | 只对有校验位的类型有效 |
| NER 模型 | 姓名、地名、机构、病症 | 领域与语言漂移，长尾姓氏与音译名漏检，仍有误报 |
| 上下文规则与词表 | 「我的主治医生是 X」「患者编号」，allow / deny list | 依赖领域词表与持续维护，规模大时冲突多 |

工程实现可参考 Presidio 的两段式：analyzer 产出 `RecognizerResult(entity_type, start, end, score)`，anonymizer 按算子处理——`replace`、`redact`、`mask`、`hash`、`encrypt`、`custom`、`keep`，需要还原时用 `decrypt` 走 deanonymize；识别器可自定义（正则、规则、校验位、NER），还支持上下文增强、allow list 与决策过程追踪。它有两个值得抄的设计：识别与处理解耦，同一份识别结果可以按不同策略落到 prompt、日志、训练三条链路；以及官方明确声明自动化检测不保证找全、必须叠加其他保护——这句话本身就是标准答案的一部分。因此必须闭环：在标注集上量 precision/recall 并分类型看召回，抽样人工复核，把误报与漏检固化成回归用例，模型换代、词表更新、新语言上线都要重跑。

### 4. prompt 侧：最小化优先，脱敏其次

处理顺序按「数据能不能不出域」排，而不是按「怎么脱敏」排：

1. **不发送**：能本地判定、能用规则回答、能从结构化字段直接取值的，不把原文拼进 prompt。
2. **发引用 id**：prompt 里只出现 `patient_ref=8842`，服务端在受控边界内按 id 取数，模型不接触标识原文。
3. **发脱敏正文**：保留结构与语义、替换标识；注意脱敏后仍可能被推断（「65 岁、某邮编、用某靶向药」去掉姓名后依旧唯一）。
4. **发原文**：只在必要、经授权、可审计的边界内，并明确留存与训练条款。

跨租户隔离是常被忽略的一层：prefix caching / prompt caching 让同一实例上的请求共享前缀块，缓存键不含租户维度时，命中即等于跨租户信息泄露（[[inference-serving-05]]）。做法是按租户分实例或分区、把租户标识做进缓存键并配逐出策略、对缓存读写做越权测试。供应商与部署形态是另一半（[[inference-serving-11]]）：第三方 API 要逐条确认留存期、是否用于训练、零保留与地域选项；私有部署把数据留在边界内，代价是合规责任与运维成本回到自己身上，但在必须保留 PII 的场景（医疗、法律）往往是唯一可行解。还有两个容易漏的载体：prompt 模板里的 few-shot 示例会随模板进版本库与评测集，必须用合成或已授权的样例；多轮会话的历史消息会被反复回填，历史里的 PII 会随会话轮数不断扩散。

### 5. 日志与 trace 侧：默认不落原文

| 字段 | 默认处理 | 备注 |
| --- | --- | --- |
| prompt / response 原文 | 不落；排障时按需加密短存（小时到天级） | 短存要有审批、TTL 与访问审计 |
| 用户标识 | HMAC(租户密钥, id) 后截断 | 保留可关联性，去掉可反查性 |
| 实体信息 | 只记类型与计数，如 `redactions={EMAIL:2, PHONE:1}` | 足够定位问题，不泄露内容 |
| 长度与哈希 | 原文长度、输入哈希 | 复现能力的下限 |
| 工具参数与返回值 | 在采集端脱敏后落库 | 整段上下文塞进参数是常见反模式（[[agents-10]]） |
| 保留期 | 分级 TTL、自动过期，备份同规则 | 备份没有 TTL 等于没有保留期 |

哈希的取舍要讲清楚：要「同一邮箱在同一租户内可关联」（去重、DSAR 定位）就必须用确定性方案，而确定性方案在盐泄露或被猜到时可被字典重算——全局固定盐尤其危险。自建实现的正确形态是每租户独立密钥加截断；Presidio 的 `hash` 算子是同一道理的另一面，它从 2.2.361 版起默认随机盐以防暴力破解，需要引用完整性时必须显式提供固定盐，且盐由使用方自行安全管理。

采集端脱敏优于事后清洗：事后清洗时，明文副本已经落在采集代理、消息队列、日志后端三处了。查询侧默认拒绝、按需开权限、查询行为本身入审计；字段设计可复用生产可观测性那套结论（[[evaluation-07]]），存储与查询的权限模型与检索侧同源（[[rag-08]]）。

### 6. 训练与微调数据侧：准入比删除便宜

- **来源与授权记录**：每个数据集登记来源、授权依据、许可范围、去标识方法与可用期限，即 datasheet 式的元数据；来源不清的数据一律不进训练集。
- **去标识与去重**：去标识降低直接标识；去重同时降低记忆化风险与训练成本。
- **记忆化是真实存在的**：Carlini 等 2021 年公开的抽取实验在 GPT-2 上确认了数百条逐字复现的训练序列（论文原文口径为 hundreds of verbatim text sequences），其中包含姓名、电话、邮箱等 PII，且这些序列在训练数据中只出现在一个文档里，模型越大越容易被抽取。这否掉了「只出现一次就不会被记住」的假设；而样本被重复的次数与可抽取概率强相关，去重因此是有效缓解手段。
- **攻击分类**：NIST AI 100-2 的对抗性机器学习分类把隐私泄露列为一类攻击者目标，其下常见手法包括模型抽取、成员推断、属性推断（property inference）与数据重建，记忆化是这些攻击的素材来源（该报告 2025 年 3 月发布 E2025 修订版，分类与术语以最新版为准）。
- **形式化保证只有一个**：差分隐私。训练时对样本贡献加噪，对数据重建、记忆化与成员推断给出有界保证；代价是隐私预算与模型质量、算力的直接权衡。工程上更现实的是「不进训练集 + 去重 + 访问控制」，把 DP 留给小模型、统计聚合与合成数据。
- **删除**：最可靠的是从训练集移除后重训；缓解手段是把数据分片训练（切片—隔离—聚合的思路），删除时只重训受影响的分片；近似机器遗忘在验证与鲁棒性上仍不成熟，不能写进合规承诺。推论是准入门槛做扎实，比上线后处理删除请求便宜一个数量级——前者是数据工程，后者是重训。

### 7. 合规要求到工程动作

| 要求 | 工程动作 | 验证方式 |
| --- | --- | --- |
| 目的限制与最小必要 | 字段级 purpose 声明，无用途字段不采集 | schema 里有 purpose，CI 检查新增字段 |
| 保留期 | 分级 TTL，含备份与缓存 | 过期任务成功率、残留扫描 |
| DSAR（访问/更正/删除） | 用户标识映射表 + 全链路清单：主库、索引、缓存、日志、备份、评测集、微调集、派生特征 | 每季度删除演练，逐链路抽样验证 |
| 跨境传输 | 数据驻留配置、供应商地域约束 | 出网流量与存储地域审计 |
| 访问控制与供应商 | 最小权限、审批、查询审计；DPA / BAA 条款与零保留选项 | 越权测试、审计覆盖率、条款与配置双向确认 |
| 事故响应 | 泄露检测与通报流程 | 桌面演练，含通知时限 |

最常见的漏洞集中在两处：缓存与备份。删除请求在主库执行成功、在向量索引与 KV/前缀缓存里还留着，或在备份里留 90 天，等于没有删除。

### 8. 用治理循环把它固定下来

NIST AI RMF 的四个核心动作可以直接映射成工件，避免「一次性合规」。**Map**：数据流图与 PII 清单——哪个字段从哪来、进哪条链路、存多久、谁能看。**Measure**：检测器的 precision/recall 与分类型召回、抽样复核结论、删除演练通过率、TTL 残留率、缓存的租户隔离测试。**Manage**：按风险排序处置，敏感类别与可推断信息优先，其次是准标识，最后才是无格式直接标识的召回优化。**Govern**：责任人、评审与变更记录，并跟踪口径版本——NIST AI RMF 1.0 正在修订中，生成式 AI 的风险条目另有 NIST AI 600-1（GenAI Profile）作为补充，引用时要写明版本。一句话：没有度量就只有声明，没有治理就只有一次性整改。

## 数值与代码验证

下面的比例、样本量、碰撞概率与存储量级都是按本节假设自行复算的结果，不是现成结论。

校验位对误报的抑制：10 万个随机数字串里，16 位数字通过 Luhn 的比例是 0.1004（理论 1/10），18 位数字通过身份证校验（ISO 7064 MOD 11-2）的比例是 0.0913（理论 1/11）。这就是「只靠格式规则时」的误报率——校验位把候选缩到 1/10 或 1/11，但它只对有校验位的类型有效。示例串 `11010519491231002X`（教材示例，非真实身份）通过校验。

k-匿名的两行对比（12 条合成记录，含邮编、生日、性别、诊断）：

| 准标识 | k | 唯一记录占比 |
| --- | --- | --- |
| 5 位邮编 + 完整生日 + 性别 | 1 | 41.7% |
| 3 位邮编 + 出生年 + 性别 | 4 | 0% |

第一行就是「去掉姓名就安全」的真实后果：41.7% 的记录在准标识上唯一，配上外部数据即可直接定位；第二行说明泛化有效，但也说明泛化要付出粒度代价。

检测器指标放大到生产规模（假设日请求 20 万、每请求 2.5 个真实实体、标注集上 TP/FP/FN = 4600/300/400）：

| 项 | 值 |
| --- | --- |
| precision / recall | 0.939 / 0.920 |
| 50 万真实实体/天下的漏检与误脱敏 | 40,000 / 30,000 |

92% 的召回单独看很漂亮，放到规模上就是每天 4 万个未处理实体——这就是抽样审计必须存在的原因。抽检样本量按 $n \approx z^2 p (1-p) / \delta^2$（$z = 1.96$）估算：

| 基线漏检率 | 允许半宽 | 需要可判样本 |
| --- | --- | --- |
| 0.5% | ±0.25pp | 3,058 |
| 0.5% | ±0.10pp | 19,112 |
| 5% | ±0.50pp | 7,299 |

把 0.5% 的漏检率分辨到 ±0.25pp 需要约 3 千条人工判定样本，按每位标注员每天 200 条算是 15 人天——这就是「抽检频率」与「置信度」之间的真实预算约束。

假名化标识的截断长度按生日界估算，$b$ 为截断位数、$N$ 为不同取值个数：

$$p \approx 1 - e^{-N(N-1)/2^{b+1}}$$

$N = 10^7$ 时，截断 48 bit（12 位十六进制）的碰撞概率是 16.3%，截断 64 bit（16 位十六进制）是 2.7e-6，128 bit 则约 1e-25 可忽略。同时用全局盐算哈希，知道原文的人可以重算验证（字典攻击）；改成每租户密钥后，同一邮箱在 tenant-a 与 tenant-b 下得到不同值，跨租户无法关联。留存体积按 20 万请求/天算：原文 payload 12 KB/请求是 2.29 GB/天（30 天 68.7 GB），只留脱敏结构化的 1.2 KB/请求是 0.23 GB/天（30 天 6.9 GB）。

一个把识别、分层策略与可审计落库串起来的最小实现：

```python
"""PII 处理链路的最小实现：多信号识别 -> 分层处理 -> 可审计的假名化。"""
import hashlib, hmac, re
from collections import namedtuple

Entity = namedtuple("Entity", "kind start end score layer")
LUHN_RE = re.compile(r"\b(?:\d[ -]?){13,19}\b")
CN_ID_RE = re.compile(r"\b\d{17}[\dXx]\b")
EMAIL_RE = re.compile(r"\b[\w.+-]+@[\w-]+\.[a-zA-Z]{2,}\b")
PHONE_RE = re.compile(r"\b1[3-9]\d{9}\b")
DOCTOR_RE = re.compile(r"(?:主治医生|接诊医生)[是为：:\s]*([\u4e00-\u9fa5]{2,4})")
ID_W = [7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2]
ID_CHECK = "10X98765432"


def luhn_ok(num):
    total, alt = 0, False
    for ch in reversed(re.sub(r"\D", "", num)):
        d = int(ch)
        if alt:
            d = d * 2 - 9 if d * 2 > 9 else d * 2
        total += d
        alt = not alt
    return total % 10 == 0


def cn_id_ok(s):
    if len(s) != 18 or not s[:17].isdigit():
        return False
    return ID_CHECK[sum(int(c) * w for c, w in zip(s[:17], ID_W)) % 11] == s[17].upper()


def detect(text):
    """正则 + 校验位给高置信分，上下文规则补一层；低分实体保留但不处理。"""
    found = []
    for m in EMAIL_RE.finditer(text):
        found.append(Entity("EMAIL", m.start(), m.end(), 0.95, "direct"))
    for m in PHONE_RE.finditer(text):
        found.append(Entity("PHONE", m.start(), m.end(), 0.90, "direct"))
    for m in LUHN_RE.finditer(text):
        found.append(Entity("CREDIT_CARD", m.start(), m.end(), 0.99 if luhn_ok(m.group()) else 0.30, "direct"))
    for m in CN_ID_RE.finditer(text):
        found.append(Entity("CN_ID", m.start(), m.end(), 0.99 if cn_id_ok(m.group()) else 0.30, "direct"))
    for m in DOCTOR_RE.finditer(text):
        found.append(Entity("PERSON", m.start(1), m.end(1), 0.70, "direct"))
    found.sort(key=lambda e: (e.start, -e.score))
    kept = []
    for e in found:                          # 处理重叠：保留分高者
        if kept and e.start < kept[-1].end:
            if e.score <= kept[-1].score:
                continue
            kept.pop()
        kept.append(e)
    return kept


def pseudonym(tenant_key, value, bits=64):
    """每租户独立密钥 + 截断：可关联、不可跨租户关联、不可反查。"""
    digest = hmac.new(tenant_key, value.encode(), hashlib.sha256).hexdigest()
    return "p_" + digest[: bits // 4]


def process(text, tenant_key, min_score=0.6):
    entities = detect(text)
    kept = [e for e in entities if e.score >= min_score]
    out, cursor = [], 0
    for e in kept:
        out += [text[cursor:e.start], "[%s]" % e.kind]     # 保留文本结构，替换标识
        cursor = e.end
    out.append(text[cursor:])
    record = {
        "redactions": {k: sum(1 for e in kept if e.kind == k) for k in sorted({e.kind for e in kept})},
        "input_len": len(text),
        "input_hmac": pseudonym(tenant_key, text, 128),
        "low_confidence": sum(1 for e in entities if e.score < min_score),
    }
    return "".join(out), record


if __name__ == "__main__":
    notes = [
        "患者张三，电话 13800138000，邮箱 zhang@example.com，卡号 4539 1488 0343 6467。",
        "我的主治医生是李伟，患者身份证 11010519491231002X，随访日期 2026-03-02。",
        "订单号 1234567890123456 只是流水号，不是银行卡。",
    ]
    for n in notes:
        redacted, record = process(n, b"tenant-a-key")
        print(redacted)
        print(record)
```

三段输入的实际输出（第一段是 `患者张三，电话 [PHONE]，邮箱 [EMAIL]，卡号 [CREDIT_CARD]。`，第二段是 `我的主治医生是[PERSON]，患者身份证 [CN_ID]，随访日期 2026-03-02。`，第三段无替换且 `low_confidence=1`）暴露三个问题：第一段姓名「张三」未被替换，因为没有 NER 模型就会漏；第二段身份证被替换但随访日期留在正文里，准标识未处理，而 Safe Harbor 要求移除与个人相关的日期元素；第三段 16 位流水号未通过 Luhn，被降级为低置信而不脱敏，说明校验位抑制了误报。每条日志记录里只有类型、计数、长度与假名，没有原文。

## 常见追问

- **追问**：为什么「正则去 PII」不够？
  - 要点：正则只覆盖有固定格式的直接标识，准标识（生日、邮编、职位）与可推断信息（「我的主治医生是 X」）没有格式特征；上面 41.7% 的唯一记录说明去姓名的表仍可定位到人。另外正则的误报会拖垮可用性——没有校验位时 16 位流水号与卡号无法区分，所以要用正则 + 校验位 + NER + 上下文规则组合，并用抽检与回归持续度量。
- **追问**：医疗、法律这类必须保留 PII 的场景怎么办？
  - 要点：把「不泄露」换成「最小暴露 + 全审计」。部署上选私有化或专属实例并把数据驻留写进合同；访问上做角色分离、审批与查询审计，且审计日志本身不可篡改；数据上分层脱敏——标识移除、日期改成相对偏移以保留时间轴、机构名泛化；训练与评测用去标识或合成数据；保留期与删除演练照做。必须保留 PHI 时，BAA / DPA 与访问控制是主要控制手段，而不是靠脱敏。
- **追问**：怎么测模型有没有记住训练数据？
  - 要点：三类测试。canary 插入——训练前往语料注入唯一随机串，训练后用前缀补全与困惑度排序把候选捞出来比对；成员推断——比较训练集内外样本在损失/困惑度上的可分性，用 AUC 量化；前缀补全抽取——用真实格式的前缀（邮箱、电话、证件号模板）批量生成，再对输出做精确匹配与人工确认。指标要同时报抽取率与置信区间，样本量不足时结论不可用；同一批 canary 在每个模型版本上重跑，形成回归。
- **追问**：用户要求删除数据，但那条数据已经在微调模型里了，怎么办？
  - 要点：先区分「能不能删」与「要不要重训」。向量索引、缓存、日志、备份、评测集这些副本必须删，且要能证明（演练 + 抽样验证）；权重内的删除只有重训可靠。工程缓解是把训练数据分片、每片独立训练再聚合，删除只重训受影响分片；近似遗忘（unlearning）目前不能作为合规承诺，只能作为实验性手段。真正的答案是准入：训练集里不放 PII，就不用面对这个问题。
- **追问**：多租户系统里怎么保证缓存不串租户？
  - 要点：把租户标识做成缓存键的一部分并参与前缀匹配，或按租户分实例/分区；对缓存读写做越权测试与命中率监控（某租户命中率异常升高是可疑信号）；逐出与 TTL 按租户配置；请求路径上任何共享状态——前缀缓存、嵌入缓存、结果缓存、向量索引——都要过一遍同样的检查（[[inference-serving-05]]）。

## 公司变体

- **Abridge**：公司产品是临床对话到结构化病历的生成，题目语境因此从泛化的 PII 收紧为 PHI，落在 HIPAA 与 BAA 的框架下——偏工程实现与合规落地，而非隐私理论的推导。准备方向是把通用答案映射到临床场景的具体约束：Safe Harbor 的 18 类标识符与「不得实际知道仍可识别」条款；保留临床可用性的去标识（药名、剂量、时间轴必须留，标识必须去，绝对日期换成相对偏移）——注意保留日期元素后就不能再按 Safe Harbor 认定，要改走 Expert Determination 并记录方法与结论，或走 limited data set（§164.514(e)：保留日期与邮编、排除 16 类直接标识、签 data use agreement，仅限研究、公共卫生与医疗运营）；供应商条款与部署形态（能否私有化、是否用于训练、留存期）；访问控制与审计日志自身要防篡改；保留期与删除演练。常见追问会落在「去标识之后病历还能不能用于模型训练」和「必须保留 PHI 时如何控制暴露面」。公开可核实的面试流程信息有限，这里只给技术侧重，不对轮次与流程做断言。
