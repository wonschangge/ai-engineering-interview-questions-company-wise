# 安全、安保与负责任 AI

这是「跨公司高频问题」里的第七个专题，共 10 道题，**已全部上线**。它回答的是**系统会不会被攻破、会不会伤人**：
注入怎么防、护栏放哪一层、数据怎么外出、价值怎么对齐、以及上线前怎么证明它足够安全。

## 这个专题的知识地图

按「攻击面 → 防线 → 治理」组织，10 道题分成三组：

| 组 | 主题 | 题目 |
| --- | --- | --- |
| A. 攻击面 | 注入、越狱与对抗样本、OWASP 威胁清单、数据外泄 | 01、03、02、06 |
| B. 防线 | guardrails、对齐方法（CAI/RLAIF）、PII 治理、可解释性 | 04、05、07、08 |
| C. 治理与验证 | 群体差异审计、红队与发布门禁 | 09、10 |

**建议顺序**：`01 → 03 → 02` 是攻击面主线（注入 → 越狱 → 系统化威胁清单）；
`04 → 06 → 07` 是工程防线（护栏 → 外泄控制 → 数据治理）；`05 → 08` 是「让模型本身更可靠」的两条路线（训练侧对齐 → 内部机制）；
`09 → 10` 是上线前的验证与治理。

与其它专题的接口：注入的后果落在 **RAG 的语料**与 **Agent 的工具调用**上（链到 [权限感知检索](../RAG%20与检索/08-设计权限感知的%20retrieval.md)、
[可逆与可审计](../Agent%20与工具调用/10-在生产系统中如何让%20agent%20的操作可逆或至少可审计.md)）；
红队与护栏的通过条件落在 **评估的门禁红线集**里（链到 [回归门禁](../评估与可观测性/04-设计一道回归门禁来决定%20prompt%20或模型改动能否上线.md)）。

## 谁在问这个专题

按 `README.md` 的统计，本专题的题目出现在 6 家公司的面试中：**Anthropic（2 题）** 问注入分层防御与 Constitutional AI；
**OpenAI（2 题）** 问注入与「工具 agent 经恶意网页外泄数据」；**Microsoft（2 题）** 问 OWASP 与群体差异审计；
**Sierra（2 题）** 关注面向消费者的护栏设计；**Character.AI** 问 guardrails；**Abridge** 问 PII 处理（医疗场景合规要求最高）。

能不看资料回答下面这些问题，说明这个专题过关了：

- 直接注入与间接注入的差别是什么？为什么间接注入更难防？
- 为什么说「让模型自己分辨数据与指令」不是边界，只是提高攻击成本？
- 注入的五层防御分别是什么？哪一层最有效、为什么？
- 越狱与对抗性 prompt 的攻击对象分别是什么？Jailbroken 归纳的两种失败模式是什么？
- 为什么「能力越强越安全」不成立？
- guardrails 为什么输入与输出两侧都要有？各自拦什么？
- 护栏加进链路后，延迟与误杀率怎么权衡？多语言为什么是坑？
- Constitutional AI 的两个阶段分别在做什么？它与 RLAIF 是什么关系？
- 越狱与 RLAIF 都会引入哪些偏差？怎么防？
- 数据外泄有哪些通道？为什么说这是能力问题而不是提示词问题？
- PII 分几层？为什么纯正则不够？删除请求要覆盖哪些地方？
- superposition 是什么？SAE 想解决什么？机制可解释性的四条用途？
- 审计群体差异时，交叉切片为什么必要？代理标签有什么风险？
- 一份合格的红队方案有哪些交付物？攻击成功率（ASR）要怎么定义才不算自欺？
