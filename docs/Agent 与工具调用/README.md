# Agent 与工具调用

这是「跨公司高频问题」里的第四个专题，共 12 道题，**已全部上线**。它回答的是**怎么让模型真的去做事**：
循环怎么转、工具怎么描述、错误怎么恢复、什么时候该停、出事了能不能回滚、跑久了偏了怎么查。

## 这个专题的知识地图

按「一次 agent 调用的生命周期」排列，12 道题正好覆盖全程：

| 阶段 | 题目 | 关键判断 |
| --- | --- | --- |
| 循环与推理 | 01、08 | ReAct 的推理—行动交错；每步的路由决策（工具 or 自答） |
| 接口层 | 03、04、05 | 结构化输出 vs function calling；MCP 的连接标准化；工具数量与 schema 设计 |
| 运行时 | 02、09 | 错误分类与幂等；终止条件与五层预算 |
| 状态 | 07 | 记忆的分层、写入判据与检索 |
| 治理 | 10、11 | 可逆与可审计；HITL 审批的状态机 |
| 复杂度与可靠性 | 06、12 | 多 agent 的收益与失败模式；长跑漂移的诊断与预防 |

**建议顺序**：`01 → 03 → 05` 是接口主线（循环 → 调用表达 → 工具设计），也是日常写得最多的部分；
`02 → 09 → 12` 是可靠性主线（出错怎么办 → 什么时候停 → 跑久了怎么办）；
`07 → 06` 是状态与复杂度（记忆 → 多 agent）；`10 → 11` 是治理（可逆审计 → 人工审批）；
`04`（MCP）与 `08`（路由）是两条相对独立的加分项。

## 谁在问这个专题

按 `README.md` 的统计，本专题的题目出现在 7 家公司的面试中：**Cognition（4 题）** 覆盖最多——工具错误处理、
工具 schema、多 agent 编排、长跑漂移诊断，这些正是 coding agent 产品的核心难题；
**OpenAI 与 Palantir（各 2 题）** 关注 HITL 审批与操作可审计；**Anthropic（2 题）** 问工具设计与长时间运行的记忆；
**Mistral AI、Apple** 问结构化输出与 function calling 的边界；**Microsoft** 问 MCP。

## 自测清单

能不看资料回答下面这些问题，说明这个专题过关了：

- ReAct 的 Thought/Action/Observation 各自解决什么问题？它在什么任务上不如纯 CoT？
- 工具调用错误有哪几类？哪几类**不该**重试？写操作重试的前提是什么？
- 结构化输出和 function calling 在「谁执行、是否循环、失败怎么处理」上分别是什么？
- MCP 解决了 M×N 里的哪一半问题？它的三个原语和安全边界是什么？
- 工具数量为什么会降低选择准确率？你会用哪三种手段控制暴露给模型的工具数？
- 多 agent 的三个真实收益是什么？MAST 归纳出的失败模式分哪三大类？
- agent 记忆的四类内容分别存什么、存在哪里、什么时候写、怎么取？
- 什么信号说明「该调用工具」？两类路由错误的代价分别是什么？
- 一个 agent 循环要几层保险才能保证终止？pass^k 与 pass@k 的区别是什么？
- 哪些操作必须设计成可逆？不可逆的怎么做审计与补偿？
- HITL 审批请求里必须包含哪些信息，否则审批者只能盲签？
- 每步 95% 正确率的 agent 跑 20 步整体成功率是多少？这个数字对设计意味着什么？
