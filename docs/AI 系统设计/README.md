# AI 系统设计

这是「跨公司高频问题」里的第九个专题，共 10 道题，**已全部上线**。它是整套题解的**压轴**：
前面八个专题给的是单点能力，这一组考的是**把它们组合成一个能上线、能算账、能运维的系统**。

## 这个专题的知识地图

系统设计题没有固定顺序，但可以按「考什么能力」分组，并指向对应的单点专题：

| 组 | 题目 | 依赖的单点专题 |
| --- | --- | --- |
| 检索型系统 | 01、04、06、07 | [RAG 与检索](../RAG%20与检索/README.md)、[多模态](../多模态、语音与声音%20AI/README.md) |
| 动作型系统 | 02、03 | [Agent 与工具调用](../Agent%20与工具调用/README.md) |
| 判定型系统 | 05 | [安全与负责任 AI](../安全、安保与负责任%20AI/README.md)、[评估](../评估与可观测性/README.md) |
| 音频型系统 | 08 | [多模态、语音与声音 AI](../多模态、语音与声音%20AI/README.md) |
| 平台型系统 | 09、10 | [推理、服务与 GPU 性能](../推理、服务与%20GPU%20性能/README.md) |

**建议顺序**：`09 → 10` 是平台底座（先有 gateway 与推理栈，才有上面所有系统）；
`01 → 04 → 07` 是「检索 + 结构化查询」三连（都涉及 schema/索引与召回精度的取舍）；
`02 → 03` 是「会动手的系统」（都依赖动作网关、幂等与审批）；
`05 → 08` 是两条相对独立的链路（审核与会议）；`06` 是唯一的重批处理题，考的是算力与重跑成本。

## 一套通用的答题骨架

系统设计题的评分点往往不在「你知道多少技术」，而在**你有没有把话说全**。这十篇题解都遵循同一骨架，可以直接当作临场清单：

1. **需求澄清与假设**——用户量、数据量、延迟 SLO、预算、权限与合规；把假设写在明面上。
2. **架构与数据流**——画链路，标出每一跳的输入输出与失败模式。
3. **容量与成本算账**——token 数、存储、GPU 数、单请求成本、总账；单位与口径要一致。
4. **失败模式与取舍**——过载、降级、超时、重复操作、数据错乱各怎么办。
5. **安全与权限边界**——过滤发生在哪一层、哪些操作需要审批、审计留什么。
6. **评测与上线路径**——离线指标 + 红线集门禁 + 灰度；先只读、再低风险写、最后高风险。

## 谁在问这个专题

按 `README.md` 的统计，本专题是公司覆盖面最广的一组，出现在 15 家公司的面试中：
**Palantir（3 题）** 最集中（文档智能、Text-to-SQL、gateway）；**OpenAI、Microsoft、Databricks、Meta（各 2 题）** 覆盖企业 RAG、会议助手、Text-to-SQL、内容审核；

**Anthropic**、**Google DeepMind**、**xAI**，以及一类**面向消费者的规模化 ML 公司**（Uber、Netflix、LinkedIn、Airbnb、Pinterest、Spotify）问客服 agent。

## 自测清单

能不看资料回答下面这些问题，说明这个专题过关了：

- 给你一个新系统，你的前三个问题是什么？（需求、规模、SLO）
- 1000 万文档的 RAG，chunk 数与向量内存大致多少？这个数字怎么影响索引选型？
- 权限过滤为什么不能放在 top-k 之后？多租户共享索引怎么保证性能？
- 代码助手为什么不能只靠向量检索？（符号图、诊断信息、编辑历史）
- 一个「能办事」的 agent，你会把哪些操作设为不可自动执行？
- 升级到人工时，哪些信息必须一起移交？
- 商品搜索的验收指标是什么？可变字段为什么要和语义向量分开存？
- 内容审核里分类器与 LLM 各自负责什么？为什么不能只用 LLM？
- 「1000 万文档」等于多少页、多少 GPU 小时？模型升级后怎么重跑？
- 数千张表的 Text-to-SQL，第一步做什么？（schema linking，不是生成 SQL）
- 生成出来的 SQL 在执行前要过哪几道闸门？
- 会议助手的行动项为什么要带时间戳？会中与会后能否共用一条链路？
- LLM gateway 的五个平面是什么？语义缓存的误命中怎么防？
- 3 亿 DAU 的聊天服务，峰值 QPS 与 GPU 数怎么估？为什么不能按峰值配置？
