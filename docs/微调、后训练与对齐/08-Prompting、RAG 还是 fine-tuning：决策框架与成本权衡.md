## 一句话答案

> 先分类再选手段：**缺知识**（事实、专有语料、时效内容、需要引用与权限）走 RAG 或长上下文；**缺行为**（格式、风格、语气、拒答边界、术语用法）走提示或微调；**缺的是模型根本没有的能力**（新语言、新领域、新任务形态）才必须微调。执行顺序是先提示建立评测基线，再 RAG 补知识，最后微调固化行为——前两者当天可迭代，微调是一次性固化，试错成本高一个量级。
> 成本上把一次性投入摊到请求量：微调值得做当且仅当 $C_{\text{一次性}} < \Delta c \cdot N$。算例是 400 美元 ÷ 0.0045 美元/请求 ≈ 8.9 万次请求回本，10 万次/月的负载约 27 天。latency 上微调去掉长示例后 TTFT 最低，纯提示随示例长度线性上升，RAG 再叠一层检索与重排且抖动最大。

## 面试官在考什么

- 有没有**给问题分类**的能力。先判断缺知识还是缺行为，再谈技术选型；上来就说"我们上 RAG"或"我们做微调"的，通常没在生产里踩过坑。
- 知不知道三者的**成本结构完全不同**。提示是纯经常性成本（示例进上下文就是持续付费），RAG 是"基础设施 + 每次多出的上下文 token + 检索链路"，微调是"一次性训练 + 近似为零的每次成本 + 版本运维"。
- 能不能把**盈亏平衡算出来**：$N^* = C_{\text{一次性}} / \Delta c$。说不出回本请求量的成本讨论都是形容词。
- 有没有把 **latency 拆开**：TTFT、TPOT、检索与重排的串行耗时、p99 抖动，而不是笼统的"更快/更慢"。
- 是否知道每种手段的**硬边界**：权重里没有可回指的引用，没有按用户裁剪权限的机制，也没有"今天改明天生效"的时效（见 [[rag-08]]、[[rag-12]]）。

常见错误答案：

- 用**数据量**当判据："数据多就微调、数据少就 RAG"。真正的判据是缺知识还是缺行为，以及是否需要引用、权限与时效。1000 条精选数据就能改行为（LIMA 的结论），而再多的数据也教不会模型"按调用者的 ACL 过滤文档"。
- **只比单价**："微调后 prompt 短了所以更便宜"。请求量只有几千次时，一次性训练与评测成本永远收不回来——必须算回本请求量。

## 原理与推导

### 1. 四个问题定骨架

| 顺序 | 问题 | 判断依据 | 结论 |
| --- | --- | --- | --- |
| ① | 缺知识还是缺行为？ | 把相关内容原样放进 prompt，模型能答对吗？能答对 → 缺的是知识；格式、语气、术语、拒答边界不对 → 缺的是行为 | 知识 → 长上下文/RAG；行为 → 提示/微调 |
| ② | 知识是否频繁变化、是否需要权限与引用？ | 每周都在变、要给出处、要按用户权限裁剪 | 必须 RAG（见 [[rag-08]]、[[rag-12]]） |
| ③ | 是否是分布外的新能力？ | 新语言、新领域术语、新任务形态（固定 schema 抽取、私有 DSL） | 数据充足 → 微调甚至继续预训练 |
| ④ | 能否先用提示 + 少样本解决？ | 加 3–8 个示例后在同一评测集上是否达标 | 能就先提示：边际成本最低、迭代最快 |

①②③ 决定**手段归属**，④ 决定**执行顺序**。①里的"能不能答对"必须做实验，不能靠感觉——这就是先建评测基线的理由。

### 2. 为什么知识不该烧进权重

三条硬约束，每一条都能写成成本或能力上的损失：

- **更新**：权重是快照。知识每周变一次就要每周重训，按第 4 节的算例是 1600 美元/月，而检索方案的新鲜度是分钟级。
- **归因**：权重里没有可回指的 span，答错了无法定位到出处（见 [[rag-12]]）。
- **权限**：权限必须在**检索时**按调用者身份过滤，权重里不存在"按用户裁剪"的机制（见 [[rag-08]]）。
- **附带风险**：用少量样本教事实，模型学到的是"编造同样句式的事实"，同时会遗忘原有能力（见 [[finetuning-07]]）。

LIMA 的实证恰好划出了这条边界：65B 模型只用 1000 条精选 prompt/response 做监督微调、不做 RL 与偏好建模，行为层面就能达标——受控人类研究中，它的回答有 43% 与 GPT-4 相当或更优，换成与 Bard、DaVinci003 对比则分别是 58% 与 65%（三个数字都是 LIMA 被评"相当或更优"的比例，不是 Bard、DaVinci003 相对 GPT-4 的得分）；而论文的结论是"几乎全部知识都在预训练阶段获得，只需有限的指令微调数据教模型产出高质量输出"。微调擅长的是**输出形式**，把新知识塞进权重是逆着这条结论走。

### 3. 三者的成本结构

$$C_{\text{总}}(N) = C_{\text{一次性}} + N \cdot c_{\text{请求}} + C_{\text{运维}}(N)$$

| 手段 | 一次性成本 | 每次请求成本 | 经常性/运维成本 | 迭代周期 |
| --- | --- | --- | --- | --- |
| 提示 | 提示工程人力、评测集建设 | 输入 token 随示例增长：$(S_{\text{sys}} + S_{\text{示例}} + S_{\text{query}}) \cdot p_{\text{in}}$ | 长前缀占 KV 显存与 prefill 算力 | 小时 |
| RAG | 全量语料 embedding、建索引、权限映射 | 查询 embedding + ANN 检索 + 重排算力 + 检索到的上下文 token | 索引新鲜度、权限同步、重排服务常驻 | 天 |
| 微调 | 数据（标注或合成）+ 训练 GPU 小时 + 评测调参 | LoRA 合并后 ≈ 0（不合并时多一次小矩阵乘） | adapter 版本管理、回归门禁、再训练流水线 | 周 |

一句话概括差异：**提示把成本放在每次请求上，RAG 把成本放在基础设施与每次请求上，微调把成本提前一次性付掉。** 所以请求量是微调唯一的朋友，而"知识频繁变化"是微调的天敌。

### 4. 盈亏平衡：微调什么时候划算

$$N^* = \frac{C_{\text{训练}} + C_{\text{数据}} + C_{\text{评测}}}{\Delta c}, \qquad \Delta c = \Delta S_{\text{输入}} \cdot p_{\text{in}} + \text{（延迟与质量收益的折现）}$$

先只算 token 侧，取保守口径：训练 200 GPU·h × 2 美元/GPU·h = 400 美元；微调后省掉 1500 token 的少样本与上下文，按 3 美元/1M token 计

$$\Delta c = 1500 \times 3 \times 10^{-6} = 0.0045 \ \text{美元/请求}, \qquad N^* = \frac{400}{0.0045} \approx 8.9 \times 10^4$$

10 万次/月的负载约 27 天回本，之后每月省 450 美元。三条必须主动说明的旁注：

- **口径**：只算输入 token。省下的示例与检索上下文都在输入侧，输出单价不影响这个差值，但检索省下的那部分要单独算（见下一段）。
- **数据成本会主导**：若额外加 1000 条人工标注（按 5 美元/条），一次性成本升到 5400 美元，$N^*$ 涨到 120 万次请求。Self-Instruct 这类自举合成数据的价值就在于把 $C_{\text{数据}}$ 压到接近零。
- **别高估节省**：若微调后仍需保留 1000 token 示例，$\Delta c$ 降到 0.003 美元，$N^*$ 升到 13.3 万次。

再算"把知识塞进权重"的账：省下 2000 token 检索上下文 = 0.006 美元/请求，但每周重训一次 = 1600 美元/月，需要 $N^*_{\text{知识入权重}} = (4 \times 400) / (2000 \times 3 \times 10^{-6}) = 2.67 \times 10^5$ 次/月才持平，而且仍然拿不到引用与权限。这是第 2 节三条硬约束的成本表达：**结论不取决于单价，取决于"要不要引用与权限"这个结构性问题。**

### 5. latency 账

$$\text{TTFT} = \underbrace{t_{\text{prefill}}(S_{\text{sys}} + S_{\text{ctx}} + S_{\text{query}})}_{\text{随提示长度线性}} + \underbrace{t_{\text{检索}} + t_{\text{重排}}}_{\text{仅 RAG}} + t_{\text{排队}}$$

- **提示**：少样本示例全部进 prefill，$\Delta \text{TTFT} = \Delta S / v_{\text{prefill}}$。1500 token 在 1 万 token/s 的 prefill 吞吐下就是 150 ms；这段 KV 还常驻显存、挤压并发（见 [[inference-serving-09]]）。
- **RAG**：新增 query embedding + ANN 检索 + rerank。embedding 与 ANN 通常是个位数毫秒，rerank 是最大头：100 个候选 × 512 token 的交叉编码器评分，按 1M token/s 吞吐约 51 ms，且随候选数与文档长度线性增长。重排若在关键路径上，它的**抖动**（p99）比均值更值得关注。
- **微调**：合并权重后每次请求零额外延迟，而且因为不再需要长示例，它同时把 TTFT 压到最低。这是微调在延迟口径上比省 token 更确定的收益。

延迟排序：微调（去掉示例）< 纯提示（短）< 纯提示（长少样本）< RAG（重排在关键路径上）。RAG 的位置可以用并行化与缓存改写，但"检索链路有方差"这一点改不掉。

### 6. 组合与顺序

1. **建基线**：固定评测集与指标（任务成功率、格式合法率、拒答正确率、引用正确率），见 [[rag-04]]。没有基线就换手段，等于不可归因的实验。
2. **先提示**：加少样本、改 system prompt、加约束与结构化输出。当天可迭代，几乎没有一次性成本。
3. **再 RAG**：知识类不足、需要引用与权限时上。到这里再考虑要不要更复杂的检索编排（见 [[rag-06]]）。
4. **最后微调**：行为、格式、领域术语、拒答边界仍不达标，或需要蒸馏出小模型承接流量时才做。
5. **常见组合**：RAG 提供事实 + 微调提供行为（引用格式、拒答策略、术语用法）。两者作用在不同维度，不互相替代。
6. **蒸馏降本**：用强模型生成数据、微调一个小模型承接高频流量，收益与路由公式 $G_{\text{route}} = 1/(\alpha/r + (1-\alpha))$ 同源（$\alpha$ 是路由到小模型的比例、$r$ 是大模型与小模型的单请求成本比，见 [[finetuning-12]]、[[inference-serving-12]]）。

顺序背后的原理：提示与 RAG 的作用点在**推理时**，改完立刻生效、可回滚、可以 A/B；微调的作用点在**权重**，一次训练固化一个版本，回滚要换权重、需求变了要重训。所以先用可迭代的手段把问题定住，再用微调固化成果；顺序反过来，微调会一次次追着变化的需求重训。

### 7. 反面清单

| 反模式 | 为什么错 | 替代 |
| --- | --- | --- |
| 数据不足就微调 | 几百条脏数据学到的是噪声与格式碎片 | 先提示/RAG，同时攒数据 |
| 用微调记事实 | 会幻觉、难更新、无引用、无法按权限裁剪 | RAG（见 [[rag-08]]） |
| 用 RAG 教格式 | 检索器对输出格式无能为力，只引入无关上下文 | 提示/微调 |
| 只比单价 | 忽略回本请求量与 p99 | 算 $N^*$ 与 TTFT 分位 |
| 没有评测基线就换手段 | 无法判断是手段有效还是数据变了 | 固定评测集（见 [[rag-04]]） |
| 把微调当一次性项目 | 数据漂移、回归、版本管理长期存在 | 训练流水线与门禁 |

**蒸馏的温度与 $T^2$ 因子**（通用背景，不来自作业单来源）。标准 KD 损失为

$$\mathcal{L} = (1-\lambda)\,\mathrm{CE}(y, p_1) + \lambda\, T^2 \, \mathrm{KL}\!\left(p_T(v) \,\|\, p_T(z)\right), \qquad p_T(x)_i = \frac{e^{x_i/T}}{\sum_j e^{x_j/T}}$$

对 logits $z$ 求导是精确的 $\partial \mathrm{KL} / \partial z_i = (q_i - p_i)/T$；在零均值 logits 与较大的 $T$ 下 $q_i - p_i \approx (z_i - v_i)/(KT)$，于是梯度 $\approx (z_i - v_i)/(K T^2)$，整体按 $1/T^2$ 缩小。乘 $T^2$ 就是让软目标项的梯度回到与硬标签项同量级——在"用强模型数据微调小模型"这条降本路线上，这是必须先调对的超参（见 [[finetuning-12]]）。

```python
import math

def softmax_T(z, T):
    m = max(z)
    e = [math.exp((x - m) / T) for x in z]
    s = sum(e)
    return [x / s for x in e]

def kl_grad(z, v, T):                      # 精确形式 (q - p) / T
    p, q = softmax_T(v, T), softmax_T(z, T)
    return [(q[i] - p[i]) / T for i in range(len(z))]

v, z = [2.0, 0.0, -2.0], [1.5, 0.2, -1.7]  # 两者零均值，Hinton 推导的前提
for T in (1, 4, 10, 40, 80):
    g = kl_grad(z, v, T)
    n = math.sqrt(sum(x * x for x in g))
    print(T, round(n, 8), round(n * T * T, 4))
# 1 0.13953462 0.1395 | 4 0.01412506 0.226 | 10 0.00217838 0.2178
# 40 0.00013066 0.209 | 80 3.239e-05 0.2073   -> |g| * T^2 稳定在 0.21 附近
```

与来源对照：LIMA 与 Self-Instruct 的数字直接取自两篇论文摘要（1000 条；43%/58%/65% 是 LIMA 相对 GPT-4/Bard/DaVinci003 被评"相当或更优"的比例；33 个百分点绝对提升、落后 InstructGPT-001 五个百分点），与摘要口径一致。作业单指定的视频来源抓取时只返回播放器外壳、没有可核对的文字，成文未引用其任何数字。成本模型、盈亏平衡、LoRA 参数量、Adam 显存账、6ND 训练算力与 $T^2$ 的数值验证都是按本节假设自行计算的，源文没有提供这些内容。

## 常见追问

- **追问**：请求量很小（比如每月 2000 次）怎么选？
  - 要点：直接排除微调。400 美元的一次性成本要 8.9 万次请求才回本，2000 次/月的负载要 3.7 年。此时提示加少量检索在质量、迭代速度和成本上都占优。微调只在"请求量大"或"行为必须绝对稳定"（合规拒答、固定 schema）时才值得，后者是**质量约束**而不是成本问题，要单独论证。
- **追问**：微调真能省掉 RAG 的检索 token 吗？
  - 要点：省的是"把知识塞进上下文"的输入 token，代价是知识冻结、没有引用、没有权限。企业场景里引用与权限常常与准确率同级重要，所以省下的 token 是账面收益，换走的是产品能力。稳的省法是"微调固化行为 + RAG 提供事实"。
- **追问**：RAG 的延迟怎么压？
  - 要点：把检索移出关键路径（与首 token 生成并行、预取）、缓存 query 与 embedding、裁掉 rerank 的低边际候选（50 个之后的增益通常很小而成本线性增长）、用小模型做重排、给检索设超时并允许降级为纯提示。延迟预算是先定的，不是事后发现的。
- **追问**：怎么证明微调这一步真的有用？
  - 要点：同一评测集、同一解码参数下做 A/B；指标拆成任务成功率、格式合法率、拒答正确率、引用正确率；同时看原能力是否回归（见 [[finetuning-07]]）；线上保留回退到提示版本的开关。训练 loss 不是证据。
- **追问**：什么时候必须用 RAG 而不能靠长上下文？
  - 要点：语料远超窗口、需要按用户权限过滤、需要引用到 span、知识每天变、或者长上下文太贵（每次请求都为全量语料付费）。长上下文适合"文档少、一次性、低并发"的场景。
- **追问**：蒸馏在决策框架里排第几？
  - 要点：蒸馏是**降本手段**而不是质量手段：用强模型生成数据或 logits 微调一个小模型，把高频简单的流量交出去，收益与路由公式同源（见 [[finetuning-12]]、[[inference-serving-12]]）。它建立在"行为已经定清楚"之后，顺序上排最后。

## 公司变体

以下按各家公开文档与产品形态判断侧重方向，不涉及具体面试流程。

- **OpenAI**：平台与 API 提供方视角，偏工程与产品决策。公开文档的口径是先用提示工程、少样本与评测把 baseline 打好，再判断是否需要微调；追问会落在成本口径（微调与推理定价、Batch API、蒸馏）以及"微调之后怎么评测与回滚"。
- **Mistral AI**：模型与微调 API 视角，偏工程实现与成本。小模型加微调 vs 大模型加提示、LoRA 微调的显存与吞吐、以及用微调把大模型能力压到小模型上做推理降本。
- **Cohere**：企业检索出身，偏"检索优先"的架构。会强调引用与可追溯、企业数据的权限与新鲜度，先把 RAG 做扎实，微调用在行为与领域语言上。
- **Microsoft**：平台与多租户视角，偏工程与治理。数据驻留与合规、按租户核算成本、先用平台的检索与索引服务（含权限同步）再考虑微调，重视门禁与评测。
- **Databricks**：数据平台视角，偏"数据在哪、质量如何、能否治理"。强调自有数据是微调的护城河、用合成数据与实验跟踪流水线支撑决策，成本按集群 GPU 小时摊给你看。
- **Glean**：企业搜索产品，天然偏 RAG。连接器、权限、引用、新鲜度是企业问答的硬需求；微调主要用于查询理解、排序与企业语气这类**行为**层，不用来记事实。
