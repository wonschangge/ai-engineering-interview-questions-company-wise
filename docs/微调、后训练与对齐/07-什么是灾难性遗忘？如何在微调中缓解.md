## 一句话答案

> 灾难性遗忘是模型在新数据上继续训练时，参数更新把原本支撑旧能力的表示覆盖掉，导致旧任务指标显著下降的现象。根因不是「记不住」，而是训练目标里只有新任务损失、没有任何约束旧行为的项，新旧梯度方向一冲突，参数就朝牺牲旧能力的方向走。缓解手段分四层：数据层回放通用数据、参数层用 PEFT/更小学习率、目标层加 KL 或蒸馏约束、流程层做持续学习与能力回归测试；实际工程里是「回放打底 + 回归集定约束强度」，而不是一味加正则。

## 面试官在考什么

- 能否区分**现象、机制、度量**三件事：知道指标怎么量（固定评测集与解码参数的前后对比），而不是只复述「模型变笨了」。
- 能否把线上常见做法（混入通用指令数据、LoRA、低学习率、少 epoch）对应到机制上，而不是背方法名清单。
- 是否理解权衡：任何抗遗忘手段都在**稳定性（stability）与可塑性（plasticity）**之间做交换，回放会拖慢新任务拟合，PEFT 可能压低新任务上限。
- 是否知道灾难性遗忘与「过拟合」「alignment tax」不是同一件事，混为一谈说明概念没打通。
- 有没有工程闭环意识：微调前后跑同一套通用能力回归集，用回归分数与目标任务指标共同决定约束强度。

常见错误答案：

- 「多训几个 epoch 让模型适应就好了」——epoch 越多，旧能力被覆盖得越彻底，方向反了。
- 「用 LoRA 就不会遗忘」——LoRA 冻结底座，遗忘被大幅削弱，但 adapter 仍会改变前向行为，低秩容量写满时同样出现能力回退。

## 原理与推导

### 1. 优化视角：目标函数里没有旧任务

设旧任务损失 $L_{\text{old}}(\theta)$、新任务损失 $L_{\text{new}}(\theta)$，微调只优化后者：

$$\theta_{t+1} = \theta_t - \eta \nabla_\theta L_{\text{new}}(\theta_t)$$

旧任务损失的一阶变化为

$$\Delta L_{\text{old}} \approx -\eta \left\langle \nabla L_{\text{old}}, \nabla L_{\text{new}} \right\rangle$$

当两个梯度内积为负（方向冲突）时 $\Delta L_{\text{old}} > 0$，即优化新任务的一步必然抬高旧任务损失。这是**纯几何结论**：只要参数容量被共享、任务梯度冲突，单目标微调就会遗忘。遗忘速度由三件事共同决定：冲突程度 $\cos$ 角、学习率 $\eta$、以及旧能力对该参数的依赖度。

缓解思路也就直接从这条式子读出来：把 $L_{\text{old}}$ 加回目标（回放）、限制 $\eta$ 与步数、按依赖度保护参数（正则/参数隔离）、或者让两者共享的参数变少（PEFT）。

### 2. 表示视角：是特征漂移，不只是记忆丢失

参数是一份共享表示，微调会同时改变特征提取器与下游映射。即使旧任务**输出**看起来还勉强对，中间表示也已经整体平移旋转——用旧表示上训练好的线性探针去读新表示会失效。所以遗忘包含两层：能力真的被覆盖，以及能力还在但「接口」变了。这两层的区别有工程意义：后一层通过少量校准数据（几十到几百条）重新对齐映射就能恢复，前一层只能靠回放或重训补回。

### 3. 与相邻概念的区别

- **过拟合**：训练集外泛化变差，表现是同一分布上的测试集指标下降；灾难性遗忘是**换了分布**之后旧分布指标下降，训练损失本身可能很低。
- **能力回退 / alignment tax**：对齐或偏好优化（RLHF、DPO）之后通用能力（数学、代码、指令遵循）整体小幅下滑。它与灾难性遗忘共享机制（优化目标偏了），但触发条件是偏好数据分布窄、KL 约束不足，量级通常是几个点，而不是领域微调那种断崖。
- **知识编辑失败**：只改事实、不改能力的定向编辑，忘记的是具体事实而非分布能力。

### 4. 实证口径（1B–7B，持续指令微调）

Luo 等人在 5 个彼此不相似的指令任务上（文本简化 → 共情对话 → 提问生成 → 解释生成 → 带约束标题生成）做**持续指令微调**：每个任务 10 万条样本、3 个 epoch、学习率 2e-5、8×A100 40G（1B 档为省资源只用 4 卡）、最大长度 512。评估从领域知识（MMLU 5-shot）、推理（BoolQ / PIQA / Winogrande / Hellaswag / MathQA / Mutual，zero-shot）、阅读理解（RACE middle & high）三个维度量。

论文给出的结论有四条，引用时要注意适用范围：

1. **遗忘普遍存在**：1b–7b 区间所有被测模型都观察到灾难性遗忘。
2. **该区间内模型越大遗忘越严重**，作者推测与大模型初始性能更高、因此在新任务上拟合时跌幅绝对值更大有关。
3. **架构有影响**：在 3b 档，decoder-only 的 BLOOMZ 比参数档接近的 encoder-decoder mT0 遗忘更少（论文 FG 均值 17.76% vs 21.77%），1b 档两者接近（11.44% vs 11.46%）；论文据此认为 decoder-only 更利于在持续微调中保留知识。
4. **通用指令微调能缓解后续微调中的遗忘**：LLAMA-7b 与 ALPACA-7b 初始分数接近，ALPACA 的平均 FG 是 12.00%，远低于 LLAMA 的 32.54%；BLOOM-7.1b 与 BLOOMZ-7.1b 这一对方向相反（10.74% vs 19.58%），论文把它归因于 BLOOMZ 的初始分更高。更直接的证据是混合训练实验：在持续任务数据里混入 1 万条通用指令数据后，LLAMA-7b 的 MMLU-human 从初始 34.72% 掉到只训指令数据的 26.8%，混合训练回到 30%。

这些都是 **1B–7B** 范围内的实验结论，不能外推到 100B 级模型；「越大越忘」未必在更大规模上成立，规模、数据量、学习率之间是耦合的。

### 5. 缓解手段的分层清单（机制与代价）

按「改数据 / 改参数 / 改目标 / 改流程」四层给，每层都能对回第 1 小节那条几何关系：

| 层 | 手段 | 机制 | 代价 |
| --- | --- | --- | --- |
| 数据 | 回放/混入通用指令数据（常见 5%–10%，论文的混合实验约 10%）、多任务联合训练、混入与预训练分布接近的语料、先去重再调配比 | 把旧任务的损失项加回目标，让新旧梯度不再单边冲突 | 旧数据每步都要过一遍前向反向，新任务拟合变慢；旧数据质量差会把噪声带回来 |
| 参数 | LoRA、prefix tuning 等 PEFT（[[finetuning-06]]）、更小的学习率、更少的 epoch、只微调上层或部分模块 | 冻结底座就是参数隔离，旧能力所在的子空间不被更新；小 $\eta$ 与少步数直接压小 $\Delta L_{\text{old}}$ | 低秩或只调部分层会压低新任务上限；冻结得越多，目标任务越难拟合 |
| 目标 | KL 约束到参考模型（[[finetuning-01]]）、soft-target 蒸馏（[[finetuning-12]]） | 在损失里显式惩罚「输出分布偏离旧模型」，等于给旧行为加约束项 | 约束越强越稳、也越快「学不动」；蒸馏还要跑教师前向，算力与显存上升 |
| 流程 | 持续学习三路线（replay / regularization / parameter isolation）、每次微调后跑通用能力回归集（[[rag-04]]） | 用范式选择与验收标准把遗忘限制在可接受范围内，而不是事后补救 | 回归集要固定评测集与解码参数、要长期维护，评测本身也有算力成本 |

判断顺序：数据分布离预训练越远、epoch 越多、学习率越大、模型相对数据量越小，越需要回放与正则；「先通用指令微调、再垂直微调」这个顺序本身就能降低遗忘（论文结论之一）。约束强度最终由**能力回归集 + 目标任务指标**共同调出来，不是拍出来的。

### 梯度冲突的可测版本

把两个任务设成完全冲突（旧任务 $y=x$，新任务 $y=-x$，单参数线性模型），可以直接量出上文的几何结论：

```python
import torch, torch.nn as nn
X = torch.linspace(-1, 1, 64).unsqueeze(1)
m = nn.Linear(1, 1)
nn.init.constant_(m.weight, 0.5); nn.init.constant_(m.bias, 0.0)
yA, yB = X.clone(), -X.clone()
lossA, lossB = nn.MSELoss(), nn.MSELoss()

def grad(loss_fn, y):
    m.zero_grad(); l = loss_fn(m(X), y); l.backward()
    return [p.grad.clone() for p in m.parameters()]

gA, gB = grad(lossA, yA), grad(lossB, yB)
dot = sum((a * b).sum() for a, b in zip(gA, gB))
nA = sum((a * a).sum() for a in gA).sqrt()
nB = sum((b * b).sum() for b in gB).sqrt()
print(f"<gA,gB>={dot:.4f}  cos={dot / (nA * nB):.4f}")   # cos = -1.0000
```

实测 $\langle g_A, g_B \rangle = -0.3548$、$\cos = -1.0000$。取 $\eta=0.1$，一阶预测 $\Delta L_A = -\eta\langle g_A,g_B\rangle = +0.0355 > 0$：走一步新任务，旧任务损失必然上升。

### 回放配比的实际效果

沿用同一设置（每步 batch 32 条，其中按配比混入旧任务样本，300 步）；这个玩具问题的初始化与数据都固定，换随机种子结果完全相同，下表是确定性的复现值：

| 回放配比 $\rho$ | 旧任务 $L_A$ | 相对初始 | 新任务 $L_B$ |
| --- | --- | --- | --- |
| 0（只训新任务） | 1.3757 | 16.0× | 0.0000 |
| 0.05 | 0.6967 | 8.1× | 0.1959 |
| 0.10 | 0.5494 | 6.4× | 0.3797 |
| 0.25 | 0.5675 | 6.6× | 1.5091 |
| 0.50 | 0.2663 | 3.1× | 0.4580 |

旧任务损失随配比总体下降（0.25 处略有波动），符合回放保旧能力的直觉；但新任务损失从 0.05 的 0.1959 一路升到 0.25 的 1.5091，**回放是在拿新任务拟合速度换旧能力**。这是把两任务梯度设成完全冲突（$\cos=-1$）的最坏情形，真实任务的冲突弱得多，所以不要把这个表里的具体数值当成通用配比结论；0.50 处 $L_B$ 又回落只是这个二维玩具问题的非单调现象。

### 回放的成本账

配比 $\rho$ 的定义是「每个 batch 里旧数据占比」，于是：

- batch 大小不变，所以单步算力不变；但要把同样多的新数据过完，必须多跑 $1/(1-\rho)$ 步，总算力倍率 $\approx 1+\rho$：$\rho=0.05$ 约 1.05×，$\rho=0.10$ 约 1.11×。
- 反向的换算：新数据过 1 个 epoch 时，旧数据只被过 $\rho/(1-\rho)$ 遍（$\rho$ 小时约等于 $\rho$）；想让旧数据也过 1 遍，需要新数据过 $(1-\rho)/\rho \approx 1/\rho$ 个 epoch（$\rho=0.05$ 约 19 个 epoch）。所以「5%–10% 配比」意味着旧数据的更新次数远少于新数据，靠的是**每步都有一个保旧能力的梯度约束**在拉住参数，而不是把旧数据重新学透。

### 显存账：为什么 PEFT 让回放变得可行

按常见的 mixed precision 训练口径，每个**可训练**参数的显存开销是 16 字节：

| 项目 | 精度 | 字节/参数 |
| --- | --- | --- |
| 参数副本 | bf16/fp16 | 2 |
| 梯度 | bf16/fp16 | 2 |
| master weight | fp32 | 4 |
| Adam 一阶矩 $m$ | fp32 | 4 |
| Adam 二阶矩 $v$ | fp32 | 4 |
| **合计** | | **16**（其中优化器状态 12） |

全量微调 7B 模型：$7\times10^9 \times 16\ \text{B} = 104.31$ GiB，其中优化器状态 $7\times10^9 \times 12 = 78.23$ GiB。这个数字就是「7B 全量微调需要 A100 80G 多卡」的来源。

LoRA 只对 adapter 计算梯度与优化器状态，底座冻结。以 Llama-7B 结构（$d_{\text{model}}=4096$、32 层）为例，每个被适配的矩阵 $W \in \mathbb{R}^{d \times d}$ 增加两个低秩矩阵，参数量 $2rd$：

| 配置 | 可训练参数 | 占 7B 比例 |
| --- | --- | --- |
| $r=8$，q、v | $32 \times 2 \times (2 \times 8 \times 4096) = 4.19$M | 0.0599% |
| $r=8$，q、k、v、o | 8.39M | 0.1198% |
| $r=16$，q、k、v、o | 16.78M | 0.2397% |

（对照：原论文的计数公式是 $|\Theta| = 2\hat L_{\text{LoRA}} d_{\text{model}} r$，$\hat L_{\text{LoRA}}$ 是被适配矩阵的个数。GPT-3 175B 有 96 层、$d_{\text{model}}=12288$，适配 $W_q$ 与 $W_v$ 时 $\hat L_{\text{LoRA}}=192$：$r=4$ 得 $2 \times 192 \times 12288 \times 4 = 18.87$M，正好是论文 Table 5 里 18M 参数预算那一档；论文 Table 4 报的是另外两个预算——$r=1$ 的 4.72M 与 $r=8$ 的 37.75M。引用时以原论文数值为准。）

$r=8$、q/v 配置下，可训练参数 4.19M：与可训练参数绑定的训练开销（bf16 权重副本 + 梯度 + fp32 master 与 Adam 状态）从全量微调的 104.31 GiB 降到 $4.19\text{M} \times 16\ \text{B} \approx 0.06$ GiB，约 1600 倍；底座权重以 bf16 常驻约 13.04 GiB，这部分两种方案都要付，所以总显存是 104.31 GiB 对约 13.1 GiB（约 8 倍）。这才是「回放成本可接受」的工程前提：回放把总算力推高约 5%–11%，PEFT 把优化器显存压掉三个数量级，两者相加总成本远低于全量重训。

```python
# 用代码确认 LoRA 参数量口径（含初始为恒等映射的性质）
import torch, torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base, r, alpha):
        super().__init__()
        self.base, self.r, self.scale = base, r, alpha / r
        for p in self.base.parameters():
            p.requires_grad = False
        self.A = nn.Parameter(torch.zeros(r, base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))
        nn.init.kaiming_uniform_(self.A, a=5 ** 0.5)

    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T) @ self.B.T

r, d, L = 8, 4096, 32
blocks = nn.ModuleList([
    nn.ModuleDict({"q": LoRALinear(nn.Linear(d, d, bias=False), r, 16),
                   "v": LoRALinear(nn.Linear(d, d, bias=False), r, 16)})
    for _ in range(L)])
trainable = sum(p.numel() for p in blocks.parameters() if p.requires_grad)
print(trainable)   # 4194304 = 4.194M
```

### KL 与蒸馏的温度因子

目标层两种约束形式：

**KL 到参考模型**（与 RLHF 里的 KL 惩罚同源）：

$$L = L_{\text{new}}(\theta) + \beta \, \mathrm{KL}\!\left(\pi_{\text{ref}}(\cdot \mid x) \,\|\, \pi_\theta(\cdot \mid x)\right)$$

$\beta$ 越大越稳、越容易「学不动」；它和 RLHF 里控制策略偏离参考模型程度的那个系数是同一个角色（[[finetuning-01]]），但方向不同：这里写的是前向 KL（以参考分布为权重，soft-target 交叉熵就是这个 KL 加一个常数），RLHF 目标里用的是反向 KL $\mathrm{KL}(\pi_\theta \| \pi_{\text{ref}})$——前向 KL 要覆盖参考分布的所有众数，反向 KL 更倾向只保留一个，做微调正则时前者更常用。

**soft-target 蒸馏**保留旧模型在旧分布上的完整输出分布，而不是只保留硬标签：

$$L = \mathrm{CE}(y, p_s^{1}) + \alpha T^2 \, \mathrm{KL}\!\left(p_t^{T} \,\|\, p_s^{T}\right), \qquad p^T = \mathrm{softmax}(z / T)$$

$T^2$ 因子不是经验玄学。对 logit $z_i$ 求导，KL 项贡献 $\frac{1}{T}(p_{s,i}^T - p_{t,i}^T)$，乘以 $T^2$ 后变成 $T(p_{s,i}^T - p_{t,i}^T)$。这里其实有两个 $1/T$：公式里显式的那个，以及高温度把分布抹平带来的那个——$p_i^T \approx \frac{1}{K}\left(1 + \frac{z_i - \bar z}{T}\right)$，逐点差 $p_{s,i}^T - p_{t,i}^T$ 本身也按 $1/T$ 缩小。两个因子相乘，不加 $T^2$ 时软标签项的梯度按 $1/T^2$ 衰减（$T=4$ 时只剩约 $1/16$），会被 $O(1)$ 的硬标签梯度淹没；$T^2$ 正好把这个尺度补偿回来，与 [[finetuning-12]] 的数值验证一致。

温度越高，教师分布的相对差异被抹平，KL 本身也随之快速变小（小 logit 极限下正是 $1/T^2$）：用一组示例 logits（教师 `[3.0, 1.0, 0.5]`、学生 `[2.6, 1.2, 0.6]`）算，$\mathrm{KL}(t\|s)$ 从 $T=1$ 的 0.026337 降到 $T=4$ 的 0.002415，小了约 10.9 倍（这组 logits 不在小 logit 极限，所以没有 $T^2=16$ 那么夸张）。这也是 $T$ 通常只取 2–8 的原因：再往上抬，软标签携带的类间差异与它能提供的梯度一起变小。

## 常见追问

- **追问**：怎么量化遗忘？
  - 要点：固定评测集、固定 few-shot 设置与解码参数（temperature、max tokens、停止条件），微调前后各跑一次，报**绝对跌幅**与**相对跌幅** $(R_o - R)/R_o$；再补一个 loss/perplexity 视角（在通用语料上算 NLL）和表示视角（旧任务线性探针在新表示上的准确率）。只报目标任务涨了多少、不报通用能力掉了多少，是无法做决策的评测。
- **追问**：怎么区分灾难性遗忘与「模型变笨了」的主观报告？
  - 要点：主观报告要能落到具体能力项和可复现的评测集上。先查四件事：是不是 chat template / 特殊 token 变了、是不是解码默认值变了、是不是 system prompt 换了、是不是量化或推理配置变了。这些都会造成「变笨」的观感但和权重无关。排掉工程变量后指标仍下降，才归因到遗忘。
- **追问**：为什么规模越大反而更抗遗忘？（与论文结论方向相反时怎么答）
  - 要点：论文的「越大越忘」限定在 1B–7B 且是相对跌幅口径，作者归因于大模型初始分数更高、同样的拟合压力下相对跌幅更显眼。容量更大的模型也能容纳更多互不干扰的子空间，所以在足够大的规模上抗遗忘性通常会改善。回答时把「实验区间」「指标口径」「容量假设」三件事分开说，不要给一条普适规律。
- **追问**：持续学习与多任务学习有什么区别？
  - 要点：多任务学习同时看到所有任务的数据，优化的是联合目标，天然没有顺序问题；持续学习按顺序到达，每个阶段只能看到当前任务数据（旧数据可能完全不可得），因此必须显式对抗顺序带来的偏置。工程上「把通用数据混进垂直数据一起训」其实就是把持续学习问题**退化成**多任务学习，这是最省事也最有效的缓解方式。
- **追问**：EWC 在 LLM 上为什么少见？
  - 要点：EWC 用 Fisher 信息量估计参数重要性，加二次惩罚 $\sum_i F_i(\theta_i - \theta_i^*)^2$ 拉住重要参数。它在小网络上有效，但 LLM 参数量在 $10^9$ 级，估计 Fisher 需要对旧数据做一遍梯度统计（旧数据往往拿不到），而且强约束会显著限制新任务可塑性。实践里 LoRA 这类参数隔离方法用更低的成本拿到了类似效果。
- **追问**：回放会挤占新任务容量，怎么定配比？
  - 要点：同时监控两条曲线——通用能力回归集分数与目标任务指标。从 $\rho=5\%$ 起步，若回归分数掉超过可接受阈值就加大配比或降低学习率；若目标任务涨不动就降配比或减少约束强度。约束强度是**调出来的**，不是拍出来的。

## 公司变体

- **Mistral AI**：这家公司的公开面试信息偏**工程实现与决策**——给定「把基座适配到某垂直领域」的场景，问选全量微调还是 LoRA、数据怎么配比、怎么防止基座能力退化、怎么用评测集验收。准备时把重心放在可执行方案上：具体配比、具体学习率与 epoch 区间、具体回归集怎么搭、显存怎么算（能报出 16 字节/参数的账和 LoRA 的可训练参数量），并说明这些超参是在哪条曲线上调的。原理推导通常只要求到「新旧梯度冲突、目标里缺少旧任务约束」这一层，不要求写 EWC 的 Fisher 推导。
