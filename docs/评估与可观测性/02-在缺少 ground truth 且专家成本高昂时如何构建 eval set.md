## 一句话答案

> 缺 ground truth 时不要去找「标准答案」，而是为每类能力设计**可判定的替代信号**，再用少量专家标注给这些信号做校准。数据来源按性价比排序：真实流量分层抽样 > 生产故障反推 > 强模型合成 > 专家小样本 > 对抗样本，五类都要有，但只有专家那部分需要花钱，规模控制在 150–300 条。专家标注的用途不是给系统打分，而是三件事：校准自动 judge 的系统偏差、仲裁分歧样本、给自动分数打出置信区间。ARES 的三阶段范式就是这条路线：合成数据训练轻量 judge，几百条人工标注做 prediction-powered inference 校正，在 8 个知识密集任务上评出可比较的 RAG 分数。

## 面试官在考什么

- **能不能把「没有 ground truth」拆成数据工程问题**：说清四类替代信号（可验证正确性、专家 rubric、模型间一致性、用户行为）各自的成本与可信度，而不是笼统地说「靠人看 case」。
- **抽样与覆盖设计**：会不会按意图、难度、长度、语言、是否可答、是否需权限过滤分层，并给稀有层留最小配额；真实日志抓一坨是最常见的减分项。
- **合成数据的边界意识**：合成能扩量，但会把生成模型的偏差和风格一起固化；知不知道合成数据的正确用途是训练 judge 与扩量，而不是直接当评分依据。
- **校准与统计素养**：少量人工标注怎么用（PPI、rubric 校准、κ 一致性）、样本量与可检测差异的关系、配对检验与置信区间会不会算。
- **治理闭环**：防污染、季度更新、争议仲裁、把 eval set 与 prompt/模型版本绑定，以及「评测集」与「judge 校准集」必须分开维护。

**常见错误答案**

- 「让强模型生成 1000 条问答对，评测集就有了。」合成集没有校准锚点，测出来的是生成模型自己的偏好；而且合成问题的风格与真实流量分布不同，常见结果是离线分数涨、线上不动。
- 「没有 ground truth，所以只能人工抽检。」人工抽检回答不了回归问题：改动前后是不是变好了，需要同一份固定样本上的配对比较，而抽检每次抽的都不是同一批。
- 「专家标注越多越好。」在 PPI 这类校正框架里，标注的边际收益不是线性的：随机抽的 150 条之后，继续加标注主要是在压 $\mathrm{Var}(Y-f)/n$ 这一项，而 $\mathrm{Var}(f)/N$ 那一项早被未标注池的规模压到可忽略（见第 4 节复算二）。

## 原理与推导

### 把「缺 ground truth」翻译成「设计可判定的替代信号」

Eval set 的目标是可复现地度量你真正关心的能力，不是复刻公开 benchmark。没有标准答案时，替代信号有四类，成本与可信度差别很大：

| 信号 | 怎么得到 | 成本 | 可信度 | 主要失效模式 |
| --- | --- | --- | --- | --- |
| 可验证正确性 | 把问题改造成有确定判定的形式：单测、正则、结构化字段比对、执行结果、引用 span 是否命中 | 一次性改造 | 高（判定无歧义） | 只覆盖任务的一个子集 |
| 专家 rubric | 领域专家写评分标准，在少量样本上打分 | 专家小时 | 高 | 贵；不同专家口径不一致 |
| 模型间一致性 | 多模型互评、同一问题多次采样 | 推理算力 | 中 | 共同偏差无法被发现 |
| 用户行为 | 采纳率、追问率、点踩、放弃会话、人工升级 | 埋点与日志 | 中低（混淆多） | 需要流量；反馈慢且有偏 |

判断标准只有一条：**每个 eval item 必须配一个在每次回归里都付得起的判定程序**。判定程序的单位成本决定 eval set 能有多大，eval set 有多大决定能检出多小的差异——这两步的算术在第 4 节复算三、复算四。

### 数据来源分层（按性价比排序）

1. **真实流量分层抽样**：从日志按意图、难度、长度、语言、是否可答、是否需权限过滤分层抽样，代表性最强。抽样的口径是「每层都要能下结论」，不是「按流量比例分」，两者的差别见复算四。
2. **生产故障反推**：工单、点踩、追问、放弃会话、人工升级记录转成用例。真实失败样本的单位价值最高，因为它既在分布内，又已经被证明会让用户不满；这一类同时是线上监控的输入，链 [[evaluation-03]] 与 [[evaluation-09]]。
3. **合成数据**：两个方向——语料反向出题（文档 → 问题 → 参考答案，链 [[rag-01]]），以及问题正向生成参考答案与判据。合成数据的定位是扩量与造 judge 的训练数据，最终评分依据仍要靠校准。
4. **专家小样本**：150–300 条，只做校准、仲裁、打区间三件事。这是全流程里唯一昂贵且不可替代的部分，所以规模要刻意压住。
5. **对抗与红队样本**：边界、越权、prompt 注入、长尾专有名词。这类样本在真实流量里出现频率极低，但对安全与合规是决定性的，必须显式构造而不能等它自然出现，链 [[rag-08]]。

### 合成 + 少量人工：ARES 的三阶段范式

ARES 把「自动化打分」和「人工标注」的职责彻底拆开，这是它能省标注的关键。论文口径的三阶段：

- **阶段一，造合成数据**：用生成模型从语料 passage 反向生成 query 和 answer。两个细节值得抄：一是**质量过滤**——只保留能把原 passage 检索回 top-1 的合成 query；二是**正负样本都要**，负样本分弱负（随机无关 passage、其它 passage 的答案）与强负（同文档的 passage 或 BM25 top-10 近邻 passage，以及刻意生成的矛盾答案）两类，各占一半。judge 是二分类器，只喂正例会学成「永远说好」。
- **阶段二，训练轻量 judge**：在合成三元组上微调三个独立的分类 judge，分别对应 context relevance、answer faithfulness、answer relevance。judge 轻量的意义是评测可以本地跑、不依赖外部 API，回归成本因此可预测。
- **阶段三，用 PPI 校正并给区间**：judge 在大量无标注数据上打分，人工标注只用来量 judge 的偏差。均值估计量是

$$
\hat\theta_{\mathrm{PPI}} = \underbrace{\frac{1}{N}\sum_{i=1}^{N} f(X_i)}_{\text{judge 在未标注池上的均值}} + \underbrace{\frac{1}{n}\sum_{i=1}^{n}\bigl(Y_i - f(X_i)\bigr)}_{\text{小样本上量到的 judge 偏差}}
$$

第一项方差小但可能整体偏高或偏低，第二项把偏差修回来，近似方差是 $\mathrm{Var}(\hat\theta_{\mathrm{PPI}}) \approx \mathrm{Var}(f)/N + \mathrm{Var}(Y-f)/n$。

由此得到两条实践结论。第一，PPI 修的是**系统性偏差**，不是随机噪声：judge 与人工的分歧率越高，$\mathrm{Var}(Y-f)$ 越大，收益越小，甚至不如全部人工（复算二给出临界点）。第二，两种人工标注的用途必须分开维护：

- 给 PPI 用的标注集必须与未标注池**同分布随机抽样**，否则偏差修正项不成立（分布不同时，在小样本上量到的偏差推不到大池子上）。
- 给 judge 迭代与仲裁用的标注集应该**专挑分歧与边界样本**，因为它的目标是提高 judge 本身的质量。

把这两种标注混成一个池子，是最常见的口径错误。

论文的实验口径与结论（均为论文自报）：三阶段所需的输入是域内 passage 集合、约 150 条以上的人工偏好验证集、5 条以上域内问答 few-shot 例子；实验里 PPI 用了 300 条人工标注（Table 1 口径）、AIS 归因实验用了 200 条；在 25 到 400 条之间扫描时，150 条被论文报告为下限；相比「每个系统各标 150 条」的采样标注基线（9 个系统共 1350 条），论文报告少用 78% 的标注。它覆盖 8 个知识密集任务：KILT 的 NQ、HotpotQA、FEVER、WoW，SuperGLUE 的 MultiRC、ReCoRD，加 AIS 的 WoW 与 CNN/DM。跨域结论是 judge 在 query 类型或文档类型变化后仍然有效；论文还报告 PPI 在全部被测数据集上都提升了 judge 的排名准确率（无 PPI 的消融对照），这是「自动打分必须配小样本人工校准」的实验依据。两条边界也要一起说：KILT 与 SuperGLUE 上**没有**评 answer faithfulness（缺少人工标注的幻觉答案），faithfulness 只在 AIS 上验证；论文还试过用 GPT-4 生成替代人工标注，结论是不如人——校准锚点里必须有一部分是真人工。

### reference-free 指标：Ragas 的口径与它的假设

Ragas 走的是另一条更轻的路：不训练 judge，直接用 LLM 提示词把三个维度算出来，链 [[rag-04]]。三个指标分别是论断支持比例 $F = |V|/|S|$、反向生成问题的相似度均值 $\mathrm{AR} = \frac{1}{n}\sum_{i=1}^{n}\mathrm{sim}(q, q_i)$、以及被抽出的句子占比 $\mathrm{CR} = \frac{\text{被抽出的句子数}}{\text{context 的句子总数}}$。

- **faithfulness $F$**：把答案拆成论断集合 $S$，逐条判断能否由 context 推出，被支持的记为 $V$。
- **answer relevance $\mathrm{AR}$**：由答案反向生成 $n$ 个问题，与原始问题做 embedding 余弦相似度取均值；不看事实性，只看是否真的回答了问题。
- **context relevance $\mathrm{CR}$**：让模型从 context 里抽出回答所必需的句子，用比例惩罚塞入无关内容。

论文在自建的 WikiEval（50 个维基页面，两名标注者；faithfulness 与 context relevance 的标注者一致率约 95%，answer relevance 约 90%，分歧讨论后解决）上给出与人工成对判断的一致率：三个指标分别为 0.95、0.78、0.70；作为对照，让同一模型直接打 0–10 分是 0.72、0.52、0.63，让它从两个候选里选一个是 0.54、0.40、0.52。论文自述 context relevance 最难，长上下文下模型抽句明显变差。

使用时必须带上假设：judge 有位置偏好、冗长偏好与自偏好；$F$ 是比例，同一个错误在短答案里被放大、在长答案里被稀释，所以长短答案的 $F$ 不可直接横向比较；论断拆分出错会同时污染分子与分母。这些偏差的校准方式（人工一致率与 κ）见 [[evaluation-01]]。

### 无 ground truth 时的五类判定方式

| 判定方式 | 怎么做 | 什么时候用 |
| --- | --- | --- |
| 改造成可验证形式 | 从评测集里切出有确定答案的子集：数值、日期、枚举、SQL/代码执行结果、引用命中 | 任务本身有一部分可判定时，优先做这一块，它没有判定噪声 |
| 专家 rubric | 把「好」写成 3–5 档的判据，专家只在小样本上打分，用来校准自动 judge | 主观质量、语气、合规性这些无法自动判定的维度 |
| 成对比较 | 同一问题给两版答案，让 judge 或人选更好的那个；交换顺序各判一次 | 比较两个版本：相对判断对尺度漂移不敏感，但位置偏差会直接变成胜率偏差，必须交换顺序；模型成对不一定优于绝对打分（上文的 GPT Ranking 0.54/0.40/0.52 低于 GPT Score 0.72/0.52/0.63），链 [[evaluation-01]] |
| 一致性采样 | 同一问题采样 $k$ 次，看事实性内容是否稳定；不稳定的部分大概率是幻觉 | 无参考答案但有生成冗余度时，做高精确率的筛查器 |
| 用户行为信号 | 采纳率、追问率、会话成功率、点踩率、人工升级率 | 上线后的最终裁判，用来验证离线指标是否测对了东西 |

### 规模、采样与治理

- **规模**：100–500 条起步。ARES 报告的 150 条下限可以当作量级参照，它对应的是「judge 偏差估计」这个用途；如果还要按层下结论，配额要求会更高（复算四）。
- **分层**：单跳、多跳、无答案、长尾、多语言、需权限过滤各留最小配额，稀有层宁可牺牲主层精度也要保底。
- **更新**：季度刷新，语料或产品形态变化时提前；新文档入库后检查是否与评测集重复（防污染，链 [[evaluation-06]]）。
- **标注治理**：写标注指南，多人标注算 κ，争议样本进仲裁队列而不是投票了事；仲裁结果要回写指南。
- **版本化**：eval set 有版本号，与 prompt 版本、模型版本一起记录，回归结论才能复现，链 [[evaluation-08]]。

## 数值与代码验证

### 复算一：ARES 的标注账与 Table 1

论文没有直接给出「78%」是怎么算的，按它自己的两组口径复算：采样标注基线是每个 mock 系统 150 条 × 9 个系统 = 1350 条，ARES 的实验用 300 条，

$$
1 - \frac{300}{1350} = 77.8\% \approx 78\%
$$

自洽。Table 1 的单条判定准确率逐项取平均（6 个数据集，C.R. 为 context relevance，A.R. 为 answer relevance）：

| 指标 | RAGAS 平均 | ARES 平均 | 差值 |
| --- | --- | --- | --- |
| context relevance | 23.30% | 83.22% | +59.92 个百分点 |
| answer relevance | 73.67% | 88.02% | +14.35 个百分点 |

A.R. 与论文正文的 14.4 一致；C.R. 复算是 59.9，与正文 5.1 节的 59.9 一致，而引言（第 1 节）写的是 59.3——同一篇论文内部这两个数字不统一，按 Table 1 逐项复算支持 59.9。引用时要么写「约 60 个百分点」并按复算口径说明，要么直接引 Table 1 的原始行，别把引言的 59.3 与正文的 59.9 混着用。

### 复算二：PPI 什么时候真的省标注

取真实通过率 $p = 0.80$、未标注池 $N = 2000$、人工标注 $n = 150$，纯人工评分的标准误是

$$
\mathrm{SE}_{\text{纯人工}} = \sqrt{\frac{p(1-p)}{n}} = \sqrt{\frac{0.16}{150}} = 0.0327
$$

PPI 的标准误按 $\sqrt{\mathrm{Var}(f)/N + \mathrm{Var}(Y-f)/n}$ 算，二值情形下 $\mathrm{Var}(Y-f) = P(\text{分歧}) - \text{bias}^2$，取 $\mathrm{Var}(f) = p(1-p) = 0.16$、偏差 0.03：

| judge 与人工的分歧率 | $\mathrm{Var}(Y-f)$ | PPI 标准误 | 等效纯人工条数 | 相比纯人工 |
| --- | --- | --- | --- | --- |
| 5% | 0.0491 | 0.0202 | 393 | 省 62% |
| 10% | 0.0991 | 0.0272 | 216 | 省 31% |
| 15% | 0.1491 | 0.0328 | 149 | 持平 |
| 25% | 0.2491 | 0.0417 | 92 | 反而更差 |

临界点是 $\mathrm{Var}(Y-f) \approx p(1-p)$，即分歧率约等于结果方差（$p = 0.8$ 时约 16%）。这条判据直接决定架构：judge 与人工一致率 90% 以上时，几百条标注就能撑起一个上万条规模的评测池；一致率只有 75% 时，PPI 不比纯人工便宜，应该先去改 judge（补分歧样本、重新微调），而不是加标注预算。这里的数字是按上述公式算的示意算例，不是论文数字。

### 复算三：样本量与可检测差异

同一份评测集上比较两个版本是配对实验，检验用 McNemar，只看两版判定不一致的样本对。所需样本量的近似式与给定样本量下的最小可检测差异（MDE）是

$$
N \approx \frac{(z_{\alpha/2} + z_\beta)^2 \pi_d}{\delta^2}
\qquad
\delta_{\min} \approx (z_{\alpha/2} + z_\beta)\sqrt{\frac{\pi_d}{N}}
$$

$\pi_d$ 是两版判定不一致的比例，取 $\pi_d = 0.10$、$\alpha = 0.05$ 双侧、功效 80%（下表按 McNemar 精确式 $N = \left(z_{\alpha/2}\sqrt{\pi_d} + z_\beta\sqrt{\pi_d - \delta^2}\right)^2/\delta^2$ 计算，与上面的简化式相差 3% 以内；下面的 MDE 用简化式）：

| 要检出的绝对差 | 所需样本量 | 说明 |
| --- | --- | --- |
| 2 个百分点 | ≈ 1960 | 200 条的集子做不到，别拿它排名 |
| 3 个百分点 | ≈ 870 | 需要跨会话累积或合并季度数据 |
| 5 个百分点 | ≈ 312 | 300 条量级的主要用途 |
| 10 个百分点 | ≈ 76 | 大改动、明显故障 |

反过来看：$N = 200$ 时 MDE 约 6.3 个百分点（$\pi_d = 0.10$）或 8.9 个百分点（$\pi_d = 0.20$），$N = 500$ 时才降到 4.0 与 5.6 个百分点。同样地，单版本正确率的 Wilson 区间在 $N = 200$、$\hat p = 0.80$ 时是 $[0.739, 0.850]$，半宽 ±5.5 个百分点。两个结论合起来就是「100–500 条起步」的算术依据，也是「评测集要分层」的原因：分层之后每层只剩几十条，只能发现大问题。

### 复算四：分层配额——稀有层的精度要用主层的精度换

取一份流量分布示意（单跳 42%、多跳 18%、无答案 6%、长尾 12%、多语言 14%、需权限过滤 8%），总量固定 300 条，比较三种分配：

| 层 | 流量占比 | 比例分配 n / 95% 半宽 | 均分 n / 半宽 | 配额（≥45）n / 半宽 |
| --- | --- | --- | --- | --- |
| 单跳事实问答 | 42% | 126 / ±6.7 个点 | 50 / ±10.5 | 66 / ±9.2 |
| 多跳、多文档 | 18% | 54 / ±12.5 | 50 / ±13.0 | 54 / ±12.5 |
| 无答案、应拒答 | 6% | 18 / ±20.9 | 50 / ±13.3 | 45 / ±14.0 |
| 长尾专有名词 | 12% | 36 / ±15.2 | 50 / ±13.1 | 45 / ±13.8 |
| 多语言 | 14% | 42 / ±13.4 | 50 / ±12.3 | 45 / ±12.9 |
| 需权限过滤 | 8% | 24 / ±18.6 | 50 / ±13.4 | 45 / ±14.0 |

三件事值得注意。第一，比例分配下「无答案」层只有 18 条，95% 半宽 ±21 个百分点——这一层退步 20 个点都看不出来，而它恰恰是 RAG 系统最容易出问题的地方（该拒答时硬答）。第二，均分看起来公平，但它把 300 条摊成六份，每层半宽都落在 ±10.5 到 ±13.4 之间，同样下不了细结论。第三，**Neyman 分配在这里帮不上忙**：它最小化的是总体均值的方差，而各层的 $p(1-p)$ 差别不大（0.148 对 0.25），分配结果几乎退化成比例分配，「无答案」层仍然只分到 20 条。Eval set 的目标是「每一层都不退化」，正确做法是给稀有层设最小配额，接受主层精度从 ±6.7 放宽到 ±9.2 的代价。另外，想把任何一层压到 ±5 个点都需要 227–385 条，单个 300 条的集合做不到——按层下结论要么合并层，要么单独建一个专项集。

### 复算五：一致性采样当筛查器，用 100 条人工标注定阈值

一致性采样的逻辑是：同一问题采样 $k$ 次，事实性内容稳定出现的部分大概率是真的。若某条幻觉论断每次被采样到的概率为 $q$，它连续 $k$ 次全部出现（伪装成稳定内容）的概率是 $q^k$：

| $q$ | $k = 1$ | $k = 3$ | $k = 5$ | $k = 7$ |
| --- | --- | --- | --- | --- |
| 0.2 | 0.2000 | 0.0080 | 0.0003 | 0.0000 |
| 0.3 | 0.3000 | 0.0270 | 0.0024 | 0.0002 |
| 0.5 | 0.5000 | 0.1250 | 0.0312 | 0.0078 |
| 0.7 | 0.7000 | 0.3430 | 0.1681 | 0.0824 |

$k = 5$ 就能把「一半时候才编出来」的幻觉压到 3% 以下，而 $q = 0.7$（模型相当自信地重复错误）在 $k = 7$ 时仍有 8% 蒙混过关——一致性采样是筛查器，不是判据。

阈值要用人标注定。示意算例：100 条人工标注，按一致性分桶后的精确率是

| 一致性区间 | 条数 | 人工判对 | 精确率 |
| --- | --- | --- | --- |
| [0, 0.4) | 8 | 3 | 0.375 |
| [0.4, 0.6) | 12 | 6 | 0.500 |
| [0.6, 0.8) | 20 | 15 | 0.750 |
| [0.8, 1.0) | 45 | 43 | 0.956 |
| = 1.0 | 15 | 15 | 1.000 |

取阈值 0.8，能筛出 60 条、精确率 96.7%，但只覆盖全部判对样本的 70.7%——**高精确率、有限召回**，正好适合当自动门禁的通过条件，剩下的 40% 交给人或 judge 处理。这 100 条标注就是「专家成本高昂」时最该花的那笔钱：它不是评测集，是校准这条曲线、让自动化信号可用的前提。

### 复算六：多名标注者的一致率与 κ

少量专家标注还有一个隐藏成本：口径不一致。若单个标注者的错误率为 $e$，3 人多数投票后的错误率是 $3e^2 - 2e^3$：$e = 0.10$ 时降到 0.028，$e = 0.20$ 时只降到 0.104。多数投票的收益随 $e$ 迅速衰减，所以「3 人标 100 条量出 $e$，其余单人标注 + 分歧仲裁」比「所有条目都 3 人标」划算。

一致率本身要用 κ 校正，因为边际分布会骗人：100 条里 A、B 各判 yes 95 条、同时 yes 90 条时一致率 0.90，而偶然一致率 $p_e = 0.905$，$\kappa = -0.05$——高一致率只是因为「判 yes」是默认行为。另一个例子：A 判 yes 60 条、B 判 55 条、同时 yes 50 条时一致率 0.85、$p_e = 0.51$、$\kappa = 0.69$。标注验收要同时报一致率、κ 与分歧样本清单，只报一致率会把「大家都懒得多想」读成标注质量好。

```python
"""分层配额 + 一致性阈值校准：无第三方依赖。"""
import math

ZA = 1.959964  # alpha = 0.05 双侧

def wilson_half(p, n):
    d = 1 + ZA * ZA / n
    return ZA * math.sqrt(p * (1 - p) / n + ZA * ZA / (4 * n * n)) / d

STRATA = [("单跳事实问答", 0.42, 0.82), ("多跳、多文档", 0.18, 0.62),
          ("无答案、应拒答", 0.06, 0.55), ("长尾专有名词", 0.12, 0.60),
          ("多语言", 0.14, 0.70), ("需权限过滤", 0.08, 0.50)]
N, FLOOR = 300, 45

quota = [max(FLOOR, round(N * w)) for _, w, _ in STRATA]
while sum(quota) > N:                      # 从最大的层回收，直到总量回到 N
    i = max(range(len(quota)), key=lambda k: quota[k] if quota[k] > FLOOR else -1)
    if quota[i] <= FLOOR:
        break
    quota[i] -= 1
for (name, w, p), n in zip(STRATA, quota):
    prop = round(N * w)
    print(f"{name:<14} 流量{w:>5.0%} 比例分配 n={prop:>3}(±{wilson_half(p, prop):.3f})"
          f" 配额 n={n:>3}(±{wilson_half(p, n):.3f})")

# 一致性分桶：(一致性下界, 条数, 人工判对条数)，最后两桶合并为阈值 0.8
BINS = [("[0,0.4)", 8, 3), ("[0.4,0.6)", 12, 6), ("[0.6,0.8)", 20, 15),
        ("[0.8,1.0)", 45, 43), ("=1.0", 15, 15)]
KEPT = BINS[3:]                            # 取一致性 >= 0.8 的两个桶
kept_n, kept_k = sum(b[1] for b in KEPT), sum(b[2] for b in KEPT)
tot_k = sum(b[2] for b in BINS)
print(f"阈值 0.8：筛出 {kept_n} 条，精确率 {kept_k / kept_n:.3f}，"
      f"召回 {kept_k / tot_k:.3f}")
```

## 常见追问

- **追问**：合成数据会不会把生成模型的偏差固化进评测？
  - 要点：会，而且最难发现，因为偏差与被评系统同源。三条对策：合成数据只用来训练 judge 或扩量，评分必须过一遍人工校准（ARES 的 PPI 就是显式量这个偏差）；生成模型、judge、被评模型尽量来自不同族，避免自偏好；保留一份**纯人工、永不参与训练**的锚点集，它的分数变动就是偏差漂移的报警器。
- **追问**：怎么证明这个 eval set 有区分度？
  - 要点：三条检验。一是能不能把已知强弱的模型分开——故意放一个明显更差的配置进去，如果评测集读不出差距，问题在评测集不在模型；二是组间方差是否够大——同一配置重复跑（换随机种子、换采样）得到的分数波动要明显小于被测差异，否则测的是噪声；三是与人工判断的一致率，抽 50–100 条算一致率与 κ。
- **追问**：评测集会不会被「刷」？
  - 要点：会。公开化、反复用于调参、或者把评测题泄漏进训练/提示，都会让分数失真（链 [[evaluation-05]]、[[evaluation-06]]）。对策是留一份只用于最终验收的 holdout 集、定期轮换、把评测题的改写版本与原始版本分开维护，并监控「分数涨但线上指标不动」这种典型信号。
- **追问**：没有足够的专家，rubric 谁来写？
  - 要点：让专家写一次、用很久。做法是把 rubric 写成明确到可操作的判据（每条含正例与反例），先让 1 名专家定稿，再用它去审核模型标注；专家的时间从「逐条打分」转为「审核与仲裁」，边际成本从小时级降到分钟级。争议样本累积到一定量再请专家批量看一次。
- **追问**：100 条够不够？
  - 要点：看用途。只做「judge 与人工的分歧率」估计，100 条约有 ±7 个点的 95% 区间（$\hat p = 0.85$ 时），够判断 judge 能不能用；要做版本间的发布门禁，按复算三，200 条只能发现 6 个百分点以上的差异。所以规模由「要回答的问题」倒推，不是拍一个数字。ARES 报告的 150 条下限也是同一个量级的经验值。
- **追问**：多语言和长尾覆盖不到怎么办？
  - 要点：不要按流量比例分配，给稀有语言和长尾术语设最小配额（复算四）；合成数据在这里最有用，因为可以定向生成稀有语言的 query，但必须由母语者或领域专家抽检一批，确认不是「机器翻译腔」。长尾层的指标单独报，不要混进总平均。

## 公司变体

- **Cohere**：落点偏工程实现。这家公司的产品形态是企业侧 LLM 平台（模型、Embed、Rerank），客户以私有语料和私有/托管部署为主，公开 benchmark 无法替代客户自己的评测。因此这题在他们那里通常不停在「推导 PPI 公式」，而是往系统侧推：在企业语料上怎么用文档反向造题得到足够有代表性的 query；怎么把少量客户方业务专家的标注用在 judge 校准与仲裁上；rerank、citation 这类可验证信号能不能直接构成评测子集；以及把评测的成本与延迟算进产品预算（judge 要能本地跑、回归要能每天跑）。统计侧的追问（置信区间、样本量、一致性）会出现，但落点仍是「这套评测能不能支撑上线决策」。具体面试流程不在公开信息范围内，这里只描述能力落点。
- **Harvey**：落点偏工程实现，但约束比通用场景更紧。这家公司的产品面向法律领域的专业任务，专家就是律师，单位时间成本极高、可支配时间极少，这正是本题「专家成本高昂」的极端版本。可以预期的落点是：怎么把律师的时间压缩到只做 rubric 定稿与争议仲裁；怎么用引用与法条检索这类**可验证信号**构造免人工的评测子集；怎么在没有标准答案的情况下度量「引用是否真的支撑该论断」；以及合规与拒答行为怎么单独成层评测。数学推导不是主戏，评测口径与专家时间的预算分配才是。同样地，具体面试流程不在公开信息范围内。
