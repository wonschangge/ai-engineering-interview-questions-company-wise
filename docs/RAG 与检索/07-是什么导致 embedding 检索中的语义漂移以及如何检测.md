## 一句话答案

> 「语义漂移」不是一种故障，而是四类故障的统称：**查询分布漂移**（新话题、新术语、新语言）、**语料漂移**（文档更新、领域扩张、版本更替）、**编码器/模型版本漂移**（换 checkpoint、换维度、换归一化或指令前缀），以及**索引写入侧漂移**（增量写入的向量与建库时的编码器或预处理不一致）。
> 四类的检测量与修复手段都不同，先把它们分开，再给每一类配敏感的信号。
> 工程上最容易犯的错是把抽样噪声当成漂移：500 条 query 的 recall@10 的 95% 置信区间有 $\pm 4.0$ 个百分点，query 向量均值位移的噪声底是 $\sqrt{2/n}\approx 0.063$。监控面板要先画出每个指标的噪声底与告警阈值，再谈「指标掉了」。

## 面试官在考什么

- 能否把「漂移」拆成可分别观测、可分别修复的几类，而不是笼统地说「模型退化了」。
- 是否理解漂移伤检索的机制：query 或 document 落到训练分布之外时，退化的不只是相似度的绝对值，而是**相似度的排序**。
- 是否区分三个观测面并知道各自的盲区：离线金标指标、向量与分数的分布统计、线上行为信号。
- 有没有统计功效意识：样本量、噪声底、阈值校准、按 segment 拆分，而不是盯着总指标的一位数小数。
- 修复路径是否完整：重嵌入与迁移方案、版本绑定、hybrid 兜底、告警与回滚。

常见的错误答案：

- 只答「定期重跑评测集，看指标有没有掉」。这既区分不了 query 侧和语料侧，也没有噪声底，指标抖 2 个点就会被当成漂移，或者漂移了 10 个点还被当成抖动。
- 把「换一个更强的 embedding 模型」当万能解。MTEB 的结论是没有模型在所有任务上都最好，换模型还会顺手引入第四类漂移（同一个索引里新旧向量混用），迁移期的检索质量可能比换之前更差。

## 原理与推导

### 四类漂移：触发条件、观测面与修复

| 类别 | 典型触发 | 对它敏感的观测面 | 修复手段 |
| --- | --- | --- | --- |
| ① 查询分布漂移 | 新话题、新术语、新语言、新租户、季节性 | query 向量均值位移、聚类数与簇心、Top-1 相似度分位数、零结果率、未命中 query 的聚类 Top 词 | query 改写/扩写、术语表、领域适配、按 segment 校准阈值 |
| ② 语料漂移 | 文档更新、领域扩张、版本更替、批量删除 | gold 缺失率、按 segment 的 recall@k、索引覆盖率、删除生效延迟 | 补齐或重建受影响分片，保持 chunker 与预处理版本一致 |
| ③ 编码器/模型版本漂移 | 换 checkpoint、换维度、换归一化、换指令前缀、换 tokenizer 或池化 | 单向量余弦、影子重编码的 Top-k 重合率、绝对相似度整体平移 | 全量重嵌入 + 双索引蓝绿切换，向量写入模型元数据 |
| ④ 索引写入侧漂移 | 增量写入用了另一个模型或另一套预处理，回填任务与实时链路不一致 | 同一 query 两次编码不一致、混用状态下的 recall 断崖、向量元数据校验 | 写入网关强校验版本，禁止跨版本原地替换 |

把这四类混成一句「embedding 漂移了」是这题最常见的失分点：①③ 的修复是换编码或改查询，② 的修复是补数据，④ 的修复是修管道，方向完全不同。

### 为什么漂移会伤检索

embedding 空间是一个**在特定数据分布上训练出来的度量**：$\cos(q, d)$ 只在训练覆盖的区域内近似等于「语义接近」。query 或 document 落到分布之外，相似度的排序就不再是相关性的排序。

BEIR 给出的是这条机制的直接证据（zero-shot 口径：18 个公开数据集、9 类检索任务、10 个检索系统；数字与结论来自论文 v4）：**BM25 是一个稳健的 baseline**，dense 与 sparse 检索在跨域场景下常常不如它；re-ranking 与 late-interaction 平均表现最好，但计算代价高。论文还指出，模型的 in-domain 表现与它的跨域泛化能力并不相关——也就是说，在 MS MARCO 上刷出来的分数不能预测漂移之后的排序质量。另外，BEIR 报告数据集本身存在 lexical bias（用 TREC-COVID 补全缺失的相关性标注后，非词汇模型的表现明显提升），这提醒我们：指标下降也可能是**评测集过时**，而不是检索退化。

MTEB 从另一个角度补上结论（口径：8 类 embedding 任务、58 个数据集、112 种语言、33 个模型）：**没有任何一种 embedding 方法在所有任务上都占优**。所以「换模型」不是漂移的通用解，必须按自己的任务与分布去评测。

### 检测统计量与它们的噪声底

**(a) query 向量均值位移。** 用两个时间窗的均值向量之差的模长衡量分布整体平移：

$$
\hat{\Delta}=\|\bar{x}_B-\bar{x}_A\|,\qquad
\mathbb{E}\big[\hat{\Delta}^2\big]=\Big(\frac{1}{n}+\frac{1}{m}\Big)\big(1-\|\mu\|^2\big)
$$

依据是两个窗内样本独立同分布、$\mathbb{E}\|\bar{x}-\mu\|^2=\frac{1}{n}\mathbb{E}\|x-\mu\|^2$。在 L2 归一化向量上，768 维随机几何的 $\|\mu\|^2\approx 1/d \ll 1$，于是**噪声底约为 $\sqrt{2/n}$**：$n=m=500$ 时是 $0.063$。这条底的用途是：位移小于它就只是抽样噪声，不要报警。

**(b) 分布形状。** 均值位移看不见「形状变了但均值没动」的情况（例如 30% 流量切到了另一个话题簇）。用两样本 KS 统计量比较 Top-1 相似度分布，5% 显著性的大样本临界值约为 $1.36\sqrt{(n+m)/(nm)}$；用直方图则用 PSI 或 JS 散度：

$$
\mathrm{PSI}=\sum_i (q_i-p_i)\ln\frac{q_i}{p_i},\qquad
\mathrm{JSD}=\tfrac12 D_{\mathrm{KL}}(P\|M)+\tfrac12 D_{\mathrm{KL}}(Q\|M),\quad M=\frac{P+Q}{2}
$$

PSI 的 0.1 提示、0.25 报警是风控领域的惯例，不是普适常数：它依赖参考窗的展布，必须在自己的数据上按周窗口校准（见第 4 节的两个例子）。

**(c) 核方法。** MMD² 的无偏估计 $\widehat{\mathrm{MMD}}^2=\frac{\sum_{i\ne j}k(x_i,x_j)}{n(n-1)}+\frac{\sum_{i\ne j}k(y_i,y_j)}{m(m-1)}-\frac{2\sum_{i,j}k(x_i,y_j)}{nm}$ 配合置换检验可以给 p 值，但置换次数 $B$ 把 p 值下限压在 $1/(B+1)$（$B=300$ 时为 0.0033），且高维小样本下 RBF 核的 median heuristic 会选出很宽的核、功效下降。均值位移这类线性统计量在这种场景往往更实用，MMD 适合做补充证据而不是唯一判据。

**(d) 编码器扰动的几何。** 把「重新编码带来的误差」建模成 $\mathrm{enc}_2(x)=\mathrm{unit}(x+\sigma n)$，$n$ 为各向同性单位噪声，则同一文本在两版编码器下的余弦期望是

$$
\mathbb{E}\cos\big(\mathrm{enc}_1(x),\mathrm{enc}_2(x)\big)\approx \frac{1}{\sqrt{1+\sigma^2}}
$$

$\sigma=0.1$ 时是 0.995——**看起来「几乎没变」，但排序只取决于 top-k 边界附近的 margin，而它只有 0.003 量级**（第 4 节表 2 的合成集口径）：$\sigma=0.1$ 这种「余弦只掉 0.005」的扰动已经让 nDCG@10 掉 8.2 个点、Top-10 集合换掉四分之一。所以「新旧向量余弦 0.995」不能作为「迁移安全」的证据。

**(e) 绝对相似度的噪声口径。** 若索引里有 $N$ 篇文档、向量是 $d$ 维近似随机方向，则「无关 query 的 Top-1 余弦」约为 $\sqrt{2\ln N/d}$：$N=2\times10^4, d=768$ 时约 0.16，$N=10^6$ 时约 0.19。这决定了「无命中」阈值不能拍脑袋定在 0.5。

### 四层检测与归因流程

1. **离线金标层**：固定的 gold（query → 期望 chunk）集合，按语言/租户/topic 簇拆开，跑 recall@k、nDCG@k、MRR 的时间序列；同时记录 **gold 缺失率**（标注的期望文档已不在索引里）。评测方法本身见 [[rag-04]]。
2. **分布统计层**：query 均值位移与 $\sqrt{2/n}$ 底、协方差与各向异性（比较同一窗 query 在前几个主方向或固定随机投影上的方差，比直接比 $768\times768$ 协方差矩阵稳）、Top-1 相似度分位数与 KS/PSI、聚类数量与簇心漂移、新词与未登录词比例。
3. **线上信号层**：零结果率、点击与采纳率、Top-1 相似度分布、rerank 前后分数差、追问率、点踩率、检索耗时。
4. **一致性自检层**：同一 query 隔时重放看排名变化；语料更新后抽样复查旧文档是否还能被召回（删除、分片重建或版本更替造成的覆盖率损失）；抽样 1% 语料做**影子重编码**，比较新旧编码器的 Top-10 重合率；校验向量元数据里的模型 id、维度、归一化方式、指令前缀与分块器版本。

归因顺序：先按 segment 拆分（聚合会稀释，见第 4 节），再看 gold 缺失率区分「模型漂移」与「语料/索引漂移」，最后用影子重编码判断是否是编码器版本主导。零结果率上升是检索侧问题；有结果但没人点，更像生成、展示或阈值问题。

修复方向对应四类漂移：查询侧用改写/扩写与术语表（[[rag-05]]）；语料侧补齐或重建分片并保证 chunker 版本一致（[[rag-11]]）；模型侧全量重嵌入 + 双索引蓝绿切换；组合层用 hybrid 检索兜底（[[rag-02]]），因为 BM25 对词汇分布变化更鲁棒。告警阈值取噪声底的若干倍（例如 3 倍），并配灰度与回滚。

落到面板上就是五条常驻曲线：① 按 segment 的离线金标 recall@k/nDCG@k（周/月粒度）；② Top-1 相似度分位数与 PSI/KS；③ 零结果率；④ 未命中 query 聚类的 Top 词与未登录词比例；⑤ query 均值位移与噪声底之比、影子重编码的 Top-10 重合率。每条线都配「噪声底 → 阈值 → 处置」三联：先按 segment 判断偏查询侧还是偏语料侧，再决定改查询（改写、术语表）、补数据/重建分片，还是全量重嵌入与蓝绿切换。

| 0.30 | 1.000 | **0.506** | 0.910 |

口径：表 3 只对文档向量加噪、查询侧保持旧编码器的输出，用来单独隔离「索引内混版本」这一项的代价；表 2 是查询与文档两侧都独立重编码，两表的 recall@10 不是同一口径，不能直接相减（两侧都重编码时 $\sigma=0.2$ 的值见表 2 的 0.926）。混用之所以致命，是因为旧向量与旧编码器产出的 query 余弦不降（约 0.894），而新编码的文档统一乘上约 $1/\sqrt{1+\sigma^2}$ 的收缩因子（$\sigma=0.2$ 时约 0.98），旧文档因此被系统性抬高、新文档被压低，排序错乱。

这就是「模型升级后必须重建、不能原地增量替换」的量化理由：$\sigma=0.2$ 时索引侧全量换新只损失 3.4 个点，而迁移到一半的中间态损失 43 个点，比任何一个一致状态都差得多。落地方式只能是双索引（新库建好、验证、切流、删旧库）。

这一格很关键：新簇的相关文档大量缺失时，Top-1 相似度分布可能完全不报警（新 query 仍然能命中一个「像」的文档），只有按 segment 拆分的离线金标指标与 gold 缺失率能抓到。反过来，若漂移是**话题整体平移**（同一批 query 移向新方向），Top-1 相似度与 KS 会非常敏感、recall@k 却可能纹丝不动——两类信号必须同时装。

重嵌入的算力本身不是瓶颈（$2PT$ 口径下 512 token 序列的 attention 项只占约 7.9%），真正贵的是索引重建、双写存储和验证窗口的工程时间——这决定了「多久做一次全量重嵌入」应该是季度级动作，日常靠影子重编码与分布监控兜住。

监控函数的核心就四行统计量，把它接到你的线上窗口上：

```python
import numpy as np

def ks_stat(a, b):
    a, b = np.sort(a), np.sort(b)
    grid = np.concatenate([a, b])
    return float(np.max(np.abs(np.searchsorted(a, grid, "right") / len(a)
                             - np.searchsorted(b, grid, "right") / len(b))))

def psi(base, cur, bins, eps=1e-4):
    b = np.clip(np.histogram(base, bins)[0] / len(base), eps, None)
    c = np.clip(np.histogram(cur, bins)[0] / len(cur), eps, None)
    return float(((c - b) * np.log(c / b)).sum())

def drift_report(mu_a, mu_b, top1_a, top1_b, bins):
    """两个时间窗的 query 侧快照：均值向量 + 每条 query 的 Top-1 相似度"""
    n, m = len(top1_a), len(top1_b)
    disp = float(np.linalg.norm(mu_b - mu_a))
    floor = float(np.sqrt((1 / n + 1 / m)))        # 归一化向量的抽样噪声底
    return {"disp": round(disp, 4), "floor": round(floor, 4),
            "disp/floor": round(disp / floor, 2),
            "PSI": round(psi(top1_a, top1_b, bins), 4),
            "KS": round(ks_stat(top1_a, top1_b), 4),
            "KS_crit5": round(1.36 * float(np.sqrt((n + m) / (n * m))), 4)}
```

在表 4 那组数据（A 窗 500 条老簇 query，B 窗 450 条老簇 + 50 条新簇 query，分箱用 A 窗的 10 个分位点）上，它输出：

```text
{'disp': 0.1022, 'floor': 0.0632, 'disp/floor': 1.62,
 'PSI': 0.0326, 'KS': 0.04, 'KS_crit5': 0.086}
```

即：均值位移是噪声底的 1.62 倍（值得看一眼），而 KS 与 PSI 都没过线——与表 4 的结论一致：**这一类漂移要靠分 segment 的金标指标抓，而不是靠分数分布**。作为对照，两个窗口都取自老簇（无新话题流量、主题混合一致）时，位移是噪声底的 1.03 倍、KS 0.052、PSI 0.018：$n=500$ 时 KS 的抽样波动本身就接近临界值的一半，单靠它报警会被噪声淹没。

## 常见追问

- **追问**：怎么判断是漂移还是评测集过时？
  - 要点：看 gold 缺失率与标注覆盖。BEIR 自己就报告了数据集存在 lexical bias，补全缺失标注后非词汇模型明显提升；同样的，你的 gold 集如果只覆盖老话题，新话题的失败不会被它反映。做法是：固定一批标注 query 做时间序列（同一批 query、同一批 gold，只看检索结果变化），另抽新 query 人工/LLM 判相关性并滚动并入 gold，把「gold 缺失率」当独立指标。
- **追问**：重嵌入的成本与停机怎么安排？全量还是增量？
  - 要点：先分类。维度、归一化、池化、指令前缀、tokenizer 任一变化都必须全量重嵌入 + 重建索引（表 3 的中间态最危险）；纯语料新增用增量 upsert 即可（[[rag-11]]）。成本按 $2PT$ 估：100 万 chunk × 300 token、110M 参数编码器约 $6.6\times10^{16}$ FLOPs，单卡 A100 按 30% 利用率约 12 分钟，可以离线跑；停机靠双索引蓝绿 + 影子流量验证避免。
- **追问**：为什么不能只监控线上点击率？
  - 要点：点击是行为信号，受位置偏差、曝光策略、结果摘要质量影响，而且滞后、稀疏；漂移期出现「有结果但都不相关」时点击率可能因为用户乱点而不降。稳健做法是把点击当作辅助证据，主判据是分 segment 的离线金标指标 + 分布统计 + 零结果率，再用 interleaving 之类的在线 A/B 做因果确认。
- **追问**：模型升级后为什么必须重建，而不是增量追加？
  - 要点：不同版本的向量空间不可比，混用会让近邻排序被打乱。表 3：$\sigma=0.2$ 时索引侧全量换新后 recall@10 仍有 0.966，而迁移一半的中间态只有 0.566。同一索引内混版本等于给每个 query 制造一个隐性偏差；跨版本内积没有任何校准意义。
- **追问**：只监控「新旧向量余弦」够不够？
  - 要点：不够。表 2 里单向量余弦 0.995 时 nDCG@10 已经掉 8.2 个点、Top-10 集合变了 24%。向量级余弦是**平均量**，会掩盖 top-k 附近的顺序变化；要加影子重编码的 Top-k 重合率、离线指标的 nDCG@k，以及分数分布的下尾（p5/p1）。
- **追问**：阈值怎么定，才不会被报警淹没？
  - 要点：先算噪声底再定阈值。均值位移取 $3\sqrt{2/n}$；KS 取 $1.36\sqrt{(n+m)/(nm)}$ 的 1.5–2 倍；PSI/JS 用过去 8–12 周窗口的分位数分布做参考并按分位分箱；所有阈值按 segment（语言、租户、topic 簇）分别校准，否则小 segment 的噪声会淹没大盘。

## 公司变体

**Cohere**：这题出现在 Cohere 的公开题库里（见仓库 README 的 Cohere 段落），从公开信息与产品形态看，它偏**工程实现与生产运维**而不是纯数学推导——Cohere 对外提供托管的 embedding 与 rerank 模型，客户会遇到模型版本升级、既有语料重新嵌入、私有化部署与索引迁移这些真实问题，所以「四类漂移怎么区分、指标噪声底怎么算、迁移怎么做到不停机不混版本」比公式本身更贴题。
